# avoidance Context

> 서비스 핵심 도메인(정책). 위험도 산출의 입력이 되는 재료 스코어·음식 정보 생성은 [`../meogo-data-ai-pipeline.md`](../meogo-data-ai-pipeline.md), 모듈 의존·입력 VO 규칙은 [`../meogo-conventions.md`](../meogo-conventions.md) 참고.
> `RiskLevel` → UI 색/아이콘은 전 화면 공통 고정 상수: `SAFE` 초록 체크 / `CAUTION` 노랑 느낌표 / `DANGER` 빨강 엑스 / `UNKNOWN` 회색 물음표 (PRD에서 사용).

## 1. 역할

`avoidance` 컨텍스트는 특정 사용자에게 특정 음식이 얼마나 안전한지 판정한다. 입력은 사용자 식이 제한 정보와 음식의 재료/성분 정보이며, 출력은 `SAFE`, `CAUTION`, `DANGER`, `UNKNOWN` 중 하나와 그 이유다.

`avoidance`는 메뉴판 스캔 상태를 관리하지 않는다. 음식 데이터를 생성하지도 않는다.

`avoidance`는 `food`나 `member`의 엔티티에 직접 의존하지 않는다. Application 계층이 음식 재료 정보와 사용자 식이 제한 정보를 `avoidance` 전용 입력 값으로 변환해 전달한다.

## 2. 포함 기능

- 사용자 식이 제한과 음식 재료 비교
- 알러지 기준 위험도 판정
- 종교상 제한 기준 위험도 판정
- 비건 기준 위험도 판정
- 위험도 사유 생성
- 재료별 위험도 생성
- 사장님에게 보여줄 한국어 질문에 필요한 값 생성
- 불확실성 반영

## 3. 제외 기능

- 사용자 식이 제한 저장
- 음식 재료 데이터 저장
- LLM 응답 종합
- 메뉴판 스캔 상태 관리
- 리뷰/평점 관리
- 정적 UI 문구 번역 관리

## 4. 핵심 개념

### RiskLevel

사용자에게 보여줄 위험도 단계다.

상태:

- `SAFE`
- `CAUTION`
- `DANGER`
- `UNKNOWN`

판단 기준:

- `SAFE`: 판정 가능한 음식이며 사용자 제한 조건과 충돌하는 주요 재료가 확인되지 않음
- `CAUTION`: 판정 가능한 음식이지만 제한 재료가 포함될 수 있거나, 재료 데이터가 부족해 안전하다고 말할 수 없음
- `DANGER`: 판정 가능한 음식이며 일반적으로 포함되는 재료가 사용자 제한 조건과 충돌함
- `UNKNOWN`: 음료, 세트/코스명, 상품명, 식별 불가 메뉴처럼 음식/재료 판정 대상이 명확하지 않아 평가할 수 없음

중요 원칙:

- 판정 가능한 음식에서 확실하지 않으면 `SAFE`로 판단하지 않는다.
- 음식으로 식별된 메뉴의 정보가 부족하면 `CAUTION`으로 판단한다.
- 음식/재료 판정 대상 자체가 명확하지 않으면 `UNKNOWN`으로 판단한다.
- 사용자의 알러지, 종교, 비건 조건만 MVP 판정 범위로 둔다.

### AssessmentResult

음식 하나에 대한 사용자별 판정 결과다.

필드 판단 기준:

- 사용자 ID 또는 사용자 조건 참조
- food ID
- 위험도
- 위험 사유 목록
- 재료별 위험 결과
- 사장님 질문 후보
- 판정 시각

도메인 로직 판단 기준:

- 같은 음식이라도 사용자 조건에 따라 결과가 달라진다.
- Food 데이터나 사용자 프로필이 바뀌면 현재 판정 결과도 달라질 수 있다.
- 과거 스캔 당시 결과는 `scan`에서 스냅샷으로 보관한다.

### AssessmentInput

위험도 판정을 위해 Application 계층이 만들어 넘기는 입력 값이다.

필드 판단 기준:

- 사용자 식이 제한 조건
- 음식 재료 목록
- 재료별 포함 가능성 스코어
- 재료별 알러지/종교/비건 매핑 정보
- 원문 메뉴명

도메인 로직 판단 기준:

- `avoidance`는 Food, Member, DietaryProfile 같은 다른 컨텍스트의 영속 모델을 직접 받지 않는다.
- 입력 값은 판정에 필요한 정보만 담는다.
- Application 계층이 `food`와 `member` 데이터를 이 입력 값으로 변환한다.

### AssessmentReason

위험도 판정 이유다.

필드 판단 기준:

- 원인이 된 재료
- 원인이 된 사용자 제한 조건
- 위험도
- 설명 문구에 필요한 값
- 포함 가능성 스코어

도메인 로직 판단 기준:

- 사용자가 왜 위험한지 이해할 수 있어야 한다.
- `CAUTION`은 매장별로 달라질 수 있다는 맥락을 포함해야 한다.
- `DANGER`는 일반적으로 해당 재료가 들어가는 경우에 사용한다.

### IngredientRisk

재료 하나에 대한 사용자별 위험 결과다.

필드 판단 기준:

- 재료 ID
- 재료명
- 포함 가능성 스코어
- 충돌한 제한 조건
- 재료 위험도

도메인 로직 판단 기준:

- 재료 포함 스코어 `2`가 사용자 제한 조건과 충돌하면 `DANGER` 후보가 된다.
- 재료 포함 스코어 `1`이 사용자 제한 조건과 충돌하면 `CAUTION` 후보가 된다.
- 식별된 음식의 재료 정보가 부족하면 `CAUTION` 후보가 된다.
- `UNKNOWN`은 재료 단위 결과가 아니라 메뉴 항목이 음식/재료 판정 대상인지 불명확할 때의 메뉴 단위 결과다.

### OwnerQuestion

사장님에게 보여줄 한국어 질문에 필요한 도메인 값이다.

필드 판단 기준:

- 메뉴판 원문 메뉴명
- 확인할 재료명
- 사용자 제한 조건
- 위험 설명

도메인 로직 판단 기준:

- 질문에 들어가는 메뉴명은 사용자가 실제 메뉴판에서 본 원문 메뉴명이어야 한다.
- `CAUTION` 재료는 질문 생성 대상이 될 수 있다.
- `UNKNOWN` 메뉴는 "이 메뉴가 어떤 음식/구성인지"를 확인하는 질문 생성 대상이 될 수 있다.
- 질문 문구 자체의 다국어 UI 처리는 정적 UI 문구 정책과 분리한다.

### AssessmentPolicy

위험도 계산 정책이다.

로직 판단 기준:

- 알러지 충돌은 가장 보수적으로 판단한다.
- 종교/비건 제한은 재료 매핑과 비교한다.
- 여러 위험 사유가 있으면 가장 높은 위험도를 최종 결과로 사용한다.
- `DANGER`가 하나라도 있으면 최종 위험도는 `DANGER`가 된다.
- `DANGER`가 없고 `CAUTION`이 있으면 최종 위험도는 `CAUTION`이 된다.
- 판정 가능한 음식에서 데이터 부족 때문에 충돌 여부를 확정할 수 없으면 `CAUTION`이 된다.
- 메뉴 항목이 음식/재료 판정 대상인지 식별되지 않으면 `UNKNOWN`이 된다.

## 5. 위험도 우선순위

위험도 우선순위는 다음 순서로 본다.

1. `UNKNOWN` (음식/재료 판정 대상 식별 불가)
2. `DANGER`
3. `CAUTION`
4. `SAFE`

`UNKNOWN`은 식별 불가 메뉴에 대한 별도 분기다. 판정 가능한 음식 안에서는 알러지 서비스 특성상 확실하지 않은 케이스를 `SAFE`로 낮추지 않고 `CAUTION`으로 둔다.

## 6. 다른 컨텍스트와의 관계

- `member`: 사용자의 DietaryProfile을 입력으로 받는다.
- `food`: FoodIngredient, AllergenMapping, DietaryRestrictionMapping을 입력으로 받는다.
- `scan`: 스캔 당시 사용자에게 보여준 결과 스냅샷을 저장할 수 있도록 결과를 제공한다.
- `review`: 직접 관련 없다.

## 7. 구현 시 주의사항

- avoidance는 정책 도메인에 가깝다.
- avoidance가 Food나 Member의 영속 구조를 직접 알면 안 된다.
- avoidance는 자기 입력 VO를 정의하고, Application 계층이 다른 컨텍스트 데이터를 그 입력으로 매핑한다.
- 판정 결과와 판정 스냅샷을 구분한다.
- 위험도는 음식 자체 속성이 아니라 사용자와 음식의 조합 결과다.
- LLM 응답 원본을 직접 판정하지 말고, 정리된 음식/재료 정보를 입력으로 받는다.
- 법적 책임 문구와 도메인 판정 로직을 섞지 않는다.
