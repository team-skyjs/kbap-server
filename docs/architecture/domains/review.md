# review Context - Deferred

## 1. 현재 결정

`review`는 제품 기획서에는 남겨두지만, 현재 도메인 설계와 초기 구현 범위에서는 고려하지 않는다.

따라서 현재 구현 기준 Bounded Context 목록에는 `review`를 포함하지 않는다. active context는 `food`, `member`, `scan`, `assessment` 네 개다.

이 문서는 추후 리뷰 기능을 다시 검토할 때 참고하기 위한 보류 메모다. 현재 도메인 클래스 설계 기준으로 사용하지 않는다.

## 2. 보류 이유

- 리뷰 기능의 제품 방향이 아직 확정되지 않았다.
- 리뷰를 MVP에 포함하면 `member`, `food`, 랭킹, 번역 정책까지 함께 복잡해진다.
- 현재 서비스의 핵심은 메뉴판 기반 음식 안전 판별이다.
- 초기 도메인 설계에서는 `scan`, `food`, `member`, `assessment` 경계를 먼저 안정화하는 것이 우선이다.

## 3. 추후 다시 설계할 때의 기본 원칙

리뷰 기능을 재개한다면 다음 원칙을 따른다.

- 리뷰는 식당이 아니라 음식에 귀속한다.
- 리뷰는 `food` 컨텍스트에 섞지 않고 별도 컨텍스트로 분리한다.
- 커뮤니티 게시판과 리뷰를 섞지 않는다.
- 댓글, 대댓글, 게시글 좋아요는 리뷰 컨텍스트의 기본 범위로 보지 않는다.
- 내 국적 리뷰 보기와 동일 국적 평점은 제품 요구사항으로 다시 검토한다.
- 리뷰 번역 저장 여부는 음식 데이터의 언어 정책과 별도로 결정한다.
- 리뷰 작성자 표시 정보는 `member`에서 제공받되, 스냅샷 저장 여부는 별도 정책으로 정한다.

## 4. 현재 제외 기능

- 커뮤니티 게시글
- 댓글/대댓글
- 게시글 좋아요
- 음식별 리뷰 작성
- 음식별 리뷰 수정/삭제
- 음식별 평점 집계
- 동일 국적 리뷰 필터
- 리뷰 번역
- 식당별 리뷰
- 지도 기반 리뷰

## 5. 다른 컨텍스트와의 잠재 관계

- `food`: 추후 리뷰는 food ID에 귀속될 수 있다.
- `member`: 추후 리뷰 작성자 ID, 국적, 랭킹 표시 정보가 필요할 수 있다.
- `assessment`: 직접 관련 없다.
- `scan`: 직접 관련 없다.

## 6. 랭킹과의 관계

랭킹의 소유권은 `member`가 가진다.

리뷰 활동이 랭킹 계산의 입력이 될 수는 있지만, 리뷰 기능이 보류된 현재 시점에서는 랭킹 계산 로직을 리뷰에 의존하도록 설계하지 않는다.

## 7. 재개 조건

- 리뷰가 음식 선택에 얼마나 중요한지 검증한다.
- 리뷰 작성/조회/번역/신고 범위를 다시 결정한다.
- 랭킹 계산에 리뷰 활동을 포함할지 결정한다.
- 리뷰 집계를 실시간으로 할지 비동기로 할지 결정한다.
- 리뷰 작성자 표시 정보를 현재값으로 볼지 스냅샷으로 저장할지 결정한다.
