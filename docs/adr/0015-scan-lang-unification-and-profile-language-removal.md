# 0015. 스캔 표시 언어를 `lang` 파라미터로 통일 + 회원 프로필 언어 설정 제거

- **상태**: Accepted
- **날짜**: 2026-07-23
- **관련**: specs/kb-229-scan-lang-param · Jira KB-229 · ADR-0013(후속 항목 해소) · 헌법 v4.0.0 원칙 V

## Context

ADR-0013(KB-201)이 표시 언어를 받는 전 API 를 `lang` 필수 + 미지원 코드 en 폴백으로 통일했지만, **스캔 API(`POST /api/v1/scans`)는 대상에서 빠졌다** — `lang` 파라미터가 없고 회원 프로필 `appLanguage`(미설정 시 `ko`)로 응답 언어를 정했다. ADR-0013 은 이를 "프로필 기반 언어 결정이 남은 유일한 지점이며 통일 여부는 별도로 판단한다" 로 남겨 두었다.

그 결과 두 문제가 있었다.

1. **앱 표시 언어와 스캔 결과 언어가 어긋난다.** 사용자가 앱 언어를 바꿔도 프로필을 갱신하지 않으면 스캔 결과는 옛 언어로 나온다.
2. **언어 출처가 둘이다.** 서버가 기억하는 프로필 언어와 요청이 싣고 오는 `lang` 이 공존해, 화면마다 어느 쪽이 이기는지 달랐다.

## Decision

1. 스캔 API 는 표시 언어를 **`lang` 쿼리 파라미터로 받는다**(필수). 회원 프로필은 응답 언어에 관여하지 않는다.
2. 미지정·미지원 코드 처리는 **ADR-0013 을 그대로 따른다** — 누락·빈 값·공백은 400 `COMMON-002`, 지원 목록에 없는 코드는 `en` 폴백(정확 일치 매칭, 관대한 정규화 없음). 스캔만의 예외를 두지 않는다.
3. **회원 프로필에서 `appLanguage` 를 전면 제거한다** — 도메인 모델(`MemberProfile`)·JSON 직렬화(`MemberProfileJson`)·온보딩/수정 입력·내 프로필 조회 응답 모두. 서버가 표시 언어를 저장·기억하는 경로는 0개가 된다.
4. 기존 회원 row 의 폐기된 `appLanguage` 키는 Flyway 데이터 마이그레이션(`JSON_REMOVE`)으로 제거한다. 롤링 배포 중 구 인스턴스가 그 키를 다시 쓸 수 있으므로 `MemberProfileJson` 은 **그 키만** 무시하도록 `@JsonIgnoreProperties("appLanguage")` 를 명시한다(전체 unknown 허용은 하지 않는다).
5. 프로필 언어 제거로 미사용이 된 `UNSUPPORTED_APP_LANGUAGE("MEMBER-007")` 는 삭제하고 번호는 재사용하지 않는다.

이로써 ADR-0013 의 후속 항목이 해소되고, 표시 언어 규칙은 전 API 에서 동일해진다.

## Alternatives Considered

- **스캔만 미지원 코드를 400 으로 거절** — 메뉴명이 요청과 다른 언어로 조용히 나가는 것을 막자는 취지로 검토했다. 그러나 클라이언트(앱)가 기기 언어를 지원 목록에 매핑해 보내고 미지원이면 영어를 기본값으로 쓰기 때문에 서버 거절이 도달하지 않는 분기가 되고, 정책만 엔드포인트별로 갈린다. 기각.
- **프로필 `appLanguage` 를 남기고 스캔만 전환** — 아무도 읽지 않는 설정이 온보딩·프로필 화면과 데이터에 남는다. 기각.
- **`appLanguage` 를 데이터에 그대로 두고 무시만 한다** — 동작은 안전하지만 폐기 키가 영구히 남는다. 마이그레이션 1건으로 정리되므로 기각.
- **`MemberProfileJson` 에 `ignoreUnknown = true`** — 편하지만 범위가 너무 넓다. `avoidanceSubstanceCodes` 가 오타 난 row 가 빈 기피 목록으로 조용히 로드되면 스캔이 "회피 성분 없음" 으로 판정해 안전 경고를 놓친다. 폐기 키 하나만 열어 두는 방식으로 기각.

## Consequences

**좋은 점**

- 표시 언어 결정 경로가 전 API 에서 요청 하나로 고정된다. 클라이언트는 화면마다 다른 규칙을 익힐 필요가 없다.
- 프로필 모델이 단순해지고, 서버가 언어를 저장·동기화할 책임이 사라진다.
- 스캔 결과 언어가 앱 표시 언어와 항상 일치한다.

**감수하는 트레이드오프**

- ADR-0013 이 명시한 "조용한 실패"(클라이언트의 코드 오타·대소문자 오류가 200 영어로 나감)를 스캔도 동일하게 감수한다.
- 기존 회원의 프로필 언어 값은 복원되지 않는다 — 표시 언어는 이제 클라이언트가 매 요청에 싣는다.

**파괴적 변경 (릴리스 조건)**

- 스캔 API 는 `lang` 없이 호출하면 400 이다. **클라이언트 배포 선행 또는 강제 업데이트가 전제**다.
- 온보딩·프로필 수정의 `appLanguage` 는 보내도 무시되므로 그 경로의 구버전 앱은 깨지지 않는다.

**후속**

- 스캔은 LLM(비전) 호출을 동반해 호출당 비용이 발생한다. 인증된 사용자의 반복 호출에 대한 남용·비용 방어(이미지 소유 검증 활성화·회원별 호출 제한·동일 이미지 재스캔 캐싱 등)는 이 ADR 범위 밖이며 별도 결정으로 다룬다.
