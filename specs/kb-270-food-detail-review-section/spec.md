# Feature Specification: 음식 상세 리뷰 섹션 응답 개편

**Feature Branch**: `kb-270-food-detail-review-section`

**Created**: 2026-07-31

**Status**: Draft

**Input**: User description: "270. 음식 상세 조회 응답에 리뷰 평점 응답이 포함되는지 체크 부탁. 없다면 작업 시작해야함"

> 사전 체크 결과: 음식 상세 응답에 리뷰 평점(전체 평균·리뷰 개수·같은 국적 평균)은 **이미 포함**되어 있으나 최상위 평탄 필드 형태다. KB-270 이 요구하는 형태(리뷰 섹션 응집·비회원 가림·평점 기본값)가 아니므로 개편 작업을 진행한다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 회원이 음식 상세에서 리뷰 요약을 하나의 섹션으로 본다 (Priority: P1)

회원이 음식 상세 화면을 열면 리뷰 요약 정보 — 전체 사용자 평균 별점, 리뷰 개수, 나와 같은 국적 사용자의 평균 별점 — 가 하나의 리뷰 묶음으로 응답에 담겨 내려온다. 화면의 리뷰 섹션(전체 사용자 카드·같은 국적 카드)이 이 묶음 하나로 렌더링된다.

**Why this priority**: 음식 상세 화면의 리뷰 섹션이 이 데이터로 그려지며, 응답 구조 응집은 이후 리뷰 기능 확장(좋아요·목록 연결)의 토대다.

**Independent Test**: 회원 토큰으로 음식 상세를 조회해 응답의 리뷰 묶음 안에 세 값(전체 평균·개수·같은 국적 평균)이 모두 있는지 확인하는 것만으로 검증 가능.

**Acceptance Scenarios**:

1. **Given** 리뷰가 3건 있는 음식, **When** 회원이 상세를 조회하면, **Then** 응답의 리뷰 묶음에 전체 평균 별점·리뷰 개수 3·같은 국적 평균 별점이 함께 담긴다
2. **Given** 조회 회원과 같은 국적의 리뷰가 없는 음식, **When** 회원이 상세를 조회하면, **Then** 전체 평균·개수는 값이 있고 같은 국적 평균은 "없음"을 나타내는 기본값으로 내려간다
3. **Given** 리뷰 관련 값이 응답 최상위에 흩어져 있던 기존 구조, **When** 개편이 적용되면, **Then** 리뷰 관련 값은 리뷰 묶음 안에서만 제공된다

---

### User Story 2 - 비회원에게는 리뷰 요약이 가려진다 (Priority: P2)

비회원(로그인하지 않은 사용자)이 음식 상세를 조회하면 리뷰 요약 수치는 노출되지 않고, 응답에 "가림" 표시가 함께 내려간다. 클라이언트는 이 표시로 "리뷰가 없는 상태"와 "로그인해야 볼 수 있는 상태"를 구분해 렌더링한다.

**Why this priority**: 리뷰 열람을 회원 혜택으로 유지하는 정책이며, 가림 표시가 없으면 비회원 화면에서 "리뷰 0개"와 "가려짐"이 구분되지 않아 오해를 만든다.

**Independent Test**: 인증 없이 음식 상세를 조회해 가림 표시가 참이고 평점 수치가 실제 값 대신 기본값으로 내려오는지 확인하는 것만으로 검증 가능.

**Acceptance Scenarios**:

1. **Given** 리뷰가 여러 건 있는 음식, **When** 비회원이 상세를 조회하면, **Then** 가림 표시는 참이고 실제 평점·개수 수치는 응답에 노출되지 않는다
2. **Given** 같은 음식, **When** 회원이 상세를 조회하면, **Then** 가림 표시는 거짓이고 실제 수치가 내려간다

---

### User Story 3 - 평점이 없어도 응답 값 형태가 일정하다 (Priority: P3)

리뷰가 하나도 없는 음식을 조회해도 평균 별점은 "값 없음(null)"이 아니라 0.0 으로 내려간다. 클라이언트는 null 분기 없이 항상 숫자를 받는다.

**Why this priority**: 클라이언트 렌더링 분기를 줄이는 계약 정리이며, 앞의 두 스토리가 적용된 뒤 마무리로 얹는 규칙이다.

**Independent Test**: 리뷰가 0건인 음식을 회원으로 조회해 전체 평균·같은 국적 평균이 0.0, 개수가 0 으로 내려오는지 확인하는 것만으로 검증 가능.

**Acceptance Scenarios**:

1. **Given** 리뷰가 0건인 음식, **When** 회원이 상세를 조회하면, **Then** 전체 평균 0.0 · 리뷰 개수 0 · 같은 국적 평균 0.0 이 내려간다
2. **Given** 전체 리뷰는 있으나 같은 국적 리뷰만 없는 음식, **When** 회원이 상세를 조회하면, **Then** 같은 국적 평균만 0.0 이고 나머지는 실제 값이다

---

### Edge Cases

- 비회원 가림과 리뷰 0건이 동시에 성립하는 음식 — 가림 표시가 우선이며 수치는 기본값으로 내려간다.
- 리뷰 개수가 많은 인기 음식의 상세 조회가 몰릴 때 — 리뷰 개수 집계가 상세 조회 응답 속도를 체감할 만큼 늦추지 않아야 한다(집계 방식 결정은 계획 단계에서 성능 근거와 함께 확정).
- 리뷰 작성 직후 상세 재조회 — 방금 작성한 리뷰가 개수·평균에 반영되어 보인다.
- 같은 국적 판별 기준 — 리뷰 작성 시점 국적 스냅샷 기준(기존 정책 유지)이며, 조회 회원이 국적 미보유면 같은 국적 평균은 기본값이다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 음식 상세 응답은 리뷰 관련 값(전체 평균 별점·리뷰 개수·같은 국적 평균 별점)을 하나의 리뷰 묶음(중첩 객체)으로 제공해야 한다. 개편 후 리뷰 관련 값은 최상위 평탄 필드로 중복 제공하지 않는다.
- **FR-002**: 리뷰 묶음에는 비회원 여부에 따른 가림 표시(blur, 불리언)가 포함되어야 한다 — 비회원 조회는 참, 회원 조회는 거짓.
- **FR-003**: 비회원 조회 시 실제 평점·개수 수치는 응답에 노출되지 않아야 한다(서버에서 가림 — 클라이언트 숨김에 의존하지 않는다).
- **FR-004**: 평균 별점(전체·같은 국적)은 해당 리뷰가 없을 때 null 이 아니라 0.0 으로 제공되어야 한다.
- **FR-005**: 리뷰 개수는 실제 활성 리뷰 수와 일치해야 하며, 리뷰 작성·삭제가 상세 조회 결과에 즉시 반영되어야 한다.
- **FR-006**: 리뷰 개수 제공 방식은 상세 조회 성능을 저하시키지 않는 방식으로 결정하고, 결정 근거(집계 조회 유지 vs 개수 저장 방식 비교)를 기록해야 한다.
- **FR-007**: API 문서(응답 스키마)는 개편된 응답 구조와 각 필드 의미(가림 표시·기본값 규칙 포함)를 반영해야 한다.

### Key Entities

- **음식(Food)**: 상세 조회 대상. 리뷰 요약의 기준 단위.
- **리뷰(Review)**: 회원이 음식에 남긴 별점·본문. 평균 별점·개수 집계의 원천이며 작성 시점 국적 스냅샷을 가진다.
- **리뷰 요약(리뷰 묶음)**: 상세 응답 안의 응집 단위 — 전체 평균 별점, 리뷰 개수, 같은 국적 평균 별점, 가림 표시로 구성.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 회원의 음식 상세 조회 응답에서 리뷰 관련 값이 100% 리뷰 묶음 안에서만 제공된다(최상위 평탄 필드 0개).
- **SC-002**: 비회원 조회의 100% 에서 가림 표시가 참이고 실제 리뷰 수치가 노출되지 않는다.
- **SC-003**: 리뷰가 없는 음식 조회의 100% 에서 평균 별점이 숫자(0.0)로 내려간다 — 클라이언트 null 분기 불필요.
- **SC-004**: 리뷰 개수 제공 방식 도입 후에도 음식 상세 조회 체감 속도가 기존과 동등하다(리뷰 집계로 인한 응답 지연 증가 없음).
- **SC-005**: 리뷰 작성·삭제 직후 상세 재조회에서 개수·평균이 즉시 일치한다.

## Assumptions

- 리뷰 섹션 실연결(FE, KB-73)이 아직 진행 중이므로 응답 구조 변경은 배포된 클라이언트를 깨뜨리지 않는다 — 별도 API 버전 분리 없이 기존 상세 응답을 개편한다.
- 비회원 가림 시 수치는 기본값(0.0·0)으로 채워 내려간다 — 실제 값을 담아 보내고 클라이언트가 숨기는 방식은 노출 위험 때문에 채택하지 않는다.
- "같은 국적" 판별은 기존 정책(리뷰 작성 시점 국적 스냅샷)을 그대로 따른다 — 이 기능에서 정책을 바꾸지 않는다.
- 리뷰 개수 집계 방식(매 조회 집계 vs 음식에 개수 저장) 결정은 계획 단계에서 데이터 규모·조회 빈도 근거로 확정한다 — 본 스펙은 "성능 저하 없이 정확한 개수 제공"이라는 결과만 요구한다.
- 비회원 리뷰 정책의 상세 범위(리뷰 목록 부분 노출 등)는 별도 태스크(KB-83)의 몫이며, 본 기능은 음식 상세의 리뷰 요약 가림만 다룬다.
