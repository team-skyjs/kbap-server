# Feature Specification: 프로필 수정 API 부분 수정 전환 — 미전송 필드는 기존 값 유지

**Feature Branch**: `kb-124-partial-profile-update`

**Created**: 2026-07-12

**Status**: Draft

**Input**: KB-124 — "[BE] 프로필 수정 API 부분 수정 전환 — 미전송 필드는 기존 값 유지"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 닉네임 화면에서 저장해도 기피 성분이 사라지지 않는다 (Priority: P1)

회원이 닉네임·국가·언어를 고치는 화면에서 저장을 누른다. 그 화면은 기피 성분을 다루지 않으므로 기피 성분을 보내지 않는다. 시스템은 보내지 않은 기피 성분을 **그대로 유지**하고 닉네임·국가·언어만 바꾼다.

**Why this priority**: 현재는 이 요청이 **조용히 기피 성분을 전부 삭제**한다. 오류도 나지 않아 사용자는 잃어버린 사실조차 모른다. 음식 안전 정보를 거르는 기준이 사라지는 것이라 데이터 손실 중에서도 위험도가 높다.

**Independent Test**: 기피 성분이 설정된 회원이 닉네임·국가·언어만 담아 수정을 요청한 뒤, 기피 성분이 그대로 남아 있는지 조회로 확인하면 단독 검증된다.

**Acceptance Scenarios**:

1. **Given** 기피 성분이 설정된 회원, **When** 닉네임·국가·언어만 담아 프로필 수정을 요청하면, **Then** 세 값은 바뀌고 기피 성분은 그대로 유지된다.
2. **Given** 온보딩을 완료한 회원, **When** 닉네임만 담아 요청하면, **Then** 닉네임만 바뀌고 국가·언어·기피 성분은 모두 유지된다.
3. **Given** 어떤 회원, **When** 아무 필드도 담지 않은 빈 요청을 보내면, **Then** 성공 응답을 받고 프로필은 하나도 바뀌지 않는다.

---

### User Story 2 - 기피 성분 화면에서 기피 성분만 저장할 수 있다 (Priority: P1)

회원이 기피 성분만 설정하는 화면에서 저장을 누른다. 그 화면은 닉네임·국가·언어를 다루지 않으므로 보내지 않는다. 시스템은 기피 성분만 교체하고 나머지는 유지한다.

**Why this priority**: 현재는 이 요청이 **아예 거절된다**(닉네임·국가·언어가 필수라 빠지면 400). 기피 성분 화면이 동작하려면 클라이언트가 관련 없는 값을 억지로 실어 보내야 한다. US1 과 같은 변경으로 함께 풀린다.

**Independent Test**: 기피 성분만 담아 수정을 요청해 성공 응답을 받고, 닉네임·국가·언어가 그대로인지 조회로 확인한다.

**Acceptance Scenarios**:

1. **Given** 닉네임·국가·언어가 설정된 회원, **When** 기피 성분 목록만 담아 요청하면, **Then** 기피 성분만 교체되고 나머지 세 값은 유지된다.
2. **Given** 기피 성분이 여러 개 설정된 회원, **When** 기피 성분에 **빈 목록**을 담아 요청하면, **Then** 기피 성분이 전부 해제된다(빈 목록은 "전부 해제"라는 명시적 의사다).
3. **Given** 기피 성분이 설정된 회원, **When** 기피 성분 필드를 **아예 보내지 않으면**, **Then** 기존 기피 성분이 유지된다 — 즉 "빈 목록"과 "미전송"이 서로 다르게 동작한다.

---

### User Story 3 - 보내지 않은 필드 때문에 거절당하지 않는다 (Priority: P2)

시스템은 **값이 전달된 필드만** 검증한다. 보내지 않은 필드는 검증 대상이 아니므로 그 때문에 요청이 거절되는 일이 없다. 전달된 값이 잘못됐을 때만 거절한다.

**Why this priority**: US1·US2 를 가능하게 하는 검증 규칙이며, 잘못된 값이 조용히 저장되지 않도록 지키는 안전선이다.

**Independent Test**: 잘못된 국가 코드만 담아 요청하면 거절되고, 유효한 닉네임만 담아 요청하면 통과하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 어떤 회원, **When** 잘못된 국가 코드만 담아 요청하면, **Then** 거절되고 프로필은 하나도 바뀌지 않는다.
2. **Given** 어떤 회원, **When** 공백뿐인 닉네임을 담아 요청하면, **Then** 거절된다.
3. **Given** 어떤 회원, **When** 유효한 닉네임만 담아 요청하면, **Then** 국가·언어를 보내지 않았다는 이유로 거절되지 않고 성공한다.
4. **Given** 온보딩을 아직 완료하지 않은 회원, **When** 프로필 수정을 요청하면, **Then** 처리되지만 온보딩 완료 상태로 전이되지는 않는다(기존 동작 유지).

---

### Edge Cases

- **빈 요청(필드 하나도 없음)**: 성공으로 처리하고 아무것도 바꾸지 않는다. 오류로 다루지 않는다.
- **기피 성분 빈 목록 vs 미전송**: 빈 목록은 "전부 해제", 미전송은 "유지". 이 둘을 반드시 구분한다.
- **기피 성분 목록에 중복 코드**: 기존과 동일하게 중복을 제거해 저장한다.
- **닉네임 앞뒤 공백**: 기존과 동일하게 제거해 저장한다.
- **온보딩 API**: 아무 영향도 받지 않는다. 전 필드 필수가 그대로다.
- **맵기 선호도**: 이 API 로 노출되지 않는 값이며, 수정 시에도 기존 값이 보존된다(현행 동작 유지).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 프로필 수정 요청의 모든 필드는 **선택**이어야 한다. 필드를 보내지 않으면 그 항목의 기존 값을 유지하고, 값을 보내면 그 항목만 교체한다.
- **FR-002**: 기피 성분은 **빈 목록**(전부 해제)과 **미전송**(유지)을 구분해야 한다.
- **FR-003**: 검증은 **값이 전달된 필드에만** 적용해야 한다. 미전송 필드 때문에 요청이 거절되어서는 안 된다.
- **FR-004**: 전달된 값이 유효하지 않으면(닉네임 공백, 지원하지 않는 국가·언어·기피 성분 코드) 요청 전체를 거절하고 **프로필을 하나도 바꾸지 않아야** 한다(부분 저장 없음).
- **FR-005**: 아무 필드도 담지 않은 요청은 성공으로 응답하고 프로필을 바꾸지 않아야 한다.
- **FR-006**: 프로필 수정은 온보딩 완료 상태를 바꾸지 않아야 한다(기존 동작 유지).
- **FR-007**: 온보딩 제출은 **전 필드 필수**를 그대로 유지해야 한다. 이번 변경의 영향을 받지 않는다.
- **FR-008**: 이 API 로 노출되지 않는 프로필 항목(맵기 선호도)은 수정 시에도 보존되어야 한다.

### Key Entities

- **회원 프로필(MemberProfile)**: 닉네임·기피 성분 목록·국가·앱 언어·맵기 선호도. 모든 항목이 개별적으로 존재하거나 비어 있을 수 있다.
- **프로필 수정 요청**: 위 항목 중 **바꾸고 싶은 것만** 담는다. 담기지 않은 항목은 "건드리지 말라"는 뜻이다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 기피 성분 화면은 기피 성분만 보내 저장할 수 있다 — 관련 없는 값을 함께 실어 보내지 않아도 100% 성공한다.
- **SC-002**: 닉네임·국가·언어 화면에서 저장할 때 기피 성분이 의도치 않게 삭제되는 일이 0건이다.
- **SC-003**: 설정 화면이 새로 늘어나도 프로필 수정 엔드포인트는 하나로 유지된다(화면별 API 분기 0건).
- **SC-004**: 잘못된 값을 보낸 요청은 100% 거절되며, 거절된 요청이 프로필을 일부라도 바꾸는 일은 0건이다.
- **SC-005**: 온보딩 흐름의 동작·검증은 변경 전과 100% 동일하다.

## Assumptions

- **명시적 `null` 전송은 미전송과 같게 다룬다.** 요청에 필드를 담지 않는 것과 그 필드에 `null` 을 담는 것 모두 "유지"로 처리한다. 개별 항목을 "비우는" 의미는 도입하지 않는다(닉네임·국가·언어를 비우는 화면이 없다). 기피 성분만 **빈 목록**으로 전부 해제할 수 있다.
- **부분 수정은 프로필 수정 API 에만 적용한다.** 온보딩은 전 필드 필수를 유지하며, 두 API 는 이미 요청 형식이 분리돼 있어 서로 영향을 주지 않는다.
- **검증 규칙 자체는 바뀌지 않는다.** 닉네임 공백 금지, 국가·언어·기피 성분 코드의 유효성 규칙과 오류 메시지는 그대로다. 달라지는 것은 **검증을 적용하는 범위**(전달된 필드만)뿐이다.
- **기존 클라이언트는 깨지지 않는다.** 지금처럼 네 필드를 모두 보내는 요청은 이전과 똑같이 동작한다(전부 교체).

## Out of Scope

- **화면별 엔드포인트 분리** — 설정 화면이 늘 때마다 API 가 늘고 검증 로직이 갈라지므로 채택하지 않는다.
- **개별 항목 비우기(닉네임·국가·언어를 비운 상태로 되돌리기)** — 그런 화면이 없다. 필요해지면 별도로 다룬다.
- **맵기 선호도의 API 노출** — 이번 범위 밖이며 현행대로 보존만 한다.
