# Feature Specification: 이미지 업로드 객체 키 환경 접두(key-prefix) 지원

**Feature Branch**: `kb-171-storage-key-prefix`

**Created**: 2026-07-20

**Status**: Draft

**Input**: User description: "kb-171 워크트리로 진행" (Jira KB-171 — [BE] 이미지 업로드 객체 키에 환경 접두(key-prefix) 지원 — prod 공유 버킷 환경별 폴더 분리)

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 환경별 업로드 폴더 분리 (Priority: P1)

이미지 저장소는 prod 버킷 하나를 전 환경(dev·staging·prod)이 공유한다. dev·staging 환경에서 사용자가 업로드한 이미지(메뉴판 스캔·프로필 사진)가 환경별 최상위 폴더(`dev/`·`staging/`)에 저장되어, prod 데이터와 섞이지 않고 환경 단위로 식별·정리·권한 통제가 가능해야 한다.

**Why this priority**: 이 기능의 존재 이유. 접두 없이는 dev·staging 테스트 업로드가 prod 실데이터와 같은 경로에 뒤섞여 정리 불가능하고, 환경별 권한 범위 제한(인프라 작업)도 불가능하다.

**Independent Test**: 환경 접두가 설정된 상태에서 발급된 업로드 객체 키가 해당 접두로 시작하는지 확인하는 것만으로 완결 검증된다.

**Acceptance Scenarios**:

1. **Given** 환경 접두가 `dev` 로 설정된 환경, **When** 사용자가 이미지 업로드 URL 을 발급받으면, **Then** 발급된 객체 키는 `dev/images/…` 형태로 환경 접두가 맨 앞에 붙는다.
2. **Given** 환경 접두가 `staging` 으로 설정된 환경, **When** 업로드 URL 을 발급받으면, **Then** 객체 키는 `staging/images/…` 로 시작한다.
3. **Given** 접두가 붙은 객체 키로 업로드를 완료한 사용자, **When** 그 키(ref)가 저장되고 이후 응답에서 이미지 URL 로 조립되면, **Then** 접두를 포함한 경로 그대로 완전한 공개 URL 이 만들어져 이미지가 정상 표시된다.

---

### User Story 2 - 빈 접두 시 기존 키 구조 유지 (Priority: P1)

접두가 빈 값이면 기존 키 구조(`images/…`)가 그대로 유지된다(env 로 빈 값을 지정한 경우 — 롤백 수단). 이미 저장된 이미지 참조는 환경과 무관하게 그대로 유효해야 한다. *(2026-07-20 개정: 최초 결정은 "prod 접두 없음"이었으나 사용자 결정으로 local·테스트 포함 전 환경이 환경명을 기본 접두로 갖는다 — 빈 접두 = 기존 구조는 코드 계약(단위 테스트)으로 유지.)*

**Why this priority**: 기존 저장 데이터·레거시 경로가 계속 유효해야 하는 안전 조건이며 P1 과 동급의 필수 성질이다.

**Independent Test**: 접두 미설정(빈 값) 상태에서 발급된 객체 키가 기존과 동일한 `images/…` 구조인지 확인하면 된다.

**Acceptance Scenarios**:

1. **Given** 환경 접두가 설정되지 않은(빈 값) 환경, **When** 업로드 URL 을 발급받으면, **Then** 객체 키는 접두 없이 기존 구조(`images/{용도}/{연}/{월}/{회원}/{고유값}.{확장자}`) 그대로 생성된다.
2. **Given** 접두 도입 이전에 저장된 기존 이미지 참조, **When** 응답 URL 조립이 일어나면, **Then** 기존과 동일한 URL 이 만들어진다(저장된 참조·조립 규칙 모두 무변경).

---

### User Story 3 - 운영자의 접두 무배포 변경 (Priority: P2)

운영자는 코드 변경·재배포 없이 환경 변수만으로 특정 환경의 접두 값을 지정하거나 바꿀 수 있다.

**Why this priority**: 환경별 값은 인프라가 소유하는 것이 기존 관례(버킷·공개 URL 과 동일 패턴) — 접두 값 변경이 배포를 요구하면 운영 부담이 생긴다.

**Independent Test**: 환경 변수로 접두를 주입해 앱을 띄우면 발급 키에 반영되고, 변수 미설정이면 접두 없이 동작하는지 확인.

**Acceptance Scenarios**:

1. **Given** dev·staging 환경 설정에 접두 항목이 선언되어 있고 환경 변수로 값이 주입된 상태, **When** 앱이 기동해 업로드 URL 을 발급하면, **Then** 주입된 접두가 키에 반영된다.
2. **Given** 환경 변수가 설정되지 않은 상태, **When** 앱이 기동하면, **Then** 접두는 빈 값으로 동작하고 기동 실패나 오류가 없다.

---

### Edge Cases

- 접두 값이 `dev/` 처럼 슬래시로 끝나거나 `/dev` 처럼 슬래시로 시작하면? → 결합 시 슬래시가 중복(`dev//images/…`)되거나 키가 `/` 로 시작하지 않도록 정규화해 결합한다.
- 접두가 빈 문자열이면? → 접두·구분 슬래시 없이 기존 키 구조 그대로 생성한다(선행 슬래시 금지).
- 음식 사진(업로드 API 를 타지 않는 환경 공유 자산)은? → 범위 밖 — 접두 없는 경로를 전 환경이 그대로 참조하며 이 기능의 영향을 받지 않는다.
- 접두 포함 키가 DB 에 참조로 저장되는데 URL 조립은? → 조립 규칙은 "베이스 URL + 저장된 경로" 그대로이므로 변경 불필요(접두가 경로의 일부가 될 뿐).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 업로드 객체 키의 환경 접두를 설정값으로 지정할 수 있어야 한다. 기본값은 빈 값이며, 미설정 시 기존 키 구조가 완전히 동일하게 유지된다.
- **FR-002**: 접두가 설정된 경우 발급되는 모든 업로드 객체 키는 `{접두}/{기존 키}` 형태로 접두가 맨 앞에 결합된다.
- **FR-003**: 접두 결합 시 슬래시가 중복되거나 키가 슬래시로 시작하지 않도록 정규화한다(접두의 앞뒤 슬래시 유무와 무관하게 동일한 결과).
- **FR-004**: 전 환경이 **환경명 기본값**을 갖는다 — base(local)·테스트는 `local`, dev·staging·prod 프로필은 각각 `dev`·`staging`·`prod`. env `STORAGE_KEY_PREFIX` 로 커밋 없이 변경(빈 값 지정 포함)할 수 있다. *(2026-07-20 개정 — 최초안: env 주입·기본 빈 값.)*
- **FR-005**: 접두가 포함된 키가 이미지 참조로 저장된 뒤의 응답 URL 조립은 기존 규칙 그대로 동작해야 한다(조립 로직 변경 금지 — 접두는 경로의 일부).
- **FR-006**: 접두 유무(빈 값 / 값 있음 / 슬래시 포함 변형)에 따른 객체 키 생성을 검증하는 테스트를 구현에 앞서 작성한다(Test-First).

### Key Entities

- **업로드 객체 키**: 업로드된 이미지가 저장소에 저장되는 경로 식별자. 현재 `images/{용도}/{연}/{월}/{회원}/{고유값}.{확장자}` 구조이며, 본 기능으로 맨 앞에 선택적 환경 접두가 붙는다. DB 에는 이 키가 이미지 참조(ref)로 저장된다.
- **환경 접두(key-prefix)**: 환경별 최상위 폴더 이름(`dev`·`staging`, prod 는 빈 값). 환경 변수로 주입되는 설정값이며 데이터로 저장되지 않는다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: dev·staging 환경에서 발급되는 업로드 객체 키의 100% 가 해당 환경 접두로 시작한다.
- **SC-002**: 빈 접두(env 빈 값 반전 시)에서 발급되는 객체 키는 기능 도입 전과 동일한 구조다. 기존 저장된 이미지 참조는 전 환경에서 계속 유효하다.
- **SC-003**: 접두가 붙은 키로 업로드한 이미지가 저장·조회 전 과정(업로드 → 참조 저장 → URL 조립 → 표시)에서 추가 조치 없이 정상 동작한다.
- **SC-004**: 접두 값 변경·설정에 코드 변경이나 재배포가 필요 없다(환경 변수만으로 반영).
- **SC-005**: 기존 전체 테스트가 무수정으로 통과한다(신규 테스트 제외).

## Assumptions

- 환경별 접두 기본값(`local`·`dev`·`staging`·`prod`)은 설정 파일(base·프로필)이 소유하고, env `STORAGE_KEY_PREFIX` 는 커밋 없는 오버라이드 수단이다(KB-169 의 프로필 기본값+env 반전 관례 — 2026-07-20 사용자 결정으로 "인프라 env 주입" 최초안 대체).
- devstg EC2 역할의 S3 권한을 `dev/*`·`staging/*` 로 제한하는 작업은 인프라 범위로 본 기능에 포함하지 않는다.
- 음식 사진은 업로드 API 를 경유하지 않는 환경 공유 자산으로 범위 밖 — 환경과 무관하게 `images/menus/…` 공용 경로를 전 환경이 그대로 참조한다(접두는 업로드 API 발급 키에만 붙으므로 구조적으로 보장).
- 버킷 이름·공개 베이스 URL 은 기존 설정 주입 체계를 그대로 사용하며 본 기능은 키 접두만 추가한다.
- DB 스키마·마이그레이션·API 계약(요청/응답 필드) 변경은 없다.
