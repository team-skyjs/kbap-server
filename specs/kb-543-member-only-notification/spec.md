# Feature Specification: 비회원 광고 알림 동의 제거 — 알림 대상을 회원 전용으로

**Feature Branch**: `kb-543-member-only-notification`

**Created**: 2026-09-11

**Status**: Draft

**Input**: User description: "543 워크트리" — Jira KB-543 「[BE] 비회원 광고 알림 동의 제거 — 토큰 등록·알림 대상을 회원 전용으로」(에픽 KB-463 푸시 알림, SP 2). 비회원의 광고 알림 동의를 제거하고, 무조건 회원만 알림을 받을 수 있도록 고친다.

## 배경

푸시 알림 저장 기반(KB-464)은 비회원도 알림 대상이 될 수 있게 설계됐다. 비회원은 기기 토큰을 등록하면서 광고성 수신 동의를 함께 남길 수 있고, 로그인하면 그 동의가 회원 동의로 인수되거나 회원이 이미 같은 동의를 갖고 있으면 철회되는 병합 규칙이 돈다. 그 뒤 기획이 바뀌어 알림함(KB-467)은 회원 전용으로 확정됐고, 발송 파이프라인(KB-468)도 회원 기기만 대상으로 한다. 비회원 동의·비회원 알림은 더 이상 쓰이지 않는 죽은 경로이고, 게스트→회원 병합 규칙은 동의 증빙을 복잡하게 만든다(로그아웃 후 옛 동의가 되살아나는 결함을 KB-464 검토에서 이미 한 번 바로잡았다).

이 기능은 비회원 경로를 걷어내 "알림은 회원만 받는다" 를 서버가 강제하게 만든다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 비회원은 기기 토큰을 등록할 수 없다 (Priority: P1)

로그인하지 않은 앱이 기기 토큰 등록을 시도하면 인증 오류를 받는다. 이전처럼 게스트 동의를 함께 실어 보내도 저장되지 않는다. 로그인한 회원의 토큰 등록은 종전과 동일하게 동작한다.

**Why this priority**: 비회원 경로의 입구를 막는 것이 이 기능의 핵심이다. 입구가 닫히면 비회원 동의·비회원 알림 데이터가 새로 생기지 않는다.

**Independent Test**: 토큰 없이 토큰 등록을 호출하면 401 을 받고 기기 행이 생기지 않는다. 회원 토큰으로 호출하면 종전대로 기기 행이 생기고 회원에 연결된다.

**Acceptance Scenarios**:

1. **Given** 로그인하지 않은 앱, **When** 기기 토큰을 등록하면, **Then** 401 을 받고 기기·동의 데이터가 생기지 않는다.
2. **Given** 로그인한 회원, **When** 기기 토큰을 등록하면, **Then** 종전과 같이 기기가 등록되고 회원에 연결된다.
3. **Given** 로그인한 회원, **When** 요청에 예전 게스트 동의 필드를 실어 보내면, **Then** 그 필드는 계약에서 사라져 무시되거나 거부되며 동의 원장은 바뀌지 않는다.

---

### User Story 2 - 로그인·로그아웃·탈퇴 시 기기 연결만 다루고 게스트 동의 병합은 하지 않는다 (Priority: P1)

로그인하면 기기가 회원에 연결되고, 로그아웃하면 연결이 풀리고, 탈퇴하면 회원의 기기 연결이 모두 풀리고 열린 동의가 닫힌다. 로그인 때 게스트 동의를 회원 동의로 옮기거나 철회하는 병합은 더 이상 일어나지 않는다.

**Why this priority**: 병합 규칙이 남아 있으면 비회원 동의가 "없어야 하는데 있는" 데이터로 되살아날 수 있다. US1 과 함께 있어야 비회원 경로가 완전히 닫힌다.

**Independent Test**: 회원 동의가 없는 상태에서 로그인해도 동의 원장이 바뀌지 않는다. 로그인·로그아웃·탈퇴의 기기 연결 동작은 기존 회귀 테스트가 그대로 통과한다.

**Acceptance Scenarios**:

1. **Given** 기기가 등록된 회원, **When** 로그인하면, **Then** 기기가 회원에 연결되고 동의 원장은 변하지 않는다.
2. **Given** 로그인된 기기, **When** 로그아웃하면, **Then** 기기의 회원 연결이 풀린다.
3. **Given** 기기 여러 대와 열린 동의를 가진 회원, **When** 탈퇴하면, **Then** 모든 기기 연결이 풀리고 열린 동의가 전부 닫힌다.

---

### User Story 3 - 비회원 알림·비회원 동의를 만드는 경로가 코드에 남지 않는다 (Priority: P2)

시스템 어디에서도 설치 id 만으로 알림이나 동의를 만들 수 없다. 알림·동의는 항상 회원에 귀속된다. 저장소의 기존 컬럼은 이번에 지우지 않고 남겨 둔다.

**Why this priority**: 입구(US1·US2)를 막은 뒤 남은 죽은 코드를 걷어내야 다음 작업(KB-468 발송 파이프라인)이 비회원 분기를 고려하지 않아도 된다.

**Independent Test**: 설치 id 기준으로 알림·동의를 만들거나 조회하는 진입점이 코드에 없고, 전체 빌드와 아키텍처 검사가 통과한다.

**Acceptance Scenarios**:

1. **Given** 코드베이스, **When** 비회원 알림·비회원 동의 생성·조회·철회 진입점을 찾으면, **Then** 없다.
2. **Given** 기존 스키마, **When** 이 기능을 배포하면, **Then** 마이그레이션 없이 배포되고 구 코드와 신 코드가 같은 스키마 위에서 공존한다.
3. **Given** API 문서, **When** 토큰 등록 계약을 보면, **Then** 게스트 동의 필드와 설명이 없고 회원 전용임이 드러난다.

---

### Edge Cases

- 이미 저장된 비회원 동의·비회원 알림 행(설치 id 만 있고 회원 id 가 없는 행)은 이번에 삭제하거나 옮기지 않는다. 회원 전용 조회는 회원 id 로만 읽으므로 그 행들은 자연히 보이지 않는다.
- 앱의 이전 버전이 로그인 전에 토큰을 등록하면 401 을 받는다. 이 요청은 실패해도 앱 동작에 영향이 없어야 하며, FE 는 로그인 이후에 등록하도록 맞춘다.
- 로그인 직후 토큰 등록이 로그인 응답보다 먼저 도착하는 순서 문제는 이 기능 범위 밖이다(FE 가 로그인 완료 후 등록).
- 저장소 컬럼 제거는 블루/그린 배포 중 구 코드가 신 스키마 위에서 도는 문제 때문에 이번에 하지 않고 별도 태스크로 미룬다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 기기 토큰 등록을 로그인한 회원에게만 허용하고, 비회원 요청은 인증 오류(401)로 거부해야 한다.
- **FR-002**: 시스템은 토큰 등록 계약에서 게스트 광고성 동의 입력을 제거해야 한다.
- **FR-003**: 시스템은 로그인 시 기기를 회원에 연결만 하고, 게스트 동의를 회원 동의로 인수하거나 철회하는 병합을 하지 않아야 한다.
- **FR-004**: 시스템은 로그아웃 시 기기 연결 해제, 탈퇴 시 기기 연결 전체 해제와 열린 동의 닫기를 종전과 동일하게 수행해야 한다.
- **FR-005**: 시스템은 설치 id 만으로 알림 또는 동의를 생성·조회·철회하는 진입점을 갖지 않아야 한다.
- **FR-006**: 시스템은 이번 변경에서 데이터베이스 스키마를 바꾸지 않아야 한다.
- **FR-007**: API 문서는 토큰 등록이 회원 전용임을 드러내고 게스트 동의 관련 서술을 포함하지 않아야 한다.
- **FR-008**: 기존 회원 경로(토큰 등록·로그인 연결·로그아웃 해제·탈퇴 정리·설정·알림함)의 회귀 테스트는 모두 통과해야 한다.

### Key Entities *(include if data involves)*

- **기기(notification_device)**: 앱 설치 단위의 푸시 토큰 대장. 회원 연결이 있거나 없을 수 있다(로그아웃 상태). 이번 변경 후에도 등록 자체는 회원만 할 수 있다.
- **동의(notification_consent)**: 광고성 수신 동의 원장. 이번 변경 후 새 행은 항상 회원에 귀속된다. 설치 id 컬럼은 남지만 새로 쓰이지 않는다.
- **알림(notification)**: 회원의 알림함 원본. 이번 변경 후 새 행은 항상 회원에 귀속된다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 배포 후 비회원 토큰 등록 요청은 100% 401 로 거부되고, 기기·동의 행이 하나도 생기지 않는다.
- **SC-002**: 회원의 토큰 등록·로그인·로그아웃·탈퇴·설정·알림함 회귀 테스트가 전부 통과한다.
- **SC-003**: 코드베이스에서 설치 id 기준 알림·동의 생성·조회·철회 진입점이 0건이다.
- **SC-004**: 마이그레이션 파일 추가 없이 배포된다.
- **SC-005**: FE 가 계약 변경(로그인 후 토큰 등록)을 전달받아 반영 계획을 확인했다.

## Assumptions

- "회원만 알림을 받는다" 는 알림함(KB-467)·발송(KB-468)·토큰 등록(이 기능) 세 곳 모두에 적용되는 기획 확정(2026-09-07)이다.
- 기존에 저장된 비회원 행은 삭제하지 않는다. 회원 전용 조회에서 자연히 배제되며, 정리는 컬럼 제거 태스크에서 함께 판단한다.
- 스키마(설치 id 컬럼) 제거는 별도 태스크로 등록하고 KB-543 에 코멘트로 연결한다.
- FE 는 로그인 완료 후에만 토큰을 등록하도록 바꾼다. 이 계약 변경은 FE 팀에 공유하며, 서버는 구버전 앱의 비회원 등록을 401 로 거부하는 것 외에 별도 호환 처리를 두지 않는다.
