# Feature Specification: 스캔 응답 DB 매칭 음식명 번역 (KB-189)

**Feature Branch**: `kb-189-scan-name-translation`

**Created**: 2026-07-20

**Status**: Draft

**Input**: User description: "kb-189 — [BE] 스캔 응답 버그 수정: DB hit 음식명이 번역되지 않고 나감"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - DB 매칭 음식명이 회원 앱 언어로 표시된다 (Priority: P1)

외국인 회원이 앱 언어를 영어로 설정하고 메뉴판을 스캔하면, 우리 서비스가 이미 알고 있는(DB 매칭·정보 준비 완료) 음식의 이름은 영어 번역명으로 표시된다. 현재는 비전 인식이 추출한 원문 표기가 그대로 나가 회원이 읽을 수 없는 이름이 보이는 버그가 있다.

**Why this priority**: 스캔은 서비스의 핵심 기능이고, 번역된 음식명 제공은 외국인 사용자 대상 서비스의 존재 이유다. 알고 있는 음식인데도 번역 없이 내보내는 것은 명백한 버그다.

**Independent Test**: 앱 언어가 영어인 회원으로 DB에 준비된(READY) 음식이 포함된 메뉴판을 스캔하면, 해당 항목의 이름이 그 음식의 영어 번역명으로 응답되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 앱 언어가 영어인 회원과 영어 번역명이 등록된 READY 음식, **When** 그 음식이 포함된 메뉴판을 스캔하면, **Then** 응답 항목의 이름은 그 음식의 영어 번역명이다(비전 추출 이름이 아님).
2. **Given** 앱 언어가 영어가 아닌 다른 지원 언어인 회원, **When** 스캔하면, **Then** 응답 항목의 이름은 그 언어의 번역명이다.

---

### User Story 2 - DB 미매칭 항목은 기존 동작을 유지한다 (Priority: P2)

DB에 없는(또는 아직 정보가 준비되지 않은) 메뉴 항목은 번역 원천이 없으므로, 지금처럼 비전 인식이 추출한 이름을 그대로 표시한다.

**Why this priority**: 회귀 방지 — 버그 수정이 미매칭 항목의 기존 동작을 깨뜨리면 안 된다.

**Independent Test**: DB에 없는 메뉴명이 포함된 메뉴판을 스캔하면, 해당 항목의 이름이 비전 인식 추출값 그대로인지 확인한다.

**Acceptance Scenarios**:

1. **Given** DB에 매칭되지 않는 메뉴 항목, **When** 스캔하면, **Then** 응답 항목의 이름은 비전 인식이 추출한 이름 그대로다.
2. **Given** DB에 매칭됐지만 아직 정보 준비가 완료되지 않은(미완성) 음식, **When** 스캔하면, **Then** 응답 항목의 이름은 비전 인식이 추출한 이름 그대로다(준비 완료 전에는 번역 제공 대상이 아님).

---

### User Story 3 - 번역 부재 시 한국어로 폴백한다 (Priority: P3)

DB 매칭 음식이라도 회원 앱 언어의 번역이 아직 등록되지 않았으면, 기존 다국어 표시 규칙과 동일하게 한국어 이름으로 폴백해 항상 읽을 수 있는 이름을 보장한다.

**Why this priority**: 번역 데이터는 점진적으로 채워지므로 부재 케이스가 실제로 존재한다. 빈 이름이나 오류 대신 일관된 폴백이 필요하다.

**Independent Test**: 회원 앱 언어의 번역 키가 비어 있는 READY 음식을 스캔하면, 응답 이름이 그 음식의 한국어 이름인지 확인한다.

**Acceptance Scenarios**:

1. **Given** 앱 언어가 영어인 회원과 영어 번역이 비어 있는 READY 음식, **When** 스캔하면, **Then** 응답 항목의 이름은 그 음식의 한국어 이름이다.

---

### Edge Cases

- 회원이 앱 언어를 아직 설정하지 않은 경우(온보딩 미완료 등) → 번역 언어를 특정할 수 없으므로 한국어 폴백과 동일하게 한국어 이름을 표시한다.
- 회원 앱 언어의 번역 값이 빈 문자열인 경우 → 부재와 동일하게 취급해 한국어로 폴백한다(기존 다국어 표시 규칙 그대로).
- 같은 스캔 안에 매칭/미매칭 항목이 섞여 있는 경우 → 항목별로 독립 적용된다(매칭 항목만 번역, 나머지는 비전 추출 이름).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 스캔 응답의 각 항목 중 DB에 매칭되고 정보 준비가 완료된(READY) 음식의 이름은 그 음식의 다국어 이름을 회원의 앱 언어로 조립한 값이어야 한다.
- **FR-002**: DB에 매칭되지 않았거나 준비가 완료되지 않은 항목의 이름은 비전 인식이 추출한 이름을 그대로 유지해야 한다.
- **FR-003**: 회원 앱 언어의 번역이 없거나 비어 있으면 기존 다국어 표시 규칙(한국어 폴백)을 그대로 따라야 한다.
- **FR-004**: 회원의 앱 언어가 미설정이면 한국어 이름을 표시해야 한다.
- **FR-005**: 이름 외 스캔 응답의 다른 필드(위험도·매칭 여부·한국어 이름·가격 등)와 스캔 이력 기록 동작은 변경되지 않아야 한다.

### Key Entities

- **스캔 결과 항목**: 메뉴판에서 인식된 메뉴 1건 — 표시 이름(이번 수정 대상), 한국어 이름, 위험도, 매칭 여부, 가격을 가진다.
- **음식**: DB에 등록된 음식 — 한국어 이름과 언어별 번역 이름을 가지며, 정보 준비 완료(READY) 상태일 때만 번역 표시 대상이 된다.
- **회원**: 앱 언어 설정을 가진 스캔 요청자 — 이 설정이 표시 언어를 결정한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: DB 매칭(READY) 항목 100%가 회원 앱 언어의 이름(번역 부재 시 한국어)으로 응답된다.
- **SC-002**: DB 미매칭·미완성 항목의 이름은 수정 전과 100% 동일하다(회귀 0건).
- **SC-003**: 스캔 응답 조립 경로에 번역·미매칭 유지·폴백을 각각 검증하는 자동화 테스트가 존재해 재발 시 즉시 감지된다.

## Assumptions

- 스캔은 인증 회원만 사용하므로 요청자의 회원 정보(앱 언어 포함)는 항상 조회 가능하다.
- 음식의 다국어 이름 조립과 한국어 폴백 규칙은 기존 시스템에 이미 존재하며 이번에 새로 정의하지 않고 재사용한다.
- 준비 미완료(미완성) 음식은 번역 데이터가 사실상 없으므로 번역 표시 대상에서 제외한다 — Jira 본문의 "DB 매칭(READY)" 표현과 일치.
- 스캔 이력에 저장되는 메뉴명은 기존대로 비전 추출 이름이며 이번 수정 범위 밖이다.
