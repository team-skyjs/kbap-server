# KB-827 리뷰 본문 최소 10자 — API 계약

대상: `POST /api/reviews`(작성), `PATCH /api/reviews/{reviewId}`(수정). 버전 헤더 무관(전 버전 동일 규칙).

## 규칙

- 본문(`content`)은 **필수**다. 판정은 `content.trim()` 의 **유니코드 코드 포인트 수 ≥ 10**.
  - 이모지 한 개(서로게이트 쌍, UTF-16 2단위)는 1자로 센다. 결합 문자(예: 피부색 수식자)는 각각 1자다.
  - 앞뒤 공백은 세지 않는다. 가운데 공백은 센다.
- 상한은 기존대로 1000자(Bean Validation, `content.length` 기준 — 기존 400 COMMON 검증 실패 그대로).
- 사진·별점만 있는 리뷰는 더 이상 만들 수 없다(정책 변경).
- 저장 값은 보낸 원문 그대로다(trim 해서 저장하지 않는다).

## 실패 응답

| 경우 | HTTP | code | payload |
|---|---|---|---|
| `content` 없음·`""`·공백만·trim 후 10자 미만 | 400 | `REVIEW-005` | `{"minLength": 10}` |

메시지(표시용, 분기 금지): "리뷰 본문은 10자 이상이어야 해요".

판정 순서: 작성은 음식 존재(FOOD-001)·사진 소유(REVIEW-003) 다음, 수정은 리뷰 존재(REVIEW-001)·본인(REVIEW-002) 다음 사진 소유 전에 본문을 본다. 실패하면 리뷰·카운터·랭킹 이벤트 모두 바뀌지 않는다.

## 영향 없음

- 기존 리뷰(본문 없음·10자 미만 포함)는 그대로 남고 조회 응답도 같다. 수정할 때만 새 규칙을 탄다.
- 리뷰 봇: 생성물 필터가 이미 20자 미만을 버리고, 저장 시 같은 규칙을 타서 trim 후 10자 미만이면 그 건을 건너뛴다(카운터 불변).
