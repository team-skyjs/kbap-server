# API Contract Delta: 맵기 선호 -1 센티널 (KB-158)

신규 엔드포인트 없음. 기존 3개 엔드포인트의 `spicinessPreference` 값 계약만 확장된다. 요청·응답 구조(필드·타입) 무변경 — additive 계약 변화.

## 공통 값 계약

- 허용 값: **-1(미설정) 또는 0~10(설정)**
- 그 외 값(-2, 11, …): **400 + `MEMBER-009`** — `{"success":false,"code":"MEMBER-009","message":"맵기 선호는 -1(미설정) 또는 0~10 사이여야 합니다"}` (메시지는 표시용, 클라이언트는 code 로만 분기)
- 클라이언트 계약: 온보딩 스킵·프로필 "설정 안 함" 선택 시 **-1 을 명시 전송**

## POST /api/v1/members/me/onboarding

`spicinessPreference` 는 **필수 필드**(-1 또는 0~10) — nickname 등 다른 필수 필드와 동일하게 non-null 로 강제한다.

| 요청 `spicinessPreference` | 결과 |
|---------------------------|------|
| 미전송(또는 null) | **400 COMMON-002 (필수 누락)** — 온보딩 미완료. 기존: 기본 5 저장 |
| -1 | -1 (미설정) 저장 — 기존: 400 MEMBER-009 |
| 0~10 | 그 값 저장 (불변) |
| 그 외 | 400 MEMBER-009 (불변, 메시지만 갱신) |

## PATCH /api/v1/members/me/profile (프로필 부분 수정)

| 요청 `spicinessPreference` | 저장 결과 |
|---------------------------|-----------|
| 미전송(또는 null) | 기존 값 유지 (불변 — 부분 수정 규약) |
| -1 | -1 (미설정으로 복귀) — 기존: 400 MEMBER-009 |
| 0~10 | 그 값으로 교체 (불변) |
| 그 외 | 400 MEMBER-009, 프로필 전체 무변경 (불변) |

## GET /api/v1/members/me/profile (프로필 조회)

| 저장 상태 | 응답 `spicinessPreference` |
|-----------|---------------------------|
| 미설정 | **-1** (신규 표현 — 타입은 기존 그대로 정수) |
| 설정(0~10) | 그 값 (불변) |
| 레거시(profile JSON 에 키 부재) | **-1** — 방어적 해석. 단 실 DB 에 키 부재 행 없음(전 행 백필 — research.md D4), 실제 표시값 변화 0건 |

## Swagger 문구 갱신 (MemberApi)

- 온보딩·프로필 수정: "맵기 `spicinessPreference` 는 -1(미설정) 또는 0~10 — 스킵/설정 안 함은 -1 을 명시 전송, 온보딩에서 미전송 시 -1 로 저장" 취지 반영.
- 프로필 수정의 "항상 값이 있는 속성이라 제거는 없다" 문구를 "-1 명시 전송으로 미설정 복귀" 로 교체.
- 조회 응답: "미설정이면 -1" 명시.
