# Feature Specification: 커뮤니티 피드 조회 + 글 상세 — 커서 페이징·게스트 게이트

**Feature Branch**: `kb-291-community-feed-read`

**Created**: 2026-08-04

**Status**: Draft

**Input**: User description: "KB-291 — 커뮤니티 피드 조회 + 글 상세. 피드는 최신순 단일 정렬 커서 페이징. 게스트는 2페이지까지만 조회 가능하고 이후 로그인 게이트. 글 상세는 게스트도 본문·사진·태그·카운트 전부 열람 가능(댓글 영역만 회원 전용 — 댓글 태스크). 탈퇴 사용자의 글은 콘텐츠를 유지하되 '탈퇴한 사용자' + 기본 프로필 이미지로 익명화. 차단·삭제 필터를 이후 태스크에서 적용할 수 있도록 조회 경로를 한 곳으로 모은다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 회원이 커뮤니티 피드를 훑어본다 (Priority: P1)

로그인한 회원이 커뮤니티 탭을 열면 최신 글부터 한 화면 분량씩 내려온다. 각 글에는 작성자, 본문, 사진(첫 장이 커버), 음식 태그, 좋아요·싫어요·댓글 수가 함께 보인다. 아래로 스크롤하면 이전 응답이 준 커서로 다음 묶음을 이어 받는다.

**Why this priority**: 피드가 없으면 커뮤니티에 진입점이 없다. 글 작성(KB-290)은 이미 있으나 아무도 그 글을 볼 수 없는 상태이며, FE 가 목으로 선작업 중인 계약이 바로 이 목록이다.

**Independent Test**: 글 여러 건을 등록한 뒤 회원 자격으로 피드를 첫 페이지·다음 페이지 순으로 호출해 최신순 정렬·중복 없음·이어받기가 성립하는지 확인하는 것으로 단독 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 등록된 글이 여러 건 있는 상태, **When** 회원이 커서 없이 피드를 조회하면, **Then** 최신 글부터 한 페이지 분량이 반환되고 다음 페이지가 있으면 다음 커서가 함께 온다.
2. **Given** 첫 페이지 응답의 다음 커서, **When** 그 커서로 다시 조회하면, **Then** 첫 페이지와 겹치지 않는 그 다음 묶음이 최신순으로 이어진다.
3. **Given** 남은 글이 한 페이지 미만인 상태, **When** 피드를 조회하면, **Then** 남은 글만 반환되고 다음 페이지 없음이 표시된다.
4. **Given** 등록된 글이 하나도 없는 상태, **When** 피드를 조회하면, **Then** 빈 목록과 다음 페이지 없음이 반환된다(오류 아님).
5. **Given** 삭제된 글, **When** 피드를 조회하면, **Then** 그 글은 목록에 나타나지 않는다.
6. **Given** 사진·음식 태그가 없는 글, **When** 피드를 조회하면, **Then** 사진·태그는 빈 값으로 내려오고 조회는 정상 동작한다.

### User Story 2 - 게스트가 피드를 맛보고 로그인 게이트를 만난다 (Priority: P1)

로그인하지 않은 방문자도 커뮤니티 피드를 볼 수 있다. 다만 최신 2페이지 분량까지만이며, 그 이상 내려가려 하면 "로그인이 필요하다"는 신호를 받아 로그인 화면으로 유도된다.

**Why this priority**: 게스트 노출은 신규 유입의 핵심 동선이고, 게이트 지점이 곧 가입 전환 지점이다. FE 가 목 단계에서 이미 게이트 UI 를 붙이고 있어 P1 과 함께 계약이 확정돼야 한다.

**Independent Test**: 비로그인 상태로 1페이지·2페이지·3페이지를 순차 호출해 앞 두 번은 성공하고 세 번째만 로그인 필요 오류로 거부되는지 확인하는 것으로 단독 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 비로그인 방문자, **When** 커서 없이 피드를 조회하면, **Then** 최신 1페이지가 회원과 동일한 형태로 반환된다.
2. **Given** 비로그인 방문자, **When** 1페이지 응답의 다음 커서로 조회하면, **Then** 2페이지가 반환된다.
3. **Given** 비로그인 방문자, **When** 게스트 허용 범위를 넘어선 커서로 조회하면, **Then** 목록 대신 로그인 필요를 뜻하는 안정적인 오류 식별자가 반환된다.
4. **Given** 글이 게스트 허용 범위보다 적은 상태, **When** 비로그인 방문자가 끝까지 조회하면, **Then** 게이트를 만나지 않고 다음 페이지 없음으로 정상 종료된다.
5. **Given** 게이트에 막혔던 방문자가 로그인한 뒤, **When** 같은 커서로 다시 조회하면, **Then** 제한 없이 다음 페이지가 반환된다.
6. **Given** 인증 정보가 아예 없거나 형식이 잘못된 요청, **When** 피드를 조회하면, **Then** 게스트와 동일한 제한이 적용된다(회원으로 승격되지 않는다).
7. **Given** 형식은 맞으나 만료·위조된 토큰을 들고 온 요청, **When** 피드를 조회하면, **Then** 기존 인증 규약과 동일한 토큰 오류로 응답해 클라이언트가 재발급 후 재시도하게 한다(조용한 게스트 강등으로 회원을 게이트에 막히게 하지 않는다).

### User Story 3 - 누구나 글 상세를 열어본다 (Priority: P2)

피드에서 글을 누르거나 공유 링크로 들어오면 글 하나의 전체 내용을 본다. 게스트도 본문·사진 전체·음식 태그·좋아요/싫어요/댓글 수를 모두 볼 수 있다. 댓글 목록 자체는 이번 범위가 아니다.

**Why this priority**: 피드가 먼저 있어야 진입 경로가 생긴다. 다만 상세는 공유 링크의 착지점이라 피드 직후에 필요하다.

**Independent Test**: 글 한 건을 등록한 뒤 회원·게스트 각각으로 상세를 조회해 동일한 본문·사진·태그·카운트가 반환되는지 확인하는 것으로 단독 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 등록된 글, **When** 회원이 상세를 조회하면, **Then** 작성자·본문·사진 전체·음식 태그·카운트가 반환된다.
2. **Given** 등록된 글, **When** 게스트가 상세를 조회하면, **Then** 회원과 동일한 내용이 반환된다(게이트 없음).
3. **Given** 삭제된 글 또는 존재하지 않는 글 식별자, **When** 상세를 조회하면, **Then** 대상 없음 오류가 반환된다.

---

### User Story 4 - 탈퇴한 사용자의 글이 숨겨진다 (Priority: P3)

작성자가 탈퇴하면 그가 남긴 글은 피드·상세 어디에도 노출되지 않는다(상세는 대상 없음 오류). 데이터는 보존한다. (개정 2026-08-04 — 초기 익명화 노출안을 사용자 결정으로 대체. 탈퇴 회원의 댓글은 "(삭제)" 표기로 남기는 정책이며 댓글 태스크(KB-292)에서 구현한다.)

**Why this priority**: 데이터 정합·개인정보 측면에서 반드시 필요하지만, 발생 빈도가 낮고 피드·상세가 동작한 뒤에 얹을 수 있는 표시 규칙이다.

**Independent Test**: 글을 쓴 회원을 탈퇴 처리한 뒤 피드·상세를 조회해 그 글이 목록에서 빠지고 상세가 대상 없음으로 거절되는지 확인하는 것으로 단독 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 작성자가 탈퇴한 글, **When** 피드를 조회하면, **Then** 그 글은 목록에 나타나지 않는다.
2. **Given** 작성자가 탈퇴한 글, **When** 상세를 조회하면, **Then** 대상 없음 오류로 거절된다.
3. **Given** 활성 회원이 쓴 글, **When** 조회하면, **Then** 실제 닉네임·프로필 이미지가 표시된다.

---

### Edge Cases

- 형식이 잘못된 커서(숫자 아님·음수)로 요청하면? → 잘못된 커서 오류로 거부한다(기존 목록 API 와 동일 규약).
- 이미 삭제된 글의 커서로 이어받기를 하면? → 그 커서 기준으로 더 오래된 글이 정상 반환된다(삭제 글은 건너뛴다).
- 조회 중 새 글이 등록되면 이미 받은 페이지가 밀리는가? → 커서가 글 식별자 기준이라 밀리지 않는다. 새 글은 다시 첫 페이지를 받을 때 보인다.
- 게스트가 아주 오래된 커서를 임의로 만들어 넣으면? → 게스트 허용 범위 밖이므로 로그인 필요 오류로 거부한다(2페이지 게이트는 순차 호출 여부와 무관하게 커서 위치로 판정한다).
- 태그된 음식이 이후 삭제되면 그 글은 어떻게 되는가? → 글은 정상 노출되고 삭제된 음식 태그만 목록에서 빠진다.
- 요청 언어의 음식명 번역이 없으면? → 기존 조회 API 와 동일한 대체 규칙(한국어 원문)을 따른다.
- 언어 파라미터를 생략하면? → 기존 조회 API 와 동일한 기본 언어가 적용된다.
- 작성자 프로필 이미지가 없는 회원의 글은? → 프로필 이미지 없음(null)으로 내려주고 클라이언트가 기본 아바타를 그린다.
- 아직 리액션·댓글 기능이 없는 시점에 카운트는? → 전부 0 으로 응답한다(필드는 지금 확정한다).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 커뮤니티 글 목록을 최신순 단일 정렬로, 커서 기반 페이징으로 제공해야 한다. 응답에는 다음 페이지 존재 여부와 이어받기용 커서가 포함된다.
- **FR-002**: 피드 각 항목은 글 식별자, 작성자(닉네임·프로필 이미지), 본문, 사진 목록(첫 장이 커버), 음식 태그, 좋아요·싫어요·댓글 수, 작성 시각을 포함해야 한다.
- **FR-003**: 시스템은 비로그인 사용자에게도 피드를 제공하되, 최신 2페이지 분량까지로 노출을 제한해야 한다. 페이지 크기는 기존 목록 API 와 동일한 값을 따른다.
- **FR-004**: 게스트가 허용 범위를 넘어 조회를 시도하면 시스템은 목록 대신 "로그인 필요"를 뜻하는 안정적인 오류 식별자를 반환해야 한다. 이 판정은 순차 호출 여부와 무관하게 요청된 커서 위치로 이뤄진다.
- **FR-005**: 시스템은 인증 정보가 없거나 형식이 잘못된 요청을 게스트로 취급해야 한다(제한 우회 불가). 형식은 맞으나 만료·위조된 토큰은 기존 인증 규약과 동일한 토큰 오류로 거절한다 — 로그인한 회원이 조용히 게스트로 강등돼 게이트에 막히는 일을 막는다.
- **FR-006**: 시스템은 글 한 건의 상세를 제공해야 하며, 게스트도 제한 없이 조회할 수 있어야 한다. 상세는 피드 항목과 동일한 정보에 사진 전체를 포함한다.
- **FR-007**: 삭제된 글은 피드·상세 어느 경로에도 노출되지 않아야 하며, 상세 조회 시 대상 없음 오류로 응답해야 한다.
- **FR-008**: 작성자가 탈퇴한 글은 피드·상세 어느 경로에도 노출되지 않아야 하며, 상세 조회 시 대상 없음 오류로 응답해야 한다. 데이터는 보존한다(작성자 복귀·정책 변경 대비).
- **FR-009**: 시스템은 태그된 음식 중 삭제된 것을 응답에서 제외해야 하며, 그로 인해 글 자체가 조회 실패하지 않아야 한다.
- **FR-010**: 피드와 상세의 조회·응답 조립 경로는 한 곳에 모여 있어야 한다. 이후 태스크(차단 사용자 필터·신고 처리 숨김·번역)가 이 한 곳만 고쳐 전 조회 경로에 반영할 수 있어야 한다.
- **FR-011**: 잘못된 형식의 커서는 기존 목록 API 와 동일한 잘못된 커서 오류로 거부해야 한다.
- **FR-012**: 좋아요·싫어요·댓글 수는 응답 계약에 지금 포함하되, 해당 기능이 도입되기 전까지는 0 으로 응답한다.
- **FR-013**: 음식 태그는 음식 식별자와 표시용 음식명을 함께 내려줘야 한다. 음식명은 요청 언어 기준으로 제공하며(기존 조회 API 의 언어 파라미터 규약을 따른다), 클라이언트가 태그를 표시하려고 별도 조회를 하지 않아도 된다. 태그 썸네일은 이번 범위가 아니다.

### Key Entities

- **피드 항목(Feed Item)**: 피드에 한 줄로 표시되는 글 요약. 글 식별자, 작성자 표시 정보, 본문, 사진 목록, 음식 태그, 반응·댓글 수, 작성 시각으로 구성된다. 새로 저장되는 데이터가 아니라 기존 게시글로부터 조립되는 읽기 표현이다.
- **작성자 표시 정보(Author View)**: 글에 함께 보이는 작성자 표현. 노출되는 글의 작성자는 항상 활성 회원이므로 실제 닉네임·프로필 이미지다(탈퇴 작성자의 글은 조회 자체에서 제외).
- **피드 커서(Feed Cursor)**: 다음 묶음의 시작점을 가리키는 값. 최신순 정렬에서 이미 받은 마지막 글 이후를 지목하며, 게스트 노출 한도 판정의 기준이기도 하다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 회원은 커서를 이어받는 것만으로 등록된 모든 글을 중복·누락 없이 끝까지 훑을 수 있다.
- **SC-002**: 게스트는 최신 2페이지 분량까지 조회에 100% 성공하고, 그 범위를 넘는 요청은 100% 로그인 필요 오류로 응답된다.
- **SC-003**: 삭제된 글이 피드·상세에 노출되는 비율은 0%다.
- **SC-004**: 탈퇴 회원이 쓴 글이 피드·상세에 노출되는 비율은 0%다(데이터는 보존).
- **SC-005**: 피드 한 페이지 응답에 필요한 데이터 조회 횟수가 글 수에 비례해 늘지 않는다(항목 수와 무관하게 일정 횟수).
- **SC-006**: 후속 태스크(차단 필터·신고 숨김·번역)가 조회 경로 한 곳만 수정해 피드·상세 양쪽에 동시에 반영할 수 있다.
- **SC-007**: FE 가 목으로 만들어 둔 피드·상세 화면을 응답 구조 변경 없이 실제 API 로 교체할 수 있다.

## Assumptions

- 페이지 크기는 기존 목록 API(리뷰·북마크·음식)와 동일한 20 건을 따른다. 따라서 게스트 노출 한도는 최신 40 건이다.
- 커서·페이지 응답 형태(`items` / `hasNext` / `nextCursor`)는 기존 목록 API 규약을 그대로 재사용하며 새 페이징 방식을 만들지 않는다.
- 정렬은 최신순 단일 정렬만 제공한다. 인기순·팔로잉 등 다른 정렬은 이번 범위가 아니다.
- 좋아요·싫어요(리액션)와 댓글 도메인은 후속 태스크에서 만든다. 이번 태스크는 응답 계약에 카운트 자리를 확정하고 0 으로 채우는 데까지만 책임진다.
- 차단 사용자 글 숨김·신고 처리 글 숨김은 후속 태스크의 범위다. 이번 태스크는 그 필터가 들어갈 단일 조회 경로를 확보하는 것까지만 책임진다.
- 게시글 도메인(KB-290)은 이미 머지되어 있으며, 이번 태스크는 스키마 변경 없이 조회만 얹는다(성능을 위한 인덱스 추가는 예외로 허용).
- 사진은 저장된 이미지 위치를 공개 URL 로 변환해 응답한다(기존 이미지 URL 변환 규약 재사용).
- 게스트 판정은 기존 선택적 인증 방식(토큰이 있으면 회원, 없거나 유효하지 않으면 게스트)을 재사용한다.
- 음식 태그의 언어 파라미터·번역 대체 규칙은 기존 조회 API(음식 목록·스캔·홈)의 규약을 그대로 따르고 새 규칙을 만들지 않는다.
- 탈퇴 회원의 글은 숨기고, 탈퇴 회원의 댓글은 "(삭제)" 표기로 남긴다 — 글은 피드의 1급 콘텐츠라 익명 잔존 가치가 낮고, 댓글은 스레드 맥락 보존이 필요하다는 판단. 댓글 표기는 댓글 태스크(KB-292)에서 구현한다.
