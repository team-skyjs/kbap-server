# Feature Specification: 커뮤니티 댓글/대댓글 — 1depth·멘션·등록순 커서

**Feature Branch**: `kb-292-community-comments`

**Status**: Draft

**Input**: User description: "KB-292 — 커뮤니티 댓글/대댓글 API. 유튜브식 1depth 답글 구조(대댓글에 답글을 달면 마지막 대댓글 뒤에 붙는다). 텍스트만 첨부 가능(사진·태그 불가). @멘션은 알림·프로필 조회가 없는 현 단계에서는 본문 텍스트의 일부로 취급한다(구조화 저장 없음, 표시는 FE 책임). 등록순(오래된 순) 커서 페이징. 댓글 삭제 시 하위 대댓글 통삭제, 대댓글은 단독 삭제. 게스트는 조회 불가(개수만 노출), 쓰기는 회원 전용. 탈퇴 사용자 댓글은 익명화 유지."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 회원이 댓글과 대댓글을 작성한다 (Priority: P1)

로그인한 회원이 커뮤니티 글에 텍스트 댓글을 단다. 댓글에는 답글(대댓글)을 달 수 있고, 답글 구조는 1depth로 고정된다 — 대댓글에 다시 답글을 달면 별도 깊이가 생기는 대신 같은 댓글의 대댓글로 등록돼 등록순 목록의 마지막에 위치한다. 원 작성자 @멘션은 본문 텍스트의 일부일 뿐이며 시스템이 별도로 저장·해석하지 않는다. 댓글에는 텍스트만 담을 수 있다(사진·음식 태그 불가).

**Why this priority**: 댓글 작성이 없으면 목록·수정·삭제·카운트 등 이 기능의 나머지 전부가 성립하지 않는다. 커뮤니티 상호작용의 시작점이다.

**Independent Test**: 회원 자격으로 글에 댓글 1건, 그 댓글에 대댓글 1건, 그 대댓글에 다시 답글 1건을 등록하고 — 마지막 답글이 같은 댓글의 대댓글로 저장돼 등록순 목록 끝에 위치하는지 확인하는 것으로 단독 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 로그인한 회원과 게시된 글, **When** 텍스트로 댓글을 등록하면, **Then** 댓글이 저장되고 작성자·작성 시각이 기록된다.
2. **Given** 기존 댓글, **When** 그 댓글에 답글을 등록하면, **Then** 해당 댓글의 대댓글로 저장된다.
3. **Given** 기존 대댓글, **When** 그 대댓글에 답글을 등록하면, **Then** 같은 댓글의 대댓글로 저장돼 등록순 목록 마지막에 위치한다(멘션 텍스트는 본문에 포함될 뿐 별도 처리 없음).
4. **Given** 로그인한 회원, **When** 빈 본문 또는 최대 길이 초과 본문으로 등록을 시도하면, **Then** 등록이 거부되고 원인을 식별할 수 있는 오류가 반환된다.
5. **Given** 비회원(게스트), **When** 댓글 등록을 시도하면, **Then** 인증 오류로 거부된다.
6. **Given** 삭제된 글 또는 삭제된 댓글, **When** 거기에 댓글·답글 등록을 시도하면, **Then** 대상 없음 오류로 거부된다.

### User Story 2 - 회원이 댓글 목록을 등록순으로 조회한다 (Priority: P2)

로그인한 회원이 글의 댓글 목록을 본다. 정렬은 등록순(오래된 댓글부터)이고, 커서 기반으로 이어서 조회한다. 삭제된 댓글·대댓글은 응답에서 제외되며, 탈퇴한 사용자의 댓글은 내용을 유지한 채 작성자만 "(삭제)"로 익명화된다. 게스트는 댓글 목록을 조회할 수 없다(화면 블러는 FE 책임, 댓글 개수만 노출).

**Why this priority**: 작성된 댓글이 보여야 상호작용이 완성된다. 작성(P1)이 선행돼야 하므로 P2.

**Independent Test**: 댓글 여러 건을 시간차로 등록한 뒤 커서로 나눠 조회해 — 등록순 정렬, 누락·중복 없음, 삭제분 제외, 탈퇴 사용자 익명화를 확인하는 것으로 단독 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 댓글이 여러 건 달린 글, **When** 회원이 목록을 조회하면, **Then** 등록순(오래된 순)으로 반환되고 각 댓글 아래 대댓글도 등록순으로 반환된다.
2. **Given** 첫 페이지 조회 결과와 커서, **When** 커서로 다음 페이지를 조회하면, **Then** 이전 페이지와 중복·누락 없이 이어진다.
3. **Given** 삭제된 댓글·대댓글이 섞인 글, **When** 목록을 조회하면, **Then** 삭제분은 응답에 포함되지 않는다.
4. **Given** 탈퇴한 사용자가 남긴 댓글, **When** 목록을 조회하면, **Then** 내용은 그대로, 작성자는 "(삭제)"로 표시되고 개인 식별 정보는 노출되지 않는다.
5. **Given** 비회원(게스트), **When** 댓글 목록 조회를 시도하면, **Then** 인증 오류로 거부된다.

### User Story 3 - 작성자가 자기 댓글을 수정·삭제한다 (Priority: P3)

댓글 작성자가 본문을 수정하거나 댓글을 삭제한다. 수정 시각은 기록된다. 댓글(최상위)을 삭제하면 그 아래 대댓글까지 모두 보이지 않게 되고(통삭제), 대댓글을 삭제하면 해당 대댓글만 보이지 않는다. 삭제는 소프트 삭제이며, 글 상세·피드의 댓글 개수에서 삭제분(통삭제된 대댓글 포함)이 제외된다.

**Why this priority**: 수정·삭제는 작성·조회 다음의 정리 행위다. P1·P2 없이 성립하지 않는다.

**Independent Test**: 대댓글이 달린 댓글을 삭제해 하위까지 목록·개수에서 사라지는지, 대댓글 단독 삭제 시 해당 건만 사라지는지 확인하는 것으로 단독 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 자기 댓글이 있는 작성자, **When** 본문을 수정하면, **Then** 변경 내용이 반영되고 수정 시각이 갱신된다.
2. **Given** 타인의 댓글, **When** 수정·삭제를 시도하면, **Then** 권한 오류로 거부된다.
3. **Given** 대댓글 2건이 달린 댓글, **When** 그 댓글을 삭제하면, **Then** 댓글과 대댓글 2건 모두 목록에서 사라지고 댓글 개수가 3 줄어든다.
4. **Given** 대댓글, **When** 그 대댓글만 삭제하면, **Then** 해당 대댓글만 사라지고 부모 댓글과 다른 대댓글은 유지된다.
5. **Given** 이미 삭제된 댓글, **When** 다시 수정·삭제를 시도하면, **Then** 대상 없음 오류로 거부된다.

---

### Edge Cases

- 본문이 최대 길이 경계(정확히 상한)인 댓글은 허용, 상한+1자는 거부되는가?
- 삭제된 대댓글에 답글을 시도하면? → 부모 댓글이 살아 있으면 허용(답글의 부모는 최상위 댓글이므로 대상이 존재).
- 탈퇴한 사용자의 대댓글에 답글을 달면? → 등록 허용, 본문 텍스트는 그대로 저장된다.
- 커서 조회 도중 새 댓글이 등록되면? → 등록순이므로 목록 끝에 붙어 기존 페이지에 중복·누락을 만들지 않는다.
- 글이 삭제되면 그 글의 댓글 목록·작성 요청은? → 대상 없음 오류(글 통삭제 정책은 KB-290에서 확정).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 회원이 게시된 글에 텍스트 댓글을 등록할 수 있게 해야 한다. 첨부는 텍스트뿐이다(사진·태그 불가). @멘션은 본문 텍스트의 일부로 취급하며 시스템이 별도로 저장·해석하지 않는다.
- **FR-002**: 답글 구조는 1depth로 고정한다 — 답글은 항상 최상위 댓글 소속이며, 등록순 정렬에 따라 같은 댓글의 대댓글 목록 마지막에 위치한다.
- **FR-003**: 시스템은 댓글 목록을 회원에게만, 등록순(오래된 순) 커서 페이징으로 제공해야 한다. 커서 계약은 BE가 정의하고 FE는 이를 따른다.
- **FR-004**: 시스템은 삭제된 댓글·대댓글을 목록 응답에서 제외해야 한다(필터링은 BE 책임).
- **FR-005**: 댓글 작성·수정·삭제는 회원 전용이며, 수정·삭제는 작성자 본인에게만 허용한다.
- **FR-006**: 댓글 수정 시 수정 시각을 기록해야 한다.
- **FR-007**: 삭제는 소프트 삭제로 처리한다 — 최상위 댓글 삭제 시 하위 대댓글까지 모두 노출이 중단되고(통삭제), 대댓글 삭제 시 해당 대댓글만 노출이 중단된다.
- **FR-008**: 글 상세·피드의 댓글 개수는 노출 가능한 댓글·대댓글 수와 일치해야 한다 — 삭제분(통삭제로 숨겨진 대댓글 포함)을 제외한다.
- **FR-009**: 탈퇴한 사용자의 댓글은 내용을 유지하되 작성자를 "(삭제)"로 익명화해 응답해야 하며, 개인 식별 정보를 노출하지 않는다.
- **FR-010**: 게스트에게는 댓글 내용을 제공하지 않는다 — 목록 조회는 인증 오류로 거부하고, 댓글 개수만 기존 피드·글 상세 응답으로 노출한다(블러 처리는 FE 책임).
- **FR-011**: 삭제된 글·댓글·대댓글을 대상으로 한 등록·수정·삭제 요청은 거부하고, 클라이언트가 분기할 수 있는 안정적인 오류 식별자를 반환해야 한다.

### Key Entities

- **댓글(Comment)**: 글에 달린 텍스트 한 건. 소속 글, 작성자, 본문, 작성/수정 시각, 소프트 삭제 상태를 가진다. 최상위 댓글과 대댓글을 하나의 개체로 표현하며, 대댓글은 부모(최상위 댓글) 참조를 추가로 가진다. 깊이는 1을 넘지 않는다. 멘션은 본문 텍스트에 포함될 뿐 별도 속성이 아니다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 회원은 글에 댓글을 한 번의 등록 동작으로 게시할 수 있다.
- **SC-002**: 대댓글에 단 답글은 100% 같은 댓글의 대댓글 목록 마지막에 위치한다.
- **SC-003**: 삭제된 댓글·대댓글(통삭제로 숨겨진 대댓글 포함)이 목록 응답에 노출되는 비율은 0%다.
- **SC-004**: 타인 댓글에 대한 수정·삭제 시도와 게스트의 목록 조회·작성 시도는 100% 거부된다.
- **SC-005**: 글 상세·피드의 댓글 개수는 목록에서 실제 노출 가능한 댓글·대댓글 수와 항상 일치한다.
- **SC-006**: 커서로 나눠 조회한 전체 결과는 한 번에 조회한 결과와 중복·누락 없이 동일하다.
- **SC-007**: 탈퇴한 사용자의 댓글은 100% "(삭제)"로 표시되고 개인 식별 정보가 노출되지 않는다.

## Assumptions

- 댓글 본문 최대 길이는 별도 지정이 없어 게시글 본문과 동일한 2,000자 상한을 재사용한다.
- @멘션은 텍스트로만 취급한다 — 알림·회원 프로필 조회가 없는 현 단계에서 구조화 저장의 실익이 없다. 멘션 삽입·표시는 FE 책임이며, 멘션 알림·프로필 연결이 생기는 시점에 별도 태스크로 구조화한다.
- 수정 대상은 본문 텍스트뿐이다. 답글의 소속(부모 댓글)은 이동할 수 없다.
- 게시글 도메인(KB-290)과 피드·상세 조회(KB-291)는 머지 완료 상태를 전제한다. 댓글 개수 필드는 KB-291의 기존 응답 계약을 재사용하고 값 산정만 이번 태스크가 책임진다.
- 멘션 알림(푸시 등)은 이번 스코프에서 제외한다 — 별도 태스크에서 다룬다.
- 댓글 신고·차단·번역은 별도 태스크의 범위다.
