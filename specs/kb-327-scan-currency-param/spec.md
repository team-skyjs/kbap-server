# Feature Specification: 스캔 2.0 통화 환산 기준을 currency 요청 파라미터로 전환

**Feature Branch**: `kb-327-scan-currency-param`

**Created**: 2026-08-11

**Status**: Draft

**Input**: User description: "스캔할 때 currency를 파라미터로 노출시켜서 회원 프로필 설정대로 반환되지 않도록 해야 돼. 비회원도 스캔을 일정 횟수 가능하도록 제공해줄거야. 따라서 회원, 비회원 모두 외부 파라미터 기준으로 환율 정보를 응답으로 내려줘야 할 것 같다 (KB-327, 워크트리)"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 요청 파라미터로 환산 통화 지정 (Priority: P1)

사용자가 2.0 스캔을 요청할 때 `currency` 파라미터로 원하는 통화를 지정하면, 응답의 통화 환산 정보(통화 코드 + 1단위당 원화 환율)가 회원 프로필 설정과 무관하게 그 파라미터 통화 기준으로 내려온다. 비회원 스캔이 도입되어 회원 프로필이 아예 없는 요청에서도 같은 방식이 그대로 동작한다.

**Why this priority**: 이 기능의 존재 이유다. 현재 환산 통화는 회원 프로필에서만 나오므로, 프로필이 없는 비회원에게는 통화 환산 정보를 내려줄 방법이 없다. 통화 결정을 외부 파라미터로 옮겨야 비회원 스캔이 열렸을 때 그대로 동작한다.

**Independent Test**: 프로필 통화가 USD 인 회원으로 `currency=JPY` 를 지정해 2.0 스캔을 호출하고, 응답의 통화 환산 정보가 프로필(USD)이 아닌 JPY 기준인지 확인하는 것만으로 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 프로필 통화가 USD 로 설정된 회원, **When** `currency=JPY` 로 2.0 스캔을 요청하면, **Then** 응답의 통화 환산 정보는 JPY 코드와 JPY 의 1단위당 원화 환율 값이다 (프로필 USD 는 무시된다).
2. **Given** 프로필 통화가 설정되지 않은 회원, **When** `currency=USD` 로 2.0 스캔을 요청하면, **Then** 응답의 통화 환산 정보는 USD 기준으로 내려온다.
3. **Given** 임의 회원, **When** 지원하지 않는 값(`currency=XXX`)으로 2.0 스캔을 요청하면, **Then** 스캔은 실행되지 않고 지원하지 않는 통화 코드 오류(400)로 실패한다.

---

### User Story 2 - 파라미터 미전달 시 기존 동작 보존 (Priority: P2)

기존 클라이언트처럼 `currency` 파라미터 없이 2.0 스캔을 요청하면, 지금과 동일하게 회원 프로필 통화 기준으로 환산 정보가 내려오고, 프로필 통화가 없으면 환산 정보만 빈 채 스캔은 성공한다.

**Why this priority**: 파라미터 도입이 기존 2.0 응답 계약을 깨서는 안 된다. 파라미터를 모르는 클라이언트의 동작을 그대로 보존한다.

**Independent Test**: 프로필 통화가 USD 인 회원으로 파라미터 없이 2.0 스캔을 호출해 응답이 USD 기준인지, 통화 미설정 회원은 환산 정보가 비어 있는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 프로필 통화가 USD 인 회원, **When** `currency` 파라미터 없이 2.0 스캔을 요청하면, **Then** 응답의 통화 환산 정보는 지금처럼 USD 기준이다.
2. **Given** 프로필 통화가 설정되지 않은 회원, **When** `currency` 파라미터 없이 2.0 스캔을 요청하면, **Then** 스캔은 성공하고 통화 환산 정보는 포함되지 않는다(빈 값) — 기존 동작과 동일.

---

### Edge Cases

- 지원 목록에 없는 통화 값 → 스캔 실행 전 400 실패 (User Story 1, 프로필 통화 변경과 동일한 오류 정책). 조용히 무시하고 프로필로 fallback 하지 않는다 — 클라이언트 오타가 잘못된 환산 표시로 이어지는 것을 막는다.
- 파라미터 통화와 프로필 통화가 같은 경우 → 파라미터 우선 규칙이 그대로 적용되며 결과는 동일하다.
- 1.0 스캔 응답에는 통화 환산 정보 자체가 없으므로 이번 변경의 영향이 없다 — 1.0 은 불변.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 2.0 스캔 요청은 선택(optional) 파라미터 `currency`(ISO 4217 코드)를 받을 수 있어야 한다.
- **FR-002**: `currency` 파라미터가 지정되면 응답의 통화 환산 정보는 회원 프로필 설정과 무관하게 파라미터 통화 기준이어야 한다 (파라미터 우선).
- **FR-003**: `currency` 파라미터가 없으면 기존과 동일하게 회원 프로필 통화로 fallback 하고, 프로필 통화도 없으면 환산 정보 없이 정상 응답해야 한다.
- **FR-004**: 지원하지 않는 통화 값이 오면 지원하지 않는 통화 코드 오류(`MEMBER-010`, 400)로 실패해야 한다 — 프로필 통화 변경과 동일한 정책.
- **FR-005**: 기존 2.0 응답의 필드 형태·의미와 1.0 스캔 응답은 변경하지 않는다. 환율 값은 기존 참고용 고정 스냅샷(1단위당 원화)을 그대로 쓴다.
- **FR-006**: 응답 통화 결정 로직은 회원 프로필 존재에 의존하지 않는 구조여야 한다 — 비회원 스캔(후속 과제)이 도입되면 파라미터 경로가 수정 없이 동작해야 한다.

### Key Entities

- **currency 요청 파라미터**: 클라이언트가 지정하는 환산 통화. 선택 값이며, 지원 통화 목록(기존 통화 스냅샷)에 있어야 한다.
- **회원 프로필 통화**: 파라미터 부재 시의 fallback. 미설정일 수 있다.
- **통화 환산 정보(2.0 응답)**: 통화 코드 + 1단위당 원화 환율. 이번 변경으로 값의 출처만 바뀌고 형태는 그대로다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: `currency` 파라미터를 지정한 2.0 스캔 성공 응답 100%가 파라미터 통화 기준 환산 정보를 포함한다 — 프로필 설정과 불일치 0건.
- **SC-002**: 파라미터를 지정하지 않은 기존 클라이언트의 2.0 스캔 응답이 도입 전과 완전히 동일하다.
- **SC-003**: 통화 결정에 추가 외부 조회·DB 조회가 없어 스캔 응답 시간이 도입 전과 체감 차이가 없다.

## Assumptions

- **비회원 스캔 자체는 이번 범위 밖이다.** 비회원 허용(인증 완화·횟수 제한)은 별도 태스크로 진행한다. 이번 작업은 통화 결정을 프로필 의존에서 파라미터 우선으로 전환해 그 선행 조건을 만드는 것까지다.
- **적용 범위는 2.0 스캔뿐이다.** 1.0 스캔 응답에는 통화 환산 정보가 없으므로 파라미터도 추가하지 않는다.
- **파라미터 우선, 프로필 fallback.** Jira KB-327 DoD 의 기본 동작 정의를 이렇게 확정한다: 파라미터 > 프로필 > 없음(빈 값).
- **잘못된 통화 값은 명시적 실패다.** 조용한 fallback 은 잘못된 환산 표시 위험이 있어 채택하지 않으며, 기존 `MEMBER-010` 오류 코드를 재사용한다.
- **버전 번호는 올리지 않는다.** 선택 파라미터 추가 + 미전달 시 동작 불변이라 하위 호환이며, 2.0 매핑 그대로 둔다.
