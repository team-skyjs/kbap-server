# Feature Specification: 스캔 2.0 — 메뉴판 아닌 사진의 빈 결과 처리

**Feature Branch**: `kb-330-scan-non-menu-board`

**Created**: 2026-08-13

**Status**: Draft

**Input**: User description: "스캔 2.0 에서 사용자가 찍은 사진이 메뉴판으로 추정되지 않으면 1.0 스캔과 동일하게 처리한다 — 1.0 의 주 경로인 환각 제외 규칙(빈 결과 수렴)을 2.0 인식 지시에 추가한다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 메뉴판 아닌 사진의 일관된 빈 결과 (Priority: P1)

사용자가 메뉴판이 아닌 사진(풍경·셀카·영수증·간판 등)을 스캔하면, 시스템은 메뉴를 지어내지 않고 항상 빈 결과 목록을 성공 응답으로 반환한다. 앱은 빈 결과를 받아 1.0 과 동일한 안내(결과 없음/재촬영)를 띄울 수 있다.

**Why this priority**: 현재는 같은 비메뉴판 사진이라도 어떤 때는 빈 결과(200), 어떤 때는 인식 실패(503)로 갈리고, 최악의 경우 사진에 없는 메뉴가 지어져 위험 평가까지 붙어 나간다 — 알러지 안전 서비스에서 지어낸 메뉴는 신뢰를 직접 훼손한다.

**Independent Test**: 메뉴판이 아닌 사진 여러 장을 스캔해 모두 빈 결과 목록의 성공 응답이 반환되고, 지어낸 메뉴 항목이 0건인 것으로 검증된다.

**Acceptance Scenarios**:

1. **Given** 메뉴판이 아닌 사진(예: 풍경)을 업로드한 상태에서, **When** 2.0 스캔을 요청하면, **Then** 성공 응답에 빈 결과 목록이 담기고 지어낸 메뉴 항목이 없다.
2. **Given** 글자는 있지만 메뉴판이 아닌 사진(예: 영수증·간판)으로, **When** 2.0 스캔을 요청하면, **Then** 메뉴가 아닌 텍스트는 결과에 포함되지 않고 빈 결과 목록이 반환된다.

---

### User Story 2 - 정상 메뉴판 스캔 무회귀 (Priority: P2)

실제 메뉴판 사진을 스캔하는 기존 사용자 경험은 그대로다 — 인식 지시에 규칙을 추가해도 정상 메뉴판의 메뉴·가격 추출 결과가 나빠지지 않는다.

**Why this priority**: 이 변경은 예외 상황 처리이며, 주 사용 경로(정상 메뉴판)를 해치면 본말이 전도된다.

**Independent Test**: 기존에 정상 인식되던 메뉴판 사진 표본을 변경 후 다시 스캔해 추출 결과(메뉴 수·이름·가격)가 동등한 것으로 검증된다.

**Acceptance Scenarios**:

1. **Given** 정상 메뉴판 사진으로, **When** 2.0 스캔을 요청하면, **Then** 변경 전과 동등한 메뉴·가격 결과가 반환된다.

---

### Edge Cases

- 메뉴판이지만 화질·각도 문제로 메뉴를 하나도 확인할 수 없는 사진 → 지어내지 않고 빈 결과로 처리한다(비메뉴판과 동일).
- 인식 응답 형식 자체가 무너지는 경우의 기존 동작(인식 실패 에러)은 이 기능의 범위 밖이며 그대로 유지한다.
- 1.0 스캔(클라이언트 OCR 방식)의 동작은 변경하지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 메뉴판으로 추정되지 않는 사진의 2.0 스캔은 빈 결과 목록의 성공 응답으로 일관되게 처리되어야 한다.
- **FR-002**: 사진에서 확인되지 않는 메뉴를 결과에 포함해서는 안 된다(환각 금지) — 메뉴가 아닌 텍스트(상호·전화번호·안내문 등)도 결과에서 제외한다.
- **FR-003**: 빈 결과의 응답 형태는 1.0 스캔이 빈 결과를 반환할 때와 동일해야 한다(클라이언트가 두 버전을 같은 방식으로 처리 가능).
- **FR-004**: 정상 메뉴판 사진의 인식 결과는 변경 전과 동등해야 한다(회귀 없음).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 메뉴판이 아닌 사진 표본 스캔의 100% 가 빈 결과 성공 응답으로 처리되며, 지어낸 메뉴 항목이 0건이다.
- **SC-002**: 같은 비메뉴판 사진을 반복 스캔해도 응답 유형이 갈리지 않는다(항상 동일한 빈 결과 처리).
- **SC-003**: 기존 정상 메뉴판 표본의 인식 결과가 변경 전과 동등하다.

## Assumptions

- "메뉴판으로 추정되지 않음"의 판정은 인식 단계가 수행하며, 별도의 사전 분류 단계를 두지 않는다.
- 빈 결과에 대한 사용자 안내(재촬영 유도 UI 등)는 클라이언트 책임이고, 서버는 1.0 과 동일한 형태의 빈 결과만 제공한다.
- 인식 실패(형식 붕괴) 시의 기존 에러 계약(SCAN-002)은 변경하지 않는다 — 이 기능은 "정상적으로 인식했으나 메뉴판이 아님" 경로만 다룬다.
- 스캔 횟수 집계 등 부수 동작은 기존 빈 결과 처리와 동일하게 유지한다.
