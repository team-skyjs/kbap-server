# Feature Specification: 회원 통화 설정 — 국가 기반 자동 지정 및 프로필에서 개별 변경

**Feature Branch**: `kb-322-member-currency`

**Created**: 2026-08-11

**Status**: Draft

**Input**: User description: "KB-322 [BE] 회원 통화 설정 — 국가 기반 자동 지정 및 프로필에서 개별 변경"

## 배경

회원 프로필에는 국가(`countryCode`)만 있고 통화 개념이 없다. 메뉴 가격은 원화 정수 하나로만 다뤄, 외국인 사용자가 자국 통화로 얼마인지 가늠할 수 없다.

금액 환산을 붙이려면 **"이 회원이 어떤 통화를 쓰는가"를 먼저 저장**해야 한다. 이 기능은 그 저장소를 만든다 — 환산·환율은 후속 작업의 몫이다.

사용자에게 통화를 고르는 단계를 새로 만들지 않는다. 온보딩에서 이미 받는 국가로부터 통화를 자동으로 정하고, 그 값이 맞지 않는 사용자(해외 거주자 등)만 프로필에서 바꾼다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 온보딩만 마치면 통화가 정해져 있다 (Priority: P1)

신규 사용자가 온보딩에서 국가를 고른다. 통화를 묻는 화면은 없지만, 가입이 끝나면 그 국가의 통화가 프로필에 저장돼 있다.

**Why this priority**: 이 기능의 존재 이유다. 통화가 저장돼야 후속 환산 기능이 성립하고, 자동 지정이 아니면 온보딩 단계가 하나 늘어난다.

**Independent Test**: 국가를 지정해 온보딩을 마친 뒤 프로필을 조회해 통화가 채워져 있는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 한국을 선택해 온보딩할 때, **When** 온보딩을 마치면, **Then** 프로필의 통화가 원화다.
2. **Given** 일본을 선택해 온보딩할 때, **When** 온보딩을 마치면, **Then** 프로필의 통화가 엔화다.
3. **Given** 여러 국가가 같은 통화를 쓰는 국가(예: 유로존 국가)를 선택할 때, **When** 온보딩을 마치면, **Then** 그 공통 통화가 지정된다.
4. **Given** 온보딩 요청에 통화 값을 임의로 실어 보낼 때, **When** 온보딩을 마치면, **Then** 무시되고 국가 기준 통화가 지정된다.

---

### User Story 2 - 국가와 다른 통화를 쓰는 사용자가 직접 바꾼다 (Priority: P1)

일본에 사는 한국인처럼 국가와 실제 사용 통화가 어긋나는 사용자가, 프로필 수정에서 통화만 따로 바꾼다.

**Why this priority**: 자동 지정만 있으면 어긋나는 사용자가 영영 고칠 수 없다. 자동 지정과 짝을 이뤄야 기능이 완결된다.

**Independent Test**: 프로필 수정으로 통화만 바꾸고 다시 조회해 바뀐 값이 유지되는지, 국가는 그대로인지 확인한다.

**Acceptance Scenarios**:

1. **Given** 통화가 원화인 회원일 때, **When** 프로필 수정으로 통화를 엔화로 바꾸면, **Then** 통화는 엔화가 되고 국가는 바뀌지 않는다.
2. **Given** 프로필 수정 요청에 통화를 넣지 않을 때, **When** 다른 필드만 수정하면, **Then** 기존 통화가 유지된다.
3. **Given** 지원하지 않는 통화 값을 보낼 때, **When** 프로필을 수정하면, **Then** 요청이 거절되고 기존 통화가 유지된다.
4. **Given** 통화를 엔화로 바꿔 둔 회원일 때, **When** 프로필 수정으로 국가만 미국으로 바꾸면, **Then** 국가는 미국이 되고 **통화는 엔화 그대로**다.

---

### User Story 3 - 앱이 현재 통화를 읽을 수 있다 (Priority: P1)

클라이언트가 내 프로필을 조회할 때 현재 통화를 함께 받아, 프로필 화면에 보여주고 수정 폼의 초기값으로 쓴다.

**Why this priority**: 저장만 되고 읽을 수 없으면 US1·US2 를 화면에서 확인할 방법이 없다. 같은 릴리스에서 함께 성립해야 한다.

**Independent Test**: 프로필 조회 응답에 통화 필드가 있고 저장된 값과 일치하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 온보딩을 마친 회원일 때, **When** 내 프로필을 조회하면, **Then** 응답에 현재 통화가 담겨 있다.
2. **Given** 아직 온보딩하지 않아 국가가 없는 회원일 때, **When** 내 프로필을 조회하면, **Then** 통화는 비어 있고 조회는 정상이다.

---

### User Story 4 - 이미 가입한 회원도 통화를 갖는다 (Priority: P2)

이 기능 이전에 가입한 회원이 앱을 열었을 때, 아무 조작 없이 자기 국가에 맞는 통화가 이미 채워져 있다.

**Why this priority**: 기존 회원이 비어 있으면 후속 환산 기능이 그들에게만 동작하지 않는다. 다만 신규 가입 흐름과 독립적이라 P2.

**Independent Test**: 기능 적용 전 데이터를 가진 회원을 조회해 통화가 국가 기준으로 채워져 있는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 국가가 저장된 기존 회원일 때, **When** 프로필을 조회하면, **Then** 통화가 그 국가 기준으로 채워져 있다.
2. **Given** 국가가 없는 기존 회원일 때, **When** 프로필을 조회하면, **Then** 통화는 비어 있고 조회는 정상이다.

---

### Edge Cases

- 국가는 있으나 통화 매핑이 정의되지 않은 국가 — 매핑을 197개 전수로 채워 이 상태가 나오지 않게 한다. 그래도 발생하면 통화를 비우고 조회는 정상 동작한다.
- 온보딩을 마치지 않은 회원 — 국가가 없으므로 통화도 비어 있다. 오류가 아니다.
- 프로필 수정에서 국가와 통화를 **동시에** 보낼 때 — 두 값 모두 요청대로 저장된다(통화가 국가에 의해 덮어써지지 않는다).
- 국가만 바꿀 때 — 통화는 이전 값 그대로다. 새 국가와 통화가 어긋나는 상태가 될 수 있으며, 이는 허용된 상태다(사용자가 통화를 따로 바꾸면 된다).
- 국가를 바꿔 통화가 어긋난 사용자가 새 국가 기준으로 되돌리고 싶을 때 — 통화를 직접 그 값으로 지정하면 된다. 자동 되돌림은 제공하지 않는다.
- 통화 값의 대소문자·공백 — 정확 일치로만 받는다(관대한 정규화를 하지 않는다, 헌법 원칙 V 의 언어 코드 취급과 동일한 태도).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 회원별 통화를 저장해야 한다.
- **FR-002**: 온보딩에서 국가를 확정할 때 그 국가에 대응하는 통화가 자동으로 지정돼야 한다.
- **FR-003**: 온보딩 요청이 통화 값을 보내더라도 무시되고 국가 기준 통화가 지정돼야 한다 — 온보딩에서 통화는 사용자 입력이 아니다.
- **FR-004**: 국가에서 통화로 가는 매핑이 지원하는 197개 국가 전부에 대해 정의돼야 한다. 취급 통화(46종) 밖 통화를 쓰는 국가는 **미국 달러로 대체 지정**한다.
- **FR-005**: 프로필 수정에서 통화를 국가와 독립적으로 변경할 수 있어야 한다.
- **FR-006**: 프로필 수정에서 통화를 보내지 않으면 기존 값이 유지돼야 한다.
- **FR-007**: 프로필 수정에서 국가를 바꿔도 통화는 변경되지 않아야 한다 — 국가 기준 자동 지정은 **온보딩에서만** 일어난다.
- **FR-008**: 지원하지 않는 통화 값 요청은 거절되고 기존 값이 유지돼야 한다.
- **FR-009**: 내 프로필 조회 응답에 현재 통화가 포함돼야 한다.
- **FR-010**: 기능 적용 시점 이전에 가입한 회원의 통화가 각자의 국가 기준으로 채워져야 한다.
- **FR-011**: 국가가 없는 회원은 통화도 비어 있어야 하며, 그 상태에서 프로필 조회·수정이 정상 동작해야 한다.
- **FR-012**: 통화 필드 추가로 기존 클라이언트의 요청·응답 처리가 깨지지 않아야 한다.

### Key Entities

- **회원 프로필**: 닉네임·기피성분·국가·프로필사진·맵기선호에 **통화**가 더해진다. 국가와 통화는 서로 독립적으로 저장되며, 통화는 국가로부터 초기값을 받을 뿐 종속되지 않는다.
- **국가→통화 매핑**: 지원 국가 각각에 통화 하나를 대응시키는 고정 표. 국가→통화는 1:1 이고 통화→국가는 1:N 이다(유로존 등). 운영자 런타임 편집 대상이 아니다.
- **지원 통화 집합**: 매핑에 등장하는 통화들의 합집합. 프로필 수정에서 받을 수 있는 값의 범위이기도 하다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 온보딩을 마친 신규 회원 중 통화가 비어 있는 비율이 0% 다(국가를 고르지 않을 수 없으므로).
- **SC-002**: 지원 국가 197개 각각에 대해 통화가 하나씩 결정된다 — 미정의 국가 0개. 취급 통화 46종 전부가 환율을 갖는다 — 환율 없는 통화 0종.
- **SC-003**: 사용자가 통화를 바꾼 뒤 다시 조회했을 때 바뀐 값이 그대로 보이는 비율 100%.
- **SC-004**: 기능 적용 이후, 국가가 저장된 기존 회원 중 통화가 비어 있는 비율이 0% 다.
- **SC-005**: 온보딩 단계 수가 늘지 않는다 — 사용자가 통화를 입력하는 화면이 0개다.
- **SC-006**: 기존 클라이언트를 수정하지 않아도 프로필 조회·수정이 정상 동작한다(요청 거절·응답 파싱 실패 0건).

## Assumptions

- **취급 통화는 46종**(국내 은행 고시 대상 45종 + 원화)으로 한정한다. 그 밖의 통화를 쓰는 국가(117개)는 **미국 달러로 대체 지정**한다 — 통화가 비어 조회·환산이 막히는 상태를 만들지 않기 위함이다.
- **환율은 고정 스냅샷**이다. 국내 은행 고시 매매기준율을 코드에 박아 두고 실시간 갱신하지 않는다. 시간이 지나면 실제 시세와 벌어지며, 그 오차는 감수한다(참고용 근사).
- 환율은 **1단위당 원화 금액**으로 저장한다. 은행 고시의 `100엔`·`100루피아`·`100동` 표기는 100으로 나눠 정규화했다.
- 통화 표기는 국제 표준 통화 코드(3자 영문 대문자)를 쓴다. 표시용 기호·명칭은 클라이언트가 가진다 — 서버는 코드만 저장·응답한다.
- **환율과 금액 환산은 이 기능의 범위 밖**이다. 후속 작업(KB-323)이 이 통화 값을 읽어 환산한다.
- 통화 값을 요청 본문에 추가하는 것과 응답에 필드를 더하는 것은 하위 호환이라 API 버전을 올리지 않는다.
- 온보딩을 마치지 않은 회원은 국가가 없으므로 통화도 비어 있는 것이 정상 상태다.
- **국가와 통화가 어긋난 상태를 허용한다**(FR-007). 자동 지정을 온보딩으로 한정한 결과이며, 사용자가 직접 고른 값을 말없이 덮어쓰지 않기 위한 선택이다. 대신 이사 등으로 국가를 바꾼 사용자는 통화도 따로 바꿔야 한다 — 이 불편은 감수한다.
- 국가→통화 매핑은 고정 기준표이므로 운영 중 변경이 필요 없다고 본다. 통화 개편(국가의 통화 교체) 같은 사건은 코드 변경으로 대응한다.
