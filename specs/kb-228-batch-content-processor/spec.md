# Feature Specification: 배치 음식 콘텐츠 프로세서의 작업별 구현 — 이름 번역·설명 생성+번역·기피성분+맵기

**Feature Branch**: `kb-228-batch-content-processor`

**Created**: 2026-07-23

**Status**: Draft

**Input**: User description: "KB-228 — 배치 음식 콘텐츠 프로세서의 작업별 구현. 콘텐츠 작업을 3개 그룹으로 재편: ① 이름 번역 ② 설명 생성 + 설명 번역(한 호출) ③ 기피성분 조사 + 맵기. 맵기를 설명 계약에서 기피성분 계약으로 이동. 이미지 생성은 범위 제외. 워크트리에서 진행."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 기피성분 조사가 맵기까지 판정한다 (Priority: P1)

미완성 음식이 배치를 거치면 기피성분 포함 확률과 함께 맵기(0~10)가 판정되어 저장된다. 맵기는 회원의 맵기 선호와 매칭되는 안전 직결 값이므로, 기피성분과 같은 다중 모델 종합 판정으로 결정된다.

**Why this priority**: 맵기·기피성분은 회원 안전(알레르기·기피·맵기 선호)과 직결된 데이터다. 단일 모델 판단을 금지하는 기존 기피성분 종합 방식에 맵기를 편입하는 것이 이번 재편의 핵심 계약 변경이며, 다른 작업이 이 계약 위에 얹힌다.

**Independent Test**: 맵기 미판정(-1)·기피성분 미조사(null) 음식 1건을 배치에 태우면, 기피성분 목록과 맵기가 함께 채워진 상태로 저장되는 것으로 검증한다.

**Acceptance Scenarios**:

1. **Given** 기피성분 미조사·맵기 미판정 음식, **When** 배치 콘텐츠 처리 실행, **Then** 기피성분 포함 확률 목록과 맵기(0~10)가 함께 저장된다
2. **Given** 다중 모델 중 유효 응답이 합의 최소치(2개) 미만, **When** 기피성분·맵기 조사 실행, **Then** 판정을 저장하지 않고 해당 음식은 실패로 건너뛴다(다음 실행에서 재시도)
3. **Given** 모델이 범위 밖 맵기(예: 11)를 반환, **When** 응답 종합, **Then** 해당 모델 응답은 무효 처리되어 종합에서 제외된다

---

### User Story 2 - 설명 생성이 설명 번역까지 함께 만든다 (Priority: P2)

설명이 없는(플레이스홀더) 음식이 배치를 거치면 한국어 한 줄 설명과 그 설명의 9개 언어 번역이 한 번의 생성으로 함께 채워진다. 원문과 번역이 같은 생성 맥락에서 나오므로 정합성이 보장된다.

**Why this priority**: 설명·설명 번역은 홈/상세 화면 노출 콘텐츠의 본체다. 맵기가 기피성분 쪽으로 이동한 뒤의 설명 계약(설명+번역만)을 확정한다.

**Independent Test**: 설명이 플레이스홀더인 음식 1건을 배치에 태우면, 설명과 설명 번역 9개 언어가 함께 채워지고 맵기는 이 작업에서 변경되지 않는 것으로 검증한다.

**Acceptance Scenarios**:

1. **Given** 설명이 플레이스홀더인 음식, **When** 배치 콘텐츠 처리 실행, **Then** 한국어 설명(255자 이하)과 9개 대상 언어 번역이 함께 저장된다
2. **Given** 설명 생성 응답이 계약 위반(빈 설명·언어 누락 등), **When** 처리, **Then** 해당 음식은 실패로 건너뛰고 기존 값은 훼손되지 않는다

---

### User Story 3 - 이름 번역이 채워진다 (Priority: P3)

이름 번역이 비어 있는 음식이 배치를 거치면 메뉴판 표기용 이름 번역 9개 언어가 채워진다.

**Why this priority**: 이름 번역은 통용 표기 우선의 독립 작업으로, 설명 계열과 분리된 별도 호출이다. 다른 두 작업과 독립적으로 완성 가능하다.

**Independent Test**: 이름 번역이 비어 있는 음식 1건을 배치에 태우면 이름 번역 9개 언어가 채워지는 것으로 검증한다.

**Acceptance Scenarios**:

1. **Given** 이름 번역이 없는 음식, **When** 배치 콘텐츠 처리 실행, **Then** 9개 대상 언어의 이름 번역이 저장된다
2. **Given** 이름 번역만 비어 있고 나머지는 완비된 음식, **When** 처리, **Then** 이름 번역 작업만 수행된다(설명·기피성분 재호출 없음)

---

### Edge Cases

- 한 작업이 성공하고 뒤 작업이 실패하면? → 성공한 작업 결과는 즉시 저장되어 유지되고, 다음 실행에서 실패한 작업만 재시도된다
- 모든 작업이 완료된 음식은? → READY 로 전환된다. 단 이미지가 없으면(이번 범위 제외) INCOMPLETE 로 남는다
- 기피성분 후보 목록이 비어 있으면? → 기피성분·맵기 조사를 수행하지 않는다(현행 동작 유지)
- 이미 일부 언어 번역이 있는 음식은? → 대상 언어 전수가 없으면 미완으로 보고 전체를 다시 생성한다(부분 병합 없음)

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 배치 콘텐츠 처리는 음식 1건에 대해 ① 이름 번역 ② 설명 생성+설명 번역 ③ 기피성분 조사+맵기 판정의 3개 작업을 필요한 것만 수행해야 한다
- **FR-002**: 설명 생성은 한국어 설명과 9개 대상 언어의 설명 번역을 한 번의 생성으로 함께 반환해야 하며, 맵기는 포함하지 않는다
- **FR-003**: 기피성분 조사는 기피성분 포함 확률 목록과 함께 맵기(0~10 정수)를 반환해야 하며, 다중 모델 응답 종합으로 판정한다(유효 응답 2개 미만이면 판정 거부)
- **FR-004**: 맵기 종합 시 범위(0~10) 밖 값을 반환한 모델 응답은 무효 처리되어야 한다
- **FR-005**: 이름 번역은 9개 대상 언어 전수를 반환해야 하며, 이름 번역이 미완일 때만 수행한다
- **FR-006**: 각 작업 성공 결과는 즉시 저장되어, 이후 작업 실패 시에도 유지되어야 한다(재실행 시 실패 작업만 재시도)
- **FR-007**: 계약 위반 응답(빈 값·언어 누락·범위 밖 값)은 해당 음식의 처리 실패로 이어지고, 기존 저장 값은 훼손되지 않아야 한다
- **FR-008**: 이미지 생성은 이번 범위에서 수행하지 않는다(스텁 유지). 이미지 미보유 음식은 다른 작업이 모두 완료되어도 READY 로 전환되지 않는다

### Key Entities

- **음식(Food)**: 한국어 이름, 설명, 맵기, 이름 번역, 설명 번역, 기피성분 목록, 콘텐츠 상태(INCOMPLETE/READY)를 갖는 콘텐츠 단위
- **기피성분 판정**: 성분 코드별 포함 확률(1~100)의 목록 + 음식 맵기(0~10) — 다중 모델 종합 결과
- **설명 콘텐츠**: 한국어 설명(255자 이하) + 9개 대상 언어 번역 — 단일 생성 결과
- **이름 번역**: 9개 대상 언어의 메뉴판 표기용 번역

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 미완성 음식 1건이 배치 1회 실행으로 이름 번역·설명(+번역)·기피성분·맵기가 모두 채워진다(이미지 제외)
- **SC-002**: 중간 작업 실패 시에도 이미 성공한 작업 결과는 100% 보존되고, 재실행 시 실패 작업만 다시 수행된다
- **SC-003**: 맵기 판정은 항상 2개 이상 모델의 유효 응답 종합으로만 저장된다(단일 모델 판정 0건)
- **SC-004**: 처리 실패 음식은 배치 전체를 중단시키지 않고 건너뛰어지며, 실패 사유가 로그로 남는다

## Assumptions

- 맵기 판정 루브릭(0~10 스케일)은 기존 설명 생성에서 쓰던 기준을 기피성분 조사로 옮겨 유지한다
- 맵기 종합은 기피성분과 동일하게 유효 응답 평균(반올림)으로 한다
- 기피성분 조사와 맵기 판정은 한 번의 다중 모델 호출로 함께 수행된다(별도 호출 없음)
- 이름 번역·설명 생성은 각각 단일 모델 호출로 충분하다(안전 직결 아님)
- 배치 인프라(리더·청크·건너뛰기·작업별 즉시 저장)는 기존 골격을 그대로 사용한다
- READY 전환 조건(이미지 포함 전 항목 완비 + 맵기 판정됨)은 변경하지 않는다
