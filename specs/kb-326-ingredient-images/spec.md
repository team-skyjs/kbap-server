# Feature Specification: 온보딩 재료 81종 이름·이미지 공개 조회

**Feature Branch**: `kb-326-ingredient-images`

**Created**: 2026-08-11

**Status**: Draft

**Input**: User description: "온보딩 과정 중 재료 81종 이름과 사진까지 함께 조회하는 요구사항이 추가되었다. 따라서 현재 db에 이미지 path를 매칭해서 저장할 것이다. 또한 누구나 조회 가능한 api를 하나 만들어서 온보딩 과정에서 조회하도록 연결할 것이다." (Jira KB-326)

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 온보딩에서 재료 목록을 사진과 함께 본다 (Priority: P1)

앱을 처음 설치한 사용자가 온보딩에서 기피 재료를 선택할 때, 재료 81종이 이름과 사진과 함께 목록으로 표시된다. 온보딩은 로그인(토큰 발급) 전 단계이므로 인증 없이도 목록을 받아볼 수 있어야 한다.

**Why this priority**: 온보딩 화면이 이 목록 없이는 새 요구사항(사진 포함 재료 선택 UI)을 구현할 수 없다 — 기능의 존재 이유.

**Independent Test**: 인증 정보 없이 재료 목록 조회를 호출해 81종 전체가 이름·이미지 경로와 함께 반환되는지 확인하는 것만으로 완결 검증된다.

**Acceptance Scenarios**:

1. **Given** 인증되지 않은 사용자, **When** 재료 목록을 조회하면, **Then** 재료 81종 전체가 각각 식별자·이름·이미지 경로를 포함해 반환된다.
2. **Given** 인증된 사용자(토큰 보유), **When** 같은 목록을 조회하면, **Then** 동일한 결과가 반환된다(인증 여부와 무관).
3. **Given** 사용자의 표시 언어가 한국어가 아닌 경우, **When** 언어를 지정해 목록을 조회하면, **Then** 재료 이름이 해당 언어로 표시된다(번역이 없으면 한국어로 폴백).

---

### User Story 2 - 재료마다 이미지가 매칭되어 있다 (Priority: P2)

서비스 운영 관점에서, 재료 81종 각각에 표시할 이미지가 저장소에 준비되어 있고 재료 데이터에 그 이미지 경로가 매칭되어 저장된다. 온보딩 목록은 이 매칭을 그대로 반환한다.

**Why this priority**: P1 목록이 "사진까지 함께"라는 요구를 충족하려면 데이터가 채워져 있어야 한다. 다만 목록 조회 자체는 이미지 미매칭 상태에서도 동작한다.

**Independent Test**: 재료 데이터 전수를 조회해 81종 모두 이미지 경로가 비어 있지 않은지 확인하는 것으로 검증된다.

**Acceptance Scenarios**:

1. **Given** 이미지 매칭 적재가 완료된 상태, **When** 재료 81종을 전수 조회하면, **Then** 이미지 경로가 누락된 재료가 0건이다.
2. **Given** 이미지 경로가 아직 매칭되지 않은 재료가 있는 상태, **When** 목록을 조회하면, **Then** 해당 재료는 이미지 없음(빈 값)으로 표시되고 목록 조회는 실패하지 않는다.

---

### Edge Cases

- 이미지 경로가 매칭되지 않은 재료가 있으면? → 목록은 정상 반환하고 해당 재료만 이미지 없음으로 내려준다(조회 실패 금지).
- 지원하지 않는 언어로 조회하면? → 한국어 이름으로 폴백한다(기존 재료 이름 표시 규칙과 동일).
- 인증 토큰이 잘못된 값으로 함께 오면? → 공개 조회이므로 토큰 유효성과 무관하게 목록을 반환한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 재료 81종 전체를 한 번의 조회로 반환하는 목록 조회를 제공해야 한다(페이지네이션 없음).
- **FR-002**: 목록의 각 재료는 안정 식별자(코드), 표시 이름, 이미지 경로를 포함해야 한다.
- **FR-003**: 목록 조회는 인증 없이 누구나 호출할 수 있어야 한다.
- **FR-004**: 재료 이름은 요청한 언어로 표시하고, 번역이 없으면 한국어로 폴백해야 한다(기존 재료 이름 표시 규칙 재사용).
- **FR-005**: 재료 데이터는 재료별 이미지 경로를 저장할 수 있어야 하며, 81종 전체에 이미지 경로가 매칭 적재되어야 한다.
- **FR-006**: 이미지 경로가 없는 재료가 존재해도 목록 조회는 실패하지 않고 해당 재료를 이미지 없음으로 반환해야 한다.

### Key Entities

- **재료(Ingredient)**: 기피 선택 대상이 되는 식재료 81종. 안정 코드, 한국어 이름, 언어별 번역 이름을 가지며 이번 기능으로 **이미지 경로** 속성이 추가된다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 온보딩 사용자가 로그인 없이 재료 81종 전체를 이름·사진과 함께 받아볼 수 있다.
- **SC-002**: 이미지 경로가 누락된 재료가 0건이다(적재 완료 기준).
- **SC-003**: 지원 언어로 조회 시 재료 이름이 해당 언어로 표시되고, 미지원 언어는 한국어로 표시된다.
- **SC-004**: 클라이언트(온보딩 화면)가 이 목록 하나만 호출해 재료 선택 UI 를 구성할 수 있다(추가 호출 불필요).

## Assumptions

- 응답의 이미지는 저장소 내 경로(또는 공개 URL 로 조합 가능한 경로)로 내려주며, 이미지 파일 자체의 준비·업로드는 운영 측에서 수행한다.
- 표시 언어는 서비스가 이미 지원하는 언어 집합을 따르며, 재료 이름 다국어 데이터(한국어 + 번역)는 기존 데이터를 그대로 사용한다.
- 목록 정렬은 클라이언트 표시 순서에 특별한 요구가 없어 안정적(항상 동일)이기만 하면 된다.
- 재료 종수는 현재 81종이며, 목록은 카탈로그 전체를 반환한다(종수가 늘어도 동작 불변).
- 이미지 경로 매칭 적재는 일회성 데이터 작업으로 이번 기능 범위에 포함된다.
