## User Scenarios & Testing *(mandatory)*

### User Story 1 - 마케팅 기간에 홈의 인기 음식 자리에 외국인 선호 음식이 보인다 (Priority: P1)

마케팅 기간 동안, 홈을 여는 모든 사용자(회원·비회원, 앱 버전 무관)는 인기 음식 자리에서 운영자가 정해 둔 "외국인 선호 음식" 목록을 운영자가 정한 순서 그대로 본다. 목록은 실제 조회 수와 무관하며, 홈의 다른 섹션(기피 성분·리뷰 인기·최근 스캔)과 응답 구조는 지금과 같다.

**Why this priority**: 기능의 본체다. 운영자가 노출할 음식을 고를 수 없던 인기 섹션을 마케팅 기간에 한해 큐레이션 목록으로 바꾸는 것이 이 작업의 목적이다.

**Independent Test**: 적용 기간 안에 임시 목록을 설정하고 홈을 조회하면 인기 음식이 설정한 음식·순서와 정확히 일치한다.

**Acceptance Scenarios**:

1. **Given** 임시 목록이 `[A, B, C]` 순서로 설정돼 있고 현재 시각이 적용 기간 안일 때, **When** 홈을 조회하면, **Then** 인기 음식은 `[A, B, C]` 순서로 내려온다.
2. **Given** 임시 목록이 적용 중일 때, **When** 회원이 홈을 조회하면, **Then** 각 음식의 안전 여부·북마크·평점은 기존과 같이 그 회원 기준으로 계산된다.
3. **Given** 임시 목록이 적용 중일 때, **When** 비회원이 홈을 조회하면, **Then** 인기 음식은 임시 목록이고 나머지 섹션은 비회원 규칙(기존과 동일)으로 나온다.
4. **Given** 임시 목록이 적용 중일 때, **When** 표시 언어가 다른 사용자가 조회하면, **Then** 같은 음식들이 요청한 언어의 이름으로 나온다.

---

### User Story 2 - 인기 음식 외의 홈 응답은 바뀌지 않는다 (Priority: P1)

마케팅 기간 중에도 홈의 경로·요청·응답 구조·필드는 그대로이고, 기피 성분·리뷰 인기·최근 스캔 섹션은 평소와 같다. 바뀌는 것은 인기 음식 목록의 **내용 선택 규칙** 하나뿐이다. 별도 API 나 버전 분기를 두지 않는다.

**Why this priority**: 클라이언트 수정 없이 서버 설정만으로 켜고 꺼야 하므로 응답 계약이 흔들리면 안 된다. US1 과 같은 릴리스에서 반드시 함께 보장돼야 한다.

**Independent Test**: 같은 시각에서 설정이 활성일 때와 비활성일 때 홈을 조회하면 인기 음식만 다르고 나머지 응답은 같다.

**Acceptance Scenarios**:

1. **Given** 임시 목록이 적용 중일 때, **When** 홈을 조회하면, **Then** 인기 음식 섹션을 제외한 모든 필드는 설정이 없을 때와 같다.
2. **Given** 임시 목록이 적용 중일 때, **When** 어떤 `X-API-Version` 으로 홈을 조회해도, **Then** 같은 규칙으로 같은 인기 음식이 내려온다(버전 분기 없음).

---

### User Story 3 - 기간이 끝나거나 목록이 비면 자동으로 조회 수 집계로 돌아간다 (Priority: P2)

운영자는 적용 기간의 시작·종료와 임시 목록을 설정값으로만 관리한다. 기간이 시작되기 전이나 끝난 뒤, 또는 목록이 비어 있으면 기존 조회 수 집계 결과를 본다. 코드 배포 없이 설정만으로 켜고 끈다.

**Why this priority**: 마케팅은 한시적이다. 종료 시점에 별도 배포 없이 원래 동작으로 돌아가야 운영 부담이 없다. US1 이 있어야 의미가 있어 P2 다.

**Independent Test**: 임시 목록은 그대로 두고 적용 기간만 과거로 설정하면 홈의 인기 음식이 조회 수 집계 결과로 바뀐다.

**Acceptance Scenarios**:

1. **Given** 임시 목록이 설정돼 있지만 현재 시각이 적용 기간 시작 전일 때, **When** 홈을 조회하면, **Then** 인기 음식은 조회 수 집계 결과다.
2. **Given** 임시 목록이 설정돼 있지만 현재 시각이 적용 기간 종료 후일 때, **When** 홈을 조회하면, **Then** 인기 음식은 조회 수 집계 결과다.
3. **Given** 적용 기간 안이지만 임시 목록이 비어 있을 때, **When** 홈을 조회하면, **Then** 인기 음식은 조회 수 집계 결과다.
4. **Given** 적용 기간이 설정돼 있지 않을 때(시작 또는 종료 누락), **When** 홈을 조회하면, **Then** 인기 음식은 조회 수 집계 결과다.

---

### User Story 4 - 보여줄 수 없는 음식은 목록에서 조용히 빠진다 (Priority: P2)

임시 목록에 콘텐츠가 준비되지 않은(READY 가 아닌) 음식이나 존재하지 않는·삭제된 음식 id 가 섞여 있으면 그 항목만 제외하고 나머지를 설정 순서대로 내려준다. 빠진 자리는 조회 수 집계 결과로 채우지 않는다.

**Why this priority**: 설정 실수나 음식 상태 변화로 홈이 깨지거나 준비 안 된 음식이 노출되는 것을 막는다. 기능 완성도 항목이라 P2 다.

**Independent Test**: `[A, B(비READY), C]` 로 설정하면 홈의 인기 음식은 `[A, C]` 두 건이다.

**Acceptance Scenarios**:

1. **Given** 임시 목록 `[A, B, C]` 중 B 가 READY 가 아닐 때, **When** 홈을 조회하면, **Then** 인기 음식은 `[A, C]` 이고 길이는 2 다.
2. **Given** 임시 목록에 존재하지 않거나 삭제된 음식 id 가 있을 때, **When** 홈을 조회하면, **Then** 그 id 는 제외되고 나머지는 설정 순서를 유지한다.
3. **Given** 임시 목록의 모든 음식이 READY 가 아닐 때, **When** 홈을 조회하면, **Then** 인기 음식은 빈 목록이다(조회 수 집계로 폴백하지 않는다).

---

### Edge Cases

- 임시 목록에 같은 음식 id 가 중복으로 들어 있으면 첫 등장 위치 한 번만 노출한다.
- 임시 목록이 10건을 넘으면 설정 순서대로 앞 10건만 노출한다(기존 인기 섹션 크기와 동일).
- 적용 기간의 시작이 종료보다 늦게 설정되면 "적용 기간 아님" 으로 취급해 조회 수 집계로 폴백한다.
- 적용 기간 경계(시작 시각·종료 시각 정각)는 시작은 포함, 종료는 제외한다.
- 임시 목록 적용 중에도 조회 수 집계 캐시를 매 요청 건드려 계속 유지·갱신하므로, 기간 종료 직후 첫 요청이 집계 부하를 새로 유발하지 않는다.
- 설정 형식이 잘못돼(숫자가 아닌 id, 파싱 불가한 시각) 읽을 수 없으면 앱 기동 시 실패해 배포 전에 드러난다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 임시 목록은 기존 홈 조회 API 의 인기 음식 자리를 대체한다 — 별도 경로·버전 분기를 두지 않으며 응답 구조는 바뀌지 않는다.
- **FR-002**: 임시 목록(음식 id 의 순서 있는 목록)과 적용 기간(시작·종료 시각)은 배포 환경 설정값으로 관리한다. 변경에 코드 수정이 필요하지 않다.
- **FR-003**: 현재 시각이 적용 기간 안(시작 포함, 종료 제외)이고 임시 목록이 비어 있지 않으면, 홈 응답의 인기 음식은 임시 목록의 음식을 설정 순서 그대로 담는다.
- **FR-004**: 적용 기간 밖이거나, 적용 기간이 설정되지 않았거나, 임시 목록이 비어 있으면 홈 응답의 인기 음식은 기존 조회 수 집계 결과(KB-725 캐시)와 동일하다.
- **FR-005**: 임시 목록 중 콘텐츠 상태가 READY 가 아니거나 존재하지 않는(삭제 포함) 음식은 제외한다. 제외로 생긴 빈자리는 다른 음식으로 채우지 않는다. 모두 제외되면 빈 목록을 내려준다.
- **FR-006**: 임시 목록의 중복 id 는 첫 등장만 남기고, 노출 상한은 기존 인기 섹션과 같은 10건이다.
- **FR-007**: 임시 목록 적용 여부와 무관하게 각 음식의 안전 여부·북마크·평점·표시 언어는 요청자 기준으로 기존과 동일하게 계산된다.
- **FR-008**: 임시 목록 적용 여부와 무관하게 홈의 나머지 섹션(기피 성분·리뷰 인기·최근 스캔)은 기존과 동일하다.
- **FR-009**: 테스트로 (a) 활성 설정에서 설정 순서 노출, (b) 적용 기간 밖 폴백, (c) 비READY 음식 제외를 검증한다.

### Key Entities

- **임시 인기 음식 설정**: 적용 시작 시각, 적용 종료 시각, 음식 id 순서 목록. 배포 환경 설정값이며 DB 에 저장하지 않는다.
- **음식(Food)**: 기존 엔티티. 콘텐츠 상태(READY 여부)와 소프트 삭제 상태가 노출 가능 여부를 결정한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 적용 기간 안에서 홈의 인기 음식은 설정한 목록·순서와 100% 일치한다(비READY·미존재 제외분 제외).
- **SC-002**: 인기 음식 섹션을 제외한 홈 응답은 이 기능 도입 전과 동일한 구조·값을 유지하고, 설정이 비활성이면 응답 전체가 도입 전과 같다.
- **SC-003**: 적용 기간 종료 후 첫 홈 조회부터 코드 배포 없이 조회 수 집계 결과로 돌아간다.
- **SC-004**: 임시 목록 적용 중 홈 응답 시간은 기존 대비 체감 차이가 없다(추가 DB 집계 없음 — id 목록으로 음식을 한 번 조회하는 기존 경로 재사용).

## Assumptions

- 버전 분기를 두지 않는다(2026-10-13 정정 — Jira 본문의 "상위 X-API-Version 매핑" 은 폐기). 기존 홈 매핑 하나가 전 버전에 같은 규칙을 적용한다.
- 임시 목록은 설정값 한 종류(전 사용자 공통)다. 회원 국적·언어별로 다른 목록은 범위 밖이다.
- 적용 기간의 시각은 서비스 운영 시간대(Asia/Seoul) 기준으로 해석한다.
- 설정 변경의 반영 시점은 앱 재기동(배포)이다. 무중단 핫 리로드는 범위 밖이다.
- 임시 목록은 음식 id 로만 지정한다. 음식명·검색어 지정은 범위 밖이다.
- 관리자 화면·API 로 목록을 편집하는 기능은 범위 밖이다(설정값 관리로 한정).
- 기존 조회 수 집계 캐시(KB-725)의 동작·TTL 은 변경하지 않는다.
