# Feature Specification: 프로필 사진 URL·맵기 선호 필드 추가

**Feature Branch**: `kb-147-profile-image-url`

**Created**: 2026-07-15

**Status**: Draft

**Input**: User description: "kb-147을 시작하자. 프로필 사진 url 필드를 추가하는 간단 작업임" (Jira KB-147 — [BE] 프로필 사진 URL 필드 추가 — 온보딩·프로필 조회·프로필 수정 API) + 추가 요청(2026-07-15): "동시에 프로필 수정·조회에서 맵기를 추가하고, 온보딩에서 맵기를 입력받도록" — 맵기 선호는 회원 프로필에 이미 존재하는 속성(0~10, 기본 5)이나 현재 온보딩 입력·수정·조회 노출이 전부 막혀 있어 함께 개방한다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 온보딩에서 프로필 사진·맵기 등록 후 프로필에서 확인 (Priority: P1)

신규 회원이 온보딩 시 프로필 사진 URL 과 맵기 선호(0~10)를 선택적으로 등록하고, 내 프로필 조회에서 등록한 값을 확인한다. 이미지 파일 자체는 서버를 거치지 않는다 — 클라이언트가 스토리지에 직접 업로드한 뒤 그 URL 만 전달한다(업로드 창구는 별도 태스크).

**Why this priority**: 두 필드 도입의 최소 가치 단위 — 등록과 노출이 되어야 나머지(변경·제거)가 의미 있다.

**Independent Test**: 온보딩 요청에 사진 URL·맵기를 포함해 호출한 뒤 프로필 조회 응답에 같은 값이 돌아오는지로 단독 검증 가능.

**Acceptance Scenarios**:

1. **Given** 온보딩 전 회원, **When** 사진 URL 을 포함해 온보딩을 완료하면, **Then** 프로필 조회 응답에 그 URL 이 포함된다
2. **Given** 온보딩 전 회원, **When** 사진 URL 없이 온보딩을 완료하면, **Then** 온보딩은 정상 완료되고 프로필 조회의 사진 값은 비어 있다(null)
3. **Given** 사진을 등록한 적 없는 기존 회원, **When** 프로필을 조회하면, **Then** 사진 값은 비어 있고(null) 나머지 응답은 기존과 동일하다
4. **Given** 온보딩 전 회원, **When** 맵기 7 을 포함해 온보딩을 완료하면, **Then** 프로필 조회 응답의 맵기는 7 이다
5. **Given** 온보딩 전 회원, **When** 맵기 없이 온보딩을 완료하면, **Then** 프로필 조회 응답의 맵기는 기본값(5)이다
6. **Given** 온보딩 전 회원, **When** 범위 밖 맵기(예: 11, -1)를 포함해 온보딩하면, **Then** 요청은 거절되고 아무것도 저장되지 않는다

---

### User Story 2 - 프로필 수정에서 사진·맵기 변경 (Priority: P2)

회원이 프로필 부분 수정으로 사진을 새 URL 로 교체하거나 맵기 선호를 바꾼다. 기존 부분 수정 규칙(미전송 필드는 기존 값 유지)을 그대로 따른다.

**Why this priority**: 등록(P1) 다음으로 자연스러운 후속 행위 — 기존 부분 수정 API 의 계약을 깨지 않는 것이 핵심.

**Independent Test**: 사진이 있는 회원에게 새 URL 만 담아 수정 호출 후 조회로 교체 확인, 사진 필드를 뺀 수정 호출 후 기존 URL 유지 확인. 맵기만 담아 수정 후 조회로 변경 확인.

**Acceptance Scenarios**:

1. **Given** 사진이 등록된 회원, **When** 새 사진 URL 만 담아 프로필을 수정하면, **Then** 사진은 새 URL 로 바뀌고 나머지 프로필 값은 유지된다
2. **Given** 사진이 등록된 회원, **When** 사진 필드 없이 닉네임만 수정하면, **Then** 사진은 기존 URL 그대로 유지된다
3. **Given** 맵기 5 인 회원, **When** 맵기 9 만 담아 프로필을 수정하면, **Then** 맵기는 9 로 바뀌고 나머지 프로필 값은 유지된다
4. **Given** 맵기 9 인 회원, **When** 맵기 필드 없이 닉네임만 수정하면, **Then** 맵기는 9 그대로 유지된다
5. **Given** 회원, **When** 범위 밖 맵기(11, -1)를 담아 수정하면, **Then** 요청은 거절되고 아무 필드도 변경되지 않는다

---

### User Story 3 - 프로필 사진 제거 (Priority: P3)

회원이 등록한 사진을 제거해 사진 없는 상태(null)로 되돌린다.

**Why this priority**: 빈도가 가장 낮은 보조 행위 — 부분 수정의 "미전송 = 유지" 규칙과 공존하도록 빈 문자열 전송을 제거로 해석한다(FR-005).

**Independent Test**: 사진이 있는 회원에게 사진 값을 빈 문자열로 담아 수정 요청 후 프로필 조회에서 사진 값이 비어 있는지(null) 확인.

**Acceptance Scenarios**:

1. **Given** 사진이 등록된 회원, **When** 사진 값을 빈 문자열로 담아 프로필을 수정하면, **Then** 프로필 조회의 사진 값은 비어 있다(null)

---

### Edge Cases

- 형식이 잘못된 URL(스킴 없음, http, URL 아님)이나 허용 도메인 밖의 URL 을 전달하면? → 요청 실패로 명확히 거절한다(FR-006).
- 부분 수정에서 "미전송(유지)"과 "제거"를 어떻게 구분하나? → 빈 문자열 전송 = 제거(FR-005). 온보딩에서 빈 문자열이 오면 미설정과 동일하게 취급한다.
- 사진 URL 이 매우 길면? → 저장 한도를 두고 초과 시 거절한다(한도는 Assumptions 참고).
- 온보딩을 사진 포함으로 두 번 호출하면? → 기존 온보딩 재호출 정책을 그대로 따른다(이 기능이 정책을 바꾸지 않는다).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 회원 프로필은 프로필 사진 URL 을 선택값으로 보관한다 — 미설정 상태(null)가 기본이며, 기존 회원은 전부 미설정으로 유지된다
- **FR-002**: 온보딩 요청에서 프로필 사진 URL 을 선택적으로 받을 수 있다 — 없이 호출해도 온보딩은 성공한다
- **FR-003**: 내 프로필 조회 응답에 프로필 사진 URL 을 포함한다 — 미설정이면 null
- **FR-004**: 프로필 부분 수정에서 사진 URL 을 전송하면 교체, 미전송하면 기존 값을 유지한다
- **FR-005**: 회원은 부분 수정에서 사진 값으로 **빈 문자열을 전송해 사진을 제거**(미설정 상태로 복귀)할 수 있다 — 미전송=유지, 값=교체, 빈 문자열=제거의 3분법. 별도 삭제 API 는 두지 않는다
- **FR-006**: 시스템은 전달된 사진 URL 을 검증하고 불합격 시 요청을 거절한다 — (1) https URL 형식이어야 하고, (2) **허용 이미지 도메인 목록(자체 CDN 도메인, 환경별 설정으로 관리)** 이 설정된 환경에서는 그 도메인의 URL 만 허용한다. 허용 목록이 비어 있는 환경은 형식 검증만 적용한다
- **FR-007**: 온보딩 요청에서 맵기 선호(0~10 정수)를 선택적으로 받을 수 있다 — 미전송이면 기본값(5)이 유지되고, 온보딩은 성공한다
- **FR-008**: 내 프로필 조회 응답에 맵기 선호를 포함한다
- **FR-009**: 프로필 부분 수정에서 맵기 선호를 전송하면 교체, 미전송하면 기존 값을 유지한다 (맵기는 항상 값이 있으므로 제거 개념 없음)
- **FR-010**: 범위(0~10) 밖 맵기 값은 요청 단계에서 거절되고 아무것도 저장되지 않는다

### Key Entities

- **회원 프로필**: 기존 속성(닉네임·회피 성분·맵기 선호·국가·앱 언어)에 **프로필 사진 URL(선택)** 이 추가된다. 사진은 URL 참조만 보관하며 이미지 데이터 자체는 다루지 않는다. **맵기 선호(0~10, 기본 5)는 이미 존재하는 속성** — 이번에 온보딩 입력·수정·조회 노출 경로를 개방한다(저장 구조 무변경).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 온보딩에서 사진 URL 을 등록한 회원은 직후 프로필 조회에서 100% 동일한 URL 을 확인할 수 있다
- **SC-002**: 사진 필드를 보내지 않는 기존 클라이언트의 온보딩·조회·수정 동작이 전부 기존과 동일하다(하위 호환 회귀 0건)
- **SC-003**: 사진 미전송 부분 수정 후 사진이 소실되는 사례 0건(미전송 = 유지 규칙 준수)
- **SC-004**: 형식 불합격 URL 은 100% 요청 단계에서 거절되고 저장되지 않는다
- **SC-005**: 온보딩·수정에서 등록한 맵기 값은 직후 프로필 조회에서 100% 동일하게 확인되고, 범위 밖 값은 100% 거절된다

## Assumptions

- 이미지 업로드(presigned URL 발급)는 별도 태스크 범위 — 이 기능은 URL 문자열의 저장·노출만 다룬다.
- 사진 URL 은 회원당 1개다(갤러리·이력 없음).
- URL 저장 한도는 일반적 URL 길이를 넉넉히 수용하는 수준(수백 자)으로 두고 초과 시 거절한다.
- 서버는 URL 의 실제 도달 가능성(이미지 존재 여부)을 검증하지 않는다 — 형식·도메인 검증까지만 한다.
- 이미지는 S3 에 올라가 CloudFront CDN 으로 서빙된다 — 허용 도메인 목록에는 이 CDN 도메인을 등록하며, 도메인 값 자체는 환경 설정이므로 스펙 범위 밖이다.
- 랭킹 조회 등 사진과 무관한 기존 응답은 변경하지 않는다.
