# Feature Specification: E2E 시나리오 테스트 도입 — 핵심 사용자 여정 4종 인수 테스트

**Feature Branch**: `kb-167-e2e-scenario-tests`

**Created**: 2026-07-17

**Status**: Implemented

**Input**: User description: "kb-167" (Jira KB-167 — [BE] E2E 시나리오 테스트 도입 — 핵심 사용자 여정 4종(해피패스·인증 생명주기·메뉴판 스캔·탈퇴) 인수 테스트)

## User Scenarios & Testing *(mandatory)*

> 이 기능의 "사용자"는 개발팀이다. 산출물은 실제 앱 사용자가 서비스를 이용하는 여정을 그대로 재현하는 자동 인수 테스트로,
> 개별 API 는 정상이어도 여정 중간의 상태 전이(토큰 발급→갱신, 온보딩 완료→홈 노출, 업로드 완료→스캔)가 어긋나는 회귀를
> 배포 전에 잡는 것이 목적이다.

### User Story 1 - 해피패스 여정이 자동으로 검증된다 (Priority: P1)

신규 사용자가 서비스를 처음 만나 가치를 얻기까지의 대표 여정 — 소셜 로그인(신규 가입) → 온보딩 → 홈 조회 → 음식 검색 → 상세 조회 → 북마크 추가/조회 — 을 API 를 실제 순서대로 호출하는 시나리오 테스트 하나로 검증한다.

**Why this priority**: 서비스의 핵심 가치 흐름 그 자체다. 이 여정이 깨지면 신규 사용자는 서비스를 전혀 쓸 수 없으므로, 회귀 방지 가치가 가장 크다. 또한 이 여정을 구현하며 시나리오 테스트의 공통 기반(호출 헬퍼·계정 격리·선별 실행)이 함께 만들어져 나머지 여정의 토대가 된다.

**Independent Test**: 시나리오 테스트 1개를 단독 실행해, 신규 소셜 계정 가입부터 북마크 조회까지 전 스텝이 순서대로 성공하고 각 스텝의 응답이 다음 스텝의 전제 상태를 만족함을 확인한다.

**Acceptance Scenarios**:

1. **Given** 가입 이력이 없는 신규 소셜 계정, **When** 소셜 로그인하면, **Then** 신규 회원이 생성되고 이후 호출에 쓸 인증 토큰이 발급된다
2. **Given** 로그인 직후(온보딩 미완료) 상태, **When** 온보딩을 완료하면, **Then** 홈 조회에 온보딩 결과가 반영되어 노출된다
3. **Given** 온보딩을 마친 회원, **When** 음식을 검색하고 상세를 조회한 뒤 북마크를 추가하면, **Then** 북마크 목록 조회에 해당 음식이 나타난다

---

### User Story 2 - 인증 생명주기 여정이 자동으로 검증된다 (Priority: P2)

로그인 → 액세스 토큰 만료 → 리프레시 갱신 → 로그아웃 → 재로그인으로 이어지는 인증 상태 전이 전체를 시나리오 테스트 하나로 검증한다.

**Why this priority**: 인증은 모든 여정의 관문이며, 토큰 만료·갱신·로그아웃 같은 상태 전이는 단일 API 테스트로는 재현되지 않는 대표적 회귀 지점이다. 클라이언트가 의존하는 에러 코드 계약(액세스 만료 시 갱신 유도)도 여정 문맥에서 함께 보증된다.

**Independent Test**: 시나리오 테스트 1개를 단독 실행해, 만료된 액세스 토큰이 약속된 에러 코드로 거절되고, 리프레시 갱신 후 새 토큰으로 호출이 재개되며, 로그아웃 후에는 갱신이 불가하고 재로그인으로 복구됨을 확인한다.

**Acceptance Scenarios**:

1. **Given** 로그인한 회원의 만료된 액세스 토큰, **When** 인증이 필요한 API 를 호출하면, **Then** 액세스 만료를 뜻하는 안정 에러 코드(AUTH-004)로 거절된다
2. **Given** 유효한 리프레시 토큰, **When** 토큰 갱신을 요청하면, **Then** 새 토큰이 발급되고 그 토큰으로 API 호출이 성공한다
3. **Given** 로그아웃한 회원, **When** 이전 리프레시 토큰으로 갱신을 시도하면, **Then** 거절되고, 재로그인하면 정상적으로 새 세션이 시작된다

---

### User Story 3 - 메뉴판 스캔 여정이 자동으로 검증된다 (Priority: P3)

로그인 → 업로드용 URL 발급 → 업로드 완료 신고 → 메뉴판 스캔 요청 → 위험도 결과 확인 → 스캔 히스토리 조회로 이어지는 스캔 여정을 시나리오 테스트 하나로 검증한다.

**Why this priority**: 서비스의 차별화 기능이며, 업로드 완료→스캔의 상태 전이(발급받은 이미지 경로의 소유·업로드 검증)가 여러 API 에 걸쳐 있어 여정 단위 회귀 위험이 크다. 다만 해피패스·인증이 먼저 보증되어야 의미가 있으므로 P3.

**Independent Test**: 시나리오 테스트 1개를 단독 실행해, URL 발급부터 히스토리 조회까지 전 스텝이 순서대로 성공하고, 스캔 결과가 히스토리에서 다시 조회됨을 확인한다.

**Acceptance Scenarios**:

1. **Given** 로그인한 회원, **When** 업로드용 URL 을 발급받고 업로드 완료를 신고하면, **Then** 해당 이미지 경로로 스캔을 요청할 수 있는 상태가 된다
2. **Given** 업로드 완료된 이미지, **When** 스캔을 요청하면, **Then** 메뉴 항목별 위험도 결과가 반환된다
3. **Given** 스캔을 마친 회원, **When** 스캔 히스토리를 조회하면, **Then** 방금 수행한 스캔이 목록에 나타난다

---

### User Story 4 - 탈퇴 여정이 자동으로 검증된다 (Priority: P4)

로그인 → 활동(북마크) → 탈퇴 → 토큰 무효 확인 → 재가입 시 신규 회원 생성 확인으로 이어지는 탈퇴 여정을 시나리오 테스트 하나로 검증한다.

**Why this priority**: 빈도는 낮지만 개인정보·계정 상태가 걸린 여정으로, 탈퇴 후 토큰이 살아있거나 재가입이 기존 데이터에 이어붙는 회귀는 심각도가 높다. 발생 빈도 대비 우선순위는 마지막.

**Independent Test**: 시나리오 테스트 1개를 단독 실행해, 탈퇴 직후 기존 토큰이 무효화되고, 같은 소셜 계정으로 재가입하면 이전 활동과 이어지지 않는 신규 회원이 생성됨을 확인한다.

**Acceptance Scenarios**:

1. **Given** 북마크 등 활동 이력이 있는 회원, **When** 탈퇴하면, **Then** 기존 액세스·리프레시 토큰으로는 더 이상 API 를 호출할 수 없다
2. **Given** 탈퇴한 소셜 계정, **When** 같은 계정으로 다시 로그인하면, **Then** 신규 회원으로 가입되고 이전 활동(북마크 등)이 노출되지 않는다

---

### Edge Cases

- 여정 중간 스텝이 실패하면 이후 스텝은 무의미하다 — 시나리오는 스텝을 정의된 순서대로 실행하고, 실패 지점이 어느 스텝인지 명확히 드러나야 한다.
- 시나리오 테스트가 기존 단위·통합 테스트와 같은 데이터 저장소를 공유하므로, 계정 격리가 깨지면(고정 계정 재사용 등) 반복 실행·병행 실행에서 간헐 실패가 난다 — 여정마다 신규 소셜 계정으로 가입해 회원 단위로 격리한다.
- 외부 시스템(소셜 인증·이미지 분석·스토리지)이 실물로 연결되면 네트워크·과금·비결정성이 생긴다 — 전부 기존 대역(페이크)으로 대체되어야 하며, 실물 호출이 하나라도 섞이면 안 된다.
- 액세스 토큰 "만료" 상태를 실제 시간 경과로 만들면 테스트가 느리고 불안정하다 — 시간 경과 없이 만료 상태를 재현할 수단이 필요하다.
- 음식 검색·스캔 결과는 공유 마스터 데이터(음식·기피물질 카탈로그)에 의존한다 — 시나리오는 마스터 데이터를 읽기 전용으로만 사용하고 변경하지 않아야 다른 테스트와 충돌하지 않는다.
- 시나리오 테스트는 전체 스위트보다 느릴 수 있다 — 필요 시 시나리오만 선별하거나 제외하고 실행할 수 있어야 한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 핵심 사용자 여정 4종(해피패스·인증 생명주기·메뉴판 스캔·탈퇴) 각각에 대해, 실제 사용 순서대로 API 를 호출하며 응답과 상태 전이를 검증하는 시나리오 테스트가 1개씩 존재해야 한다.
- **FR-002**: 각 시나리오는 스텝을 정의된 순서대로 실행하고, 앞 스텝의 산출물(토큰·식별자 등)을 뒤 스텝이 이어받아 사용해야 한다.
- **FR-003**: 스텝 검증은 **다음 스텝의 전제가 되는 상태**를 중심으로 한다 — 응답 필드 전수 검증은 기존 컨트롤러(단일 API) 테스트의 몫으로 남긴다.
- **FR-004**: 시나리오 본문은 여정 서사로 읽혀야 한다 — 호출·응답 파싱의 기계적 세부는 공용 호출 헬퍼 하나로 감싸고, 시나리오 본문에 원시 호출 코드가 노출되지 않아야 한다.
- **FR-005**: 각 여정은 신규 소셜 계정 가입으로 시작해 회원 단위로 데이터가 격리되어야 한다 — 테이블 청소 없이 반복 실행이 가능하고, 다른 테스트와 데이터가 충돌하지 않는다. 공유 마스터 데이터(음식·기피물질)는 읽기 전용으로만 사용한다.
- **FR-006**: 외부 시스템(소셜 인증·이미지 분석·스토리지)은 기존 대역(페이크)으로 대체되어 네트워크 없이 결정적으로 실행되어야 한다. 데이터 저장소(관계형 DB·토큰 저장소)는 기존 테스트 인프라의 실물 컨테이너를 그대로 재사용한다.
- **FR-007**: 시나리오 테스트에 식별 태그를 달아, 시나리오만 선별 실행하거나 제외하고 실행할 수 있어야 한다.
- **FR-008**: 시나리오 테스트 추가 후에도 기존 전체 테스트 스위트가 통과해야 한다 — 신규 인프라 코드 없이 기존 테스트 기반(컨테이너 구성·페이크) 위에 시나리오만 추가한다.

### Key Entities

- **시나리오(여정) 테스트**: 하나의 사용자 여정을 스텝 순서대로 실행하는 인수 테스트. 여정당 1개, 총 4개.
- **시나리오 호출 헬퍼**: API 호출·응답 파싱을 감싸 시나리오 본문을 여정 서사로 유지하는 공용 헬퍼 1개.
- **여정 상태**: 스텝 간 전달되는 산출물(인증 토큰, 회원·이미지·스캔 식별자 등). 시나리오 내부에서만 유지된다.
- **시나리오 태그**: 시나리오 테스트를 선별/제외 실행하기 위한 식별자.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 핵심 사용자 여정 4종이 각 1개의 시나리오 테스트로 커버되고, 4개 모두 통과한다.
- **SC-002**: 시나리오 테스트를 포함한 대상 모듈 전체 테스트 스위트 통과율 100%.
- **SC-003**: 시나리오 테스트는 외부 네트워크 호출 0건으로 실행된다(외부 시스템 전부 대역 대체).
- **SC-004**: 동일 시나리오를 연속 2회 이상 실행해도 데이터 충돌 없이 모두 통과한다(반복 실행 안전).
- **SC-005**: 태그 선별 실행 시 시나리오 4개만 실행되고, 태그 제외 실행 시 시나리오 0개가 실행된다.
- **SC-006**: 여정 중간 상태 전이가 어긋나는 회귀(예: 갱신된 토큰이 후속 호출에서 거절)는 시나리오 테스트 실패로 배포 전에 드러난다.

## Assumptions

- **실행 경계는 인프로세스 방식**(서버를 별도 프로세스로 띄우지 않고 애플리케이션 내부에서 HTTP 계층을 구동)으로 한다 — Jira 이슈에서 확정한 제약이며, 기존 컨트롤러 테스트 인프라(컨테이너 구성·외부 시스템 페이크)를 신규 코드 없이 그대로 재사용하기 위함이다.
- **시나리오 위치·형식은 기존 테스트 컨벤션을 따른다** — 대상 모듈 테스트 소스의 시나리오 전용 패키지에 여정당 1개 스펙, 스텝 간 상태는 스펙 필드로 전달(이슈 명시).
- **액세스 토큰 만료 재현은 시간 경과 없이 가능하다** — 만료 시각을 과거로 둔 토큰을 만들 수단이 기존 인증 구성(페이크 또는 짧은 TTL 설정)으로 확보 가능하다고 본다.
- **음식 마스터 데이터는 시드로 존재한다** — 검색·상세·스캔 매칭 스텝이 조회할 음식 데이터가 테스트 환경에 준비되어 있거나, 시나리오가 자체 준비(읽기 전용 전제 유지) 가능하다.
- **성능 목표는 별도로 두지 않는다** — 시나리오 4개 추가로 인한 테스트 시간 증가는 태그 선별/제외 실행으로 관리한다.
- **CI 파이프라인 변경은 범위 밖** — 기존 전체 테스트 실행 경로에 시나리오가 자연 포함되는 것으로 충분하다.
