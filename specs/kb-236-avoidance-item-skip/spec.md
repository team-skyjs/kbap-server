# Feature Specification: 기피성분 조사에서 후보 밖 성분은 항목 단위로 스킵

**Feature Branch**: `kb-236-avoidance-item-skip`

**Created**: 2026-07-24

**Status**: Draft

**Input**: User description: "kb-236 — [BE] 기피성분 조사에서 후보 밖 성분은 항목 단위로 스킵 — 정상 성분만 종합·저장"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 후보 밖 성분이 섞인 응답도 정상 성분만 종합해 저장 (Priority: P1)

배치 기피성분 조사에서 모델이 후보 목록(성분 카탈로그)에 없는 코드(예: OIL, KOREAN_SOYSAUCE, CABBAGE, PEPPER)를 섞어 반환해도, 그 항목만 버리고 후보 안의 정상 성분과 맵기는 그대로 종합해 저장된다. 운영자는 유효한 데이터가 응답 하나의 잡음 때문에 통째로 버려지는 일을 겪지 않는다.

**Why this priority**: 단일 모델 과도기(최소 합의 1)에서는 후보 밖 코드 하나로 유효 응답이 0개가 되어 음식 전체가 실패로 스킵된다 — dev 실측으로 확인된 실제 장애 패턴이며, 이 기능의 존재 이유다.

**Independent Test**: 후보 밖 코드가 섞인 모델 응답을 주입해 정상 성분·맵기만 종합되는지 단독 검증 가능.

**Acceptance Scenarios**:

1. **Given** 후보 목록이 {WHEAT, SOY}인 조사에서, **When** 모델이 WHEAT 90 · OIL 80 · spiciness 3 을 반환하면, **Then** OIL 항목만 제외되고 WHEAT 90 과 맵기 3 이 종합에 반영된다.
2. **Given** 최소 합의 1 인 단일 모델 구성에서, **When** 유일한 응답에 후보 밖 코드가 섞여 있으면, **Then** 응답은 유효로 인정되어 음식이 실패로 스킵되지 않는다.
3. **Given** 후보 밖 코드만으로 이루어진 응답(정상 항목 0개)이라도, **When** 맵기가 유효 범위라면, **Then** 응답은 유효로 인정되고 성분 없음 · 해당 맵기로 종합된다.

---

### User Story 2 - 나머지 무효 규칙은 응답 단위 무효 유지 (Priority: P2)

포함 확률 범위 밖(0~100 이탈), 같은 코드 중복, 맵기 범위 밖, JSON 파싱 실패는 지금처럼 응답 전체를 무효로 처리한다. 이 규칙들은 응답 자체의 신뢰성이 깨졌다는 신호이므로 항목 단위 구제를 하지 않는다.

**Why this priority**: 정책 변경의 안전 가드 — 완화 대상을 "후보 밖 코드"로만 한정해 데이터 품질 저하를 막는다.

**Independent Test**: 각 무효 규칙별 응답을 주입해 여전히 응답 단위로 무효 처리되는지 기존 테스트로 검증 가능.

**Acceptance Scenarios**:

1. **Given** 후보 안 코드지만 포함 확률이 0~100 밖인 항목이 있는 응답, **When** 검증하면, **Then** 응답 전체가 무효다.
2. **Given** 같은 코드가 중복된 응답, **When** 검증하면, **Then** 응답 전체가 무효다.
3. **Given** 맵기가 유효 범위 밖인 응답, **When** 검증하면, **Then** 응답 전체가 무효다.
4. **Given** JSON 으로 파싱되지 않는 응답, **When** 검증하면, **Then** 응답 전체가 무효다.

---

### Edge Cases

- 후보 밖 코드가 여러 개 섞여 있어도 각각 독립적으로 제외되고 나머지는 종합된다.
- 후보 밖 코드끼리 중복된 경우(예: OIL 이 두 번): 제외 대상이므로 중복 무효 규칙을 촉발하지 않고 모두 스킵된다.
- 후보 밖 코드가 포함 확률 범위 밖 값을 가진 경우(예: OIL 150): 항목이 제외 대상이므로 응답 무효를 촉발하지 않는다 — 후보 안 항목의 범위 위반만 응답 무효 사유다.
- 모든 항목이 스킵돼 정상 성분이 0개인 응답: 빈 배열 응답과 동일하게 유효 — 성분 없음으로 종합된다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 기피성분 조사 응답에서 후보 목록에 없는 성분 코드 항목을 발견하면 해당 항목만 제외하고 나머지 항목으로 검증을 계속해야 한다 (응답 전체 무효 금지).
- **FR-002**: 후보 안 정상 항목의 포함 확률과 응답의 맵기는 항목 스킵과 무관하게 그대로 종합·저장되어야 한다.
- **FR-003**: 후보 안 항목의 포함 확률 범위 이탈(0~100 밖), 후보 안 코드의 중복, 맵기 범위 이탈, JSON 파싱 실패는 기존대로 응답 단위 무효로 유지되어야 한다.
- **FR-004**: 후보 밖 코드로만 이루어진 응답(스킵 후 정상 항목 0개)은 맵기가 유효하면 유효 응답으로 인정되어야 한다.

### Key Entities

- **모델 응답(AssessmentResponse)**: 한 모델이 반환한 성분 항목 목록 + 맵기. 검증 후 유효/무효가 판정되는 단위.
- **성분 항목(AssessmentItem)**: 성분 코드 + 포함 확률(1~100). 후보 밖 코드일 때 개별 스킵되는 단위.
- **후보 목록(candidateCodes)**: 성분 카탈로그에서 온 허용 코드 집합 — 항목 유효성의 기준.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 후보 밖 코드가 섞인 응답이 단일 모델 구성(최소 합의 1)에서 유효 응답으로 집계되어, 해당 음식이 실패 스킵 없이 조사 결과를 저장한다.
- **SC-002**: dev 에서 관찰된 "후보 밖 코드 → 유효 응답 0/1 → 음식이 미완료 상태에 갇혀 실행마다 재시도 비용 반복" 패턴이 해소된다 — 동일 입력 재실행 시 성공으로 종결된다.
- **SC-003**: 후보 밖 코드 이외의 무효 사유(확률 범위·중복·맵기 범위·파싱 실패)에 대한 기존 테스트가 전부 그대로 통과한다.
- **SC-004**: 전체 빌드(테스트 포함)가 그린이다.

## Assumptions

- 완화 범위는 "후보 밖 코드" 단 하나다 — Jira 이슈가 나머지 규칙의 응답 단위 무효 유지를 명시했다.
- 후보 밖 항목은 존재하지 않는 것으로 취급한다: 그 항목의 확률 값 이상 여부·중복 여부는 응답 유효성 판정에 영향을 주지 않는다 (스킵이 검증보다 먼저).
- 종합(평균) 방식·저장 구조는 변경하지 않는다 — 검증 단계의 항목 필터링만 바뀐다.
- 다중 모델 합의(minAgreement ≥ 2) 복원 시에도 이 정책은 동일하게 적용된다.
