# Feature Specification: 프로필 수정 국가 코드 변경 불가 — v2 프로필 수정 창구 신설

**Feature Branch**: `kb-268-profile-update-v2`

**Created**: 2026-07-30

**Status**: Draft

**Input**: User description: "KB-268 프로필 수정 시 국가 코드는 최초 온보딩 과정에서 설정한 값에서 정해진 후 변경 불가하도록 기획이 바뀜. 1.0.0 버전의 앱에서 사용 중인 API 라서 버저닝을 붙여 추가 API 를 만든다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 신버전 앱 사용자는 프로필을 수정해도 국적이 바뀌지 않는다 (Priority: P1)

신버전 앱 사용자가 프로필(닉네임·기피 성분·프로필 이미지·맵기 선호)을 수정한다. 새 프로필 수정 창구(v2)에는 국적 입력 수단 자체가 없어, 어떤 수정을 하더라도 온보딩에서 확정된 국적은 그대로 유지된다.

**Why this priority**: 기획 변경의 핵심 — 국적은 온보딩에서 확정되고 이후 변경 불가. 이 창구가 없으면 신버전 앱이 정책을 지킬 방법이 없다.

**Independent Test**: 온보딩을 마친 회원이 v2 창구로 닉네임 등 프로필 항목을 수정한 뒤, 수정한 항목은 반영되고 국적은 온보딩 값 그대로임을 확인하면 단독으로 검증된다.

**Acceptance Scenarios**:

1. **Given** 국적 A 로 온보딩을 마친 회원, **When** v2 창구로 닉네임을 수정하면, **Then** 닉네임은 변경되고 국적은 A 그대로다.
2. **Given** 국적 A 로 온보딩을 마친 회원, **When** v2 창구 요청에 국적 값을 임의로 끼워 넣어 보내면, **Then** 해당 값은 무시되고 국적은 A 그대로다.
3. **Given** 국적 A 로 온보딩을 마친 회원, **When** v2 창구로 기피 성분·프로필 이미지·맵기 선호를 수정하면, **Then** 각 항목은 반영되고 국적은 A 그대로다.

---

### User Story 2 - 1.0.0 앱 사용자는 기존과 동일하게 프로필을 수정할 수 있다 (Priority: P2)

이미 배포된 1.0.0 앱은 기존 프로필 수정 창구(v1)를 그대로 사용한다. v1 의 요청·응답 계약과 동작은 변경되지 않아 구버전 앱 사용자는 아무 영향을 받지 않는다.

**Why this priority**: 스토어에 배포된 앱은 즉시 업데이트할 수 없다. v1 계약이 깨지면 실사용자 프로필 수정이 실패한다.

**Independent Test**: v1 창구로 기존 요청 형태 그대로 프로필을 수정해 기존과 동일하게 동작함(국적 변경 포함)을 확인하면 단독으로 검증된다.

**Acceptance Scenarios**:

1. **Given** 1.0.0 앱을 쓰는 회원, **When** v1 창구로 기존 요청 형태 그대로 프로필을 수정하면, **Then** 기존과 동일하게 모든 항목(국적 포함)이 반영된다.
2. **Given** v2 창구가 추가된 이후, **When** v1 창구를 호출하면, **Then** 응답 형태·결과가 추가 이전과 동일하다.

---

### Edge Cases

- v2 요청에 정의되지 않은 국적 값이 포함되면? → 무시되고 국적은 불변이다(오류가 아니라 무시 — 클라이언트 실수에 관대).
- 온보딩을 마치지 않은 회원이 v2 로 프로필을 수정하면? → 기존 v1 과 동일한 정책(인증·상태 검증)을 따른다.
- 구버전(1.0.0) 앱 사용자가 v1 로 국적을 변경하면? → 여전히 변경된다. 정책 구멍이지만 구앱 호환을 위해 잠정 허용하며, 구앱 지원 종료 시점에 후속 결정한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 프로필 수정의 새 버전 창구(v2)를 제공해야 하며, 닉네임·기피 성분·프로필 이미지·맵기 선호를 수정할 수 있어야 한다.
- **FR-002**: v2 창구에는 국적 입력 수단이 존재하지 않아야 하며, 어떤 요청 내용으로도 국적이 변경되지 않아야 한다.
- **FR-003**: 기존 v1 프로필 수정 창구는 요청·응답 계약과 동작(국적 변경 가능 포함)을 그대로 유지해야 한다 (1.0.0 앱 호환).
- **FR-004**: 국적은 최초 온보딩 과정에서만 설정되며, 온보딩 완료 이후 신버전 창구(v2)로는 변경 경로가 없어야 한다.
- **FR-005**: v1 과 v2 창구는 동시에 제공되어야 한다(공존 — 기존 버전 경로를 깨지 않는다).
- **FR-006**: v2 창구는 API 문서에 노출되어 신버전 앱 개발자가 계약을 확인할 수 있어야 한다.

### Key Entities

- **회원(Member)**: 프로필(닉네임·기피 성분·프로필 이미지·맵기 선호)과 국적을 가진다. 국적은 온보딩에서 확정되는 불변 속성으로 취급이 바뀐다(신버전 창구 기준).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 신버전 앱(v2 창구) 경유로 국적이 변경되는 사례가 0건이다 — 어떤 요청 조합으로도 재현 불가.
- **SC-002**: v2 추가 이후에도 1.0.0 앱의 프로필 수정 성공률·동작이 추가 이전과 동일하다(회귀 0건).
- **SC-003**: v2 창구로 수정 가능한 프로필 항목(닉네임·기피 성분·프로필 이미지·맵기 선호)은 전부 기존과 동일하게 수정된다.
- **SC-004**: 신버전 앱 개발자가 문서만 보고 v2 계약(국적 없음)을 확인할 수 있다.

## Assumptions

- v1 창구는 동작을 전혀 바꾸지 않는다 — 1.0.0 앱에서는 여전히 국적 변경이 가능하며, 이 정책 구멍은 구앱 지원 종료 시점의 후속 결정으로 남긴다(KB-268 DoD 합의).
- 버저닝 대상은 프로필 수정 창구 하나뿐이다 — 프로필 조회·온보딩 등 다른 창구는 이번 범위에서 버전을 올리지 않는다.
- 온보딩 창구는 변경하지 않는다(국적 최초 설정 경로는 기존 그대로).
- 관리자용 경로·백오피스는 이번 범위 밖이다.
