# Feature Specification: 회피·주의 성분 — 식별자 enum + 도메인 어그리게이트 분리

**Feature Branch**: `007-avoidance-substance-aggregate`

**Created**: 2026-07-02

**Status**: Draft

**Input**: User description: "#21번 이슈로 시작 — refactor: AvoidanceSubstance enum → 식별자 enum + 도메인 어그리게이트 분리"

## 배경

006(이슈 #15)에서 회피·주의 성분 카탈로그를 DB로 영속화하면서 004 의 `AvoidanceSubstance` enum 을 그대로 유지했다. 그 결과 enum 하나가 **식별자 + 데이터(한국어명·분류·번역) + 타입 통화**를 겸직해 세 가지 문제가 남았다:

1. **잘못된 한국어명(데이터 누수)** — 어떤 성분의 한국어 표시명을 물으면 DB `korean_name` 이 아니라 enum 에 하드코딩된 값을 읽는다. 운영자가 DB 의 한국어명을 고쳐도 한국어 조회만 옛 값을 반환하고, 검증 테스트도 이를 잡지 못한다.
2. **데이터 중복** — 한국어명·분류·번역이 enum 과 DB 양쪽에 존재한다. 조회의 단일 출처가 DB 여야 하는데 enum 이 같은 데이터를 이고 있다.
3. **결합** — 영속 계층이 도메인 분류(카테고리) 타입을 저장 형식에 직접 사용해, 코드베이스의 다른 참조 데이터(String 저장 + 경계 변환) 관례와 어긋난다.

이 기능은 위 세 문제를 해소한다. **식별자(enum)와 데이터(도메인 모델)를 분리**해 enum 은 순수 코드 식별자로 축소하고, 데이터·행위는 DB 에서 복원되는 도메인 어그리게이트가 보유한다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 운영자가 고친 한국어명이 즉시 반영된다 (Priority: P1)

성분의 표시명(모든 언어)은 **저장된 카탈로그 데이터**를 단일 출처로 조회된다. 운영자가 카탈로그의 한국어명을 수정하면, 이후 그 성분의 한국어 표시명 조회는 수정된 값을 반환한다. 코드에 박힌 옛 값을 반환하지 않는다.

**Why this priority**: 안전 직결 데이터(알러지/식이 제한)의 정확성 문제이자 실제 회귀 위험(Finding ①). 잘못된 표시명은 사용자에게 잘못된 성분 안내로 이어질 수 있어 가장 시급하다.

**Independent Test**: 카탈로그에서 한 성분의 한국어명을 기존과 다른 값으로 준비한 뒤, 그 성분의 한국어 표시명을 조회하면 카탈로그 값과 일치하는지 검증한다. 이전(코드 하드코딩) 값을 반환하지 않아야 한다.

**Acceptance Scenarios**:

1. **Given** 카탈로그에 저장된 성분의 한국어명이 "값 A" 일 때, **When** 그 성분의 한국어 표시명을 조회하면, **Then** "값 A"(저장된 값)를 반환한다.
2. **Given** 카탈로그의 어떤 성분 한국어명을 "값 A" → "값 B" 로 바꿨을 때, **When** 그 성분의 한국어 표시명을 다시 조회하면, **Then** "값 B"를 반환한다(코드 하드코딩 값을 반환하지 않는다).
3. **Given** 대상 언어 번역이 비어 있는 성분일 때, **When** 그 언어로 표시명을 조회하면, **Then** 한국어 원문으로 폴백한다.

---

### User Story 2 - 성분 데이터·행위를 단일 도메인 모델로 다룬다 (Priority: P2)

성분을 다루는 코드는 데이터 필드를 가진 enum 이 아니라 **도메인 어그리게이트**를 받는다. 어그리게이트는 코드 식별자, 한국어명, 언어별 번역, 분류(카테고리) 집합을 갖고 "언어별 표시명"·"특정 분류에 속하는가" 같은 행위를 스스로 제공한다. 데이터 조회 결과(코드 목록으로 찾기, 분류로 찾기)는 이 어그리게이트로 반환된다.

**Why this priority**: 데이터 중복(문제 2)의 근본 원인을 제거하고 후속 판정 로직(이슈 #16)이 소비할 안정적 모델을 제공한다. P1 의 데이터 누수도 이 모델 위에서 구조적으로 사라진다.

**Independent Test**: 코드 목록/분류로 성분을 조회했을 때, 반환된 각 항목이 코드·한국어명·번역·분류 집합을 담고 "언어별 표시명"·"분류 포함 여부"를 스스로 답하는지 검증한다.

**Acceptance Scenarios**:

1. **Given** 저장된 성분 카탈로그가 있을 때, **When** 코드 집합으로 성분을 조회하면, **Then** 각 코드에 해당하는 어그리게이트(코드·한국어명·번역·분류 포함)를 반환한다.
2. **Given** 저장된 성분 카탈로그가 있을 때, **When** 특정 분류로 성분을 조회하면, **Then** 그 분류에 속하는 성분 어그리게이트만 반환한다.
3. **Given** 조회된 성분 어그리게이트가 있을 때, **When** 특정 언어의 표시명을 물으면, **Then** 그 언어의 저장된 번역(없으면 한국어 폴백)을 스스로 반환한다.
4. **Given** 조회된 성분 어그리게이트가 있을 때, **When** 특정 분류 포함 여부를 물으면, **Then** 자신의 분류 집합에 근거해 참/거짓을 반환한다.

---

### User Story 3 - 식별자 enum·저장 형식·시드 정합이 일관된다 (Priority: P3)

`AvoidanceSubstance` enum 은 데이터 필드 없는 **순수 코드 식별자**(`AvoidanceSubstanceCode`)로 축소되어, 다른 컨텍스트가 컴파일 타임 타입 안전하게 특정 성분을 참조·망라 매칭하는 용도로만 쓰인다. 영속 저장 형식은 코드베이스의 참조 데이터 관례(코드·분류를 문자열로 저장, 경계에서 변환)를 따른다. 시드 정합 불변식은 데이터 중복 대조가 아니라 **코드 집합 일치**로 축소된다.

**Why this priority**: 일관성·유지보수 개선으로 사용자 가시성은 없지만, 향후 드리프트를 막고 P1·P2 의 구조를 완결한다.

**Independent Test**: 식별자 enum 이 데이터 필드를 갖지 않음을 확인하고, 시드 데이터의 코드 집합과 식별자 enum 의 코드 집합이 정확히 일치함을 검증한다.

**Acceptance Scenarios**:

1. **Given** 식별자 enum 이 정의되어 있을 때, **When** 그 정의를 확인하면, **Then** 데이터 필드(한국어명·분류·번역) 없이 코드 상수만 갖는다.
2. **Given** 시드 카탈로그와 식별자 enum 이 있을 때, **When** 양쪽 코드 집합을 비교하면, **Then** 정확히 일치한다(누락·초과 없음).
3. **Given** 저장된 성분·분류 데이터가 있을 때, **When** 저장 형식을 확인하면, **Then** 분류가 문자열 코드로 저장되고 조회 경계에서 도메인 분류로 변환된다.

---

### Edge Cases

- 저장된 코드가 식별자 enum 에 없는 경우(데이터/코드 드리프트) 어떻게 처리하는가? → 해당 행은 조회 결과에서 조용히 제외하되(현행 동작 유지), 시드 정합 불변식이 이런 드리프트를 사전에 실패로 잡는다.
- 코드 집합으로 조회 시 존재하지 않는 코드가 섞여 있으면? → 매칭되는 것만 반환하고 없는 코드는 무시한다.
- 한 성분이 여러 분류(최대 3종)에 속할 때, 분류 조회 결과에 중복 없이 한 번만 나타나는가?
- 어떤 대상 언어 번역이 빈 문자열/누락일 때 한국어 폴백이 일관되게 적용되는가?

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 성분의 모든 언어 표시명을 **저장된 카탈로그 데이터를 단일 출처**로 조회해야 한다. 한국어를 포함해 어떤 언어도 코드에 하드코딩된 값에서 읽지 않는다.
- **FR-002**: 성분의 언어별 표시명 결정 로직은 **성분 도메인 모델 자체**가 제공해야 하며(예: `displayName(언어)`), 영속 어댑터에 별도 "번역명 조회" 책임을 두지 않는다.
- **FR-003**: 시스템은 요청 언어의 번역이 없거나 비어 있으면 **한국어 원문으로 폴백**해야 한다.
- **FR-004**: 성분 조회 연산(코드 집합으로 찾기, 분류로 찾기)은 **성분 도메인 어그리게이트**를 반환해야 한다. 어그리게이트는 코드 식별자·한국어명·언어별 번역·분류 집합을 담는다.
- **FR-005**: 성분 도메인 어그리게이트는 "특정 분류에 속하는가"(예: `belongsTo(분류)`)를 스스로 답해야 한다.
- **FR-006**: 성분 코드 식별자(enum)는 **데이터 필드 없이** 코드 상수만 가져야 한다(한국어명·분류·번역을 지니지 않는다). 다른 컨텍스트는 이 식별자를 코드로만 참조한다(성분 컨텍스트 소유 유지).
- **FR-007**: 영속 저장 형식은 성분 코드·분류를 **문자열 코드**로 저장하고, 도메인 모델로의 변환은 **조회 경계에서** 수행해야 한다(저장 형식이 도메인 분류 타입에 직접 결합되지 않는다).
- **FR-008**: 성분 어그리게이트 복원은 한 성분의 번역 컬럼과 분류 멤버십을 모아 구성하되 **N+1 조회를 유발하지 않아야** 한다.
- **FR-009**: 시드 정합 불변식은 **시드 카탈로그의 코드 집합 = 식별자 enum 의 코드 집합** 일치로 정의해야 한다(한국어명·번역까지 코드-데이터로 대조하지 않는다). 시드의 단일 출처는 카탈로그 시드 데이터다.
- **FR-010**: 이 리팩터는 기존 회피·주의 카탈로그의 **관측 가능한 동작(성분 목록, 분류 소속, 표시명, 재료↔성분 매핑 결과)을 보존**해야 한다(P1 의 한국어명 정확화는 의도된 동작 개선이며 회귀가 아니다).
- **FR-011**: 프로젝트 헌법 원칙 V 의 "고정 reference taxonomy = 공유 컴파일 enum 저장 허용" 예외 단서를, enum 이 더 이상 데이터를 이지 않는(식별자만) 전제에 맞게 조정해야 한다(별도 헌법 갱신 절차로 반영).

### Key Entities *(include if feature involves data)*

- **성분 코드 식별자 (AvoidanceSubstanceCode)**: 데이터 없는 순수 코드 상수 집합(81종). 컴파일 타임 타입 안전 참조·망라 매칭용. 다른 컨텍스트는 코드로만 참조한다.
- **성분 어그리게이트 (AvoidanceSubstance 도메인 모델)**: DB 에서 복원되는 도메인 루트. 속성 — 식별자(id), 코드, 한국어명, 언어별 번역, 분류 집합. 행위 — 언어별 표시명, 분류 포함 여부.
- **분류 (AvoidanceCategory)**: 데이터 없는 값 enum(3종: 알러지원·식이 규칙·개인 회피). 그대로 유지.
- **저장된 성분 카탈로그**: 성분별 코드·한국어명·9개 언어 번역 컬럼 + 성분↔분류 멤버십. 표시명·분류 조회의 단일 출처.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 카탈로그에서 어떤 성분의 한국어명을 바꾼 뒤 그 성분의 한국어 표시명을 조회하면 **100%** 바뀐(저장된) 값을 반환한다(옛 하드코딩 값 반환 0건).
- **SC-002**: 성분의 한국어명·분류·번역 데이터가 **한 곳(저장된 카탈로그)에만** 존재한다(코드 내 성분별 한국어명/번역/분류 데이터 정의 0건).
- **SC-003**: 코드 집합·분류로 성분을 조회할 때 어떤 성분 수에 대해서도 조회 횟수가 성분 개수에 비례해 늘지 않는다(N+1 없음 — 조회 횟수가 성분 수와 무관하게 상수 단계).
- **SC-004**: 시드 카탈로그의 코드 집합과 식별자 enum 의 코드 집합 불일치가 발생하면 자동 검증이 **즉시 실패**로 알린다(불일치 통과 0건).
- **SC-005**: 리팩터 전후로 기존 회피·주의 카탈로그의 관측 가능한 동작(성분 목록·분류 소속·재료↔성분 매핑) 테스트가 **100% 통과**를 유지한다.

## Assumptions

- 회피·주의 성분 데이터는 **006 에서 이미 DB(카탈로그 테이블·번역 컬럼·성분↔분류 멤버십)로 영속화**되어 있으며, 이 기능은 조회·모델 구조만 바꾼다(스키마 대규모 변경 없음, 필요 시 분류 저장 형식 정렬 수준).
- 성분 목록(81종)과 3개 분류는 고정·읽기 전용 기준 목록이며 운영자 런타임 편집 흐름은 이 기능 범위 밖이다.
- 시드의 단일 출처는 `specs/004-avoidance-catalog/seed/avoidance-substances.json`(006 이 DB 로 적재)로 유지한다.
- 후속 판정 로직(이슈 #16)이 이 어그리게이트·코드 식별자를 소비한다. 본 리팩터는 #16 의 선행으로 두는 것을 권장한다.
- 한국어명 정확화(Finding ①)를 006 에서 최소 수정으로 먼저 처리하지 않고 **이 리팩터로 통합**한다(기본 결정).
- 헌법 원칙 V 예외 단서 조정은 이 기능의 산출물에 포함하되, 실제 문서 갱신은 헌법 갱신 절차(`/speckit-constitution`)로 수행한다.
- 9개 대상 언어·한국어 원문·한국어 폴백 정책은 기존 콘텐츠 언어 정책(헌법 원칙 V)을 그대로 따른다.
