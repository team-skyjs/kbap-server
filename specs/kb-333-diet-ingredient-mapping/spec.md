# Feature Specification: diet 카테고리별 회피 재료 매핑 조회

**Feature Branch**: `kb-333-diet-ingredient-mapping`

**Created**: 2026-08-14

**Status**: Draft

**Input**: User description: "diet 카테고리(15종)마다 어떤 재료(ingredient)가 매핑되는지 조회하는 API 하나를 만든다. 카테고리별로 매핑된 재료의 id와 재료명을 응답에 담는다. (Jira KB-333)"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 식단 유형별 회피 재료 확인 (Priority: P1)

앱 사용자가 식단 유형(비건·할랄·글루텐 프리 등) 선택 화면에서 각 유형을 살펴볼 때, 그 유형이 회피하는 재료 목록을 확인할 수 있다. 클라이언트는 한 번의 조회로 15개 카테고리 전체와 각 카테고리에 매핑된 재료(식별자·이름)를 받아 화면을 구성한다.

**Why this priority**: 이 기능의 존재 이유 그 자체다. 카테고리→재료 매핑이 서버에 없으면 클라이언트가 식단 유형 선택 UX를 만들 수 없다.

**Independent Test**: 조회 요청 한 번으로 15개 카테고리와 각 카테고리의 재료 목록(식별자·이름)이 기획 매핑 표와 일치하게 오는지 확인하는 것만으로 완결 검증된다.

**Acceptance Scenarios**:

1. **Given** 재료 카탈로그가 시드되어 있는 상태, **When** 매핑 조회를 요청하면, **Then** 15개 카테고리 각각에 대해 카테고리 코드·표시명과 매핑된 재료 목록(식별자·이름)이 응답된다.
2. **Given** 매핑 조회 응답, **When** VEGAN 카테고리를 보면, **Then** 재료 번호 1~11, 37~66에 해당하는 재료가 전부·정확히 포함된다(다른 카테고리도 동일하게 기획 표와 일치).

---

### User Story 2 - 다국어 사용자 재료명 표시 (Priority: P2)

한국어가 익숙하지 않은 사용자도 자신의 언어로 회피 재료 이름을 읽을 수 있다. 조회 시 언어를 지정하면 재료명이 해당 언어로 표시되고, 지원하지 않는 언어면 영어로 표시된다(기존 재료 목록 조회와 같은 규칙).

**Why this priority**: 서비스 이용자 다수가 외국인 여행자·거주자다. 다만 P1의 매핑 자체가 먼저 있어야 의미가 있다.

**Independent Test**: 같은 매핑 조회를 언어만 바꿔 두 번 호출해 재료명이 요청 언어를 따라 달라지는지, 미지원 언어가 영어로 폴백되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 지원 언어(예: en) 지정, **When** 매핑을 조회하면, **Then** 재료명이 해당 언어 표시명으로 응답된다(번역 부재 시 한국어).
2. **Given** 미지원 언어 코드 지정, **When** 매핑을 조회하면, **Then** 재료명이 영어 표시명으로 응답된다.

---

### Edge Cases

- 매핑 표의 재료 번호가 재료 카탈로그에 존재하지 않으면(시드 불일치) 어떻게 되는가? — 배포 전에 검증으로 걸러져야 하며, 매핑과 카탈로그의 정합을 확인하는 테스트가 있어야 한다.
- 언어 값을 지정하지 않으면? — 필수 입력으로 두고 누락 시 실패로 응답한다(기존 재료 목록 조회와 동일).
- 카테고리에 매핑된 재료가 하나도 없는 경우는? — 현재 15종 모두 매핑을 가지므로 발생하지 않으며, 매핑이 빈 카테고리를 만들지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 아래 15종 diet 카테고리와 각 카테고리의 회피 재료 매핑을 제공해야 한다(번호는 재료 시드 id):
  - VEGAN(비건): 1~11, 37~66
  - VEGETARIAN(베지테리언·락토오보): 8, 9, 11, 37~66
  - LACTO_VEGETARIAN(락토 베지테리언·계란 제외): 1, 8, 9, 11, 37~66
  - OVO_VEGETARIAN(오보 베지테리언·유제품 제외): 2~9, 11, 37~66
  - PESCATARIAN(페스코테리언·생선 허용): 8, 9, 11, 59, 61~66
  - GLUTEN_FREE(글루텐 프리·셀리악): 26, 28, 29, 30
  - LACTOSE_FREE(유당 불내증): 2~7
  - NO_ALCOHOL(무알코올): 78, 79, 80
  - MUSLIM(무슬림·할랄): 8, 9, 11, 59, 62, 63, 64, 78, 79, 80
  - HINDU(힌두·소고기 금지): 8, 9, 59, 61, 64
  - KOSHER(유대교·코셔): 8, 9, 11, 37~51, 59, 62, 63
  - BUDDHIST(불교·사찰식·오신채): 1, 8, 9, 11, 37~66, 72~77
  - JAIN(자이나교): 1, 8, 9, 10, 11, 37~66, 70~76
  - NUT_ALLERGY(견과류 알레르기): 13~22
  - SHELLFISH_ALLERGY(갑각류·조개 알레르기): 37~51
- **FR-002**: 클라이언트는 조회 요청 한 번으로 15개 카테고리 전체와 각 카테고리의 매핑 재료를 받을 수 있어야 한다.
- **FR-003**: 각 카테고리 항목은 카테고리 코드(클라이언트 분기용 안정 식별자)와 표시명을 포함해야 한다.
- **FR-004**: 각 매핑 재료 항목은 재료 식별자(id)와 재료명을 포함해야 한다.
- **FR-005**: 재료명은 요청 언어의 표시명으로 제공해야 하며, 미지원 언어는 영어로, 번역 부재 시 한국어로 폴백한다(기존 재료 목록 조회와 동일 규칙).
- **FR-006**: 매핑 내용은 FR-001의 표와 전부·정확히 일치해야 하며, 정합이 자동 검증되어야 한다(카탈로그에 없는 재료 번호가 매핑에 남지 않게).
- **FR-007**: 조회는 비회원(가입 전 온보딩)도 할 수 있어야 한다 — 인증 없이 호출하는 공개 API 다(2026-08-14 개정 — 종전 "로그인 사용자만"은 온보딩이 가입 후라는 잘못된 전제였다).

### Key Entities

- **식단 카테고리(diet category)**: 식이 제한 유형. 코드(예: VEGAN)·표시명(예: 비건)·회피 재료 집합을 가진다. 15종으로 고정.
- **재료(ingredient)**: 기존 재료 카탈로그의 항목. 식별자(id)와 언어별 표시명을 가진다. 한 재료가 여러 카테고리에 속할 수 있다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 클라이언트가 조회 1회로 15개 카테고리 전체의 매핑을 받아 식단 유형 선택 화면을 추가 요청 없이 구성할 수 있다.
- **SC-002**: 응답의 카테고리·재료 매핑이 기획 매핑 표와 100% 일치한다(카테고리 15종 전수 검증).
- **SC-003**: 지원 언어로 조회하면 재료명이 해당 언어로 표시되고, 미지원 언어는 영어로 표시된다.
- **SC-004**: 사용자는 식단 유형 선택 화면 진입 시 회피 재료 목록을 지연 체감 없이 확인할 수 있다.

## Assumptions

- 매핑(카테고리→재료 번호)은 기획이 확정한 고정 표이며 변경 빈도가 낮다 — 운영 중 실시간 편집은 범위 밖이고, 변경은 릴리스 단위로 반영한다.
- 카테고리 표시명의 다국어 번역 리소스는 아직 없다 — 우선 코드 + 한국어 표시명을 제공하고, 클라이언트는 코드로 분기한다(재료명은 기존 다국어 규칙 재사용).
- 재료 번호는 재료 카탈로그 시드의 id 와 일치한다(81종 시드 기준, 매핑에 등장하는 번호는 1~80 범위).
- 식단 유형 선택은 가입 전 온보딩 화면에서도 이뤄진다 — 비회원 호출을 허용하는 공개 API 다(기존 재료 목록 조회와 동일).
- 회원이 선택한 식단 유형을 저장하는 기능은 이 기능의 범위 밖이다 — 이 기능은 매핑 정보 조회만 다룬다.
