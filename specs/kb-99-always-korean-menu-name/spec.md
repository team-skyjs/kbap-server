# Feature Specification: 언어 무관 메뉴명 한국어 항상 포함

**Feature Branch**: `kb-99-always-korean-menu-name`

**Created**: 2026-07-08

**Status**: Draft

**Input**: User description: "kb-99 작업 워크트리에서 시작. 메뉴 리스트 조회와 상세 조회 API를 수정하는 것 외에 추가로 수정할 API 있는지 검토"

## 배경 / 문제

현재 음식 메뉴명은 요청 언어(`lang`)에 맞게 지역화되며, 해당 언어 번역이 없으면 한국어로 폴백한다(상세 조회·목록 페이징 공통). 따라서 외국어(예: en)로 요청하면 응답 메뉴명이 지역화된 표기만 담고 한국어 원문을 포함하지 않아, 외국인 사용자가 식당 실물 메뉴판(한국어)과 대조하거나 주문할 때 소통하기 어렵다.

언어와 무관하게 **한국어 메뉴명을 항상 함께 내려준다** — 지역화된 이름과 별개 필드로. 이렇게 하면 사용자는 앱 언어로 메뉴를 이해하면서, 실제 주문 시에는 한국어 메뉴명으로 식당과 소통할 수 있다.

## 범위 검토 결과 (수정 대상 API)

사용자 요청("리스트·상세 외 추가로 수정할 API 있는지 검토")에 따라 음식/메뉴명을 반환하는 전 API를 조사했다. 현재 앱 컨트롤러는 3개다.

| API | 지역화 메뉴명 반환? | KB-99 대상 |
|-----|------|-----------|
| 음식 상세 조회 (`FoodDetailController`) | 예 — 응답 `name` 이 지역화됨 | **대상** |
| 메뉴 목록 페이징 (`MenuListController`) | 예 — 각 항목 `name` 이 지역화됨 | **대상** |
| 메뉴 스캔 제출 (`MenuScanController`) | 아니오 — 위험도 판정만 반환. 메뉴명은 클라이언트가 요청(`rawMenuName`)으로 보내며 응답에 에코하지 않음 | 범위 밖 |

**결론: 추가로 수정할 API 는 없다.** 지역화 메뉴명을 반환하는 API 는 상세·목록 둘뿐이며, 스캔 API 는 서버가 메뉴명을 지역화해 내려주지 않으므로 이번 변경과 무관하다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 외국어 상세 조회에서 한국어 메뉴명 확인 (Priority: P1)

외국인 사용자가 앱 언어(en/ja 등)로 음식 상세를 조회하면, 지역화된 음식명과 **함께** 한국어 원문 메뉴명을 받는다. 실물 메뉴판(한국어)과 즉시 대조할 수 있다.

**Why this priority**: 상세 화면이 외국인 사용자가 특정 음식을 주문 직전 확인하는 핵심 지점이다. 이 슬라이스만으로도 "메뉴판 대조" 가치를 단독 전달한다.

**Independent Test**: `lang=en` 으로 상세 조회 시 지역화명과 별개로 한국어 메뉴명 필드가 채워져 내려오는지 검증.

**Acceptance Scenarios**:

1. **Given** 한국어·영어 번역이 모두 있는 음식, **When** `lang=en` 으로 상세 조회, **Then** 지역화명은 영어이고 한국어 메뉴명 필드에 한국어 원문이 채워진다.
2. **Given** 같은 음식, **When** `lang=ja` 로 상세 조회, **Then** 지역화명은 일본어이고 한국어 메뉴명 필드에 한국어 원문이 채워진다.
3. **Given** 영어 번역이 없어 한국어로 폴백되는 음식, **When** `lang=en` 으로 상세 조회, **Then** 지역화명은 한국어이고 한국어 메뉴명 필드는 `null`(지역화명과 동일하므로 중복 미노출)이다.
4. **Given** 같은 음식, **When** `lang=ko`(또는 `lang` 미지정)로 상세 조회, **Then** 지역화명은 한국어이고 한국어 메뉴명 필드는 `null`이다.

---

### User Story 2 - 외국어 목록 조회에서 각 항목 한국어 메뉴명 확인 (Priority: P1)

외국인 사용자가 앱 언어로 메뉴 목록(페이징)을 훑을 때, 각 항목이 지역화명과 함께 한국어 원문 메뉴명을 담는다. 목록을 스크롤하며 실물 메뉴판과 대조할 수 있다.

**Why this priority**: 상세와 동일한 사용자 가치를 목록 진입점에서 제공한다. 상세와 규약을 공유해야 하므로 함께 P1 로 둔다.

**Independent Test**: `lang=en` 으로 목록 조회 시 각 항목에 한국어 메뉴명 필드가 상세와 동일한 규약으로 채워지는지 검증.

**Acceptance Scenarios**:

1. **Given** 영어 번역이 있는 음식들이 포함된 목록, **When** `lang=en` 으로 목록 조회, **Then** 각 항목의 지역화명은 영어, 한국어 메뉴명 필드는 한국어 원문으로 채워진다.
2. **Given** 지역화명이 곧 한국어인 항목(폴백 또는 `lang=ko`), **When** 목록 조회, **Then** 해당 항목의 한국어 메뉴명 필드는 `null`이다.
3. **Given** 페이징 커서로 다음 페이지 요청, **Then** 다음 페이지 항목도 동일 규약으로 한국어 메뉴명을 포함한다.

---

### Edge Cases

- 지역화명이 한국어와 동일한 경우(`lang=ko` 또는 미지원/번역 부재로 한국어 폴백): 한국어 메뉴명 필드는 `null` — 중복 노출하지 않는다.
- 미지원 언어 코드(예: 존재하지 않는 lang) 요청: 기존 폴백 규칙(한국어)이 그대로 적용되며, 지역화명=한국어이므로 한국어 메뉴명 필드는 `null`.
- 한국어 메뉴명 자체가 존재하지 않는 음식은 데이터 정합상 없다고 가정한다(한국어가 원본 소스). 만약 없다면 지역화 폴백도 성립하지 않으므로 별도 처리 대상이 아니다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 상세 조회 응답은 요청 언어와 무관하게 지역화 메뉴명과 별개 필드로 한국어 메뉴명을 제공해야 한다.
- **FR-002**: 목록(페이징) 조회 응답의 각 항목도 지역화 메뉴명과 별개 필드로 한국어 메뉴명을 제공해야 한다.
- **FR-003**: 한국어 메뉴명 필드가 지역화 메뉴명과 값이 동일한 경우(지역화명이 이미 한국어) 해당 필드는 `null`로 내려 중복 노출을 피해야 한다.
- **FR-004**: 상세·목록의 한국어 메뉴명 표현 규약(필드 의미·null 정책)은 서로 일관되어야 한다.
- **FR-005**: 기존 지역화 메뉴명 산출·폴백 동작(지역화 → 없으면 한국어)은 변경 없이 유지되어야 한다 — 이번 변경은 한국어 필드 추가일 뿐 기존 필드 의미를 바꾸지 않는다.
- **FR-006**: 스캔 API 를 포함해 지역화 메뉴명을 반환하지 않는 API 는 변경하지 않는다(범위 밖).

### Key Entities

- **음식(Food)**: 지역화 메뉴명(요청 언어)과 한국어 원문 메뉴명을 함께 노출한다. 한국어 원문은 언어 무관 고정값이며, 지역화명은 요청 `lang` 에 따라 달라진다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 임의 지원 언어(en/ja 등)로 상세·목록을 조회했을 때, 해당 언어에 번역이 있는 음식은 100% 응답에 한국어 원문 메뉴명이 함께 담긴다.
- **SC-002**: 지역화명이 한국어와 동일한 모든 경우(`lang=ko` 및 폴백)에 한국어 메뉴명 필드가 `null`로 내려간다(중복 노출 0건).
- **SC-003**: 언어별(en/ja/ko·미지원 폴백) 한국어 포함 여부가 BehaviorSpec 통합 테스트로 상세·목록 모두 검증된다.
- **SC-004**: 기존 지역화명·폴백 응답 값은 이번 변경 전후로 동일하다(회귀 없음).

## Assumptions

- 모든 음식은 한국어 메뉴명을 원본으로 보유한다(한국어가 데이터 소스 언어이며 지역화 폴백의 종착지).
- 응답 스키마 변경은 필드 **추가**이며, 기존 클라이언트는 새 필드를 무시해도 동작한다(하위 호환).
- 한국어 메뉴명 필드는 지역화명과 동일할 때 `null`을 사용한다(사용자 결정) — 클라이언트는 `null`이면 지역화명을 한국어로 간주한다.
- 스캔 API 는 서버가 메뉴명을 지역화·반환하지 않으므로(클라이언트가 `rawMenuName` 제공) 범위 밖이다.
- 이 변경은 기존 상세·목록 API 의 요청 파라미터(`lang`·페이징 커서)를 바꾸지 않는다.
