**Feature Branch**: `kb-104-onboarding-profile`

**Created**: 2026-07-11

**Status**: Draft

**Input**: User description: "kb-104 태스크 진행" (Jira KB-104 — [BE] 온보딩 — 기피 음식·국가·앱 언어(10개국어) 설정 + 완료 처리)

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 온보딩 정보 제출로 프로필 설정·온보딩 완료 (Priority: P1)

최초 가입 직후의 회원은 온보딩 미완료 상태다. 로그인한 회원이 온보딩 화면에서 닉네임, 기피 음식(회피 성분 목록), 거주 국가, 앱에서 사용할 언어를 제출하면, 서비스는 각 항목이 허용된 값인지 검증한 뒤 프로필로 저장하고 온보딩을 완료 상태로 전환한다. 이후 클라이언트는 온보딩 화면을 건너뛰고 홈으로 진입한다.

**Why this priority**: 온보딩 프로필(기피 성분·언어)이 없으면 서비스의 핵심 가치인 개인화된 음식 위험도 안내(KB-9)와 사용자 언어 응답이 동작할 수 없다 — 가입 후 첫 필수 관문.

**Independent Test**: 인증된 회원으로 온보딩 제출을 호출해 프로필 저장과 온보딩 상태 전환을 통합 테스트로 검증할 수 있다. 이 스토리만으로 "가입 회원이 개인화 프로필을 갖게 된다"는 가치가 완결된다.

**Acceptance Scenarios**:

1. **Given** 온보딩 미완료 회원이, **When** 유효한 닉네임·기피 성분(카탈로그 내)·국가(지정 코드 내)·언어(지원 10개국어 내)를 제출하면, **Then** 프로필이 저장되고 온보딩 상태가 완료로 전이된다.
2. **Given** 온보딩 미완료 회원이, **When** 기피 음식이 하나도 없다고 제출하면(빈 목록), **Then** 정상 처리된다 — 기피 성분 없음도 유효한 프로필이다.
3. **Given** 이미 온보딩을 완료한 회원이, **When** 온보딩을 다시 제출하면, **Then** 400 으로 거절되고 기존 프로필은 변하지 않는다(재설정은 후속 프로필 수정 기능).
4. **Given** 인증되지 않은 요청이, **When** 온보딩을 제출하면, **Then** 401 로 거절된다.

---

### User Story 2 - 입력 검증 실패 시 저장 없이 거절 (Priority: P2)

회원이 카탈로그에 없는 성분 코드, 지정 목록에 없는 국가 코드, 지원하지 않는 언어, 또는 규격에 맞지 않는 닉네임을 제출하면, 서비스는 아무것도 저장하지 않고 사유와 함께 요청을 거절한다. 온보딩 상태도 미완료로 유지된다.

**Why this priority**: 무효 코드가 프로필에 저장되면 위험도 판정·번역 등 하위 기능 전체가 오동작한다. 저장 전 차단이 데이터 정합의 방어선이다.

**Independent Test**: 각 항목별 무효 입력으로 제출을 호출해 400 응답과 상태 불변(프로필 미저장·온보딩 미완료 유지)을 독립적으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 온보딩 미완료 회원이, **When** 카탈로그 81종에 없는 성분 코드를 포함해 제출하면, **Then** 400 으로 거절되고 프로필·온보딩 상태가 변하지 않는다.
2. **Given** 온보딩 미완료 회원이, **When** 지정 목록에 없는 국가 코드로 제출하면, **Then** 400 으로 거절된다.
3. **Given** 온보딩 미완료 회원이, **When** 지원 10개국어에 없는 언어로 제출하면, **Then** 400 으로 거절된다.
4. **Given** 온보딩 미완료 회원이, **When** 빈 닉네임(공백만 포함 등)으로 제출하면, **Then** 400 으로 거절된다.
5. **Given** 무효 입력으로 거절된 회원이, **When** 유효한 입력으로 다시 제출하면, **Then** 정상적으로 프로필이 저장되고 온보딩이 완료된다.

---

### User Story 3 - 홈화면 진입 시 내 온보딩 프로필·상태 확인 (Priority: P3)

로그인한 회원이 앱을 열어 홈화면에 진입할 때, 클라이언트는 현재 회원의 온보딩 프로필(닉네임·기피 성분·국가·앱 언어)과 온보딩 완료 여부를 조회한다. 미완료면 온보딩 화면으로, 완료면 개인화된 홈으로 분기한다.

**Why this priority**: 제출(US1)이 있어야 조회할 내용이 생긴다. 다만 이 조회가 없으면 클라이언트가 온보딩 분기·개인화를 할 수 없으므로 같은 사이클에서 함께 제공한다.

**Independent Test**: 온보딩 완료/미완료 각 상태의 회원으로 조회를 호출해 프로필 내용과 상태 플래그를 독립적으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 온보딩을 완료한 회원이, **When** 내 프로필을 조회하면, **Then** 저장된 닉네임·기피 성분·국가·앱 언어와 온보딩 완료 상태가 응답에 포함된다.
2. **Given** 온보딩 미완료 회원이, **When** 내 프로필을 조회하면, **Then** 온보딩 미완료 상태가 표시되어 클라이언트가 온보딩 화면으로 분기할 수 있다.
3. **Given** 인증되지 않은 요청이, **When** 내 프로필을 조회하면, **Then** 401 로 거절된다.

---

### Edge Cases

- 이미 온보딩 완료된 회원의 재제출 → 400, 기존 프로필 불변 (재설정은 후속 이슈).
- 기피 성분 목록에 같은 코드가 중복 포함되어 제출 → 중복이 제거된 집합으로 저장된다(오류 아님).
- 기피 성분 목록이 빈 경우 → 허용 (기피 음식 없는 사용자).
- 닉네임 앞뒤 공백 → 제거 후 검증·저장.
- 무효 코드가 여러 항목에 동시에 존재 → 400 한 번으로 거절 (저장 없음).
- 탈퇴·비활성 회원의 인증 토큰으로 제출 → 회원 조회 실패로 거절된다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 온보딩 제출·내 프로필 조회는 인증된 회원만 가능해야 하며, 미인증 요청은 401 로 거절해야 한다.
- **FR-002**: 온보딩 제출은 닉네임, 기피 성분 코드 목록, 국가 코드, 앱 언어를 입력으로 받아야 한다.
- **FR-003**: 기피 성분 코드는 회피 성분 카탈로그(81종) 내의 값만 허용해야 하며, 위반 시 400(BaseResponse 실패 봉투)으로 거절해야 한다.
- **FR-004**: 국가 코드는 지정된 국가 코드 목록 내의 값만 허용해야 하며, 위반 시 400 으로 거절해야 한다.
- **FR-005**: 앱 언어는 지원 10개국어(한국어 + 9개 대상 언어 — 음식 콘텐츠 번역과 같은 집합) 내의 값만 허용해야 하며, 위반 시 400 으로 거절해야 한다.
- **FR-006**: 닉네임은 공백 제거 후 비어 있지 않아야 하며, 위반 시 400 으로 거절해야 한다.
- **FR-007**: 유효한 제출이면 프로필(닉네임·기피 성분 집합·국가·앱 언어)을 저장하고 온보딩 상태를 미완료→완료로 전이해야 한다. 저장과 상태 전이는 함께 성공하거나 함께 실패해야 한다.
- **FR-008**: 이미 온보딩을 완료한 회원의 재제출은 400 으로 거절하고 기존 프로필을 보존해야 한다.
- **FR-009**: 검증 실패 시 어떤 프로필 항목도 저장되지 않고 온보딩 상태도 변하지 않아야 한다.
- **FR-010**: 인증된 회원은 자신의 온보딩 프로필(닉네임·기피 성분·국가·앱 언어)과 온보딩 완료 여부를 조회할 수 있어야 한다.
- **FR-011**: 모든 응답은 서비스 공통 응답 규약(BaseResponse 봉투, 실패 메시지는 ~습니다 체)을 따라야 한다.

### Key Entities

- **회원(Member)**: 소셜 신원으로 가입된 사용자. 프로필과 온보딩 상태(미완료/완료)를 가진다.
- **회원 프로필(MemberProfile)**: 닉네임, 기피 성분 코드 집합, 국가 코드, 앱 언어. 가입 직후엔 비어 있고 온보딩 제출로 채워진다.
- **회피 성분 카탈로그**: 81종의 회피·주의 성분 코드 목록. 기피 성분 입력의 허용 범위(소유 컨텍스트: avoidance — 회원은 코드로만 참조).
- **국가 코드**: 서비스가 지정한 국가 코드 목록(ENUM). 회원의 거주/출신 국가 표현.
- **앱 언어**: 지원 10개국어 코드. 음식 콘텐츠 번역 대상 언어 집합과 동일.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 온보딩 미완료 회원이 유효한 정보를 한 번 제출하면 100% 프로필이 저장되고 완료 상태로 전환된다.
- **SC-002**: 허용 범위 밖 코드(성분·국가·언어)를 포함한 제출은 100% 저장 없이 거절된다 — 무효 코드가 프로필에 남는 경우 0건.
- **SC-003**: 미인증 요청이 온보딩 제출·프로필 조회에 성공하는 경우 0건.
- **SC-004**: 클라이언트는 홈화면 진입 시 조회 한 번으로 온보딩 분기(온보딩 화면 vs 홈)를 판별할 수 있다.
- **SC-005**: 유효·무효 입력과 상태 전이가 통합 테스트로 검증된다(DoD).

## Assumptions

- 맵기 선호도(spiciness)는 이번 온보딩 입력에 포함하지 않는다 — 프로필 기본값(5)이 유지되며, 조정은 후속 프로필 수정 기능에서 다룬다(Jira KB-104 입력 목록에 없음).
- 닉네임은 중복을 허용한다(유니크 제약 없음). 규격은 "공백 제거 후 비어 있지 않음"을 최소 기준으로 하며, 길이 상한은 프로필 저장소 칼럼 길이를 따른다.
- 온보딩 완료 후 프로필 수정(재설정)은 이 기능의 범위 밖이다 — 후속 이슈.
- 회원 프로필 기반 음식 종합 위험도 연결(KB-9)은 이 기능의 범위 밖이다 — 후속 이슈.
- 인증은 기존 자체 JWT(access 토큰, KB-118)를 재사용한다 — 신규 인증 수단을 도입하지 않는다.
- 국가 코드 ENUM·언어 10개국어·회피 성분 카탈로그 81종은 이미 서비스에 정의되어 있는 목록을 그대로 사용한다(신규 목록 정의 없음).
