# Feature Specification: 사용자 프로필 맵기 설정 ENUM 전환

**Feature Branch**: `kb-262-spiciness-enum`

**Created**: 2026-07-30

**Status**: Draft

**Input**: User description: "kb-262 — 사용자 프로필 맵기 설정을 정수에서 ENUM 으로 전환 (SKIP·NONE·MILD·MEDIUM·HOT·EXTREME)"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 온보딩·프로필에서 맵기 단계 선택 (Priority: P1)

신규 사용자는 온보딩에서 자신의 맵기 선호를 6단계(건너뛰기 SKIP, 못 먹음 NONE, 순한맛 MILD, 보통 MEDIUM, 매운맛 HOT, 극한맛 EXTREME) 중 하나로 선택한다. 기존 사용자는 프로필 수정에서 같은 6단계로 변경하고, 내 프로필 조회에서 선택한 단계를 그대로 확인한다.

**Why this priority**: 기획 변경의 핵심 — 클라이언트가 0~10 슬라이더 대신 단계 선택 UI 로 전환되므로, 요청·응답이 단계 문자열을 주고받지 못하면 기능 자체가 성립하지 않는다.

**Independent Test**: 온보딩 요청에 단계 문자열을 담아 호출하고 내 프로필 조회로 같은 값이 돌아오는지 확인하는 것만으로 완결 검증 가능.

**Acceptance Scenarios**:

1. **Given** 온보딩 전 회원, **When** 맵기 단계 `HOT` 으로 온보딩을 완료하면, **Then** 내 프로필 조회에 `HOT` 이 반환된다
2. **Given** 맵기 화면을 건너뛴 회원, **When** `SKIP` 으로 온보딩을 완료하면, **Then** 미설정 상태로 저장되고 조회에 `SKIP` 이 반환된다
3. **Given** 온보딩 완료 회원, **When** 프로필 수정으로 `MILD` 로 변경하면, **Then** 조회에 `MILD` 가 반환된다
4. **Given** 어떤 요청이든, **When** 6단계에 없는 값(예: `SUPER_HOT`, `5`)을 보내면, **Then** 요청이 검증 실패로 거절되고 기존 값은 유지된다

---

### User Story 2 - 기존 회원 데이터 자동 이관 (Priority: P2)

이미 정수(-1, 0~10)로 맵기를 설정해 둔 기존 회원은 아무 조치 없이도, 전환 후 자신의 설정이 가장 근접한 단계로 유지된 것을 확인한다.

**Why this priority**: 전환 시점에 기존 회원의 설정이 유실되면 안 되지만, 신규 입출력(P1)이 먼저 성립해야 이관 결과를 노출할 수 있다.

**Independent Test**: 정수 값별 대표 회원 데이터를 만들어 이관을 수행한 뒤, 각 회원의 조회 결과가 매핑 규칙대로 나오는지 확인.

**Acceptance Scenarios**:

1. **Given** 정수 -1(미설정)로 저장된 기존 회원, **When** 전환이 적용되면, **Then** 조회에 `SKIP` 이 반환된다
2. **Given** 정수 0~10 로 저장된 기존 회원, **When** 전환이 적용되면, **Then** 매핑 규칙(Assumptions 참조)에 따른 단계가 반환된다

---

### User Story 3 - 관리자 회원 목록에서 단계 확인 (Priority: P3)

관리자는 회원 관리 화면에서 각 회원의 맵기 설정을 정수가 아닌 단계 값으로 확인한다.

**Why this priority**: 운영 편의 — 사용자 기능이 아니므로 후순위지만, 정수가 남으면 관리자 화면이 깨진 데이터처럼 보인다.

**Independent Test**: 관리자 회원 목록 조회 응답에 단계 문자열이 담기는지 확인.

**Acceptance Scenarios**:

1. **Given** 맵기 `EXTREME` 인 회원, **When** 관리자가 회원 목록을 조회하면, **Then** 해당 회원의 맵기가 `EXTREME` 으로 표시된다

### Edge Cases

- 6단계에 없는 문자열·정수·null 을 요청에 담으면 검증 실패로 거절된다(기존 -1~10 정수는 더 이상 유효 입력이 아니다).
- 프로필 수정에서 맵기를 생략하면 기존 단계가 그대로 유지된다(부분 수정 규약 유지).
- 저장된 프로필에 맵기 값이 없는 회원(결손 데이터)은 미설정(`SKIP`)으로 취급된다.
- 이관 규칙 범위(-1~10) 밖의 비정상 정수가 저장돼 있으면 이관이 실패로 드러나야 한다(조용한 유실 금지).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 맵기 선호를 SKIP·NONE·MILD·MEDIUM·HOT·EXTREME 6단계 중 하나로만 보유한다. SKIP 은 맵기 화면을 건너뛴 미설정 상태다.
- **FR-002**: 온보딩·프로필 수정 요청은 맵기를 6단계 문자열로 받고, 그 외 값은 검증 실패로 거절한다.
- **FR-003**: 내 프로필 응답·관리자 회원 목록 응답은 맵기를 6단계 문자열로 반환한다.
- **FR-004**: API 문서(스키마·예시)는 6단계 문자열 기준으로 갱신된다.
- **FR-005**: 저장된 기존 정수 값은 일회성 이관으로 단계 값으로 전환된다: -1→SKIP, 0~10 은 확정된 매핑 규칙에 따라 NONE~EXTREME 5단계로 통합된다.
- **FR-006**: 이관 이후 신규 저장·조회 경로에 정수 표현이 남지 않는다(입출력·저장 모두 단계 값 단일 표현).
- **FR-007**: 기존 회원·온보딩 검증(테스트)은 전환 후에도 모두 통과 상태를 유지한다.

### Key Entities

- **회원 프로필(MemberProfile)**: 회원의 온보딩 설정 묶음. 맵기 선호가 정수에서 6단계 값으로 바뀌는 대상. 회원 저장소의 프로필 데이터(JSON)에 함께 저장된다.
- **맵기 선호 단계(SpicinessPreference)**: SKIP(미설정)·NONE·MILD·MEDIUM·HOT·EXTREME 6단계 열거값. 음식의 맵기 점수(food.spiciness, 0~10)와는 별개 개념으로 이번 범위 밖.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 온보딩·프로필 수정·내 프로필 조회 전 구간에서 맵기가 6단계 문자열로 왕복되고, 정수를 보내는 요청은 100% 거절된다.
- **SC-002**: 기존 회원 전원의 저장된 맵기 값이 이관 후 6단계 중 하나이며, 정수로 남은 회원이 0명이다.
- **SC-003**: 전환 배포 후 기존 회원·온보딩 관련 자동 검증이 전부 통과한다(회귀 0건).

## Assumptions

- **정수→단계 매핑 규칙(기본안)**: -1→SKIP, 0→NONE, 1~3→MILD, 4~6→MEDIUM, 7~8→HOT, 9~10→EXTREME. 기획에서 다른 구간을 확정하면 이 규칙만 교체한다.
- 클라이언트(앱)는 같은 기획 변경으로 단계 선택 UI 로 함께 전환된다 — 정수 입력에 대한 하위 호환(이중 수용 기간)은 두지 않는다.
- 회원 맵기 설정은 현재 다른 기능(음식 추천·위험도 판정 등)의 계산에 쓰이지 않으므로, 표현 전환이 다른 도메인 동작에 영향을 주지 않는다.
- 음식의 맵기 점수(0~10, 미조사 -1)는 이번 전환 대상이 아니다.
