# Contract: 비전 프롬프트 — 이 브랜치는 바꾸지 않는다

**Owner**: `infra/llm/.../menu/OpenAiMenuBoardVisionExtractor.kt` (코드 상수)

**상태**: KB-320 은 프롬프트를 **수정하지 않는다.** develop(KB-319) 상태를 그대로 쓴다.

## 왜 안 바꾸는가

초안 목표는 "프롬프트를 고쳐 클라이언트 OCR 을 판단에서 배제한다"였다. 그런데 KB-319 가 먼저 머지되며 **구조로 같은 목표를 달성**했다 — v2 는 `items` 를 아예 받지 않고 `ocrItems = emptyList()` 로 호출하므로, OCR 이 판단에 개입할 경로 자체가 없다. 지시로 막을 필요가 없다.

프롬프트를 추가로 손대면 v1(구버전 앱) 동작이 바뀌는데, v1 은 동결 대상이다. 그래서 이 브랜치의 프롬프트 변경량은 0 이다.

## 현재 상태 (develop 소유)

| 프롬프트 | 선택 조건 | 성격 |
|----------|-----------|------|
| `SYSTEM_PROMPT` | `ocrItems` 가 **비어 있지 않음** (= v1) | `[진실의 출처]` 절에서 사진과 OCR 을 대조해 오탈자를 교정하고, `matchedIdx` 로 클라이언트 항목에 매칭 |
| `SERVER_OCR_SYSTEM_PROMPT` | `ocrItems` 가 **비어 있음** (= v2) | 사진 픽셀이 유일한 근거. 클라이언트 힌트·`matchedIdx` 지시 없음. 응답 형식에도 `matchedIdx` 가 없다 |

분기는 `extract()` 안의 `if (ocrItems.isEmpty())` 하나다. seam 시그니처는 `extract(imagePath, ocrItems)` 그대로이며 이 브랜치가 한때 추가했던 `MenuBoardReadingMode` 인자는 **철회했다**.

## 폐기된 설계 (기록용)

이 브랜치는 중간에 프롬프트를 두 벌(`PHOTO_ONLY` / `OCR_ASSISTED`)로 나누고 `X-API-Version >= 2026.08.08` 로 고르는 구조를 만들었다가 되돌렸다. 폐기 이유:

1. **KB-319 와 중복** — 같은 엔드포인트에 임계값이 둘(`2026.08.07`, `2026.08.08`), 프롬프트 분기 기준이 둘이 됐다.
2. **과거 동작이 재현되지 않는다** — 같은 릴리스에서 모델도 `gpt-4o-mini` → `gpt-5.6-luna` 로 바뀐다. 옛 프롬프트 + 새 모델은 옛 응답이 아니다. 게이트가 보장하는 것은 "판단 근거의 계약"이지 "출력의 동일성"이 아니었다.
3. **정책 불일치** — 요청에서 `items` 가 사라지는 것은 리소스 구조 변경이라 URL 경로가 담당한다(`api-versioning-policy`).

## 프롬프트를 바꾸게 될 때의 규칙

모델 출력은 비결정적이라 CI 에서 "모델이 지시를 따랐다"를 단정할 수 없다. 검증 가능한 유일한 표면은 **프롬프트 문자열**이며, `OpenAiMenuBoardVisionExtractorTest` 가 가짜 `ChatModel` 로 `Prompt` 를 캡처해 assert 한다.

assert 는 **전문 일치가 아니라 핵심 문구 포함/미포함**으로 쓴다. 전문 일치면 문장을 다듬을 때마다 테스트가 깨져 아무도 프롬프트에 손대지 않게 된다.
