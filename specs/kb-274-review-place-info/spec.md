# Feature Specification: 리뷰 작성 시 식당(장소) 검색·선택 저장

**Feature Branch**: `kb-274-review-place-info`

**Created**: 2026-08-01 (개정: 검색 API 를 서버 제공으로 확정 — 클라이언트 직접 호출 전제 폐기)

**Status**: Draft

**Input**: User description: "KB-274 — 리뷰 작성 시 카카오 지도 검색 API로 식당을 찾는 기능이 포함됨. 장소 검색은 별도 컨트롤러(서버 API)로 제공하고, 리뷰 작성 시 그 식당의 주소 정보를 함께 저장. 없을 수도 있어서 선택값."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 리뷰 작성 화면에서 식당 검색 (Priority: P1)

리뷰 작성자가 작성 화면에서 식당 이름(키워드)으로 검색하면, 서비스가 지도 검색 결과(식당명·주소·좌표 등) 목록을 돌려준다. 작성자는 그중 하나를 선택한다.

**Why this priority**: 검색이 없으면 사용자가 식당 정보를 만들 방법이 없다 — 전체 흐름(검색 → 선택 → 저장)의 진입점.

**Independent Test**: 키워드로 검색 요청을 보내 결과 목록이 반환되는지, 빈 키워드는 거절되는지, 로그인 없이는 사용할 수 없는지로 독립 검증 가능.

**Acceptance Scenarios**:

1. **Given** 로그인한 회원이 리뷰 작성 화면에 있을 때, **When** 식당 이름 키워드로 검색하면, **Then** 식당명·주소·좌표가 담긴 결과 목록이 반환된다.
2. **Given** 검색 결과가 없는 키워드일 때, **When** 검색하면, **Then** 빈 목록이 정상 반환된다(오류 아님).
3. **Given** 빈 키워드(누락·공백)로, **When** 검색하면, **Then** 요청이 거절된다.
4. **Given** 외부 지도 검색이 장애일 때, **When** 검색하면, **Then** 명확한 오류가 반환되고, 리뷰 작성 자체(식당 없이)는 계속 가능하다.

---

### User Story 2 - 선택한 식당 정보와 함께 리뷰 작성 (Priority: P2)

리뷰 작성자가 검색에서 선택한 식당의 장소 정보가 리뷰와 함께 저장된다. 식당을 선택하지 않고 작성하면 기존과 동일하게 장소 정보 없이 저장된다.

**Why this priority**: 검색(P1) 다음의 핵심 — 저장돼야 이후 노출이 가능하다. 리뷰 작성 API 관점의 변경은 선택 장소값 저장 하나뿐이다.

**Independent Test**: 식당 정보를 포함해 리뷰를 작성한 뒤 저장된 리뷰에 해당 식당 정보가 남아 있는지, 식당 정보 없이 작성한 리뷰는 기존과 동일하게 저장되는지로 독립 검증 가능(검색 API 없이도 값을 직접 만들어 검증 가능).

**Acceptance Scenarios**:

1. **Given** 로그인한 회원이 식당을 검색·선택한 상태, **When** 별점·본문과 함께 리뷰를 등록하면, **Then** 리뷰가 저장되고 선택한 식당의 장소 정보가 함께 보존된다.
2. **Given** 로그인한 회원이 식당을 선택하지 않은 상태, **When** 별점·본문만으로 리뷰를 등록하면, **Then** 리뷰가 기존과 동일하게 저장되고 장소 정보는 비어 있다.

---

### User Story 3 - 리뷰 조회 시 식당 정보 확인 (Priority: P3)

리뷰를 조회하는 사용자는 각 리뷰에 저장된 식당 정보(식당명·주소)를 함께 볼 수 있다. 식당 정보가 없는 리뷰는 지금과 동일하게 표시된다.

**Why this priority**: 저장된 위치 맥락이 다른 사용자에게 노출되어야 기능의 가치가 실현된다. 저장(P2)이 선행돼야 한다.

**Independent Test**: 식당 정보가 있는 리뷰와 없는 리뷰를 각각 조회해, 있는 쪽은 식당 정보가 응답에 포함되고 없는 쪽은 비어 있음을 확인.

**Acceptance Scenarios**:

1. **Given** 식당 정보가 저장된 리뷰가 존재할 때, **When** 해당 리뷰를 목록/상세에서 조회하면, **Then** 식당명과 주소가 함께 반환된다.
2. **Given** 식당 정보 없이 작성된 리뷰(기존 리뷰 포함)가 존재할 때, **When** 해당 리뷰를 조회하면, **Then** 리뷰는 정상 반환되고 식당 정보 자리는 비어 있다.

---

### User Story 4 - 리뷰 수정 시 식당 정보 변경 (Priority: P4)

리뷰 작성자가 리뷰를 수정할 때 식당 정보를 새로 지정하거나, 다른 식당으로 바꾸거나, 제거할 수 있다.

**Why this priority**: 작성·조회가 갖춰진 뒤의 보완 흐름. 수정 빈도는 낮지만 잘못 선택한 식당을 바로잡을 수단이 필요하다.

**Independent Test**: 식당 정보가 있는 리뷰를 식당 정보 없이 수정하면 제거되고, 없는 리뷰에 식당 정보를 넣어 수정하면 추가되는지로 검증.

**Acceptance Scenarios**:

1. **Given** 식당 정보가 저장된 본인 리뷰가 있을 때, **When** 다른 식당 정보로 수정하면, **Then** 새 식당 정보로 교체된다.
2. **Given** 식당 정보가 저장된 본인 리뷰가 있을 때, **When** 식당 정보를 보내지 않고 수정하면, **Then** 식당 정보가 제거된다(본문·사진과 동일한 전량 교체 규칙).

---

### Edge Cases

- 검색 키워드가 비어 있음(누락·공백) — 요청 거절.
- 외부 지도 검색 장애·시간 초과 — 검색만 명확한 오류로 실패하고, 식당 없는 리뷰 작성은 영향받지 않는다.
- 식당 정보의 일부 항목만 있는 경우(예: 도로명주소가 없는 장소) — 검색 결과의 항목 단위 결측을 허용한다.
- 식당명이나 주소가 비정상적으로 긴 경우 — 저장 가능한 최대 길이를 정하고 초과 시 요청을 거부한다.
- 식당 정보 없이 저장된 기존 리뷰 — 조회·수정 흐름이 깨지지 않아야 한다.
- 식당 정보만 있고 별점 등 필수 항목이 빠진 요청 — 기존 필수 검증이 그대로 동작해야 한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 서비스는 키워드로 식당을 검색하는 API 를 **리뷰 API 와 별도의 전용 창구(컨트롤러)** 로 제공해야 한다. 검색은 외부 지도 검색(카카오)을 서버가 대신 호출해 결과(식당명·주소·외부 장소 식별자·좌표 목록)를 반환한다.
- **FR-002**: 검색 API 는 로그인한 회원만 사용할 수 있어야 하고, 빈 키워드는 거절해야 한다. 결과 없음은 빈 목록으로 정상 반환한다.
- **FR-003**: 외부 지도 검색 실패(장애·시간 초과) 시 검색 API 는 명확한 오류 코드로 실패해야 하며, 리뷰 작성·조회·수정 기능에는 영향을 주지 않아야 한다.
- **FR-004**: 리뷰 작성 시 식당(장소) 정보를 선택적으로 함께 제출할 수 있어야 한다. 식당 정보 전체가 없어도 작성은 성공해야 한다. **리뷰 작성 창구의 변경은 이 선택 장소값 저장 하나뿐이다**(검색은 FR-001 의 별도 창구).
- **FR-005**: 저장하는 식당 정보는 식당명·주소·외부 장소 식별자·좌표로 하며, 모두 선택값으로 취급한다(항목 단위 결측 허용). 서버는 저장 시 전달값의 형식·길이만 검증하고 실존 여부를 재검증하지 않는다.
- **FR-006**: 리뷰 조회 응답(리뷰 목록, 음식 상세의 리뷰 섹션 등 리뷰가 노출되는 조회)에 저장된 식당 정보가 포함되어야 하며, 없는 리뷰는 식당 정보가 빈 값으로 반환되어야 한다.
- **FR-007**: 리뷰 수정 시 식당 정보를 교체하거나 제거할 수 있어야 한다. 수정 요청에 식당 정보가 없으면 기존 식당 정보는 제거된다(본문·사진과 동일한 전량 교체 규칙).
- **FR-008**: 식당 정보 각 항목에 저장 가능한 최대 길이를 정의하고, 초과하는 요청은 명확한 오류로 거부해야 한다.
- **FR-009**: 기존에 저장된 리뷰(식당 정보 없음)의 조회·수정·삭제 흐름은 변경 없이 동작해야 한다.

### Key Entities

- **리뷰**: 회원이 음식에 남기는 별점·본문·사진 기록(기존). 이번 기능으로 선택적 식당 정보가 부가된다.
- **식당(장소) 정보**: 리뷰에 부속되는 선택 정보 묶음 — 식당명, 주소, 외부 장소 식별자, 좌표. 독립 생명주기를 갖지 않고 리뷰와 함께 저장·수정·삭제된다.
- **식당 검색 결과**: 검색 API 가 반환하는 일시적 목록(식당명·주소·외부 장소 식별자·좌표). **저장되지 않는다** — 작성자가 선택한 한 건만 리뷰에 실려 저장된다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 리뷰 작성 화면에서 식당 키워드 검색 결과가 사용자 체감 즉시(수 초 내) 반환된다.
- **SC-002**: 식당을 선택해 작성한 리뷰는 100% 조회 시 식당명·주소가 함께 노출된다.
- **SC-003**: 식당을 선택하지 않은 리뷰 작성·수정·조회는 기능 도입 전과 동일하게 성공한다(기존 흐름 회귀 0건).
- **SC-004**: 기능 배포 이전에 작성된 모든 리뷰가 조회·수정에서 오류 없이 처리된다.
- **SC-005**: 외부 지도 검색 장애 중에도 식당 없는 리뷰 작성 성공률은 영향받지 않는다.

## Assumptions

- 식당 검색은 **서버가 카카오 지도 검색을 대신 호출**해 제공한다(검색 자격증명을 클라이언트에 노출하지 않기 위함). 검색 결과 목록은 저장하지 않는 일시 데이터다.
- 리뷰 저장 시 서버는 클라이언트가 전달한(=검색에서 선택한) 식당 정보 스냅샷을 그대로 저장하며, 실존 여부를 재검증하지 않는다 — 형식·길이 검증만 수행한다.
- 저장 항목의 정확한 구성(식당명·주소·외부 장소 식별자·좌표의 길이·타입)은 구현 설계에서 확정한다. 본 스펙은 항목 범위와 "전 항목 선택값" 원칙만 고정한다.
- 식당 정보는 리뷰 단위로 저장되는 부가 정보이며, 별도의 식당 목록 관리·식당별 리뷰 조회 기능은 이번 범위 밖이다.
- 리뷰 신고·차단·삭제 등 기존 리뷰 부가 기능은 식당 정보와 무관하게 기존 동작을 유지한다.
