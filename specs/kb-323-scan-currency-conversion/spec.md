# Feature Specification: 스캔 응답에 회원 통화 환산 정보 제공

**Feature Branch**: `kb-323-scan-currency-conversion`

**Created**: 2026-08-11

**Status**: Draft

**Input**: User description: "323. 2.0 스캔 api 응답에 포함시킨다. 사용자의 프로필에 설정된 통화로 환산 정보를 포함시켜 내려주는 것이다. 따라서 실제 계산은 클라이언트 레벨에서 동작하도록 할 것이다. currency 코드와 그 값을 기존 스캔 응답에 포함시키면된다. 워크트리 ㄱㄱ"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 자국 통화로 메뉴 가격 가늠 (Priority: P1)

통화가 설정된 외국인 사용자가 메뉴판을 스캔하면, 스캔 결과(2.0)에 사용자의 통화 코드와 그 통화의 환율 값이 함께 내려온다. 클라이언트 앱은 이 값으로 각 메뉴의 원화 가격을 사용자 통화 금액으로 환산해 표시할 수 있다.

**Why this priority**: 이 기능의 존재 이유다. 스캔 응답에는 원화 정수 가격만 있어 외국인 사용자가 자국 통화로 얼마인지 알 수 없다.

**Independent Test**: 통화가 설정된 회원으로 2.0 스캔을 호출해 응답에 통화 코드와 환율 값이 포함되는지 확인하는 것만으로 검증 가능하며, 그 자체로 클라이언트 환산 표시를 가능하게 하는 완결된 가치를 제공한다.

**Acceptance Scenarios**:

1. **Given** 프로필에 통화(예: USD)가 설정된 회원, **When** 2.0 스캔을 요청하면, **Then** 응답에 통화 코드(USD)와 해당 통화 1단위당 원화 금액인 환율 값이 포함된다.
2. **Given** 프로필 통화가 KRW 인 회원, **When** 2.0 스캔을 요청하면, **Then** 동일한 형식으로 통화 코드(KRW)와 환율 값 1이 포함된다.
3. **Given** 통화가 설정된 회원, **When** 2.0 스캔을 요청하면, **Then** 기존 응답의 모든 필드(원화 가격 포함)는 변경 없이 그대로 유지된다.

---

### User Story 2 - 통화 미설정 회원의 스캔 (Priority: P2)

프로필에 통화가 설정되지 않은 회원(통화 설정 도입 이전 가입자 등)이 스캔하면, 통화 환산 정보만 빠진 채 스캔은 기존과 동일하게 성공한다.

**Why this priority**: 통화 정보 부재가 핵심 기능(스캔)을 막아서는 안 된다. 부분 성공 정책으로 기존 사용자 경험을 보존한다.

**Independent Test**: 통화가 없는 회원으로 2.0 스캔을 호출해, 스캔 결과는 정상이고 통화 환산 정보만 비어 있는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 프로필에 통화가 설정되지 않은 회원, **When** 2.0 스캔을 요청하면, **Then** 스캔은 성공하고 통화 환산 정보는 포함되지 않는다(빈 값).

---

### Edge Cases

- 통화가 설정되지 않은 회원의 스캔 → 통화 환산 정보만 비우고 스캔은 성공한다 (User Story 2).
- 스캔 결과에 가격이 없는 메뉴 항목이 섞여 있어도 통화 환산 정보 제공 여부에는 영향이 없다 — 환산 정보는 응답 수준의 값이고, 가격 없는 항목의 환산 표시는 클라이언트 소관이다.
- 스캔이 실패(비메뉴판 이미지 등)하면 기존 실패 응답 그대로다 — 통화 환산 정보는 성공 응답에만 실린다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 2.0 스캔 성공 응답은 회원 프로필에 설정된 통화의 코드와 환율 값을 포함해야 한다.
- **FR-002**: 환율 값은 "해당 통화 1단위당 원화 금액"을 의미한다. 금액 환산(원화 가격 ÷ 환율, 통화별 소수점·반올림 처리)은 클라이언트가 수행하며, 서버는 항목별 환산 금액을 계산하지 않는다.
- **FR-003**: 회원 프로필에 통화가 설정되어 있지 않으면 통화 환산 정보 없이 스캔 응답을 정상 반환해야 한다.
- **FR-004**: 기존 2.0 스캔 응답의 필드(원화 가격 포함)는 형태·의미를 변경하지 않고 유지해야 한다 — 통화 환산 정보는 추가 필드로만 제공한다.
- **FR-005**: 환율 값은 회원 통화 기능이 보유한 참고용 고정 스냅샷 값을 사용한다. 실시간 시세 조회나 외부 환율 서비스 호출을 스캔 경로에 추가하지 않는다.

### Key Entities

- **회원 프로필 통화**: 회원이 온보딩 시 국가 기반으로 자동 지정받거나 프로필에서 직접 변경한 통화. 미설정(빈 값)일 수 있다.
- **환율 스냅샷**: 통화별 "1단위당 원화 금액" 참고값. 통화 목록과 함께 관리되는 고정 값이며 실시간 시세가 아니다.
- **스캔 결과(2.0)**: 메뉴 항목별 위험도·원화 가격 목록. 이번 기능으로 응답 수준의 통화 코드·환율 값이 더해진다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 통화가 설정된 회원의 2.0 스캔 성공 응답 100%에 통화 코드와 환율 값이 포함된다.
- **SC-002**: 통화가 설정되지 않은 회원의 스캔 성공률이 기능 도입 전과 동일하다 — 통화 정보 부재로 실패하는 스캔이 0건이다.
- **SC-003**: 스캔 응답 소요 시간이 기능 도입 전과 체감 차이가 없다 (외부 조회가 추가되지 않으므로).
- **SC-004**: 기존 클라이언트(추가 필드를 모르는 버전)가 변경 없이 스캔 기능을 계속 사용할 수 있다.

## Assumptions

- **적용 범위는 2.0 스캔 응답만이다.** Jira KB-323 원문은 v1·v2 양쪽 추가를 언급하지만, 사용자 지시가 2.0 으로 좁혔다 — 1.0 응답은 변경하지 않는다.
- **서버 환산 없음.** Jira 원문의 "환산한 금액 추가·통화별 반올림 규칙" 항목은 클라이언트 환산 결정으로 클라이언트 소관이 됐다. 서버는 통화 코드와 환율 값만 제공한다.
- **환율 출처는 기존 참고용 고정 스냅샷이다.** 외부 환율 API 연동·주기 갱신·캐시 인프라(Jira 고려사항)는 이번 범위 밖이며, 값이 참고용 근사값임은 클라이언트 표시 정책으로 다룬다. 환율 기준 시각 제공도 고정 스냅샷이므로 범위 밖이다.
- **KRW 통화 회원에게도 동일 형식으로 제공한다**(환율 값 1). 표시 생략 여부는 클라이언트가 결정한다.
- **선행 조건 충족됨**: 회원 통화 설정 기능(국가 기반 자동 지정·프로필 개별 변경)은 이미 반영되어 있다.
