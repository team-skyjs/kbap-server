# Feature Specification: 프로필 사진 필수화 — null·빈 문자열 불가, 미설정은 기본 이미지 경로 저장

**Feature Branch**: `kb-188-profile-image-required`

**Created**: 2026-07-20

**Status**: Draft

**Input**: User description: "KB-188 [BE] 프로필 사진 필수화 — null·빈 문자열 불가, 미설정은 기본 이미지 경로 저장"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 온보딩 시 프로필 사진 필수 전송 (Priority: P1)

신규 회원이 온보딩을 완료할 때 프로필 사진 경로를 반드시 전송한다. 사진을 직접 올리지 않은 회원도 클라이언트가 기본 이미지 경로(`/images/default/profile/profile-default-512.png`)를 명시적으로 전송하므로, 온보딩을 마친 모든 회원은 예외 없이 프로필 사진 값을 가진다.

**Why this priority**: 저장값 non-null 계약의 진입점이다. 온보딩에서 필수화하지 않으면 이후 어떤 검증·백필도 신규 null 유입을 막지 못한다.

**Independent Test**: 온보딩 요청에서 프로필 사진을 생략/null 전송하면 400(COMMON-002)이 반환되고, 기본 이미지 경로를 전송하면 온보딩이 성공해 조회 시 해당 경로 기반 완전한 URL 이 노출되는 것으로 단독 검증 가능.

**Acceptance Scenarios**:

1. **Given** 온보딩 전 회원, **When** 프로필 사진 없이(미전송 또는 null) 온보딩을 요청하면, **Then** 400 과 코드 `COMMON-002` 로 거절된다
2. **Given** 온보딩 전 회원, **When** 기본 이미지 경로를 프로필 사진으로 전송해 온보딩하면, **Then** 온보딩이 성공하고 프로필 조회 시 기본 이미지의 완전한 URL 이 노출된다
3. **Given** 온보딩 전 회원, **When** 직접 업로드한 이미지 경로를 전송해 온보딩하면, **Then** 온보딩이 성공하고 해당 경로가 저장된다

---

### User Story 2 - 빈 문자열 "사진 제거" 센티널 폐기 (Priority: P1)

프로필 사진 값으로 빈 문자열은 어떤 경로(온보딩·프로필 수정)로도 허용되지 않는다. 기존의 "빈 문자열 = 사진 제거(null 저장)" 동작은 폐기된다 — 사진을 없애고 싶은 회원은 기본 이미지 경로를 명시 전송한다.

**Why this priority**: 빈 문자열 센티널이 남아 있으면 필수화 이후에도 null 저장 경로가 재생되어 US1·US3 의 계약이 깨진다.

**Independent Test**: 온보딩·프로필 수정 각각에 빈 문자열을 전송해 400(MEMBER-008)을 확인하는 것으로 단독 검증 가능.

**Acceptance Scenarios**:

1. **Given** 임의 회원, **When** 프로필 사진에 빈 문자열을 전송하면(온보딩·수정 무관), **Then** 400 과 코드 `MEMBER-008` 로 거절된다
2. **Given** 사진이 설정된 회원, **When** 프로필 수정에서 사진 필드를 생략(null)하면, **Then** 기존 사진이 유지된다 (부분 수정 규약 불변)
3. **Given** 사진이 설정된 회원, **When** 프로필 수정에서 기본 이미지 경로를 전송하면, **Then** 기본 이미지로 교체된다
4. **Given** 임의 회원, **When** 전체 URL(`http(s)://…`) 형태나 512자 초과 경로를 전송하면, **Then** 기존과 동일하게 거절된다 (기존 검증 유지)

---

### User Story 3 - 기존 미설정 회원 백필 (Priority: P2)

계약 변경 이전에 가입해 프로필 사진이 비어 있는(null) 기존 회원도, 배포 후에는 기본 이미지 경로가 저장되어 있어 다른 회원과 동일하게 프로필 사진 URL 이 노출된다.

**Why this priority**: 신규 유입 차단(US1·US2)만으로는 기존 null 행이 남아 "전 행 non-null" 계약이 완성되지 않는다. 다만 조회 응답은 null 허용으로 이미 동작 중이므로 신규 차단보다 한 단계 낮다.

**Independent Test**: 사진이 null 인 회원 데이터를 만들고 백필을 적용한 뒤 조회하면 기본 이미지 URL 이 노출되는 것으로 단독 검증 가능.

**Acceptance Scenarios**:

1. **Given** 프로필 사진이 null 로 저장된 기존 회원, **When** 백필이 적용되면, **Then** 저장값이 기본 이미지 경로로 채워진다
2. **Given** 백필 완료 상태, **When** 해당 회원이 프로필을 조회하면, **Then** 기본 이미지의 완전한 URL 이 노출된다
3. **Given** 프로필 사진을 이미 설정한 회원, **When** 백필이 적용되면, **Then** 기존 저장값은 변경되지 않는다

---

### Edge Cases

- 공백만으로 이루어진 문자열(`" "`)은 빈 문자열과 동일하게 거절되는가? → 기존 검증 규칙을 따른다(별도 완화 없음).
- 백필 대상에 탈퇴(소프트 삭제) 회원 행이 포함되는가? → 포함한다. 저장값 계약은 상태와 무관하게 전 행에 적용한다(복귀·감사 시 일관성).
- 클라이언트가 기본 이미지 경로가 아닌 임의의 존재하지 않는 경로를 보내면? → 서버는 경로 실존을 검증하지 않는다(기존 계약 유지 — 형식·길이 검증만).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 온보딩 요청의 프로필 사진 필드는 필수다 — 미전송·null 이면 400 과 코드 `COMMON-002` 로 거절한다.
- **FR-002**: 프로필 사진 값으로 빈 문자열은 온보딩·프로필 수정 어디서도 허용하지 않는다 — 400 과 코드 `MEMBER-008` 로 거절하며, 기존의 "빈 문자열 = 사진 제거" 동작은 폐기한다.
- **FR-003**: 기존 프로필 사진 경로 검증(전체 URL `http(s)://` 시작 거부, 길이 512 이하)은 그대로 유지한다.
- **FR-004**: 프로필 수정의 부분 수정 규약(필드 미전송/null = 기존 값 유지)은 그대로 유지한다.
- **FR-005**: 프로필 사진이 null 로 저장된 기존 회원 전 행에 기본 이미지 경로 `/images/default/profile/profile-default-512.png` 를 1회성으로 백필한다. 이미 값이 있는 행은 변경하지 않는다.
- **FR-006**: 조회 응답 조립은 변경하지 않는다 — 기본 이미지 경로도 다른 저장 경로와 동일한 방식으로 CDN 도메인과 조합되어 완전한 URL 로 노출된다.
- **FR-007**: API 문서에 프로필 사진 필드의 필수 여부와 기본 이미지 경로 계약(미설정 시 클라이언트가 기본 경로를 명시 전송)을 명시한다.

### Key Entities

- **회원 프로필(Member Profile)**: 회원의 표시 정보. 이 변경으로 프로필 사진 참조가 "선택 값(null 허용)"에서 "필수 값(항상 경로 존재)"으로 계약이 바뀐다. 기본 이미지 선택 책임은 클라이언트에 있다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 배포 후 온보딩을 완료한 신규 회원의 100% 가 프로필 사진 값을 가진다(null 저장 0건).
- **SC-002**: 백필 적용 후 프로필 사진이 null 인 회원 행이 0건이다.
- **SC-003**: 프로필 사진 미전송 온보딩·빈 문자열 전송은 100% 요청 단계에서 거절되고, 클라이언트는 안정 코드(`COMMON-002`/`MEMBER-008`)로 원인을 구분할 수 있다.
- **SC-004**: 기존에 사진을 설정한 회원의 프로필 사진 노출 URL 은 배포 전후 동일하다(회귀 0건).

## Assumptions

- 기본 이미지 파일(`/images/default/profile/profile-default-512.png`)은 CDN/스토리지에 이미 존재하며 그 배포는 이 작업 범위 밖이다(인프라/클라이언트 소유).
- 기본 이미지 선택·전송은 클라이언트 책임이다 — 서버는 "기본 이미지 경로인지"를 특별 취급하지 않고 일반 경로와 동일하게 저장·검증한다.
- 프로필 수정 API 의 부분 수정 규약(null=유지)은 공용 규약이므로 이번 변경에서 건드리지 않는다.
- 백필은 소프트 삭제된 회원 행을 포함한 전 행에 적용한다.
- 조회 응답의 URL 조합 방식(저장 경로 + CDN 도메인)은 기존 구조를 그대로 재사용한다.
