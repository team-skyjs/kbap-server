# Feature Specification: 회원 프로필 diet 카테고리 복수 선택

**Feature Branch**: `kb-340-member-diet-categories`

**Created**: 2026-08-19

**Status**: Draft

**Input**: User description: "KB-340 — diet 종류를 태그처럼 회원 프로필에 중복(복수) 등록. 온보딩·프로필 수정·내 프로필 조회 API 반영"

## 맥락

- 현재 diet 카테고리 15종(비건·할랄·글루텐 프리 등)은 카테고리별 회피 재료 매핑 조회(공개 API)로만 쓰인다 — 클라이언트가 diet 를 고르면 **매핑을 펼쳐 재료 코드 목록으로 변환해 저장**하므로, 서버는 회원이 어떤 diet 를 선택했는지 모른다.
- 그 결과 프로필 화면에서 선택한 diet 를 복원할 수 없다 — 이 기능은 **회원이 고른 diet 타입을 저장하고 되돌려주는 것**이 전부다.
- diet 는 단일 선택이 아니다 — **비건 + 글루텐 프리처럼 태그식 복수 선택**을 허용한다.
- **범위 밖 (2026-08-19 확정)**: 회피 재료는 클라이언트가 커스텀하는 영역이라 **건드리지 않는다** — diet 선택을 회피 판정에 합산(합집합)하는 것, diet 매핑 개정의 자동 반영, 스캔 결과의 diet 원인 표시는 전부 이번 범위가 아니다. 회피 재료 저장·판정 흐름은 현행 그대로(클라이언트가 diet 매핑을 전개해 재료 코드로 저장).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 온보딩·프로필 수정에서 diet 를 복수 선택한다 (Priority: P1)

가입 온보딩과 프로필 수정에서 회원이 diet 카테고리를 0개 이상 복수로 선택해 저장한다.

**Why this priority**: 저장이 있어야 복원(US2)이 성립한다 — 이 기능의 시작점.

**Independent Test**: 온보딩 요청에 diet 2종 포함 → 저장 확인. 프로필 수정으로 변경·전체 해제 확인. 미지원 값 400.

**Acceptance Scenarios**:

1. **Given** 온보딩 중인 회원, **When** diet 로 [비건, 글루텐 프리]를 선택해 제출하면, **Then** 두 카테고리가 프로필에 저장된다.
2. **Given** diet 를 저장한 회원, **When** 프로필 수정으로 [무슬림] 하나로 바꾸면, **Then** 기존 선택은 사라지고 [무슬림]만 남는다(전체 교체).
3. **Given** diet 를 저장한 회원, **When** 프로필 수정에서 diet 를 빈 목록으로 보내면, **Then** 전부 해제된다.
4. **Given** 온보딩·수정 요청, **When** 지원 목록에 없는 diet 값을 보내면, **Then** 400 으로 거절된다(전용 에러 코드).
5. **Given** 같은 diet 를 중복으로 담은 요청, **When** 제출하면, **Then** 한 번만 저장된다(집합 의미).

---

### User Story 2 - 내 프로필에서 선택한 diet 를 복원한다 (Priority: P1)

내 프로필 조회에 선택한 diet 목록이 포함되어, 앱이 프로필 화면에서 선택 상태를 그대로 복원한다.

**Why this priority**: 복원 불가가 이 기능의 출발 문제 — 저장(US1)과 함께 최소 완결.

**Independent Test**: diet 저장 후 내 프로필 조회 → 동일 목록 반환. 미선택 회원 → 빈 목록.

**Acceptance Scenarios**:

1. **Given** [비건, 글루텐 프리]를 저장한 회원, **When** 내 프로필을 조회하면, **Then** 두 카테고리가 응답에 담긴다.
2. **Given** diet 를 선택한 적 없는 기존 회원, **When** 조회하면, **Then** 빈 목록이 담긴다(오류 아님).

---

### Edge Cases

- 기존 회원(diet 개념 도입 전 가입)은? — 빈 목록으로 취급(동작 불변).
- 기존 클라이언트(diet 필드를 모르는 버전)가 온보딩·수정을 호출하면? — diet 필드 없이도 종전대로 동작해야 한다(하위호환).
- diet 15종 전부 선택하면? — 허용(상한 = 지원 카테고리 수).
- 내 프로필 조회의 회피 재료 목록 표현은? — 기존 회피 재료 필드는 그대로 두고 diet 는 **별도 필드로 분리**해 내린다(명확화 확정, 2026-08-19). 프로필 편집 화면이 재료 커스텀과 diet 태그를 각자 복원한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 회원 프로필은 diet 카테고리를 0개 이상 집합으로 저장할 수 있어야 한다(중복 없음, 지원 15종 한정).
- **FR-002**: 온보딩과 프로필 수정 요청에 diet 복수 지정 필드를 추가한다. 미지원 값은 전용 에러 코드로 400 거절, 중복 값은 집합으로 정규화한다.
- **FR-003**: 내 프로필 조회 응답에 선택한 diet 목록을 별도 필드로 반환한다 — 미선택·기존 회원은 빈 목록. 기존 회피 재료 필드의 의미는 불변이다.
- **FR-004**: diet 저장은 회피 재료·위험도 판정에 어떤 영향도 주지 않는다 — 회피 재료는 현행대로 클라이언트가 커스텀해 저장한 재료 코드만으로 판정한다.
- **FR-005**: diet 필드는 추가 필드로만 들어간다 — 기존 요청·응답 필드와 기존 클라이언트(필드 미전송) 동작은 불변이다.
- **FR-006**: diet 카테고리별 회피 재료 매핑 조회(공개 API)의 계약은 변경하지 않는다.

### Key Entities

- **회원 프로필**: 기존 프로필(국적·직접 지정 회피 재료·맵기 선호 등)에 diet 카테고리 집합이 추가된다.
- **diet 카테고리**: 지원 15종 고정 목록(코드 기반) — 각 카테고리는 회피 재료 집합으로 전개된다(기존 매핑 그대로).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 회원이 온보딩 또는 프로필 수정에서 저장한 diet 선택이 내 프로필 조회에서 100% 그대로 복원된다.
- **SC-002**: 기존 회원·기존 클라이언트의 온보딩·수정·조회·위험도 판정 동작 회귀 0건 — diet 저장은 순수 추가 기능이다.

## Assumptions

- diet 선택 저장 이후에도 회피 재료 커스텀(추가·삭제)은 전적으로 클라이언트 소유다 — 서버의 diet 저장은 선택 상태 기록·복원용 태그일 뿐 판정에 개입하지 않는다.
- 프로필 수정의 diet 필드 처리 방식(누락 시 유지 vs 교체)은 기존 프로필 수정 필드들의 계약을 따른다 — plan 단계에서 기존 규칙 확인 후 확정.
- 추가 필드만의 변경이라 API 버전을 올리지 않는다(KB-334 선례). 온보딩·수정의 버전별 요청(1.0/1.1) 양쪽에 동일하게 추가한다.
- 스캔 결과의 "어떤 diet 때문에 회피인지" 표시는 범위 밖(후속 이슈).
