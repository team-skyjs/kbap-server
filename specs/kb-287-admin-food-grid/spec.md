**Feature Branch**: `kb-287-admin-food-grid`

**Created**: 2026-08-05

**Status**: Draft

**Input**: User description: "KB-287 [BE] 관리자 음식 목록 화면 개편 — 카드 그리드·상태 필터·상세 모달 (워크트리로 진행)"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 관리자가 카드 그리드로 음식을 한눈에 훑는다 (Priority: P1)

관리자는 음식 목록 화면을 열면, 세로로 길게 늘어선 행 대신 썸네일·음식명·콘텐츠 상태가 담긴 정사각형 카드가 격자로 배치된 화면을 본다. 목록 영역은 화면에서 차지하는 높이가 고정되어 있어 페이지 전체가 늘어나지 않고, 더 볼 항목이 있으면 목록 영역 안에서만 스크롤한다. 헤더(검색·필터)와 페이지 이동은 스크롤과 무관하게 항상 같은 자리에 있다.

**Why this priority**: 티켓의 핵심 불편(가로로 넓은 행·페이지 전체 세로 스크롤·정보 파악 어려움)을 직접 해소하는 여정이다. 이 하나만 구현해도 관리 효율이 즉시 올라간다.

**Independent Test**: 음식이 여러 건 있는 상태에서 목록 화면을 열어 (1) 카드가 격자로 배치되는지, (2) 각 카드에 썸네일·음식명·상태가 보이는지, (3) 페이지 자체가 아니라 목록 영역 안에서만 스크롤되는지 확인하면 단독 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 음식이 여러 건 등록되어 있을 때, **When** 관리자가 음식 목록 화면을 열면, **Then** 음식들이 정사각형 카드의 격자 형태로 배치되고 각 카드에 썸네일·음식명·콘텐츠 상태가 함께 표시된다.
2. **Given** 한 페이지 분량의 카드가 목록 영역 높이를 넘길 때, **When** 관리자가 스크롤하면, **Then** 목록 영역 내부만 스크롤되고 검색·필터·페이지 이동 영역은 화면에 그대로 남는다.
3. **Given** 이미지가 없는 음식이 있을 때, **When** 목록을 조회하면, **Then** 해당 카드는 이미지 자리에 대체 표시(플레이스홀더)를 보여주고 카드 크기·정렬은 다른 카드와 동일하게 유지된다.
4. **Given** 이미지 주소는 있으나 이미지를 불러오지 못하는 음식이 있을 때, **When** 목록을 조회하면, **Then** 해당 카드는 깨진 이미지 대신 대체 표시로 바뀌고 나머지 카드는 정상 표시된다.
5. **Given** 검색·필터 결과가 0건일 때, **When** 목록을 조회하면, **Then** 목록 영역은 고정 높이를 유지한 채 결과 없음 안내를 보여준다.

### User Story 2 - 관리자가 콘텐츠 상태로 작업 대상을 좁힌다 (Priority: P2)

관리자는 "검수해야 할 음식만", "아직 내용이 비어 있는 음식만" 같은 식으로 콘텐츠 상태를 골라 목록을 좁힌다. 상태 선택은 음식명 검색과 함께 걸리며, 좁혀진 결과 안에서 페이지를 넘겨도 선택한 상태와 검색어가 유지된다.

**Why this priority**: 카드 그리드로 훑을 수 있게 된 뒤, 실제 작업(검수·보완) 대상만 모아 보는 것이 다음으로 큰 효율 이득이다. P1 없이도 동작하지만 P1 위에서 가치가 가장 크다.

**Independent Test**: 서로 다른 콘텐츠 상태의 음식을 섞어 둔 뒤 특정 상태를 선택해 그 상태의 음식만 남는지, 전체를 선택하면 다시 모두 보이는지, 검색어와 함께 걸리는지 확인하면 단독 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 여러 콘텐츠 상태의 음식이 섞여 있을 때, **When** 관리자가 특정 상태를 선택하면, **Then** 그 상태의 음식만 목록에 남고 총 건수도 그 기준으로 표시된다.
2. **Given** 상태 필터가 적용된 상태에서, **When** 관리자가 "전체"를 선택하면, **Then** 상태 조건이 해제되고 모든 상태의 음식이 다시 보인다.
3. **Given** 상태 필터와 음식명 검색어가 함께 적용되었을 때, **When** 목록을 조회하면, **Then** 두 조건을 모두 만족하는 음식만 표시된다.
4. **Given** 상태 필터·검색어가 적용된 상태에서, **When** 관리자가 다음/이전 페이지로 이동하면, **Then** 선택한 상태와 검색어가 유지된 채 해당 페이지가 표시된다.
5. **Given** 선택한 상태에 해당하는 음식이 하나도 없을 때, **When** 목록을 조회하면, **Then** 오류 없이 결과 없음 안내가 표시된다.

### User Story 3 - 관리자가 모달에서 상세를 확인하고 편집·삭제한다 (Priority: P2)

관리자는 카드의 상세 보기를 눌러 모달 창을 연다. 모달 안에서 음식의 전체 정보를 읽고, 편집을 눌러 값을 고쳐 저장하거나 삭제한다. 모달을 닫으면 보고 있던 목록(페이지·검색어·상태 필터·스크롤 위치)이 그대로 남아 다음 음식으로 바로 넘어갈 수 있다.

**Why this priority**: 카드 그리드에서는 기존 우측 패널보다 모달이 목록 폭을 온전히 쓰는 데 유리하다. 다만 편집·삭제 기능 자체는 이미 존재하므로 표현 방식 전환이 주 내용이라 P2다.

**Independent Test**: 카드의 상세 보기를 눌러 모달이 열리는지, 모달 안에서 편집→저장·삭제가 동작하는지, 닫은 뒤 목록 상태가 유지되는지 확인하면 단독 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 카드 그리드가 표시된 상태에서, **When** 관리자가 어떤 카드의 상세 보기를 누르면, **Then** 그 음식의 상세 정보가 모달로 열리고 뒤의 목록은 가려진 채 유지된다.
2. **Given** 상세 모달이 열려 있을 때, **When** 관리자가 닫기를 누르면, **Then** 모달이 닫히고 보고 있던 페이지·검색어·상태 필터·목록 스크롤 위치가 그대로 유지된다.
3. **Given** 상세 모달이 열린 직후, **When** 관리자가 값을 보면, **Then** 모든 입력은 읽기 전용이고 저장 수단은 노출되지 않는다(기존 편집 안전장치 유지).
4. **Given** 상세 모달에서 편집을 눌렀을 때, **When** 관리자가 값을 고쳐 저장하면, **Then** 변경이 저장되고 성공 안내와 함께 같은 목록 위치로 돌아온다.
5. **Given** 상세 모달에서 편집 중일 때, **When** 관리자가 취소를 누르면, **Then** 변경이 반영되지 않고 읽기 전용 상태로 되돌아간다.
6. **Given** 상세 모달이 열려 있을 때, **When** 관리자가 삭제를 확정하면, **Then** 음식이 삭제되고 모달이 닫힌 뒤 같은 목록 위치로 돌아온다.
7. **Given** 저장이 유효성 오류(잘못된 JSON·중복 이름·빈 이름)로 실패했을 때, **When** 화면이 다시 표시되면, **Then** 해당 음식의 상세 모달이 편집 상태로 다시 열려 있고 오류 내용이 안내된다.

### User Story 4 - 관리자가 버튼을 눈으로 빠르게 구분한다 (Priority: P3)

관리자는 상세 모달의 편집·삭제·취소·저장 버튼을 색으로 구분해 실수 없이 누른다.

**Why this priority**: 가시성·가독성 개선으로 실수와 인지 부하를 줄인다. 없어도 기능은 동작하므로 마지막이다.

**Independent Test**: 상세 모달에서 네 버튼이 동일한 형태에 각기 다른 색으로 구분되는지 확인하면 단독 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 상세 모달이 열려 있을 때, **When** 관리자가 버튼 영역을 보면, **Then** 편집·삭제·취소·저장 버튼이 동일한 형태·크기 규격을 따르되 역할별로 다른 색으로 구분된다.
2. **Given** 삭제처럼 되돌리기 어려운 동작일 때, **When** 관리자가 버튼을 보면, **Then** 다른 버튼과 뚜렷이 구분되는 경고 색으로 표시된다.

---

### Edge Cases

- 목록 영역 고정 높이보다 카드 수가 적을 때 — 빈 공간이 남더라도 영역 높이와 페이지 이동 위치는 그대로 유지된다.
- 음식명이 카드 폭을 넘길 만큼 길 때 — 카드 크기가 늘어나 격자가 흐트러지지 않고 이름 표시만 잘려서 처리된다.
- 상태 필터 값으로 알 수 없는 값이 들어왔을 때 — 오류 화면 대신 필터가 적용되지 않은 전체 목록으로 처리한다.
- 상세 모달을 연 상태에서 다른 관리자가 그 음식을 이미 삭제했을 때 — 저장·삭제 시도는 찾을 수 없음으로 실패하고 목록으로 돌아간다.
- 상태 필터가 걸린 목록에서 음식을 편집해 그 음식이 필터 조건에서 벗어났을 때 — 저장 후 목록에서는 해당 음식이 사라지며 필터·페이지는 유지된다.
- 마지막 페이지의 마지막 음식을 삭제해 그 페이지가 비었을 때 — 빈 목록이 아니라 유효한 페이지가 표시된다.

## Requirements *(mandatory)*

### Functional Requirements

**목록 표시**

- **FR-001**: 관리자 음식 목록은 항목을 정사각형 카드의 격자로 배치해야 한다.
- **FR-002**: 각 카드는 음식 썸네일 이미지, 음식명, 콘텐츠 상태를 표시해야 한다.
- **FR-003**: 이미지가 없거나 불러오지 못한 음식의 카드는 대체 표시를 보여주되, 카드 크기와 격자 정렬은 다른 카드와 동일해야 한다.
- **FR-004**: 목록 표시 영역은 높이가 고정되어야 하며, 항목이 넘칠 경우 페이지 전체가 아니라 그 영역 내부에서 스크롤되어야 한다.
- **FR-005**: 검색·필터 입력 영역과 페이지 이동 영역은 목록 영역 스크롤과 무관하게 화면에 유지되어야 한다.
- **FR-006**: 각 카드는 상세 보기 수단을 제공해야 한다.

**상태 필터**

- **FR-007**: 관리자는 콘텐츠 상태를 선택해 목록을 해당 상태의 음식으로 좁힐 수 있어야 하며, 선택지에는 현재 시스템이 사용하는 모든 콘텐츠 상태와 "전체"가 포함되어야 한다.
- **FR-008**: 상태 필터와 음식명 검색은 동시에 적용되어야 한다(AND 조건).
- **FR-009**: 총 건수·페이지 수는 적용된 상태 필터와 검색어를 반영해 계산되어야 한다.
- **FR-010**: 페이지 이동·상세 열기·저장·삭제 후에도 선택한 상태 필터와 검색어가 유지되어야 한다.
- **FR-011**: 알 수 없는 상태 값이 전달되면 오류를 내지 않고 상태 조건 없이 조회해야 한다.

**상세 모달**

- **FR-012**: 상세 보기는 목록 위에 겹쳐지는 모달로 열려야 하며, 열린 동안 뒤의 목록은 유지되어야 한다.
- **FR-013**: 모달은 명시적인 닫기 수단을 제공해야 하고, 닫으면 목록의 페이지·검색어·상태 필터·스크롤 위치가 유지되어야 한다.
- **FR-014**: 모달은 열릴 때 읽기 전용 상태여야 하며, 편집으로 전환해야만 값을 수정하고 저장할 수 있어야 한다(기존 편집 안전장치 유지).
- **FR-015**: 모달 안에서 편집·저장·취소·삭제를 모두 수행할 수 있어야 하며, 삭제는 확인 단계를 거쳐야 한다.
- **FR-016**: 저장이 유효성 오류로 실패하면 해당 음식의 모달이 편집 상태로 다시 열린 채 오류 내용이 표시되어야 한다.
- **FR-017**: 저장·삭제 후에는 성공 안내와 함께 직전에 보던 목록 위치(페이지·검색어·상태 필터·스크롤 위치)로 돌아가야 한다.

**버튼 가독성**

- **FR-018**: 편집·삭제·취소·저장 버튼은 하나의 공통 규격(형태·크기·여백)을 따라야 한다.
- **FR-019**: 각 버튼은 역할에 따라 서로 구분되는 색을 가져야 하며, 삭제는 되돌리기 어려운 동작임이 드러나는 경고 색이어야 한다.

### Key Entities

- **음식(Food)**: 관리 대상. 목록 카드에는 식별자·한국어 이름·콘텐츠 상태·이미지가 쓰이고, 상세 모달에는 번역·회피 성분 JSON을 포함한 전체 속성이 쓰인다.
- **콘텐츠 상태(FoodContentStatus)**: 음식 콘텐츠의 준비·검수 단계를 나타내는 값. 필터의 선택지이자 카드에 표시되는 배지의 근거다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 관리자는 한 화면에서 스크롤 없이 최소 8개 이상의 음식을 썸네일·이름·상태와 함께 확인할 수 있다(기존 행 목록 대비 2배 이상).
- **SC-002**: 특정 콘텐츠 상태의 음식만 모아 보는 데 필요한 조작이 2회 이하다(상태 선택 → 조회).
- **SC-003**: 상세를 열고 닫아도 목록 위치가 유지되어, 연속된 음식 10건을 검수하는 동안 목록 위치를 다시 찾는 조작이 0회다.
- **SC-004**: 상세 모달의 네 가지 동작(편집·저장·취소·삭제)이 색으로 구분되어, 처음 쓰는 관리자도 안내 없이 각 버튼의 역할을 구분할 수 있다.
- **SC-005**: 목록·상세의 기존 동작(음식명 검색, 편집 안전장치, 소프트 삭제, 저장 후 위치 유지)이 개편 후에도 모두 그대로 동작한다.

## Assumptions

- **콘텐츠 상태 목록**: 티켓 본문은 상태를 `INCOMPLETE·TEXT_READY·PENDING_REVIEW·READY` 4종으로 적었으나, 시스템이 실제로 쓰는 상태는 6종(`INCOMPLETE`·`PENDING_IMAGE`·`PENDING_REVIEW`·`REVIEWED`·`REVIEW_REJECTED`·`READY`)이다. 필터는 티켓의 예시 4종이 아니라 **시스템의 실제 상태 전부**를 선택지로 노출한다(`TEXT_READY`는 존재하지 않는 값이라 제외).
- **모달 vs 우측 패널**: 현재 상세는 우측 고정 패널이고 그것이 기존 선호였으나, 이 티켓이 명시적으로 모달을 요구하므로 **모달로 전환**한다. 카드 그리드가 목록 폭을 온전히 쓰기 때문에 패널보다 모달이 적합하다는 판단도 같은 방향이다.
- **페이지 이동 방식 유지**: 목록 영역 내부 스크롤은 "표시 영역 고정"을 위한 것이고, 페이지 넘김은 기존 페이지 이동 방식을 그대로 유지한다(무한 스크롤 도입은 범위 밖).
- **새 외부 의존성 없음**: 모달은 새 프론트엔드 라이브러리·빌드 도구 없이 기존 화면 구성 방식 안에서 해결한다.
- **JSON 색상 강조는 범위에서 제외**(2026-08-05 결정): 티켓의 syntax highlighting 항목은 구현하지 않는다. JSON 컬럼(MySQL `JSON` 타입)이 무효 값을 애초에 차단해 "깨진 값 방어" 명분이 없고, 남는 이득이 표시 색상뿐이라 인라인 토크나이저를 유지할 값어치가 없다. JSON 필드는 기존 textarea 표시를 그대로 쓴다.
- **화면 폭**: 기존 관리자 화면과 동일하게 데스크톱 브라우저를 전제하며 모바일 대응은 범위 밖이다.
- **권한·인증**: 기존 관리자 세션 인증을 그대로 사용하며 변경하지 않는다.
- **앱 사용자 영향 없음**: 이 작업은 관리자 화면 전용이며 앱 사용자용 조회 경로의 동작·응답은 바뀌지 않는다.
