# Feature Specification: 메뉴판 스캔 — 사진 판독 메뉴명이 OCR 텍스트를 덮어쓰도록 인식 지시 개선

**Feature Branch**: `kb-239-scan-prompt-ocr-override`

**Created**: 2026-07-24

**Status**: Draft

**Input**: User description: "메뉴판 스캔 정확도 향상 — 클라이언트 OCR 텍스트는 오타가 있을 수 있는 참고 정보임을 인식 단계에 고지하고, 사진에서 판독한 음식명이 OCR 텍스트와 다르면 판독 결과로 덮어쓴다. 요청·응답 규격은 그대로 두고 인식 지시문만 우선 수정한다. 음식명 같지 않은 항목을 결과에서 버리는 규칙은 유지한다. (KB-239)"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 오타 섞인 OCR 에도 제대로 된 메뉴명을 본다 (Priority: P1)

외국인 사용자가 식당에서 메뉴판을 촬영해 스캔한다. 앱이 사진에서 읽어낸 글자에는 오타가 섞여 있다(예: 사진의 "김치찌개"를 "김치피개"로 인식). 사용자는 결과 목록에서 사진에 적힌 그대로의 메뉴명과, 그 메뉴에 대한 위험도·번역명을 본다 — 앱이 잘못 읽은 글자가 결과에 그대로 노출되지 않는다.

**Why this priority**: 잘못된 메뉴명은 그 자체로 오정보일 뿐 아니라, 저장된 음식과 매칭되지 않아 위험도 판정까지 "알 수 없음"으로 떨어뜨린다. 이 앱의 핵심 가치(회피 성분 판정)가 통째로 무력화되는 지점이라 최우선이다.

**Independent Test**: 오타가 섞인 인식 텍스트를 포함한 메뉴판 사진 한 장으로 스캔을 수행해, 결과의 표시 메뉴명이 오타 텍스트가 아니라 사진 표기와 일치하는지 확인하면 단독 검증된다.

**Acceptance Scenarios**:

1. **Given** 사진에는 "김치찌개"가 적혀 있고 함께 제출된 인식 텍스트는 "김치피개"인 상태, **When** 사용자가 메뉴판 스캔을 요청하면, **Then** 결과의 메뉴명은 "김치찌개"로 나오고 저장된 음식과 매칭돼 위험도가 판정된다.
2. **Given** 사진 표기와 인식 텍스트가 동일한 상태, **When** 스캔을 요청하면, **Then** 결과의 메뉴명은 기존과 동일하게 사진 표기 그대로 나온다(회귀 없음).
3. **Given** 오타 항목이 여러 개 섞인 메뉴판, **When** 스캔을 요청하면, **Then** 각 항목이 사진 표기 기준으로 교정되며 서로 뒤바뀌지 않는다.

---

### User Story 2 - 메뉴가 아닌 글자는 여전히 결과에 없다 (Priority: P2)

메뉴판 사진에는 상호·전화번호·원산지 표기·영업시간 같은 메뉴가 아닌 글자가 함께 찍힌다. 사용자는 스캔 결과에서 이런 항목을 보지 않는다.

**Why this priority**: 이미 동작하는 규칙이라 새 가치는 아니지만, 인식 지시문을 손대는 변경이라 이 규칙이 함께 흔들릴 위험이 있다. 회귀 방지 목적의 스토리다.

**Independent Test**: 상호·원산지·영업시간 텍스트가 섞인 메뉴판 사진으로 스캔해, 결과에 해당 항목이 없는지 확인하면 단독 검증된다.

**Acceptance Scenarios**:

1. **Given** 메뉴 사이에 상호·원산지·영업시간 텍스트가 섞인 메뉴판, **When** 스캔을 요청하면, **Then** 결과에는 메뉴 항목만 담기고 나머지는 제외된다.
2. **Given** 메뉴판이 아닌 사진(간판·풍경 등), **When** 스캔을 요청하면, **Then** 빈 결과가 정상 응답으로 돌아온다(실패 아님).

---

### User Story 3 - 앱 업데이트 없이 개선 효과를 받는다 (Priority: P3)

이미 배포된 클라이언트 앱은 아무 수정 없이도 이번 개선의 효과를 받는다. 요청에 담는 값도, 응답에서 읽는 값도 그대로다.

**Why this priority**: 개선 효과를 즉시 전 사용자에게 전달하는 조건이자, 이번 작업의 범위를 묶어 두는 제약이다. 좌표 기반 매칭 전환은 이번 범위 밖이다.

**Independent Test**: 기존 요청 형식 그대로 스캔을 호출해 응답 필드 구성이 변하지 않았는지 확인하면 단독 검증된다.

**Acceptance Scenarios**:

1. **Given** 현재 배포된 앱이 보내는 것과 동일한 스캔 요청, **When** 스캔을 요청하면, **Then** 기존과 같은 필드 구성의 응답을 받으며 박스 표시가 그대로 동작한다.

---

### Edge Cases

- 사진 판독 메뉴명과 인식 텍스트가 크게 다를 때(예: 인식 텍스트가 다른 메뉴의 글자를 잘못 붙여 왔을 때) — 사진 판독 결과를 채택하되, 그 항목에 이어 붙일 박스가 마땅치 않으면 매칭 없음으로 둔다.
- 사진에 없는 메뉴가 인식 텍스트에만 있을 때 — 사진 기준으로 결과를 만들므로 그 항목은 결과에 나타나지 않는다.
- 사진이 흐리거나 잘려 특정 메뉴를 판독할 수 없을 때 — 억지 추정 대신 그 항목을 결과에서 제외한다.
- 사진 표기가 외국어뿐일 때 — 표시 메뉴명은 사진 표기를 따르되, 매칭·저장에 쓰는 한국어 메뉴명은 표준 한국어명으로 정리한다(기존 동작 유지).
- 같은 메뉴가 사이즈별로 여러 가격을 가질 때 — 기존대로 항목을 분리한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 사진 인식 단계에 전달하는 지시문에서, 함께 넘기는 클라이언트 인식 텍스트가 **오타를 포함할 수 있는 참고 정보**임을 명시해야 한다.
- **FR-002**: 사진에서 판독한 메뉴명이 클라이언트 인식 텍스트와 다를 경우, 시스템은 **사진 판독 결과를 최종 메뉴명으로 채택**해야 한다.
- **FR-003**: 클라이언트 인식 텍스트는 결과를 화면 박스에 이어 붙이기 위한 **매칭 힌트로는 계속 사용**되어야 하며, 매칭 결과를 담는 식별자의 의미와 산출 규칙은 그대로 유지되어야 한다.
- **FR-004**: 메뉴가 아닌 글자(상호·전화번호·원산지 표기·영업 안내 등)는 결과에서 제외되어야 한다(기존 규칙 유지).
- **FR-005**: 스캔 요청·응답의 필드 구성은 변경되지 않아야 한다 — 클라이언트는 좌표를 보내지 않고, 기존 필드만 주고받는다.
- **FR-006**: 사진에서 추출된 메뉴에 대응하는 인식 텍스트 항목이 없으면, 매칭 없음으로 표시되어야 한다(기존 동작 유지).
- **FR-007**: 가격 해석 규칙(원 단위 정수 변환, 축약 표기 복원, 미표기 시 없음)은 그대로 유지되어야 한다.
- **FR-008**: 인식 결과를 해석할 수 없어 스캔을 수행하지 못하면, 빈 결과를 조용히 돌려주지 않고 인식 실패로 처리되어야 한다(기존 동작 유지).

### Key Entities

- **스캔 요청 항목**: 클라이언트가 사진에서 읽어 보낸 글자 한 건 — 박스 식별자와 원문 텍스트로 구성된다. 이번 변경에서 구성은 바뀌지 않는다.
- **추출 메뉴**: 사진 판독으로 얻은 메뉴 한 건 — 표시 메뉴명, 표준 한국어 메뉴명, 가격, 매칭된 박스 식별자를 가진다. 표시 메뉴명의 **출처가 사진 판독으로 확정**되는 것이 이번 변경의 핵심이다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 오타가 섞인 인식 텍스트를 포함한 검증용 메뉴판 표본(최소 10개 메뉴 항목)에서, 표시 메뉴명이 사진 표기와 일치하는 항목 비율이 **95% 이상**이다.
- **SC-002**: 같은 표본에서 저장된 음식과 매칭돼 위험도가 판정되는 항목 비율이 **변경 전보다 높다**(오타로 매칭에 실패하던 항목이 줄어든다).
- **SC-003**: 인식 텍스트가 정확한 표본에서는 변경 전후 결과가 **동일**하다(개선이 정상 경로를 훼손하지 않는다).
- **SC-004**: 메뉴가 아닌 글자가 결과에 포함되는 비율이 **0%** 로 유지된다.
- **SC-005**: 스캔 요청·응답의 필드 변경 건수가 **0** 이며, 기존 클라이언트가 수정 없이 동작한다.

## Assumptions

- 사진이 인식 텍스트보다 신뢰도가 높다고 전제한다 — 둘이 충돌하면 예외 없이 사진 판독을 따른다(사용자 결정 사항).
- 클라이언트 인식 텍스트의 역할은 이번 변경 이후 "메뉴명의 근거"가 아니라 "결과를 박스에 잇는 힌트"로 좁혀진다.
- 바운딩 박스 좌표를 주고받는 방식으로의 전환은 이번 범위에서 제외한다. 이번 개선만으로 정확도가 얼마나 오르는지 확인한 뒤 별도로 판단한다.
- 클라이언트가 이미 읽어 둔 가격 텍스트를 서버로 함께 넘기는 것도 이번 범위 밖이다 — 가격은 계속 사진 판독으로만 얻는다.
- 검증은 실제 메뉴판 사진 표본으로 수행하며, 인식 모델·모델 설정은 현행 그대로 둔다(모델 교체는 이번 범위 밖).
