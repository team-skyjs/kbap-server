**Feature Branch**: `008-unsupported-language-error`

**Created**: 2026-07-02

**Status**: Superseded by specs/kb-201-home-lang-param (2026-07-20)

**Input**: 이슈 #18 — 언어 파라미터를 받는 조회에서 지원하지 않는 언어 코드가 들어오면 에러를 던지고, 에러 메시지에 지원 언어 목록을 포함한다. 현재처럼 조용히 `ko` 로 기본 처리하지 않는다(fail-fast + 안내).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 미지원 언어 코드 요청 시 명확한 에러와 안내 (Priority: P1)

외국인 사용자(또는 클라이언트 앱)가 음식 상세조회에서 지원하지 않는 언어 코드(예: `fr`)를 보내면, 시스템이 조용히 한국어로 응답하지 않고 **요청이 잘못됐음을 알리는 에러**를 반환한다. 에러 메시지에는 **어떤 언어를 지원하는지 목록**이 담겨 있어 사용자/개발자가 즉시 올바른 코드로 고칠 수 있다.

**Why this priority**: 이 스토리 하나만으로도 "잘못된 언어 요청이 조용히 숨겨지던" 핵심 문제를 해결한다. 잘못된 응답(엉뚱한 한국어)을 받는 대신 명확한 실패와 교정 안내를 받으므로, 이것이 MVP 이자 이슈의 본질이다.

**Independent Test**: 음식 상세조회 API 에 미지원 언어 코드를 붙여 호출하면 성공 응답 대신 실패 응답이 오고, 응답 메시지에 지원 언어 10종이 나열되는지 확인하면 독립적으로 검증된다.

**Acceptance Scenarios**:

1. **Given** 정상 등록된 음식과 미지원 언어 코드 `fr`, **When** 음식 상세조회를 요청하면, **Then** 성공 응답 대신 실패 응답을 반환하고 메시지에 지원 언어 목록(`ko, zh-Hans, en, ja, zh-Hant, vi, id, th, ru, es`)을 포함한다.
2. **Given** 미지원 코드 `EN`(대문자)·`ko-KR`(지역 변형)·`xx`(오타), **When** 각각을 조회에 사용하면, **Then** 모두 미지원으로 판정돼 실패 응답을 반환한다(조용한 한국어 폴백 없음).
3. **Given** 지원 언어 코드 `en`, **When** 조회를 요청하면, **Then** 정상적으로 영어(또는 번역 부재 시 기존 정책대로 한국어 폴백) 결과를 성공 응답으로 반환한다.

---

### User Story 2 - 언어 미지정 시 한국어 기본 동작 유지 (Priority: P2)

클라이언트가 언어를 지정하지 않거나(파라미터 생략) 빈 값/공백을 보낸 경우, 시스템은 에러 없이 **한국어로 응답**한다. 언어는 선택 파라미터이므로 "미지정 = 한국어"가 자연스러운 기본이다.

**Why this priority**: fail-fast 를 도입하되 기존 정상 흐름(언어 미지정 → 한국어)을 깨지 않도록 보장한다. P1 의 에러 경로가 정상 요청까지 잘못 막지 않는지 회귀를 방어한다.

**Independent Test**: 언어 파라미터 없이(또는 빈 문자열로) 음식 상세조회를 호출해 한국어 결과가 성공 응답으로 오는지 확인하면 독립 검증된다.

**Acceptance Scenarios**:

1. **Given** 언어 파라미터를 생략(null), **When** 음식 상세조회를 요청하면, **Then** 에러 없이 한국어 결과를 성공 응답으로 반환한다.
2. **Given** 언어 값이 빈 문자열 `""` 또는 공백 `"   "`, **When** 조회를 요청하면, **Then** 에러 없이 한국어 결과를 성공 응답으로 반환한다.

---

### Edge Cases

- **미지원 코드의 앞뒤 공백**(예: `" fr "`): 공백을 제거한 뒤 판정하며, 실제 코드가 미지원이면 에러를 반환한다.
- **대소문자·지역 변형**(`EN`, `KO`, `ko-KR`, `en-US`): 지원 코드와 **정확히 일치**하지 않으므로 모두 미지원 에러로 판정한다(정규화하지 않는다).
- **지원 언어이나 번역 데이터가 없는 경우**(예: `ja` 인데 일본어 번역 미보유): 에러가 아니라 **기존 한국어 폴백 정책을 유지**한다(이번 범위 밖, 006 정책 존치).
- **메뉴 스캔 등 현재 언어 파라미터를 소비하지 않는 API**: 언어 검증 대상이 아니므로 이번 변경으로 동작이 바뀌지 않는다. 단, 향후 언어 파라미터를 받게 되면 동일한 strict 규칙을 자동으로 적용받는다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 언어 코드 해석 시, 값이 존재하고(=null·빈·공백이 아님) 지원 목록과 **정확히 일치하지 않으면** 해당 요청을 **미지원 언어 에러**로 처리해야 한다(조용한 한국어 폴백 금지).
- **FR-002**: 미지원 언어 에러의 안내 메시지에는 **지원 언어 코드 전체 목록**(`ko, zh-Hans, en, ja, zh-Hant, vi, id, th, ru, es`)이 포함되어야 한다.
- **FR-003**: 언어 값이 **없거나(null)·빈 문자열·공백뿐**인 경우, 시스템은 에러 없이 **한국어(ko)를 기본**으로 해석해야 한다.
- **FR-004**: 언어 코드 매칭은 **정확 일치**여야 한다 — 대소문자 차이(`EN`)나 지역 변형(`ko-KR`)은 미지원으로 처리한다(정규화하지 않는다).
- **FR-005**: 음식 상세조회는 미지원 언어 코드에 대해 **성공 응답 대신 실패 응답을 반환**하며, 표준 응답 봉투(성공 여부 + 사유 메시지 구조)를 따르고 클라이언트 오류임을 나타내는 상태로 응답해야 한다.
- **FR-006**: 실패 응답의 상태는 **클라이언트 요청 오류(HTTP 400 Bad Request)** 로 표현해야 한다.
- **FR-007**: 지원 언어이나 번역 데이터가 없는 경우의 **한국어 폴백 정책은 변경 없이 유지**되어야 한다(에러 아님).
- **FR-008**: 미지원 언어 판정은 **공유 언어 어휘(LanguageCode) 레벨의 단일 규칙**으로 강제되어, 이 어휘를 소비하는 모든 조회가 동일하게 동작해야 한다.

### Key Entities *(include if feature involves data)*

- **지원 언어 목록**: 시스템이 응답을 제공할 수 있는 언어 코드의 확정 집합(`ko, zh-Hans, en, ja, zh-Hant, vi, id, th, ru, es`). 미지원 판정과 안내 메시지의 단일 출처다.
- **미지원 언어 오류**: 값이 있으나 지원 목록에 없는 언어 코드가 들어왔을 때 발생하는 도메인 오류. 지원 언어 목록을 안내로 동반한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 미지원 언어 코드(대문자·지역 변형·오타 포함)로 음식 상세조회를 요청하면 **100%** 실패 응답이 반환되고, 조용한 한국어 응답은 **0건**이다.
- **SC-002**: 미지원 언어 에러 응답의 **100%** 가 지원 언어 10종 목록을 안내 메시지에 포함한다.
- **SC-003**: 언어 미지정(생략·빈·공백) 요청은 **100%** 기존대로 한국어 결과를 성공 응답으로 받는다(회귀 0건).
- **SC-004**: 지원 언어이나 번역이 없는 요청은 **100%** 기존 한국어 폴백으로 성공 응답을 받는다(에러 0건).

## Assumptions

- 언어 파라미터는 **선택**이며, 미지정은 정상적인 한국어 요청을 의미한다(사용자 확인 완료).
- 언어 코드 매칭은 **정확 일치**로 한다 — 관대한 정규화(대소문자·지역 변형)는 도입하지 않는다(사용자 확인 완료).
- 미지원 에러의 HTTP 상태는 **400 Bad Request** 로 한다(이슈 권장).
- 현재 언어 파라미터를 실제로 소비하는 조회는 **음식 상세조회뿐**이며, 메뉴 스캔은 언어 파라미터를 받지 않는다(코드 확인). 따라서 이번 변경의 사용자 표면 회귀 대상은 음식 상세조회다.
- 기존의 관대한 해석(미지원 → ko 폴백)은 **strict 규칙으로 전면 교체**하며, 조용한 폴백을 남기지 않는다(이슈 권장).
