# Feature Specification: v2 스캔 응답 기피성분 겹침 표시

**Feature Branch**: `kb-332-scan-avoidance-overlap`

**Created**: 2026-08-13

**Status**: Draft

**Input**: User description: "v2 스캔 api 응답에 각 음식 정보와 함께 - 스캔 결과에서 나의 기피성분을 쭉 깔아주면서 겹치는지 여부를 표시해줘라" (Jira: KB-332)

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 매칭된 음식의 기피성분 겹침 확인 (Priority: P1)

기피성분을 등록한 회원이 메뉴판을 스캔하면, 결과의 각 음식 항목마다 자신의 기피성분 전체가 나열되고 성분별로 그 음식에 포함되는지(겹침 여부)가 표시된다. 회원은 "왜 이 메뉴가 위험한가"를 종합 위험도 한 글자가 아니라 성분 단위로 확인할 수 있다.

**Why this priority**: 이 기능의 핵심 가치. 현재는 종합 위험도만 내려가 어떤 성분 때문에 위험한지 알 수 없다.

**Independent Test**: 기피성분 2개를 등록한 회원으로 매칭 가능한 메뉴를 스캔하여, 응답의 음식 항목에 기피성분 2개가 모두 나열되고 각각의 포함 여부가 음식의 실제 성분 데이터와 일치하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 기피성분 A·B 를 등록한 회원, **When** 성분 A 를 포함하고 B 를 포함하지 않는 음식이 매칭된 스캔 결과를 받으면, **Then** 해당 항목에 A(겹침)·B(겹치지 않음)가 모두 나열된다.
2. **Given** 기피성분을 하나도 등록하지 않은 회원, **When** 스캔하면, **Then** 각 항목의 기피성분 목록은 빈 목록이고 응답은 정상 동작한다.
3. **Given** 기피성분을 등록한 회원, **When** 스캔 결과에 매칭 음식이 여러 개면, **Then** 모든 매칭 항목 각각에 동일한 기피성분 목록이 항목별 겹침 여부와 함께 나열된다.

---

### User Story 2 - 미매칭 항목의 일관된 표시 (Priority: P2)

스캔 결과에 아직 등록되지 않은(매칭 실패) 메뉴가 섞여 있어도, 클라이언트가 항목별 화면을 일관되게 그릴 수 있도록 미매칭 항목의 기피성분 표시 방식이 정의되어 있다.

**Why this priority**: 미매칭 항목은 성분 정보가 없어 겹침을 판정할 수 없다. 방침이 정의되지 않으면 클라이언트가 항목마다 다른 형태를 방어적으로 처리해야 한다.

**Independent Test**: 매칭 항목과 미매칭 항목이 섞인 스캔 결과에서 미매칭 항목의 기피성분 표시가 정의된 방침대로 내려오는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 기피성분을 등록한 회원, **When** 매칭 실패(조사 대기 또는 판정 불가) 항목이 포함된 결과를 받으면, **Then** 해당 항목의 기피성분 목록은 빈 목록으로 내려온다(겹침 판정 불가 — 종합 위험도 UNKNOWN 과 일관).

---

### Edge Cases

- 프로필 없는 회원(게스트·온보딩 미완료): 모든 항목의 기피성분 목록이 null — 기피 정보의 주체가 없다.
- 프로필은 있으나 기피성분 미등록 회원: 모든 항목의 기피성분 목록이 빈 목록 — 오류가 아니다.
- 정제 실패(degraded) 응답: 전 항목이 미매칭이므로 전 항목 빈 목록.
- 유사 음식 대체(similarFood)가 붙은 미매칭 항목: 원 항목은 미매칭이므로 겹침을 판정하지 않는다(유사 음식의 성분으로 대체 판정하지 않음 — 종합 위험도가 UNKNOWN 인 것과 일관).
- 회원 기피성분이 스캔 시점과 조회 시점 사이에 변경되는 경합: 스캔 요청 처리 시점의 기피성분 스냅샷 기준으로 판정한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 스캔 v2 응답의 각 메뉴 항목은 요청 회원의 기피성분 전체 목록을 포함해야 한다(등록 순서 무관, 전 항목 동일 목록).
- **FR-002**: 각 기피성분 항목은 성분 식별자, 요청 언어 기준 표시명(번역 부재 시 한국어), 해당 음식 포함(겹침) 여부를 포함해야 한다.
- **FR-003**: 매칭된(matched=true) 음식의 겹침 여부는 그 음식의 실제 성분 데이터 기준으로 판정해야 한다. 겹친 성분에는 음식 상세 판정과 동일한 규칙의 성분별 경고 수준(위험도)을 함께 표시해야 한다(미겹침 성분은 경고 없음).
- **FR-004**: 매칭 실패(matched=false) 항목의 기피성분 목록은 빈 목록이어야 한다(겹침 판정 불가).
- **FR-005**: 프로필이 없는 회원(게스트 — 온보딩 미완료)의 응답은 모든 항목에서 기피성분 목록이 null 이어야 한다(기피 정보 주체 부재). 프로필은 있으나 기피성분을 등록하지 않은 회원은 빈 목록이어야 한다. 두 경우 모두 오류가 발생하지 않아야 한다.
- **FR-006**: 기존 v2 응답 필드(종합 위험도·이름·가격·유사 음식·통화 등)는 변경 없이 유지되어야 한다(추가만 허용 — 기존 클라이언트 무영향).
- **FR-007**: API 문서(스키마 설명)에 신규 필드의 의미와 미매칭 처리 방침이 명시되어야 한다.

### Key Entities

- **기피성분(회원)**: 회원이 온보딩/프로필에서 등록한 피하고 싶은 성분 집합. 이 기능의 나열 대상.
- **음식 성분**: 음식별 성분 구성(성분 코드 + 포함 확률). 겹침 판정의 근거 데이터.
- **스캔 결과 항목**: 사진에서 추출된 메뉴 1건의 판정 결과. 신규로 "기피성분별 겹침 목록"을 갖는다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 기피성분을 등록한 회원의 스캔 결과에서, 매칭된 모든 항목에 등록 기피성분 100% 가 겹침 여부와 함께 나열된다.
- **SC-002**: 겹침 여부 판정이 음식 성분 데이터와 100% 일치한다(겹침·미겹침 케이스 각각 검증).
- **SC-003**: 기존 v2 스캔 클라이언트(신규 필드를 모르는 버전)가 수정 없이 계속 동작한다.
- **SC-004**: 스캔 응답 시간이 기능 추가 전과 체감 차이가 없다(외부 호출 추가 없음 — 성분 카탈로그 조회 1건 외 기존 조회 데이터 재사용).

## Assumptions

- v2 스캔은 인증된 회원 전용이나, 게스트(온보딩 미완료) 회원은 프로필이 없을 수 있다 — 이 경우 기피성분 목록은 null 로 내려 "기피 정보 없음"을 표현한다(빈 목록 = 기피 0개와 구분).
- 기피성분 목록은 항목마다 동일하지만, 클라이언트가 항목 단위로 화면을 그리므로 각 항목에 반복 포함한다(항목 수가 메뉴판 수준이라 응답 크기 부담 미미).
- 겹침 판정에 포함 확률 임계값은 두지 않는다 — 음식 성분 데이터에 존재하면 "겹침"이다. 겹친 성분의 경고 수준은 음식 상세 판정과 동일 규칙(포함 확률 기반 성분별 위험도)을 재사용한다 — 새 규칙을 만들지 않는다.
- 성분 표시명은 기존 성분 카탈로그(DB 단일 출처)의 언어별 번역을 재사용한다 — 스캔 요청의 표시 언어로 해석하고 번역 부재 시 한국어 원문을 쓴다(음식 상세와 동일).
- 미매칭 항목의 방침은 "빈 목록"을 기본으로 한다 — 종합 위험도 UNKNOWN 과 의미가 일관되고, 클라이언트는 목록 유무로 판정 가능/불가를 구분한다.
- 스캔 이력(조회 API)에 대한 소급 적용은 범위 밖 — 이번 스캔 응답에만 적용한다.
