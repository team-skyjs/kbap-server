## Clarifications

### Session 2026-06-29

- Q: 간단·자세 설명의 한국어(ko) 원문은 모든 음식에 필수인가? (DB NOT NULL + 도메인 불변조건 + 응답 필드 non-null) → A: 둘 다 필수 — ko 원문 non-null(컬럼 NOT NULL·도메인 require·응답 필드 non-null `String`).
- Q: 간단·자세 설명의 저장 길이/컬럼 타입은? (원문·번역 컬럼 동일 적용) → A: 간단 `VARCHAR(255)`(최대 255자), 자세 `VARCHAR(1024)`(최대 1024자). 원문 컬럼과 번역 테이블 컬럼 모두 동일 길이로 맞춘다(TEXT 미사용 — 길이 명시 규약).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 외국인 사용자가 음식 소개를 모국어로 읽는다 (Priority: P1)

음식 상세 화면에 진입한 사용자는, 음식명·대표 이미지·재료 목록과 함께 그 음식을 소개하는 **간단 설명**과 **자세한 설명**을 요청 언어로 본다(둘 다 한 응답에 포함). 지원 언어면 해당 언어 번역으로, 미지원/미지정이면 한국어 원문으로 제공된다.

**Why this priority**: 외국인 사용자가 낯선 한국 음식을 이해하는 데 음식명·재료만으로는 부족하다. 한눈에 들어오는 간단 설명과, 더 알고 싶을 때의 자세한 설명이 함께 음식 상세 화면의 정보 완성도를 좌우하므로 P1.

**Independent Test**: 두 설명이 등록된 음식을 `lang=en` 으로 조회하면 응답에 간단·자세 영어 설명이 모두 포함되고, `lang` 미지정/미지원으로 조회하면 둘 다 한국어 설명으로 제공되는 것으로 단독 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** seed 음식 "된장찌개"에 간단·자세 설명의 ko 원문과 en 번역이 등록돼 있고, **When** `GET /api/v1/foods/detail?menuName=된장찌개&lang=en` 을 호출하면, **Then** 응답 payload 에 영어 **간단 설명**과 영어 **자세한 설명**이 각각 포함된다.
2. **Given** 사용자가 `lang` 을 지정하지 않고, **When** `GET /api/v1/foods/detail?menuName=된장찌개` 를 호출하면, **Then** 간단·자세 설명 모두 한국어 원문으로 반환된다.
3. **Given** "된장찌개"의 자세한 설명에는 요청 언어(`ru`) 번역이 있으나 간단 설명에는 `ru` 번역이 없고, **When** `lang=ru` 로 조회하면, **Then** 자세한 설명은 `ru` 번역으로, 간단 설명은 한국어 원문으로 **각각 독립적으로** 반환된다.
4. **Given** 음식 상세를 조회하면, **When** 응답을 받으면, **Then** 간단·자세 설명은 기존 응답 필드(음식명·이미지·재료 목록)와 **함께** 한 응답 안에 포함된다(추가 호출 불필요).

---

### Edge Cases

- 요청 언어가 지원 9개 언어 목록 밖이거나 형식이 잘못된 경우 → 음식명과 동일하게 두 설명 모두 한국어로 폴백한다.
- 두 설명 중 하나의 번역만 없는 경우(부분 번역) → **설명별로 독립적으로** 한국어로 폴백하며, 다른 설명·음식명은 영향받지 않는다(필드별 독립 폴백).
- 미수록 메뉴명으로 조회한 경우 → 기존 동작(400)을 유지하며, 본 기능이 이를 바꾸지 않는다.
- 설명 길이 차이 → 간단 설명은 짧은 한두 문장, 자세한 설명은 한 문단(수백 자) 범위를 가정한다(Assumptions 참조).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 음식 상세 조회(`GET /api/v1/foods/detail`) 응답에 해당 음식의 **간단 설명**과 **자세한 설명**을 각각 별도 텍스트 필드로 포함해야 한다(둘 다 한 응답에 동시 제공). 두 설명의 ko 원문은 모든 음식에 **필수(non-null)** 이며, 응답에서 두 필드는 항상 채워진다.
- **FR-002**: 간단 설명과 자세한 설명은 음식별 **고유 소개 콘텐츠**로, 음식의 정체·특징을 자연어로 기술한다(고정 UI 템플릿이 아님). 두 설명의 구체적 편집 의도·분량 기준은 기획 정의에 따른다(Assumptions·Dependencies 참조).
- **FR-003**: 시스템은 두 설명 각각을 **한국어(ko) 원문** + **9개 대상 언어(zh-Hans·en·ja·zh-Hant·vi·id·th·ru·es)** 번역으로 저장해야 한다(음식명·재료명과 동일한 언어 정책).
- **FR-004**: 조회 시 시스템은 각 설명에 대해 요청 `lang` 번역을 반환하고, **요청 언어 미지원/미지정/번역 부재** 시 한국어 원문으로 폴백해야 한다.
- **FR-005**: 두 설명의 언어 폴백은 **서로 그리고 음식명·재료명의 폴백과 독립적**으로 동작해야 한다(한 필드의 번역 부재가 다른 필드의 언어 선택에 영향을 주지 않는다).
- **FR-006**: 시스템은 데모 대상 기존 seed 음식들에 대해 간단·자세 설명(각 ko 원문 + 9개 언어 번역) seed 데이터를 보유해야 한다.
- **FR-007**: 본 기능은 기존 음식 상세 조회의 동작(매칭 키 = ko 음식명 trim exact match, 미수록 메뉴 400, `menuName` 누락/blank 400, 재료 정렬·mock 위험도)을 **변경하지 않아야** 한다 — 응답에 설명 필드를 더하는 가산적(additive) 변경이다.

### Key Entities *(include if feature involves data)*

- **간단 설명 (Brief description)**: 한 음식에 1:1로 귀속되는 짧은 한국어 원문 소개. 음식(Food)의 한 속성.
- **자세한 설명 (Detailed description)**: 한 음식에 1:1로 귀속되는 긴(한 문단) 한국어 원문 소개. 음식(Food)의 한 속성.
- **설명 번역 (Description translation)**: 각 설명(간단·자세)에 대한 특정 대상 언어 번역본. (음식, 설명 종류, 언어코드) 조합으로 유일하며, 9개 대상 언어만 허용한다. 한국어는 번역 테이블에 저장하지 않고 원문에서 온다(음식명 번역과 동일 정책). 두 설명을 한 테이블에서 종류로 구분할지 별도 테이블로 둘지는 설계(plan) 결정.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 두 설명이 등록된 음식을 지원 언어로 조회하면 100% 간단·자세 설명 모두 해당 언어로 응답에 포함된다.
- **SC-002**: 요청 언어 번역이 없는 설명은 100% 한국어 원문으로 폴백되며, 빈 값·오류 없이 항상 두 설명 텍스트가 채워진다.
- **SC-003**: 음식 상세 조회 응답이 음식명·이미지·재료·간단 설명·자세한 설명을 **단일 응답**으로 제공해, 사용자가 추가 호출 없이 음식 소개를 즉시 확인한다.
- **SC-004**: 기존 음식 상세 조회의 모든 기존 시나리오(정상·폴백·미수록 400·blank 400)가 회귀 없이 그대로 통과한다.

## Assumptions

- **설명 필수성**: 데모 범위의 모든 음식은 간단·자세 설명의 한국어 원문을 보유한다(ko 설명 non-null). 설명이 없는 음식은 가정하지 않는다 — 두 설명 모두 응답에서 항상 채워진다.
- **콘텐츠 출처(mock)**: 이번 슬라이스의 설명·번역 텍스트는 데모용으로, 실제 번역 품질·생성 파이프라인(배치/LLM)은 범위 밖이다(향후 교체). 기존 음식명 번역 seed 와 동일한 mock 성격이다.
- **언어 해석**: 요청 언어는 기존과 동일하게 `lang` 쿼리 파라미터에서 온다(회원 출처 언어 해석은 후속). 지원 언어 집합·폴백 규칙은 음식명과 동일하다.
- **길이**: 간단 설명은 짧은 한두 문장 → `VARCHAR(255)`(최대 255자), 자세한 설명은 한 문단 → `VARCHAR(1024)`(최대 1024자). 원문 컬럼·번역 테이블 컬럼 모두 동일 길이를 적용하며 TEXT 는 쓰지 않는다(MySQL 길이 명시 규약).
- **마이그레이션**: 기존 적용 완료된 마이그레이션은 수정하지 않고, 설명 저장 구조·seed 는 신규 마이그레이션으로 추가한다.
- **범위 제외**: 판정·재료 위험도 로직·LLM·회원/인증은 본 기능 범위 밖이며 기존 동작을 유지한다.

## Dependencies / Open Questions

- **간단 설명·자세한 설명의 구체 콘텐츠 정의는 기획자 확인 대기** — 각 설명에 어떤 내용(분량·관점·포함 항목)이 들어가야 하는지는 기획 정의에 따른다. 본 슬라이스는 구조(필드 2종·다국어·폴백·seed)를 확정하고, 실제 편집 콘텐츠는 기획 확정 시 seed 텍스트로 채워 교체한다. 이 미정 사항은 **데이터 구조·API 형태를 막지 않으며**, mock seed 텍스트로 진행 가능하다.
