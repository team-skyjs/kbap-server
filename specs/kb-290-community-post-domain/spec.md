# Feature Specification: 커뮤니티 게시글 도메인 — 작성/수정/삭제

**Feature Branch**: `kb-290-community-post-domain`

**Created**: 2026-08-04

**Status**: Draft

**Input**: User description: "KB-290 — 커뮤니티 게시글 도메인·스키마 + 작성/수정/삭제 API. 커뮤니티 게시판(트위터/스레드형 피드)의 토대가 되는 게시글 도메인. 본문 최대 2,000자, 사진 최대 4장(첫 장이 피드 커버), 음식 태그 최대 3개(우리 DB 음식만). 장소 태그는 현재 제공 불가라 스코프 제외. 수정 허용(표시 없음, 수정 시각만 확보), 삭제는 소프트 삭제 + 하위 댓글 통삭제."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 회원이 커뮤니티 글을 작성한다 (Priority: P1)

로그인한 회원이 커뮤니티 게시판에 글을 올린다. 제목 없이 본문이 곧 글이며(최대 2,000자), 사진을 최대 4장까지 붙일 수 있고 첫 번째 사진이 피드 커버가 된다. 우리 서비스에 등록된 음식을 최대 3개까지 태그로 첨부할 수 있다.

**Why this priority**: 게시글 생성이 없으면 커뮤니티의 다른 모든 기능(피드·댓글·리액션·신고·번역)이 성립하지 않는다. 이후 5개 병렬 태스크가 전부 이 도메인 위에서 진행되는 토대다.

**Independent Test**: 회원 자격으로 본문만 있는 글, 사진 4장 글, 음식 태그 3개 글을 각각 등록하고 저장된 내용이 입력과 일치하는지 확인하는 것으로 단독 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 로그인한 회원, **When** 본문 1자 이상 2,000자 이하로 글을 등록하면, **Then** 글이 저장되고 작성자·작성 시각이 기록된다.
2. **Given** 로그인한 회원, **When** 사진 4장을 순서와 함께 첨부해 등록하면, **Then** 사진 순서가 보존되고 첫 번째 사진이 커버로 식별된다.
3. **Given** 로그인한 회원, **When** 등록된 음식 3개를 태그로 첨부해 등록하면, **Then** 태그가 글과 함께 저장된다.
4. **Given** 로그인한 회원, **When** 본문 없이(또는 2,000자 초과로) 등록을 시도하면, **Then** 등록이 거부되고 원인을 식별할 수 있는 오류가 반환된다.
5. **Given** 비회원(게스트), **When** 글 등록을 시도하면, **Then** 인증 오류로 거부된다.

---

### User Story 2 - 작성자가 자기 글을 수정한다 (Priority: P2)

글 작성자가 본문·사진·음식 태그를 수정한다. 수정 사실은 다른 사용자에게 표시되지 않지만, 수정 시각은 내부적으로 기록된다(추후 "(edited)" 표시를 도입할 때 그대로 쓸 수 있도록).

**Why this priority**: 작성 직후 오타·내용 교정은 기본 기대 행동이다. 다만 작성이 먼저 있어야 하므로 P2.

**Independent Test**: 글을 하나 등록한 뒤 본문·사진·태그를 바꿔 저장하고, 변경 내용 반영과 수정 시각 갱신을 확인하는 것으로 단독 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 자기 글이 있는 작성자, **When** 본문·사진·태그를 수정하면, **Then** 변경 내용이 반영되고 수정 시각이 갱신된다.
2. **Given** 타인의 글, **When** 수정을 시도하면, **Then** 권한 오류로 거부된다.
3. **Given** 자기 글, **When** 수정 내용이 작성 제약(본문 2,000자·사진 4장·태그 3개)을 위반하면, **Then** 수정이 거부된다.

---

### User Story 3 - 작성자가 자기 글을 삭제한다 (Priority: P3)

글 작성자가 글을 삭제한다. 삭제는 데이터 제거가 아닌 소프트 삭제이며, 삭제된 글은 어떤 조회에도 노출되지 않는다. 글에 달린 댓글도 함께 보이지 않게 된다(통삭제 정책).

**Why this priority**: 삭제는 작성·수정 다음의 정리 행위이고, 댓글 통삭제 규칙의 완전한 검증은 댓글 도메인(후속 태스크) 합류 후 가능하다.

**Independent Test**: 글을 등록한 뒤 삭제하고, 삭제된 글이 조회되지 않으며 데이터는 보존 상태인지 확인하는 것으로 단독 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 자기 글이 있는 작성자, **When** 글을 삭제하면, **Then** 글이 조회에서 사라지되 데이터는 소프트 삭제 상태로 보존된다.
2. **Given** 타인의 글, **When** 삭제를 시도하면, **Then** 권한 오류로 거부된다.
3. **Given** 이미 삭제된 글, **When** 다시 삭제·수정을 시도하면, **Then** 대상 없음 오류로 거부된다.

---

### Edge Cases

- 본문이 정확히 2,000자인 글은 허용, 2,001자는 거부되는가?
- 존재하지 않거나 삭제된 음식을 태그로 첨부하면 어떻게 되는가? → 등록 거부.
- 같은 음식을 중복으로 태그하면 어떻게 되는가? → 거부(하나의 음식은 글당 한 번만 태그).
- 사진 순서가 중복되거나 누락된 채 요청되면 어떻게 되는가? → 요청 거부.
- 수정 시 사진·태그를 전부 제거하는 것은 허용되는가? → 허용(사진·태그는 선택 항목).
- 탈퇴한 회원의 글은 어떻게 되는가? → 글은 유지되며, 노출 정책(익명화)은 조회 태스크(KB-291)에서 다룬다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 회원이 본문(1자 이상 2,000자 이하)으로 커뮤니티 글을 등록할 수 있게 해야 한다. 제목은 없다.
- **FR-002**: 시스템은 글당 사진을 최대 4장까지, 표시 순서와 함께 첨부할 수 있게 해야 하며 첫 번째 사진을 피드 커버로 식별할 수 있어야 한다.
- **FR-003**: 시스템은 글당 음식 태그를 최대 3개까지 첨부할 수 있게 해야 하며, 태그 대상은 서비스에 등록된 음식으로 한정한다(자유입력 음식·장소 태그 불가).
- **FR-004**: 시스템은 작성 제약(본문 길이·사진 수·태그 수·태그 유효성) 위반 시 등록·수정을 거부하고 클라이언트가 분기할 수 있는 안정적인 오류 식별자를 반환해야 한다.
- **FR-005**: 시스템은 글 작성·수정·삭제를 회원에게만 허용하고, 수정·삭제는 작성자 본인에게만 허용해야 한다.
- **FR-006**: 시스템은 글 수정 시 수정 시각을 기록해야 한다. 수정 여부는 다른 사용자에게 표시하지 않는다.
- **FR-007**: 시스템은 글 삭제를 소프트 삭제로 처리해야 하며, 삭제된 글은 이후 모든 조회에서 제외되어야 한다.
- **FR-008**: 글 삭제 시 해당 글에 달린 댓글도 함께 노출되지 않아야 한다(통삭제 정책 — 댓글 도메인 합류 시 이 규칙이 성립하도록 삭제 모델을 설계한다).
- **FR-009**: 게시글 데이터는 이후 피드 조회·댓글·리액션·신고/차단·번역 기능이 병렬로 얹힐 수 있는 공유 도메인으로 자리 잡아야 한다.

### Key Entities

- **게시글(Post)**: 커뮤니티 글 한 건. 작성자, 본문(≤2,000자), 작성/수정 시각, 소프트 삭제 상태를 가진다.
- **게시글 이미지(PostImage)**: 글에 첨부된 사진. 소속 글, 이미지 위치(키), 표시 순서(1~4)를 가진다. 순서 1번이 피드 커버.
- **게시글 음식 태그(PostFoodTag)**: 글에 첨부된 음식 참조. 소속 글과 등록된 음식을 연결하며 글당 최대 3개, 같은 음식은 글당 1회만.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 회원은 본문만 입력한 글을 한 번의 등록 동작으로 게시할 수 있다.
- **SC-002**: 제약 위반(본문 초과·사진 5장·태그 4개·미등록 음식) 등록 시도는 100% 거부되고, 각각 원인을 구분할 수 있는 오류로 응답된다.
- **SC-003**: 타인 글에 대한 수정·삭제 시도는 100% 거부된다.
- **SC-004**: 삭제된 글이 일반 조회 경로에 노출되는 비율은 0%다.
- **SC-005**: 후속 태스크(피드 조회·댓글)가 이 도메인의 변경 없이(스키마 추가만으로) 착수 가능하다.

## Assumptions

- 사진 파일 업로드 자체는 기존 이미지 업로드 인프라(사전 서명 URL 방식)를 재사용하며, 이 기능은 업로드 완료된 이미지 위치(키)를 받아 글에 연결하는 책임만 진다.
- 장소 태그({name, roadAddress})는 현재 제공 불가 상태로 이번 스코프에서 제외한다. 도입 시 별도 태스크로 진행하며, 이번 설계가 장소 태그를 막는 구조가 되지 않도록만 유의한다.
- 댓글 도메인은 후속 태스크(KB-292)에서 만든다. 이번 태스크는 "글 삭제 → 하위 댓글 통삭제" 규칙이 성립 가능한 삭제 모델(소프트 삭제)까지만 책임진다.
- 피드 목록·글 상세 등 조회 계약은 후속 태스크(KB-291)의 범위다. 이번 태스크의 조회는 검증에 필요한 최소 수준(저장 결과 확인)이면 된다.
- 게스트(비회원) 열람 정책·탈퇴 회원 익명화 표시 정책은 조회 태스크(KB-291)에서 다룬다.
- 음식 태그 선택 UI는 기존 음식 검색 기능을 그대로 재사용하므로 신규 검색 기능은 만들지 않는다.
