# Feature Specification: 관리자 음식 상세 모달 UX 개선 — 목록 스크롤 유지·이미지 렌더링

**Feature Branch**: `kb-259-admin-food-modal-ux`

**Created**: 2026-07-30

**Status**: Draft

**Input**: User description: "KB-259 — 관리자 음식 목록에서 상세 조회 시 페이지가 다시 로드되며 스크롤이 최상단으로 이동해 보던 위치를 잃고, 상세 모달에는 이미지 키 텍스트만 표시되고 실제 사진이 렌더링되지 않는다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 상세 모달을 여닫아도 목록 위치가 유지된다 (Priority: P1)

관리자가 음식 목록을 아래로 스크롤해 검수하다가 특정 음식의 상세 조회를 열고, 확인 후 닫거나 수정 내용을 저장한다. 어떤 경우든 화면은 직전에 보던 목록 위치로 돌아와, 다음 항목 검수를 끊김 없이 이어간다.

**Why this priority**: 음식 검수는 목록을 순서대로 훑으며 여러 건을 연속 처리하는 작업이다. 매번 최상단으로 튕기면 건마다 스크롤을 다시 내려야 해 검수 흐름이 끊기는 것이 이 이슈의 핵심 불편이다.

**Independent Test**: 목록을 스크롤한 상태에서 상세 열기 → 닫기 → 수정 저장의 각 동작 후 화면 위치가 직전 목록 위치인지 확인하는 것만으로 독립 검증 가능.

**Acceptance Scenarios**:

1. **Given** 관리자가 음식 목록을 중간 지점까지 스크롤한 상태, **When** 특정 음식의 상세 조회를 연다, **Then** 목록의 스크롤 위치가 유지된 채 상세 모달이 표시된다
2. **Given** 상세 모달이 열린 상태, **When** 모달을 닫는다, **Then** 직전에 보던 목록 위치가 그대로 유지된다
3. **Given** 상세 모달에서 내용을 수정한 상태, **When** 저장한다, **Then** 저장 결과가 반영된 목록에서 직전 위치가 유지된다
4. **Given** 상세 모달에서 잘못된 값으로 저장을 시도한 상태, **When** 오류와 함께 모달이 다시 표시된다, **Then** 뒤편 목록의 위치도 여전히 유지된다

---

### User Story 2 - 상세 모달에서 실제 이미지를 확인한다 (Priority: P2)

관리자가 음식 상세 모달을 열면 이미지 키 문자열 대신 실제 음식 사진이 표시되어, 등록된 이미지가 올바른지 눈으로 즉시 확인한다.

**Why this priority**: 이미지 검수가 목적인 화면에서 키 텍스트만 보여서는 검수가 불가능하다. 다만 스크롤 유지(P1) 없이도 단독으로 가치를 내는 개선이라 P2.

**Independent Test**: 이미지가 등록된 음식과 없는 음식 각각의 상세 모달을 열어 사진/플레이스홀더 표시를 확인하는 것만으로 독립 검증 가능.

**Acceptance Scenarios**:

1. **Given** 이미지가 등록된 음식, **When** 상세 모달을 연다, **Then** 이미지 키가 공개 URL로 해석되어 실제 사진이 렌더링된다
2. **Given** 이미지가 등록되지 않은 음식, **When** 상세 모달을 연다, **Then** 플레이스홀더가 표시된다
3. **Given** 상세 모달이 열린 상태, **When** 이미지 키 값을 수정한다, **Then** 저장 후 다시 연 모달에 변경된 키 기준의 사진이 표시된다

---

### Edge Cases

- 이미지 키는 있으나 해당 키의 실제 이미지가 존재하지 않아 로드에 실패하면? → 깨진 이미지 아이콘 대신 플레이스홀더로 대체 표시한다.
- 목록 마지막 페이지 하단에서 상세를 열고 저장한 뒤 해당 행이 조건 변경으로 목록에서 사라지면? → 화면 위치는 가능한 범위 내에서 유지하고 오류 없이 목록을 표시한다.
- 스크롤 없이(목록 최상단에서) 상세를 여닫으면? → 기존과 동일하게 최상단이 유지된다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 상세 모달을 열 때 음식 목록의 스크롤 위치가 유지되어야 한다
- **FR-002**: 상세 모달을 닫을 때 직전 목록 스크롤 위치로 복귀해야 한다
- **FR-003**: 상세 모달에서 저장(성공·검증 실패 모두)한 뒤에도 직전 목록 스크롤 위치가 유지되어야 한다
- **FR-004**: 상세 모달은 음식의 이미지 키를 공개 URL로 해석해 실제 이미지를 렌더링해야 한다
- **FR-005**: 이미지 키가 없거나 이미지 로드에 실패하면 플레이스홀더를 표시해야 한다
- **FR-006**: 기존 음식 목록 조회·수정 동작(및 이를 검증하는 기존 테스트)은 변경 전과 동일하게 동작해야 한다

### Key Entities

- **음식(Food)**: 검수 대상. 이름·번역·이미지 키(imageRef) 등 관리자가 상세 모달에서 확인·수정하는 속성을 가진다.
- **이미지 키(imageRef)**: 저장소 내 이미지 위치 식별자. 화면에는 키 원문과 함께 공개 URL로 해석된 실제 이미지가 표시된다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 관리자가 목록 중간에서 상세를 열고 닫거나 저장하는 전 과정에서 스크롤 위치 이탈이 0회다
- **SC-002**: 연속으로 여러 건을 검수할 때 건당 목록 위치를 다시 찾는 데 쓰는 시간이 0초다(재스크롤 불필요)
- **SC-003**: 이미지가 등록된 음식의 상세 모달에서 100% 실제 사진이 표시되고, 미등록·로드 실패 건은 100% 플레이스홀더로 표시된다
- **SC-004**: 기존 음식 목록·수정 검증 절차가 전부 통과 상태를 유지한다

## Assumptions

- 상세 모달의 이미지는 확인(읽기) 용도다 — 이미지 업로드·교체 UI 추가는 범위 밖이다.
- 이미지 키 → 공개 URL 해석은 회원 상세 화면에서 이미 쓰이는 기존 해석 방식을 그대로 따른다.
- 목록 페이지네이션 구조(페이지 단위 이동)는 변경하지 않는다 — 유지 대상은 현재 페이지 안에서의 화면 위치다.
- 대상 사용자는 내부 관리자이며, 관리자 인증 등 접근 제어는 기존 체계를 그대로 사용한다.
