# Feature Specification: 회피·주의 성분 카탈로그 저장 (3분류 81종)

**Feature Branch**: `004-avoidance-catalog`

**Created**: 2026-06-29

**Status**: Draft

**Input**: User description: "ALLERGEN(건강 위험 — 가장 보수적 경고) · DIETARY_RULE(종교·윤리·채식·건강 식단 기준 — 기준 불일치 안내) · PERSONAL_AVOIDANCE(개인 취향 — 부드러운 안내) 3개 분류로 81종 항목을 저장하고 사용자별 메뉴 판별 시점에 사용한다. 오직 조회 목적의 하드코딩 데이터. 분류는 확정돼 있어 요청 시 분류된 값을 제공. 각 항목은 한국어가 기본이며 서비스가 다루는 다른 언어 번역도 저장한다."

> **맥락**: Meogo는 외국인 사용자가 메뉴가 자신의 제약과 충돌하는지 판단하도록 돕는다. 이를 위해 사용자가 **피하거나 주의해야 할 성분**의 단일 기준 목록이 필요하다. 각 성분은 **회피 사유 분류**(ALLERGEN / DIETARY_RULE / PERSONAL_AVOIDANCE) 중 **1~3개**에 속하고, 분류에 따라 사용자별 판정 시점의 **경고 강도/문구**가 달라진다. 본 기능은 그 **81종 성분의 기준 목록(코드·분류·명칭·다국어 번역)을 읽기 전용 하드코딩 참조 데이터로 저장·시드**하는 데 한정한다. 재료↔성분 매핑, 사용자 프로필 입력, 판정 로직, 조회 API는 후속에서 이 카탈로그를 참조한다.

## Clarifications

### Session 2026-06-29

- Q: 한 성분은 분류 몇 개에 속하나? (단일 vs 복수) → A: **복수 가능 — 같은 성분이 1~3개 분류에 중복 포함될 수 있다.** (성분↔분류 다대다, 성분당 1~3개)
- Q: 이 마스터 카탈로그의 소유 바운디드 컨텍스트는? → A: **avoidance** 컨텍스트가 소유한다.
- Q: 분류별 경고 문구(3종)를 본 범위에서 저장·관리하나? → A: **관리하지 않는다.** 경고 문구는 본 기능에서 저장하지 않고, 추후(판정/표현 단계) 별도 처리한다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 시스템이 분류된 회피·주의 성분 기준 목록을 보유한다 (Priority: P1)

서비스가 다루는 81종의 회피·주의 성분이, 각각 **안정적 코드 + 회피 사유 분류(3종 중 1~3개) + 한국어 원문 명칭 + 서비스 대상 언어 번역**을 갖춘 단일 마스터 목록으로 저장돼 있다. 이후 사용자별 메뉴 판별이 이 동일한 코드·분류·명칭을 기준으로 동작한다.

**Why this priority**: 메뉴 판별·경고 문구·다국어 노출 등 모든 후속 기능이 이 기준 목록 없이는 성립하지 않는다. 분류별 경고 강도(보수적/기준불일치/부드러운 안내)도 이 분류값에서 나온다. 기반 데이터라 P1.

**Independent Test**: 시드 적용 후 마스터 목록을 확인하면, 81종이 각각 고유 코드·1~3개 분류·ko 명칭을 갖고, 요청 언어 번역(미보유 시 ko)으로 제공되는지 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 회피·주의 성분 시드가 적용된 상태에서, **When** 저장된 목록을 확인하면, **Then** 81종이 각각 **고유 코드**, **1~3개 분류(ALLERGEN/DIETARY_RULE/PERSONAL_AVOIDANCE)**, **ko 원문 명칭**을 갖고 존재한다.
2. **Given** 한 성분에 대상 언어 번역이 등록돼 있고, **When** 특정 대상 언어로 명칭을 확인하면, **Then** 해당 언어 번역 명칭이 제공된다.
3. **Given** 한 성분에 특정 대상 언어 번역이 없을 때, **When** 그 언어로 명칭을 확인하면, **Then** ko 원문 명칭으로 폴백된다.
4. **Given** 마스터 목록, **When** 분류별로 집계하면, **Then** 모든 항목이 1~3개 분류에 속하고(전체 81종), 분류별 멤버십 합계는 81을 초과할 수 있다(복수 분류 — 예: ALLERGEN 64·DIETARY_RULE 56·PERSONAL_AVOIDANCE 23).
5. **Given** 마스터 목록, **When** 코드 유일성을 확인하면, **Then** 동일 코드가 중복 저장되지 않는다(코드가 식별 기준).
6. **Given** 여러 분류에 해당하는 성분(예: 어떤 재료가 ALLERGEN 이면서 DIETARY_RULE), **When** 그 성분의 분류를 확인하면, **Then** 1~3개 분류가 모두 반환된다.

---

### Edge Cases

- 동일 코드 중복 시드 → 코드는 유일, 중복 적재 안 됨.
- 대상 언어 외 언어로 명칭 요청 → ko 원문 폴백(음식명·재료명 정책과 동일).
- ko 원문 명칭이 빈 성분 → 허용 안 함(모든 성분 ko 명칭 필수).
- 분류값이 3종 외 값 → 허용 안 함(분류는 ALLERGEN/DIETARY_RULE/PERSONAL_AVOIDANCE 로 고정).
- 분류가 0개인 성분 → 허용 안 함(모든 성분은 최소 1개, 최대 3개 분류). 한 성분이 3개 분류 전부에 속하는 것은 허용.
- 같은 (성분, 분류) 조합 중복 → 허용 안 함(성분당 분류는 집합, 중복 없음).
- 이 데이터는 **읽기 전용** — 런타임 생성/수정/삭제 경로 없음(시드로만 적재).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 서비스가 다루는 회피·주의 성분 **81종**을 단일 마스터 카탈로그로 저장해야 한다.
- **FR-002**: 각 성분은 **안정적이고 유일한 코드**, **1~3개의 회피 사유 분류**(ALLERGEN | DIETARY_RULE | PERSONAL_AVOIDANCE 중 최소 1개·최대 3개, 중복 없는 집합), **한국어(ko) 원문 명칭**(비어 있을 수 없음)을 가져야 한다.
- **FR-003**: 각 성분은 ko 원문 + **서비스 대상 언어(zh-Hans·en·ja·zh-Hant·vi·id·th·ru·es)** 번역 명칭을 보유할 수 있어야 한다(음식 콘텐츠 다국어 정책 ADR-0003과 동일).
- **FR-004**: 특정 대상 언어 번역이 없으면 그 성분 명칭은 **ko 원문으로 폴백**해야 한다.
- **FR-005**: 코드는 **유일성**을 보장해야 한다(중복 코드 저장 불가). 코드가 식별 기준이다.
- **FR-006**: 분류값은 **세 가지로 고정**되며 각 성분은 그중 **1~3개**에 속한다(복수 분류 허용). 분류는 사용자별 판정 시점의 경고 강도/톤을 결정한다(ALLERGEN=가장 보수적, DIETARY_RULE=기준 불일치 안내, PERSONAL_AVOIDANCE=부드러운 안내).
- **FR-007**: 시스템은 확정된 81종(코드·분류 집합·ko 명칭·번역) **시드**를 보유해야 한다(원천 분류 값은 제공받아 적재).
- **FR-008**: 본 데이터는 **읽기 전용 참조 데이터**다 — 런타임에 생성/수정/삭제하지 않고 시드로만 관리한다.
- **FR-009**: 본 기능은 카탈로그의 **저장·시드**에 한정한다 — 재료↔성분 매핑, 사용자 프로필 입력, 판정 로직, **분류별 경고 문구 저장·관리**, 조회 API/온보딩 선택은 **범위 밖**(후속에서 본 카탈로그를 참조).

### Key Entities *(include if feature involves data)*

- **회피·주의 성분 (Avoidance substance)**: 사용자가 피하거나 주의할 성분 1종. 안정적 유일 코드 + ko 원문 명칭 + **1~3개 회피 사유 분류 집합**. member의 사용자 제약 조건과 food의 재료 매핑이 이 코드로 동일하게 참조할 공통 기준.
- **회피 사유 분류 (Avoidance category)**: ALLERGEN(건강 위험) · DIETARY_RULE(종교·윤리·채식·건강 식단) · PERSONAL_AVOIDANCE(개인 취향). 분류별 경고 강도/톤을 규정하는 고정 코드(3종). 한 성분이 여러 분류에 속할 수 있어 **성분↔분류는 다대다**(성분당 1~3, 중복 없음).
- **성분 명칭 번역 (Substance name translation)**: 한 성분의 특정 대상 언어 번역 명칭. (성분, 언어코드) 쌍으로 유일, 대상 언어만 허용. ko는 번역 테이블에 저장하지 않고 원문에서 온다(음식명 번역과 동일 정책).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 시드 적용 후 81종이 100% 저장되며 코드 중복 0건, 각 성분이 ko 명칭과 1~3개 유효 분류를 갖는다.
- **SC-002**: 모든 성분이 **최소 1개·최대 3개** 분류에 속하며, 분류값은 3종 외 값이 없고 (성분,분류) 중복이 없다.
- **SC-003**: 번역이 등록된 성분은 요청 대상 언어로 100% 해당 언어 명칭이 제공되고, 번역 부재 시 100% ko 폴백된다(빈 명칭 0).
- **SC-004**: 동일 코드를 중복 시드해도 중복 행이 생기지 않는다.
- **SC-005**: 코드·분류 집합이 후속(member·food·avoidance)이 참조하기에 안정적이다(임의 변경되지 않는 식별자·고정 분류).

## Assumptions

- **콘텐츠 출처**: 81종의 실제 코드·분류·ko 명칭·번역은 사용자가 제공한다(분류 확정됨). 제공 전까지 대표 항목으로 mock/placeholder 시드, 확정 시 교체.
- **복수 분류**: 각 성분은 3분류 중 **1~3개**에 속한다(성분↔분류 다대다, 중복 없는 집합). 81종 합산이 아니라 성분별 분류 멤버십이 1~3개다.
- **코드 체계**: 코드는 안정적·의미 있는 문자열(예: 대문자 스네이크 `PEANUT`·`PORK`)을 가정. 자동 증가 숫자가 아니다.
- **경고 문구**: 분류별 경고 문장은 **본 기능에서 저장·관리하지 않는다**(clarify 2026-06-29). 판정/표현 단계에서 분류값을 근거로 별도 처리한다(고정 뼈대는 데이터 아님).
- **다국어**: 대상 언어·폴백 규칙은 음식명·재료명과 동일(ADR-0003, 9개 언어).
- **읽기 전용**: 어드민 CRUD 없음. 시드로만 적재·갱신.
- **소유 컨텍스트**: 본 카탈로그는 **avoidance 컨텍스트가 소유**한다(clarify 2026-06-29). 구체 모듈 배치·영속 어댑터 구성은 plan 결정.
- **범위 제외**: 재료↔성분 매핑, 사용자 프로필 입력, 판정 로직, 분류별 경고 문구 저장·관리, 조회 API·온보딩 UI는 본 기능 밖.

## Dependencies / Open Questions

- **확정된 81종 분류 데이터(코드·분류·ko 명칭·대상 언어 번역) 제공이 콘텐츠 의존**이다. 구조(코드·분류·명칭·번역·유일성·폴백·시드)는 본 spec으로 확정하고, 실제 값은 제공 시 시드로 채운다. 이 미정은 저장 설계를 막지 않으며, 시드 작성 단계에서 사용자에게 분류된 값을 요청한다.
