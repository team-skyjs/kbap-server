# Feature Specification: 음식 리스트·상세 조회 응답에 북마크 여부(bookmarked) 포함

**Feature Branch**: `kb-153-food-bookmark-flag`

**Created**: 2026-07-15

**Status**: Draft

**Input**: User description: "kb-153 진행" (Jira KB-153: [BE] 음식 리스트·상세 조회 응답에 북마크 여부(bookmarked) 포함 — 비회원 조회는 항상 false 고정, 회원은 실제 북마크 여부. 스토리포인트 1)

## 배경

음식 북마크 기능(등록·취소·목록 조회)은 이미 제공되지만, 음식 리스트 조회·상세 조회 응답에는 해당 음식의 북마크 여부가 없다. 클라이언트가 리스트/상세 화면에서 북마크 상태(하트 아이콘 등)를 표시하려면 북마크 목록을 따로 불러와 대조해야 해서 비효율적이고 화면 진입이 느려진다. 두 조회 기능은 비회원도 사용할 수 있으므로, 북마크 여부는 회원 여부에 따라 값이 달라진다 — 비회원은 항상 false, 회원은 실제 북마크 여부.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 회원이 리스트·상세에서 자기 북마크 상태를 바로 확인 (Priority: P1)

로그인한 회원이 음식 리스트나 음식 상세를 조회하면, 각 음식에 자신의 북마크 여부(bookmarked)가 함께 내려와 별도 대조 없이 화면에 북마크 상태를 즉시 표시할 수 있다.

**Why this priority**: 이 기능의 존재 이유 — 클라이언트의 이중 호출·대조 로직을 없애는 핵심 가치다.

**Independent Test**: 회원 토큰으로 북마크한 음식과 안 한 음식을 리스트·상세로 조회해 bookmarked 값이 실제 북마크 상태와 일치하는지 확인.

**Acceptance Scenarios**:

1. **Given** 회원이 특정 음식을 북마크한 상태에서, **When** 그 회원이 음식 리스트를 조회하면, **Then** 해당 음식 항목의 bookmarked 는 true 이고 북마크하지 않은 항목은 false 다.
2. **Given** 회원이 특정 음식을 북마크한 상태에서, **When** 그 회원이 그 음식의 상세를 조회하면, **Then** bookmarked 는 true 다.
3. **Given** 회원이 북마크를 취소한 뒤, **When** 리스트·상세를 다시 조회하면, **Then** 해당 음식의 bookmarked 는 false 다.
4. **Given** 서로 다른 두 회원이 있을 때, **When** 각자 같은 음식을 조회하면, **Then** bookmarked 는 각자 자신의 북마크 상태만 반영한다(타인 북마크 무영향).

---

### User Story 2 - 비회원 조회는 항상 false 고정 (Priority: P2)

비회원(인증 없이 조회)이 음식 리스트·상세를 조회하면 bookmarked 가 항상 false 로 내려온다 — 응답 구조는 회원과 동일해 클라이언트가 분기 없이 같은 화면을 그릴 수 있다.

**Why this priority**: 비회원 조회 허용 정책과의 정합 — 필드가 없거나 형태가 달라지면 클라이언트 분기가 생긴다.

**Independent Test**: 인증 헤더 없이 리스트·상세를 조회해 모든 bookmarked 가 false 이고 그 외 응답이 기존과 동일한지 확인.

**Acceptance Scenarios**:

1. **Given** 어떤 회원이 특정 음식을 북마크했더라도, **When** 비회원이 음식 리스트·상세를 조회하면, **Then** 모든 항목의 bookmarked 는 false 다.
2. **Given** 비회원 조회일 때, **When** 응답을 받으면, **Then** bookmarked 필드는 생략되지 않고 항상 존재한다(값 false).

---

### Edge Cases

- 회원 토큰이 아예 없으면 비회원으로 간주해 false 고정 — 유효하지 않은 토큰의 처리(거절 등)는 기존 인증 정책 그대로이며 본 기능이 바꾸지 않는다.
- 북마크 취소 직후 조회는 false 를 반영한다(취소가 소프트 삭제여도 조회 결과는 "북마크 아님").
- 리스트 한 페이지에 북마크한 음식과 아닌 음식이 섞여 있으면 항목별로 정확히 구분되어야 한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 음식 리스트 조회 응답의 각 항목에 북마크 여부 필드(bookmarked, boolean)를 포함해야 한다.
- **FR-002**: 음식 상세 조회 응답에 북마크 여부 필드(bookmarked, boolean)를 포함해야 한다.
- **FR-003**: 비회원(인증 없는) 요청에서는 bookmarked 를 항상 false 로 내려준다.
- **FR-004**: 회원 요청에서는 그 회원이 해당 음식을 북마크했는지 실제 여부를 그대로 내려준다(true/false).
- **FR-005**: bookmarked 필드 추가 외 기존 응답 구조·조회 동작(페이지네이션·정렬·언어 처리·비회원 허용)은 무변경이어야 한다.
- **FR-006**: API 문서에 bookmarked 의 의미(회원별 상태, 비회원은 항상 false)를 명시해야 한다.

### Key Entities

- **북마크 여부(bookmarked)**: 조회하는 회원 기준의 개인화 값. 비회원이면 항상 false 라는 계약이며, "false = 북마크 안 함 또는 비회원"으로 해석된다(비회원 구분은 클라이언트가 자신의 로그인 상태로 안다).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 회원이 북마크한 음식은 리스트·상세 조회에서 100% bookmarked=true, 북마크하지 않은 음식은 100% false 로 표시된다.
- **SC-002**: 비회원 조회의 bookmarked 는 100% false 이고 필드 누락이 0건이다.
- **SC-003**: 클라이언트가 리스트/상세 화면의 북마크 상태 표시를 위해 추가 호출(북마크 목록 대조)을 할 필요가 없다 — 조회 1회로 완결.
- **SC-004**: 기존 리스트·상세 조회의 응답 구조·동작 회귀가 0건이다(기존 자동화 검증 전부 통과 유지).

## Assumptions

- 대상은 Jira KB-153 이 명시한 **음식 리스트 조회·상세 조회** 두 기능이다. 음식 검색은 리스트와 같은 요약 응답 형태를 공유하므로 구현상 함께 필드가 생길 수 있으며, 그 경우에도 동일 규칙(비회원 false·회원 실제 여부)을 따른다 — 별도 요구가 아니라 구조 공유의 자연 결과로 허용한다.
- 북마크 목록 조회 응답도 같은 요약 형태를 공유하나, 그 목록의 항목은 정의상 전부 북마크된 음식이다(값이 생기면 항상 true).
- 응답 필드는 항상 존재(누락 없음)하는 boolean 이며, 클라이언트는 비회원 여부를 자체 로그인 상태로 판단한다(서버가 "비회원이라 false"를 별도로 구분해 주지 않는다).
- 성능: 리스트 조회에서 항목별 개별 확인이 아니라 페이지 단위 일괄 확인을 전제한다(조회 화면 응답 속도 저하 없음).
