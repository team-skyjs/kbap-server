# Feature Specification: 프로필 언어 설정 제거 및 메뉴판 스캔 언어 요청 파라미터 전환

**Feature Branch**: `kb-229-scan-lang-param`

**Created**: 2026-07-23

**Status**: Draft

**Input**: User description: "사용자 프로필에서 언어 설정을 제거한다. 그리고 메뉴판 스캔 api 응답이 나갈 때 lang requestParameter를 전달받아 번역결과로 내려주도록 한다." (Jira KB-229)

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 스캔 결과를 요청한 언어로 받기 (Priority: P1)

앱 사용자가 메뉴판을 스캔할 때, 요청에 원하는 언어를 함께 지정하면 스캔 결과의 메뉴 이름이 그 언어로 번역되어 내려온다. 지금은 회원 프로필에 저장된 언어(미설정이면 한국어)로 번역되기 때문에, 앱에서 표시 언어를 바꿔도 스캔 결과 언어가 따라오지 않는 불일치가 있다. 이 기능 이후에는 다른 조회 기능들과 똑같이 "요청 시점에 클라이언트가 언어를 정하는" 방식으로 통일된다.

**Why this priority**: 이 기능의 핵심 가치. 언어 결정 방식 이원화(프로필 저장값 vs 요청 파라미터)를 해소해 사용자가 보는 언어와 스캔 결과 언어를 항상 일치시킨다.

**Independent Test**: 회원 프로필과 무관하게, 스캔 요청에 서로 다른 언어를 지정해 두 번 스캔했을 때 각 요청의 언어로 번역된 결과가 오는지 확인하면 단독 검증된다.

**Acceptance Scenarios**:

1. **Given** 등록된 음식과 매칭되는 메뉴판 이미지, **When** 언어를 영어로 지정해 스캔을 요청하면, **Then** 매칭된 메뉴 이름이 영어 번역으로 내려온다.
2. **Given** 같은 이미지, **When** 언어를 일본어로 지정해 스캔을 요청하면, **Then** 같은 메뉴가 일본어 번역으로 내려온다.
3. **Given** 스캔 요청, **When** 지원하지 않는 언어 코드를 지정하면, **Then** 요청은 실패하지 않고 영어 번역으로 내려온다(전사 언어 정책과 동일한 폴백).
4. **Given** 스캔 요청, **When** 언어를 지정하지 않으면, **Then** 필수 값 누락으로 요청이 거부된다(전사 언어 정책과 동일).

---

### User Story 2 - 프로필에서 언어 설정이 사라진다 (Priority: P2)

회원 프로필은 더 이상 앱 언어 설정을 저장하지 않는다. 온보딩에서 언어를 입력하지 않아도 가입이 완료되고, 프로필 수정에서 언어 항목이 사라지며, 내 프로필 조회에도 언어가 나오지 않는다. 언어는 이제 서버가 기억하는 값이 아니라 클라이언트(앱)가 매 요청에 지정하는 값이다.

**Why this priority**: 스캔 API 전환(US1)으로 프로필 언어의 마지막 사용처가 사라진 뒤에야 안전하게 제거할 수 있는 후속 정리. 남겨두면 아무도 읽지 않는 설정이 온보딩·프로필 화면과 데이터에 계속 남는다.

**Independent Test**: 언어 입력 없이 온보딩을 완료하고, 내 프로필 조회 응답에 언어 항목이 없음을 확인하면 단독 검증된다.

**Acceptance Scenarios**:

1. **Given** 신규 회원, **When** 언어 입력 없이 온보딩(닉네임·국가 등)을 완료하면, **Then** 가입이 정상 완료된다.
2. **Given** 기존 회원, **When** 내 프로필을 조회하면, **Then** 응답에 언어 설정 항목이 포함되지 않는다.
3. **Given** 구버전 앱이 언어 값을 여전히 보내는 경우, **When** 온보딩 또는 프로필 수정을 요청하면, **Then** 언어 값은 무시되고 나머지 항목은 정상 처리된다.

---

### Edge Cases

- 지원하지 않는 언어 코드로 스캔 요청 → 실패 없이 영어로 번역해 응답(전사 정책과 동일한 폴백). 대소문자·지역 변형(`EN`·`ko-KR`)도 정확 일치가 아니므로 영어로 폴백한다(관대한 정규화 없음).
- 언어 파라미터 누락 → 필수 값 누락으로 거부(전사 정책과 동일).
- 과거에 프로필 언어를 저장해 둔 기존 회원 → 저장된 값은 무시되고, 조회·수정 어디에도 노출되지 않으며 동작에 영향을 주지 않는다.
- 구버전 앱이 온보딩·프로필 수정에 언어 값을 계속 보내는 전환기 → 값은 무시되고 요청은 정상 처리된다(구버전 앱이 깨지지 않는다).
- 스캔 결과 중 등록 음식과 매칭되지 않은 메뉴 → 기존과 동일하게 인식된 원문 이름으로 내려간다(번역 대상 아님).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 메뉴판 스캔 요청은 응답 언어를 필수 요청 파라미터로 받아야 한다.
- **FR-002**: 스캔 결과의 매칭된 메뉴 이름은 요청받은 언어의 번역으로 제공되어야 하며, 회원 프로필의 어떤 저장값에도 의존하지 않아야 한다.
- **FR-003**: 지원하지 않는 언어 코드가 오면 요청을 실패시키지 않고 영어로 번역해 응답해야 한다(기존 전사 언어 정책과 동일). 매칭은 정확 일치로 하고 관대한 정규화를 하지 않는다.
- **FR-004**: 언어 파라미터가 누락되면 요청을 거부해야 한다(기존 전사 언어 정책과 동일).
- **FR-005**: 회원 프로필은 앱 언어 설정을 더 이상 보관·노출하지 않아야 한다 — 온보딩 입력, 프로필 수정 입력, 내 프로필 조회 응답 모두에서 제거된다.
- **FR-006**: 언어 입력 없이 온보딩과 프로필 수정이 완료되어야 한다.
- **FR-007**: 구버전 앱이 언어 값을 보내더라도 해당 값은 무시되고 요청은 정상 처리되어야 한다.
- **FR-008**: 기존 회원 데이터에 남아 있는 언어 저장값은 무시되어야 하며, 이로 인해 조회·수정·스캔 어떤 동작도 실패해서는 안 된다.

### Key Entities

- **회원 프로필**: 회원의 온보딩 정보(닉네임·국가·기피 성분 등). 이번 변경으로 "앱 언어 설정" 속성이 제거된다.
- **스캔 요청/결과**: 메뉴판 이미지 한 장에 대한 인식·번역·위험도 평가 묶음. 이번 변경으로 "응답 언어"가 요청 속성이 된다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자는 프로필 설정과 무관하게, 스캔 요청에 지정한 언어로 번역된 결과를 100% 받는다.
- **SC-002**: 지원하지 않는 언어 코드로 스캔해도 실패 없이 영어 결과를 받는다(오류율 0%).
- **SC-003**: 신규 사용자는 언어를 입력하지 않고 온보딩을 완료할 수 있다.
- **SC-004**: 언어를 다루는 모든 사용자 기능이 요청 시점 지정·필수 규칙을 따르며, 서버에 언어를 저장·기억하는 경로가 0개가 된다.

## Assumptions

- 기존 회원의 프로필에 저장된 언어 값은 **Flyway 마이그레이션으로 제거**한다(`JSON_REMOVE`). 무시만으로도 동작은 안전하지만, 폐기된 키를 데이터에 남기지 않는다.
- 구버전 앱과의 전환기 호환은 "보낸 언어 값을 무시"하는 수준으로 충분하다 — 온보딩·프로필 수정이 언어 값 존재 여부와 무관하게 성공한다.
- 언어 파라미터의 필수 여부(누락·공백 400)와 미지원 코드 영어 폴백은 기존 전사 언어 정책(KB-201 · ADR-0013)을 그대로 따른다. 클라이언트(앱)는 지원 목록 밖의 기기 언어를 영어로 매핑해 보낸다.
- 매칭되지 않은 메뉴 이름의 표기(인식 원문 유지)는 기존 동작을 유지하며 이번 범위가 아니다.
- 스캔 이력 등 이미 저장된 과거 스캔 결과의 언어는 소급 변경하지 않는다.
