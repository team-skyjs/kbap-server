## User Scenarios & Testing *(mandatory)*

### User Story 1 - 리뷰 좋아요 등록/취소 (Priority: P1)

회원이 음식 리뷰를 보다가 공감되는 리뷰에 좋아요를 누르고, 마음이 바뀌면 다시 눌러 취소한다. 한 회원은 한 리뷰에 좋아요를 최대 한 번만 남길 수 있다.

**Why this priority**: 좋아요 기능의 핵심 동작이다. 이 스토리만 구현해도 회원이 리뷰에 공감을 표현하는 가치가 전달된다.

**Independent Test**: 회원이 특정 리뷰에 좋아요 등록 → 취소 → 재등록을 수행하고, 각 단계 후 좋아요 상태가 기대대로인지 확인하면 단독으로 검증된다.

**Acceptance Scenarios**:

1. **Given** 좋아요를 누르지 않은 리뷰가 있을 때, **When** 회원이 좋아요를 등록하면, **Then** 성공하고 그 회원의 좋아요가 기록된다
2. **Given** 이미 좋아요를 누른 리뷰가 있을 때, **When** 같은 회원이 다시 좋아요를 등록하면, **Then** 성공 응답이되 좋아요는 여전히 1개다 (중복 생성 없음)
3. **Given** 좋아요를 누른 리뷰가 있을 때, **When** 회원이 좋아요를 취소하면, **Then** 성공하고 그 회원의 좋아요가 제거된다
4. **Given** 좋아요를 누르지 않은 리뷰가 있을 때, **When** 회원이 좋아요를 취소하면, **Then** 성공 응답이되 아무 변화가 없다
5. **Given** 좋아요를 취소한 리뷰가 있을 때, **When** 같은 회원이 다시 좋아요를 등록하면, **Then** 성공하고 좋아요가 다시 기록된다
6. **Given** 존재하지 않거나 삭제된 리뷰 id 로, **When** 회원이 좋아요를 등록하면, **Then** 리뷰 없음 실패 응답을 받는다

---

### User Story 2 - 리뷰 목록에서 좋아요 정보 확인 (Priority: P2)

회원이 음식 리뷰 목록이나 내가 쓴 리뷰 목록을 조회할 때, 각 리뷰의 좋아요 수와 "내가 좋아요를 눌렀는지"를 함께 본다.

**Why this priority**: 좋아요를 눌러도 화면에 수·상태가 보이지 않으면 기능이 완성되지 않는다. 단, 등록/취소(P1)가 먼저 있어야 의미가 있다.

**Independent Test**: 좋아요가 여럿 달린 리뷰를 포함한 목록을 조회해, 각 리뷰 항목에 좋아요 수와 조회 회원의 좋아요 여부가 정확히 표시되는지 확인하면 단독으로 검증된다.

**Acceptance Scenarios**:

1. **Given** 리뷰에 회원 3명이 좋아요를 누른 상태에서, **When** 음식 리뷰 목록을 조회하면, **Then** 그 리뷰의 좋아요 수가 3으로 표시된다
2. **Given** 조회 회원이 좋아요를 누른 리뷰와 누르지 않은 리뷰가 섞인 목록에서, **When** 목록을 조회하면, **Then** 각 리뷰의 "내 좋아요 여부"가 정확히 구분되어 표시된다
3. **Given** 내가 쓴 리뷰 목록을, **When** 조회하면, **Then** 각 리뷰에 좋아요 수와 내 좋아요 여부가 동일하게 포함된다
4. **Given** 좋아요 등록 직후, **When** 목록을 다시 조회하면, **Then** 늘어난 좋아요 수와 내 좋아요 여부(true)가 즉시 반영된다

---

### Edge Cases

- 같은 회원이 같은 리뷰에 좋아요 등록을 동시에 두 번 요청해도 좋아요는 최대 1개만 남는다
- 리뷰가 삭제되면 그 리뷰의 좋아요는 어떤 목록/집계에도 노출되지 않는다
- 회원이 탈퇴해도 그 회원이 남긴 좋아요는 유지되어 좋아요 수에 계속 반영된다 (탈퇴 회원의 리뷰가 유지되는 기존 정책과 일관)
- 좋아요가 하나도 없는 리뷰는 좋아요 수 0, 내 좋아요 여부 false 로 표시된다

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 회원은 존재하는(삭제되지 않은) 리뷰에 좋아요를 등록할 수 있어야 한다
- **FR-002**: 한 회원은 한 리뷰에 좋아요를 최대 1개만 가질 수 있어야 한다 — 동시 요청에서도 이 규칙이 깨지지 않아야 한다
- **FR-003**: 이미 좋아요한 리뷰에 다시 등록을 요청하면 상태 변화 없이 성공으로 처리해야 한다 (멱등)
- **FR-004**: 회원은 자신이 등록한 좋아요를 취소할 수 있어야 하며, 좋아요가 없는 상태에서의 취소도 성공으로 처리해야 한다 (멱등)
- **FR-005**: 취소한 리뷰에 다시 좋아요를 등록할 수 있어야 한다
- **FR-006**: 존재하지 않거나 삭제된 리뷰에 대한 좋아요 등록 요청은 리뷰 없음 실패로 응답해야 한다
- **FR-007**: 음식 리뷰 목록과 내 리뷰 목록의 각 리뷰 항목에 좋아요 수를 포함해야 한다
- **FR-008**: 음식 리뷰 목록과 내 리뷰 목록의 각 리뷰 항목에 조회 회원의 좋아요 여부를 포함해야 한다
- **FR-009**: 좋아요 등록/취소는 인증된 회원만 수행할 수 있어야 한다

### Key Entities

- **리뷰 좋아요**: 어떤 회원이 어떤 리뷰에 공감을 표시했는지 나타내는 회원-리뷰 관계. (리뷰, 회원) 조합당 최대 1건만 존재한다
- **리뷰**: 좋아요의 대상. 기존 리뷰 도메인 그대로이며, 목록/조회 시 좋아요 수와 조회 회원의 좋아요 여부가 덧붙는다

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 회원은 요청 1번으로 리뷰 좋아요 등록 또는 취소를 완료할 수 있다
- **SC-002**: 어떤 시점에도 (리뷰, 회원) 조합의 좋아요는 1개를 초과하지 않는다 — 동시 중복 요청 포함
- **SC-003**: 리뷰 목록 조회 1번만으로 각 리뷰의 좋아요 수와 내 좋아요 여부를 모두 확인할 수 있다 (추가 요청 0회)
- **SC-004**: 좋아요 등록/취소 직후의 목록 조회에 변경된 수·여부가 100% 반영된다

## Assumptions

- 등록/취소의 멱등 처리는 기존 음식 북마크 기능의 동작 방식을 따른다 (중복 등록·빈 취소 모두 성공)
- 자신이 쓴 리뷰에도 좋아요를 누를 수 있다 (별도 제한 없음)
- 좋아요 알림, 좋아요순 정렬, 좋아요 누른 회원 목록 조회는 이번 범위 밖이다
- 리뷰 목록 조회는 기존과 같이 인증 회원 전용이므로 "내 좋아요 여부"는 항상 계산 가능하다
- 음식 상세 화면의 리뷰 요약(별점 통계)은 이번 변경의 대상이 아니다 — 리뷰 항목 단위 응답만 확장한다
- 회원 탈퇴는 회원 상태 마킹만 하고 콘텐츠(리뷰)를 지우지 않는 기존 정책을 따르므로, 탈퇴 회원의 좋아요도 유지된다
