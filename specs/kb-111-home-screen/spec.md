# Feature Specification: 홈 화면 조회 — 기피 성분·인기 음식 5개·최근 스캔 10개

**Feature Branch**: `kb-111-home-screen`

**Created**: 2026-07-12

**Status**: Draft

**Input**: User description: "kb-111" (Jira KB-111 — [BE] 홈 화면 조회 API — 기피 성분·인기 음식 5개·최근 스캔 10개)

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 회원의 홈 화면 통합 조회 (Priority: P1)

로그인한 회원이 앱 홈 화면에 진입하면, 한 번의 요청으로 세 가지 정보를 함께 받는다 — 내가 프로필에 설정한 기피 성분 목록, 인기 음식 추천 5개, 내가 최근 스캔한 메뉴 10개. 모든 텍스트는 프로필에 설정한 앱 언어로 제공되어, 회원은 추가 요청 없이 개인화된 홈을 바로 본다.

**Why this priority**: 홈은 앱의 첫 화면이자 핵심 진입점이다. 세 섹션이 묶여 내려오지 않으면 클라이언트가 여러 번 호출해야 하고, 개인화(기피 성분·내 언어·내 스캔 이력)가 없으면 서비스의 핵심 가치가 첫 화면에서 전달되지 않는다.

**Independent Test**: 온보딩을 완료한 회원으로 홈 조회를 호출해 세 섹션이 하나의 응답에 모두 포함되고 프로필 언어로 번역되는지 통합 테스트로 검증할 수 있다. 이 스토리만으로 "회원이 개인화된 홈을 본다"는 가치가 완결된다.

**Acceptance Scenarios**:

1. **Given** 기피 성분을 설정하고 스캔 이력이 있는 회원이, **When** 홈을 조회하면, **Then** 기피 성분 목록·인기 음식 5개·최근 스캔 메뉴(최대 10개)가 하나의 응답으로 내려온다.
2. **Given** 프로필 언어를 일본어로 설정한 회원이, **When** 홈을 조회하면, **Then** 모든 섹션의 텍스트가 일본어 기준으로 응답된다.
3. **Given** 기피 성분을 하나도 설정하지 않은 회원이, **When** 홈을 조회하면, **Then** 기피 성분은 빈 목록으로, 나머지 섹션은 정상적으로 내려온다.
4. **Given** 스캔 이력이 없는 회원이, **When** 홈을 조회하면, **Then** 최근 스캔은 빈 목록으로, 나머지 섹션은 정상적으로 내려온다.

---

### User Story 2 - 비회원의 홈 화면 조회 (Priority: P2)

로그인하지 않은 사용자도 홈 화면에 진입할 수 있다. 비회원에게는 개인화 정보(기피 성분·최근 스캔) 없이 인기 음식 추천 5개만 영어 기준으로 내려준다. 개인화 섹션은 값이 없음을 명확히 표시해 클라이언트가 로그인 유도 등으로 분기할 수 있다.

**Why this priority**: 가입 전 사용자가 앱의 가치를 미리 보는 진입 경험이다. 회원 플로우(US1)가 있어야 의미가 완성되지만, 비회원 차단 시 첫 사용자 이탈로 이어지므로 같은 사이클에서 제공한다.

**Independent Test**: 인증 없이 홈 조회를 호출해 인기 음식 5개만 영어로 내려오고 개인화 섹션이 비어 있음(null)으로 표시되는지 독립적으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 인증 토큰이 없는 요청이, **When** 홈을 조회하면, **Then** 기피 성분과 최근 스캔은 null 로, 인기 음식 5개는 영어 기준으로 내려온다.
2. **Given** 위조되었거나 만료된 토큰을 가진 요청이, **When** 홈을 조회하면, **Then** 비회원으로 처리되지 않고 401 로 거절된다.

---

### User Story 3 - 스캔 이력 기록과 최근 스캔 규칙 (Priority: P1)

회원이 메뉴판을 스캔하면 그 스캔 내역이 회원별로 기록된다. 홈의 "최근 스캔"은 이 기록에서 스캔 시각 내림차순으로 채우되, 같은 메뉴를 여러 번 스캔했으면 가장 최근 것 하나만 남기고 중복 없이 최대 10개를 보여준다. 스캔 항목은 음식 정보가 모두 채워진 완성 데이터에 매칭된 것만 포함한다.

**Why this priority**: 현재 스캔 이력을 어디에도 기록하지 않아 최근 스캔 섹션의 데이터 원천이 없다 — US1 이 성립하기 위한 선행 작업이므로 P1 이다.

**Independent Test**: 회원으로 스캔을 여러 번(같은 메뉴 반복 포함) 수행한 뒤 홈을 조회해, 기록·정렬·중복 제거·개수 제한이 지켜지는지 독립적으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 회원이 메뉴를 스캔하면, **When** 스캔이 처리될 때, **Then** 회원별 스캔 내역(무엇을 언제 스캔했는지)이 저장된다.
2. **Given** 같은 메뉴를 3번 스캔한 회원이, **When** 홈을 조회하면, **Then** 그 메뉴는 가장 최근 스캔 1건으로만 나타난다.
3. **Given** 서로 다른 메뉴 12개를 스캔한 회원이, **When** 홈을 조회하면, **Then** 스캔 시각 내림차순 상위 10개만 내려온다.
4. **Given** 음식 정보가 완성되지 않은 항목을 스캔한 이력이 있는 회원이, **When** 홈을 조회하면, **Then** 완성 데이터에 매칭된 항목만 최근 스캔에 포함된다.

---

### User Story 4 - 기피 성분의 실제 프로필 반영 (Priority: P2)

회원이 온보딩·프로필에서 설정한 기피 성분이 홈 화면과 기존 음식 기능(메뉴 위험도 판정 등)에 실제로 반영된다. 지금은 고정된 5개 성분을 흉내내는 임시 구성이라 어떤 회원이든 같은 기피 성분으로 판정되는데, 이를 회원 프로필에 저장된 실제 값 기반으로 교체한다.

**Why this priority**: 홈의 기피 성분 섹션이 실제 값을 보여줘야 하고, 같은 원천을 쓰는 기존 음식 기능도 함께 정확해진다. US1 의 데이터 정합을 완성하는 작업이다.

**Independent Test**: 서로 다른 기피 성분을 설정한 두 회원으로 홈 조회와 기존 음식 조회를 호출해, 각자 자신의 프로필 값이 반영되고 기존 기능이 회귀 없이 동작하는지 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 기피 성분 A·B 를 설정한 회원이, **When** 홈을 조회하면, **Then** 기피 성분 섹션에 A·B 가 그대로 내려온다.
2. **Given** 기피 성분을 설정한 회원이, **When** 기존 음식 기능(위험도 판정이 포함된 조회)을 사용하면, **Then** 고정 5개가 아니라 본인 프로필의 기피 성분 기준으로 판정된다.
3. **Given** 임시 구성을 실제 구현으로 교체한 뒤, **When** 기존 음식 기능의 전체 테스트를 수행하면, **Then** 회귀 없이 통과한다.

---

### Edge Cases

- 회원이지만 기피 성분 미설정 → 빈 목록 (비회원과는 `authenticated` 플래그로 구분된다).
- 회원이지만 스캔 이력 없음 → 빈 목록 (비회원과는 `authenticated` 플래그로 구분된다).
- 완성 데이터인 음식이 5개 미만 → 인기 음식은 있는 만큼만 내려온다.
- 중복 제거 후 최근 스캔이 10개 미만 → 있는 만큼만 내려온다.
- 요청 언어 번역이 없는 항목 → 기존 음식 조회와 동일한 언어 폴백 규칙을 따른다.
- 프로필 언어가 아직 없는(온보딩 미완료) 회원의 홈 조회 → 영어 기준으로 응답한다.
- 위조·만료 토큰 → 비회원 폴백 없이 401 (인증 헤더가 아예 없을 때만 비회원으로 처리한다).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 홈 조회는 한 번의 요청으로 기피 성분·인기 음식 5개·최근 스캔 10개 세 섹션을 하나의 응답으로 반환해야 한다.
- **FR-002**: 회원 요청은 프로필에 설정한 앱 언어로, 비회원 요청은 영어 기준으로 모든 섹션을 응답해야 한다.
- **FR-003**: 홈 조회는 인증 없이 접근 가능해야 한다. 비회원에게는 개인화 섹션(기피 성분·최근 스캔)을 빈 배열로, 인기 음식 5개만 반환한다. 인증 헤더가 있으나 무효·만료인 요청은 401 로 거절한다.
- **FR-011**: 응답은 요청자가 회원인지 여부(`authenticated`)를 boolean 으로 명시해야 한다 — 클라이언트가 개인화 영역을 가입 유도(블러)로 처리할 수 있어야 한다. 배열 필드는 null 을 반환하지 않는다(값 없으면 빈 배열).
- **FR-004**: 회원의 기피 성분 섹션은 프로필에 저장된 실제 기피 성분 목록을 반환해야 하며, 설정한 성분이 없으면 빈 목록을 반환한다.
- **FR-005**: 기존 음식 기능이 쓰는 기피 성분 원천(현재 고정 5개를 반환하는 임시 구성)을 회원 프로필 기반으로 교체해야 하며, 이를 쓰던 기존 기능은 회귀 없이 동작해야 한다.
- **FR-006**: 인기 음식은 인기도 지표가 도입되기 전까지 음식 카탈로그에서 무작위 5개를 반환하되, 응답 형태는 기존 메뉴 목록·검색의 항목 형태를 재사용하고 추후 인기도 정렬로 교체해도 응답 계약이 변하지 않아야 한다.
- **FR-007**: 회원의 메뉴 스캔 시 회원별 스캔 내역(대상 메뉴·스캔 시각)이 기록되어야 한다.
- **FR-008**: 최근 스캔 섹션은 스캔 시각 내림차순으로 정렬하고, 같은 메뉴의 반복 스캔은 가장 최근 1건만 남겨 중복 없이 최대 10개를 반환해야 한다.
- **FR-009**: 최근 스캔 항목은 음식 카탈로그에서 필요한 정보가 모두 채워진 완성 데이터에 매칭된 것만 포함해야 한다.
- **FR-010**: 홈 응답은 공통 응답 규약(성공/실패 봉투)을 따라야 한다.

### Key Entities

- **홈 화면 응답**: 세 섹션의 묶음 — 기피 성분 목록(회원 전용, null 허용), 인기 음식 목록(항상), 최근 스캔 목록(회원 전용, null 허용).
- **스캔 이력**: 어떤 회원이 어떤 메뉴를 언제 스캔했는지의 기록. 최근 스캔 섹션의 데이터 원천이며 이번에 신설된다.
- **인기 음식 항목**: 기존 메뉴 목록·검색이 쓰는 메뉴 요약 형태를 재사용 — 이름·설명·위험도 등 표시 정보.
- **기피 성분 목록**: 회원 프로필에 저장된 회피 성분 코드 집합 — 홈 표시와 음식 위험도 판정이 같은 원천을 쓴다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자는 홈 진입 시 추가 요청 없이 단일 요청으로 세 섹션을 모두 받는다.
- **SC-002**: 회원의 홈 응답 텍스트는 100% 프로필 설정 언어 기준으로, 비회원은 100% 영어 기준으로 제공된다.
- **SC-003**: 비회원도 홈에서 인기 음식 5개를 확인할 수 있다 (개인화 섹션은 없음이 명확히 구분된다).
- **SC-004**: 같은 메뉴를 아무리 반복 스캔해도 최근 스캔 목록의 중복은 0건이다.
- **SC-005**: 서로 다른 기피 성분을 설정한 회원들은 홈과 음식 위험도 판정에서 각자 자신의 프로필 값으로 판정받는다 (고정값 판정 0건).
- **SC-006**: 인기 음식이 무작위에서 실제 인기도 정렬로 바뀌어도 클라이언트 수정 없이 동작한다 (응답 계약 불변).

## Assumptions

- 인기 음식의 "무작위 5개"는 인기도 지표(조회수·스캔수)가 어디에도 쌓이지 않는 현재 상태의 임시 규칙이다 — 지표 도입 시 정렬만 교체하고 응답 계약은 유지한다.
- "완성 데이터"의 구체 판정 기준(어떤 필드가 채워져야 완성인가)은 음식 카탈로그의 기존 데이터 상태를 기준으로 계획 단계에서 확정한다.
- 스캔 이력 기록은 기존 메뉴 스캔 기능에 덧붙는 부수 동작이며, 스캔 기능의 기존 요청·응답 계약은 변하지 않는다.
- 개인화 섹션은 비회원·회원 모두 빈 배열로 내려주고, 회원 여부는 `authenticated` 플래그로 구분한다(null 분기 없는 계약).
- 프로필 언어가 없는(온보딩 미완료) 회원은 영어 기준으로 응답한다 — 클라이언트는 통상 온보딩 분기(KB-104) 후 홈에 진입하므로 드문 경로다.
- 번역이 없는 언어 폴백은 기존 음식 조회의 폴백 규칙을 그대로 따른다.
- 홈 조회 자체는 스캔 이력·프로필을 변경하지 않는 순수 조회다.
