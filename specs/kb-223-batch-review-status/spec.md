# Feature Specification: 배치 완성 콘텐츠를 검수 대기(PENDING_REVIEW)로 저장

**Feature Branch**: `kb-223-batch-review-status`

**Created**: 2026-07-23

**Status**: Draft

**Input**: User description: "kb-223 배치의 최종 상태가 관리자 검수가능한 상태로 저장되도록 할거임" (Jira KB-223 중 배치 측 범위만)

## Scope

이 브랜치는 KB-223 중 **배치 측 상태 전이만** 다룬다: 배치가 콘텐츠 4작업(음식명 번역·설명 생성·사진 생성·기피성분 조사)을 모두 채우면 음식을 노출 가능(READY)이 아니라 **검수 대기(PENDING_REVIEW)** 로 저장한다.

**범위 밖 (KB-223 후속 작업)**: 관리자 승인(PENDING_REVIEW→READY)·반려(PENDING_REVIEW→INCOMPLETE, 필드 비움)·반려 이력 기록·관리자 API. 기피성분 미조사/0건 구분(null 센티널)은 KB-209 에서 이미 구현되어 이 범위에 없다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 배치 완성 콘텐츠는 검수 대기로 저장된다 (Priority: P1)

배치가 음식 콘텐츠 4작업을 모두 채우면, 그 음식은 곧바로 사용자에게 노출되는 것이 아니라 검수 대기(PENDING_REVIEW) 상태로 저장된다. 검수 대기 음식은 관리자가 승인하기 전까지 사용자에게 노출되지 않는다.

**Why this priority**: 검토되지 않은 LLM·이미지 생성 결과(특히 안전과 직결된 기피성분)가 사용자에게 바로 노출되는 것을 막는 이 기능의 핵심이자 유일한 스토리다.

**Independent Test**: 4작업이 모두 채워진 음식을 배치가 처리한 뒤, 상태가 검수 대기로 저장되고 사용자 대상 조회에 나타나지 않음을 확인하면 단독 검증 가능.

**Acceptance Scenarios**:

1. **Given** 4작업 중 일부가 비어 있는 미완성(INCOMPLETE) 음식, **When** 배치가 남은 작업을 모두 채우면, **Then** 상태가 자동으로 검수 대기(PENDING_REVIEW)로 전이된다(READY 로 직접 전이되지 않는다).
2. **Given** 검수 대기 상태의 음식, **When** 사용자가 음식 목록·검색·상세를 조회하면, **Then** 해당 음식은 노출되지 않는다.
3. **Given** 4작업 중 일부가 여전히 비어 있는 음식, **When** 배치 처리가 끝나면, **Then** 상태는 미완성으로 유지된다.
4. **Given** 이미 노출 가능(READY)인 기존 음식, **When** 이 기능이 배포되면, **Then** 해당 음식은 READY 를 유지하고 계속 노출된다.

---

### Edge Cases

- 검수 대기 상태의 음식이 다음 배치 대상에 다시 잡히면? → 4작업이 이미 완성이므로 배치 대상이 아니며 상태도 변하지 않는다.
- 관리자 승인 기능(후속)이 배포되기 전까지 신규 완성 음식은? → 검수 대기에 머물러 노출되지 않는다(의도된 동작 — 노출은 승인 기능 배포 후).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 음식 콘텐츠 상태에 검수 대기(PENDING_REVIEW)가 추가되어 미완성(INCOMPLETE) / 검수 대기(PENDING_REVIEW) / 노출 가능(READY)의 3단계여야 한다.
- **FR-002**: 배치가 콘텐츠 4작업을 모두 채우면 상태는 자동으로 검수 대기로 전이되어야 하며, 배치가 노출 가능 상태로 직접 전이시켜서는 안 된다.
- **FR-003**: 사용자 대상 조회(목록·검색·상세·홈 등)는 노출 가능 상태의 음식만 반환해야 한다(검수 대기·미완성 비노출).
- **FR-004**: 기능 도입 전 이미 노출 가능이던 음식은 상태 변경 없이 계속 노출되어야 한다.

### Key Entities

- **음식 콘텐츠 상태**: 음식별 콘텐츠 수명주기 상태. 이번 범위에서는 미완성→검수 대기(배치 자동) 전이만 존재하며, 검수 대기→노출 가능 전이는 후속 관리자 승인 기능이 담당한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 이 기능 배포 이후 배치가 완성한 콘텐츠가 관리자 승인 없이 사용자에게 노출되는 사례가 0건이다.
- **SC-002**: 검수 대기 상태의 음식이 사용자 대상 조회에 나타나는 사례가 0건이다.
- **SC-003**: 기능 배포 전 노출 중이던 음식은 100% 그대로 노출을 유지한다.

## Assumptions

- 기능 도입 전 이미 노출 가능(READY)이던 음식은 재검수 없이 유지한다(소급 검수는 범위 밖).
- 관리자 승인 기능이 배포되기 전까지 신규 완성 음식이 노출되지 않는 공백 기간을 감수한다.
- 기피성분 미조사(null)/조사 완료 0건(빈 목록) 구분과 완성 판정은 KB-209 에서 이미 구현된 것을 그대로 사용한다.
