# Feature Specification: 관리자 음식 목록 음식명 검색

**Feature Branch**: `kb-276-admin-food-search`

**Created**: 2026-08-03

**Status**: Draft

**Input**: User description: "KB-276 — [BE] 관리자 음식 목록 음식명 검색 추가 (워크트리로 진행)"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 음식명으로 목록 검색 (Priority: P1)

관리자는 음식 목록 화면에서 검색어를 입력해 음식명이 부분 일치하는 음식만 목록으로 본다. 현재는 전체 목록을 페이지 넘겨 가며 눈으로 찾아야 하지만, 검색어 한 번으로 원하는 음식에 도달한다.

**Why this priority**: 이슈의 핵심 가치. 운영자가 잘못된 번역·기피성분을 수정하러 올 때는 대부분 특정 음식명을 알고 오므로, 검색이 없으면 매번 탐색 비용이 발생한다.

**Independent Test**: 목록 화면에서 검색어를 입력해 조회했을 때 음식명에 검색어를 포함하는 음식만 표시되는지, 검색어 없이 조회하면 기존 전체 목록이 그대로 나오는지로 단독 검증 가능.

**Acceptance Scenarios**:

1. **Given** 음식 "김치찌개"·"김치볶음밥"·"된장찌개"가 등록된 상태, **When** 관리자가 "김치"로 검색하면, **Then** "김치찌개"·"김치볶음밥"만 목록에 표시된다.
2. **Given** 음식 목록 화면, **When** 검색어 없이 조회하면, **Then** 기존과 동일하게 전체 음식이 최신 등록 순으로 표시된다.
3. **Given** 검색 결과가 페이지 크기를 초과하는 상태, **When** 검색하면, **Then** 검색 결과에 대해 페이지네이션이 동작한다.

---

### User Story 2 - 검색 상태 유지 (Priority: P2)

관리자는 검색 결과 안에서 페이지를 이동하거나 상세·수정 화면을 오가도 검색 상태가 유지된다. 특히 음식 수정을 마치고 돌아왔을 때 같은 검색 결과 목록으로 복귀해 다음 항목을 이어서 수정할 수 있다.

**Why this priority**: 검색의 주 용도가 "찾아서 수정"이므로, 수정 후 전체 목록으로 튕기면 검색을 반복해야 해 기능 가치가 반감된다.

**Independent Test**: 검색 상태에서 페이지 이동·상세·수정 링크를 따라간 뒤 목록으로 복귀했을 때 검색어가 유지되는지로 단독 검증 가능.

**Acceptance Scenarios**:

1. **Given** "김치" 검색 결과 목록, **When** 다음 페이지로 이동하면, **Then** "김치" 검색 결과의 다음 페이지가 표시된다.
2. **Given** "김치" 검색 결과 목록, **When** 특정 음식의 수정 화면으로 들어가 수정을 완료하면, **Then** "김치" 검색 결과 목록으로 돌아온다.
3. **Given** "김치" 검색 결과 목록, **When** 상세·수정 링크를 확인하면, **Then** 각 링크가 검색 상태를 유지한 채 이동하도록 구성돼 있다.

---

### User Story 3 - 빈 결과 안내와 검색 초기화 (Priority: P3)

관리자는 검색 결과가 없을 때 "결과 없음" 안내를 보고, 한 번의 동작으로 검색을 초기화해 전체 목록으로 돌아간다.

**Why this priority**: 오타·미등록 음식 검색 시 빈 화면만 나오면 오류로 오인할 수 있다. 핵심 흐름은 아니지만 완성도에 필요하다.

**Independent Test**: 존재하지 않는 음식명으로 검색해 빈 목록 안내가 표시되는지, 초기화 동선으로 전체 목록에 복귀하는지로 단독 검증 가능.

**Acceptance Scenarios**:

1. **Given** 음식 목록 화면, **When** 등록된 어떤 음식명과도 일치하지 않는 검색어로 검색하면, **Then** 빈 목록 안내 문구가 표시된다.
2. **Given** 검색 결과 화면(결과 유무 무관), **When** 검색어 초기화 동선을 사용하면, **Then** 전체 음식 목록으로 돌아간다.

---

### Edge Cases

- 검색어가 공백뿐이거나 빈 문자열이면 전체 목록 조회와 동일하게 동작한다.
- 검색 결과 범위를 벗어난 페이지를 요청하면 빈 목록 안내가 표시된다(오류 아님).
- 삭제된 음식은 검색 결과에 나타나지 않는다(기존 목록과 동일한 노출 규칙).
- 검색어 앞뒤 공백은 무시하고 일치 여부를 판단한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 관리자 음식 목록은 검색어를 받아 음식명(한글명) 부분 일치로 목록을 필터링할 수 있어야 한다.
- **FR-002**: 검색어가 없으면 기존과 동일한 전체 목록 조회로 동작해야 한다.
- **FR-003**: 검색 상태에서도 기존 페이지네이션(페이지 크기·정렬 순서)이 동일하게 동작해야 한다.
- **FR-004**: 검색 상태의 페이지 이동·상세·수정 링크는 검색어를 유지해야 한다.
- **FR-005**: 음식 수정 완료 후 목록 복귀 시 수정 전의 검색 상태로 돌아가야 한다.
- **FR-006**: 검색 결과가 없으면 빈 목록 안내를 표시하고, 검색어를 초기화해 전체 목록으로 돌아가는 동선을 제공해야 한다.
- **FR-007**: 검색어 유무에 따른 목록 조회 동작을 검증하는 자동화 테스트가 있어야 한다.

### Key Entities

- **음식(Food)**: 검색 대상. 음식명(한글명)이 검색 일치 기준 속성이며, 삭제된 음식은 노출 대상에서 제외된다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 관리자가 음식명을 아는 상태에서 해당 음식의 수정 화면까지 도달하는 데 페이지 넘김 없이 검색 1회 + 클릭 1회면 충분하다.
- **SC-002**: 검색 → 수정 → 목록 복귀 흐름에서 검색어를 다시 입력하는 일이 발생하지 않는다.
- **SC-003**: 검색어 없는 기존 목록 조회의 동작(정렬·페이지 크기·표시 항목)이 변경 전과 동일하다.
- **SC-004**: 존재하지 않는 음식명 검색 시 오류 화면이 아닌 빈 결과 안내가 표시된다.

## Assumptions

- 검색 기준은 음식명(한글명) 단일 속성이다 — 영문명·성분·카테고리 검색은 범위 밖.
- 부분 일치는 위치 무관 포함(contains) 방식이며, 별도 유사어·초성 검색은 범위 밖.
- 페이지 크기(200건)·정렬(최신 등록 순) 등 기존 목록 정책은 변경하지 않는다.
- 관리자 화면 전용 기능으로, 일반 사용자용 음식 검색 API 에는 영향이 없다.
- 이 기능은 기존 관리자 음식 목록 화면에 검색 입력을 추가하는 것으로, 별도 신규 화면은 만들지 않는다.
