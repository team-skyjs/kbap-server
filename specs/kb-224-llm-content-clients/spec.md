# Feature Specification: 배치 콘텐츠 4개 작업용 LLM 클라이언트 구현

**Feature Branch**: `kb-224-llm-content-clients`

**Created**: 2026-07-22

**Status**: Draft

**Input**: User description: "kb-224 — [BE] infra:llm 배치 콘텐츠 4개 작업용 LLM client 구현 (Spring AI)"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 기피성분 조사 콘텐츠 생성 (Priority: P1)

운영자가 신규 음식을 일괄 적재하면, 배치가 각 음식의 한국어명과 후보 기피성분 코드 목록을 바탕으로 외부 지능형 모델에 "이 음식에 어떤 기피성분이 얼마나 포함되는가"를 조사시켜, 사용자 안전 판단(알레르기·종교·식이 제한)의 근거 데이터를 자동 생성한다. 안전과 직결되므로 단일 모델의 판단이 아니라 복수 모델의 의견을 종합해 최종 판단한다.

**Why this priority**: 기피성분 회피는 서비스의 핵심 가치이자 사용자 안전과 직결된다. 이 데이터 없이는 음식이 사용자에게 노출될 수 없다.

**Independent Test**: 한국어 음식명과 후보 코드 집합을 입력해 호출하면, 후보 코드 범위 안의 코드와 0~100 포함 확률 목록이 반환되는 것으로 독립 검증 가능.

**Acceptance Scenarios**:

1. **Given** 음식 한국어명과 후보 기피성분 코드 집합, **When** 기피성분 조사를 호출하면, **Then** 복수 모델의 응답을 종합한 판단 결과(코드 + 포함 확률 0~100)가 반환된다
2. **Given** 모델 응답에 후보 집합에 없는 코드가 섞여 있음, **When** 결과를 검증하면, **Then** 계약 위반으로 실패가 전파되어 배치가 해당 건을 실패 처리할 수 있다

---

### User Story 2 - 음식명 다국어 번역 생성 (Priority: P2)

배치가 신규 음식의 한국어명을 9개 대상 언어(한국어 제외 지원 언어 전체)로 번역해, 외국인 사용자가 자기 언어로 음식명을 볼 수 있는 사전 번역 데이터를 만든다.

**Why this priority**: 다국어 노출은 서비스의 기본 기능이지만, 안전 데이터(P1)보다는 후순위다.

**Independent Test**: 한국어 음식명 하나로 호출하면 9개 대상 언어 전수에 대해 비어 있지 않은 번역 맵이 반환되는 것으로 독립 검증 가능.

**Acceptance Scenarios**:

1. **Given** 음식 한국어명, **When** 번역 생성을 호출하면, **Then** 9개 대상 언어 전수에 대한 번역 맵이 반환된다
2. **Given** 모델 응답에 일부 언어가 누락되거나 빈 값이 있음, **When** 결과를 검증하면, **Then** 계약 위반으로 실패가 전파된다

---

### User Story 3 - 음식 설명 콘텐츠 생성 (Priority: P2)

배치가 신규 음식의 한국어 설명(255자 이하), 설명의 9개 언어 번역, 맵기 수치(0~10)를 생성해, 사용자가 음식 상세에서 읽을 소개 콘텐츠를 자동으로 채운다.

**Why this priority**: 상세 화면 품질을 좌우하는 콘텐츠지만 번역과 동급의 노출 콘텐츠 계열이다.

**Independent Test**: 한국어 음식명 하나로 호출하면 길이·플레이스홀더·맵기 범위 제약을 만족하는 설명 콘텐츠가 반환되는 것으로 독립 검증 가능.

**Acceptance Scenarios**:

1. **Given** 음식 한국어명, **When** 설명 생성을 호출하면, **Then** 255자 이하·플레이스홀더가 아닌 설명 + 9개 언어 번역 + 0~10 맵기가 반환된다
2. **Given** 모델 응답의 설명이 255자를 초과하거나 맵기가 범위 밖임, **When** 결과를 검증하면, **Then** 계약 위반으로 실패가 전파된다

---

### User Story 4 - 음식 사진 생성 (Priority: P3)

배치가 신규 음식의 대표 사진을 생성해 지정된 저장 위치(storage key)에 저장하고 그 키를 반환한다. 같은 키로 다시 호출해도 덮어쓰기로 동작해 재실행이 안전하다.

**Why this priority**: 시각 콘텐츠는 사용자 경험을 높이지만, 없는 상태로도 서비스 노출이 가능하다.

**Independent Test**: 한국어 음식명과 storage key 로 호출하면 그 위치에 이미지가 저장되고 절대 URL 이 아닌 키가 반환되는 것으로 독립 검증 가능.

**Acceptance Scenarios**:

1. **Given** 음식 한국어명과 storage key, **When** 사진 생성을 호출하면, **Then** 해당 키 위치에 이미지가 저장되고 그 키(절대 URL 아님)가 반환된다
2. **Given** 이미 이미지가 저장된 키, **When** 같은 키로 재호출하면, **Then** 덮어쓰기로 완료되어 재실행(멱등)이 보장된다

---

### Edge Cases

- 모델 응답이 계약 형식(언어 전수·길이·범위·코드 소속)을 위반하면? → 예외를 전파해 배치가 그 음식 건만 실패 처리하고, 다른 건 진행은 영향받지 않는다.
- 기피성분 조사에서 복수 모델 중 일부가 실패하면? → 응답한 모델들의 의견으로 종합 판단하되, 종합이 불가능한 수준(전부 실패 등)이면 실패를 전파한다.
- 후보 기피성분 코드 집합이 비어 있으면? → 조사 대상이 없으므로 임의 코드를 생성하지 않고, 빈 결과 반환 등 계약을 지키는 동작을 한다.
- 사진 저장이 실패하면? → 키를 반환하지 않고 실패를 전파한다(저장 완료가 반환의 전제).
- 모델 키/활성 설정이 없는 환경에서 앱이 부팅되면? → 부팅은 실패하지 않는다(기존 조건부 구성 관례 유지).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 음식 한국어명으로 9개 대상 언어 전수에 대한 비어 있지 않은 번역 맵을 생성해야 한다
- **FR-002**: 시스템은 음식 한국어명으로 255자 이하·플레이스홀더("설명 준비 중")가 아닌 설명, 설명의 9개 언어 번역, 0~10 범위의 맵기를 생성해야 한다
- **FR-003**: 시스템은 음식 한국어명과 후보 기피성분 코드 집합으로, 후보 집합에 속한 코드와 0~100 포함 확률의 조사 결과를 생성해야 한다
- **FR-004**: 기피성분 조사는 복수(3개) 모델의 응답을 종합해 최종 판단해야 한다 — 단일 모델 판단 금지(안전 직결)
- **FR-005**: 시스템은 음식 한국어명과 storage key 로 사진을 생성·해당 키 위치에 저장 완료한 뒤 그 키를 반환해야 하며, 절대 URL 을 반환해서는 안 된다
- **FR-006**: 사진 생성은 같은 storage key 재호출 시 덮어쓰기로 동작해 멱등해야 한다
- **FR-007**: 모델 응답이 계약(FR-001~003 의 형식·범위 제약)을 위반하면 시스템은 예외를 전파해 배치가 해당 건을 실패 처리할 수 있어야 한다
- **FR-008**: 4개 작업 구현체는 기존 배치 콘텐츠 파이프라인이 선언한 호출 계약(KB-182 의 4개 seam)을 그대로 충족해 파이프라인 수정 없이 연결되어야 한다

### Key Entities

- **번역 맵(TargetLanguageTexts)**: 9개 대상 언어(한국어 제외) 전수 → 비어 있지 않은 텍스트. 언어 누락·빈 값 불허.
- **설명 콘텐츠(FoodDescriptionContent)**: 설명(≤255자, 플레이스홀더 금지) + 설명 번역 맵 + 맵기(0~10).
- **기피성분 조사 결과(FoodAvoidanceAssessment)**: 기피성분 코드(후보 집합 소속) + 포함 확률(0~100)의 목록.
- **사진 storage key**: 저장 위치 식별 키. 절대 URL 이 아니며, 저장 완료 후에만 반환된다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 배치 파이프라인이 신규 음식 1건에 대해 번역·설명·사진·기피성분 4종 콘텐츠를 사람 개입 없이 생성할 수 있다
- **SC-002**: 계약을 위반한 모델 응답은 100% 해당 음식 건의 실패로 격리되고, 잘못된 데이터가 저장 계층에 도달하지 않는다
- **SC-003**: 기피성분 조사 결과는 항상 복수 모델 의견 종합의 산출물이다 — 단일 모델 판단으로 저장되는 건이 0건
- **SC-004**: 같은 음식 건의 사진 생성을 재실행해도 저장 위치가 달라지거나 중복 자원이 생기지 않는다
- **SC-005**: 전체 빌드(테스트 포함)가 성공 상태를 유지한다

## Assumptions

- KB-182 에서 선언된 4개 호출 계약(seam)과 계약 DTO 불변식은 확정 상태이며 이 작업에서 변경하지 않는다
- 기피성분 조사의 복수 모델 종합은 기존 3개 모델 fan-out 기반을 재사용한다 (Jira DoD 명시)
- 모델 키·활성 플래그가 없는 환경에서 구현체 빈이 조건부로 미생성되어 부팅이 안전한 기존 관례를 따른다
- 사진 저장 위치(오브젝트 스토리지)와 storage key 관례는 기존 시스템(KB-171 키 prefix, KB-154 CDN 키)의 것을 재사용한다
- 재시도 정책·호출 비용 최적화는 배치 파이프라인(호출자) 소관이며 이 작업 범위 밖이다
