# Feature Specification: 회피·주의 성분 카탈로그 DB 영속화 + 재료 매핑

**Feature Branch**: `006-ingredient-avoidance-mapping`

**Created**: 2026-06-30 (**Revised**: 2026-07-01 — 범위 변경: 성분 카탈로그를 DB(JPA 엔티티)로 영속화. **004 enum 은 제거하지 않고 유지**하며 시드 원천·도메인 참조로 공존, 최종 제거 여부는 후속 판단)

**Status**: Draft

**Input**: User description: "JPA 엔티티 만들어서 enum이 아니라 db에 위험 재료들의 성분을 정리하고 3개 카테고리 등으로 분류하는 테이블을 만든다. 성분마다 9개국 언어 번역본이 저장되며, 성분 데이터는 자주 업데이트되지 않는 정적 데이터라 한 테이블에 국가별 번역 결과를 필드로 저장한다. 그리고 음식의 재료와 성분을 매핑해 나중에 음식 조회 시 판정 가능하게 한다."

> **맥락 & 범위 변경**: 회피·주의 성분 카탈로그(81종)는 [004](../004-avoidance-catalog/)에서 **컴파일 enum**(`AvoidanceSubstance` + `AvoidanceSubstanceTranslations` + `AvoidanceCatalog`)으로 저장됐다. 본 기능은 카탈로그를 **DB(JPA 엔티티)로 영속화**하고 재료(`ingredient`)와 **외래키 매핑**한다. 이유: (1) 재료는 이미 DB에 있어 성분도 DB에 있어야 둘을 FK로 정합 있게 연결하고 음식 조회 시 판정할 수 있다, (2) enum에 코드만 문자열로 참조하는 방식은 DB 무결성을 못 준다, (3) 성분 데이터는 정적이라 번역을 한 테이블 컬럼으로 비정규화해도 무방하다. **004 enum 은 제거하지 않는다** — 도메인 로직(예: #16 판정의 타입 안전 참조)에서 필요할 수 있어 유지하고, enum 데이터를 **DB 시드의 원천**으로 쓴다(enum 데이터 ↔ DB 시드 정합은 테스트로 강제). enum 의 최종 제거/존치는 본 작업 말미 또는 후속에 판단한다(과도기적으로 enum·DB 공존). 사용자 프로필·판정 등급·음식 상세조회 응답 연결은 후속(#16·#17)이며 본 범위 밖이다.

## Clarifications

### Session 2026-07-01

- Q: 성분 카탈로그를 enum 으로 둘까 DB 로 옮길까? → A: **DB(JPA 엔티티)로 영속화**한다. 단 **004 enum 은 제거하지 않고 유지**(도메인 로직 참조 가능성) — enum 을 시드 원천으로 쓰고 공존. enum 최종 제거 여부는 후속 판단.
- Q: 9개국 번역을 어떻게 저장? → A: **한 테이블에 언어별 컬럼으로 비정규화**(정적 데이터). 정규화 행-per-언어 테이블 아님. ko 는 원문 컬럼(`korean_name`), 번역은 9개 타겟 언어 컬럼.
- Q: 분류(3종)는? → A: 성분은 **1~3개 분류에 다대다 소속**. 분류 *값*(ALLERGEN/DIETARY_RULE/PERSONAL_AVOIDANCE)은 고정 enum(코드)으로, 성분↔분류 *멤버십*은 **별도 분류 테이블**로 저장.
- Q: 매핑은 코드 참조 vs FK? → A: 성분이 DB 에 있으므로 매핑은 성분 **FK** 로 참조(무결성 확보).
- Q: 미지원 언어 요청 시 에러(+지원 언어 목록)? → A: **본 기능 범위 밖, 후속 작업으로 미룬다.** 공유 `LanguageCode` 변경이라 음식/스캔에도 영향 → 별도 작업에서 일관 적용. 본 기능은 **ko 폴백만** 다룬다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 회피·주의 성분 카탈로그를 DB로 보유하고 다국어로 조회한다 (Priority: P1)

서비스가 다루는 81종의 회피·주의 성분이 **DB 테이블**에 저장돼 있다 — 각각 **안정적 코드 + ko 원문 명칭 + 9개 대상 언어 번역 + 1~3개 회피 사유 분류**. 시스템은 성분을 코드로 조회하고, 요청 언어로 명칭을(없으면 ko 폴백) 제공하며, 분류로 묶어 조회할 수 있다.

**Why this priority**: 성분 카탈로그는 매핑·판정·다국어 노출 등 모든 후속의 기준 데이터다. DB 영속화 자체가 본 기능의 토대라 P1이며, 이 슬라이스만으로 "성분이 DB에서 코드·번역·분류와 함께 조회된다"를 독립 검증할 수 있다.

**Independent Test**: 시드 적용 후 성분을 코드로 조회하면 ko 명칭·요청 언어 번역(미보유 시 ko 폴백)·1~3개 분류가 반환되고, 분류별 조회 시 해당 분류 성분 목록이 반환되는지 검증한다.

**Acceptance Scenarios**:

1. **Given** 성분 시드가 적용된 상태에서, **When** 저장된 카탈로그를 확인하면, **Then** 81종이 각각 **고유 코드·ko 명칭·1~3개 분류**를 갖고 존재한다.
2. **Given** 한 성분, **When** 특정 대상 언어로 명칭을 조회하면, **Then** 해당 언어 번역 명칭이 반환된다.
3. **Given** 지원 언어인데 그 언어 번역이 없는 성분, **When** 그 언어로 명칭을 요청하면, **Then** ko 원문으로 폴백된다.
4. **Given** 카탈로그, **When** 코드 유일성을 확인하면, **Then** 동일 코드가 중복 저장되지 않는다.
5. **Given** 특정 분류, **When** 그 분류 성분을 조회하면, **Then** 해당 분류에 속한(복수 분류 성분 포함) 성분들이 반환된다.
6. **Given** 여러 분류에 속한 성분, **When** 그 성분의 분류를 확인하면, **Then** 1~3개 분류가 모두 반환된다.

---

### User Story 2 - 재료를 회피·주의 성분에 매핑하고 재료로 조회한다 (Priority: P2)

각 재료(`ingredient`)가 자신이 해당하는 회피·주의 성분(0~N개)과 **외래키로 연결**돼 저장된다. 시스템은 재료 식별자 집합으로 매핑된 성분 목록을 반환한다(판정 입력).

**Why this priority**: 재료↔성분 연결이 없으면 "이 메뉴에 내가 피하는 성분이 있나"를 판정할 수 없다(#15의 직접 목표). US1(성분 카탈로그)이 전제이며, 그 위에서 매핑이 성립한다.

**Independent Test**: 매핑 시드 적용 후 재료 식별자(집합)로 조회 → 연결된 성분(코드·분류 포함) 집합이 정확히 반환되고, 미매핑 재료는 빈 집합으로 반환되는지 검증한다.

**Acceptance Scenarios**:

1. **Given** 재료↔성분 매핑이 적용된 상태에서, **When** 매핑 있는 재료 식별자로 조회하면, **Then** 연결된 1~N개 성분이 반환된다.
2. **Given** 매핑 없는 재료, **When** 조회하면, **Then** 빈 성분 집합이 반환된다.
3. **Given** 여러 재료 식별자, **When** 일괄 조회하면, **Then** 재료별 매핑 성분이 정확히 구분돼 반환된다.
4. **Given** 매핑, **When** (재료, 성분) 유일성을 확인하면, **Then** 동일 조합이 중복 저장되지 않는다.
5. **Given** 한 재료가 여러 성분에, 한 성분이 여러 재료에 연결, **When** 조회하면, **Then** 다대다 관계가 모두 반영된다.

---

### User Story 3 - 음식 단위로 포함된 회피·주의 성분 집합을 도출한다 (Priority: P3)

특정 음식에 대해, 구성 재료들에 매핑된 성분을 **합집합**(중복 없음)으로 도출한다.

**Why this priority**: 사용자 판정·음식 상세조회는 음식 단위로 동작한다. US2 위에 얹는 조합으로, #17이 소비할 형태를 만든다. 가장 상위 슬라이스라 P3.

**Independent Test**: 재료 구성이 알려진 음식에 대해 성분 합집합을 도출하면, 재료별 매핑 합집합과 일치하고 매핑 없는 재료만이면 빈 집합이 나오는지 검증한다.

**Acceptance Scenarios**:

1. **Given** 재료 구성이 있는 음식, **When** 성분 집합을 도출하면, **Then** 구성 재료 매핑 성분의 합집합(중복 없음)이 반환된다.
2. **Given** 같은 성분에 매핑된 재료가 둘 이상, **When** 도출하면, **Then** 그 성분은 한 번만 포함된다.
3. **Given** 매핑된 재료가 없는 음식, **When** 도출하면, **Then** 빈 집합이 반환된다.

---

### Edge Cases

- **번역이 비어 있는 언어로 명칭 요청** → ko 원문 폴백(음식명 정책과 동일). (미지원 언어 코드 → 에러 처리는 후속 작업.)
- **ko 원문이 빈 성분** → 허용 안 함(모든 성분 ko 명칭 필수).
- **분류 0개 성분 / 3종 외 분류값** → 허용 안 함(1~3개, 3종 고정).
- **같은 (성분, 분류) 중복 / 같은 (재료, 성분) 중복** → 허용 안 함(집합, UNIQUE 제약).
- **매핑 없는 재료** → 빈 성분 집합(후속 판정에서 미상 처리).
- **소프트 삭제된 성분/재료/매핑** → 조회 제외(소프트삭제 정책 일관).
- **동일 데이터 중복 시드** → 멱등(중복 행 없음).
- 카탈로그·매핑은 **읽기 전용 참조 데이터** — 런타임 사용자 CRUD 경로 없이 시드로만 관리.

## Requirements *(mandatory)*

### Functional Requirements

#### 성분 카탈로그 (US1)

- **FR-001**: 시스템은 회피·주의 성분 **81종**을 **DB 테이블**에 저장해야 한다(각 성분 1행).
- **FR-002**: 각 성분은 **유일한 코드**, **ko 원문 명칭**(비공백), **9개 대상 언어 번역 명칭**(zh-Hans·en·ja·zh-Hant·vi·id·th·ru·es)을 가져야 한다. 번역은 **성분 테이블의 언어별 컬럼**으로 비정규화 저장한다(정적 데이터).
- **FR-003**: 대상 언어 번역이 비어 있으면 그 명칭은 **ko 원문으로 폴백**해야 한다(미지원 언어 코드에 대한 에러 처리는 본 기능 범위 밖 — 후속 작업).
- **FR-004**: 코드는 **유일성**을 보장해야 한다(중복 코드 저장 불가).
- **FR-005**: 각 성분은 **1~3개의 회피 사유 분류**(ALLERGEN | DIETARY_RULE | PERSONAL_AVOIDANCE)에 속해야 한다(다대다, 중복 없는 집합). 분류 멤버십은 **별도 분류 테이블**에 저장하고, 분류 값은 3종으로 고정한다.
- **FR-006**: 시스템은 성분을 **코드로 조회**하고 **분류로 묶어 조회**할 수 있어야 한다.

#### 재료↔성분 매핑 (US2)

- **FR-007**: 시스템은 각 재료(`ingredient`)에 **0개 이상의 회피·주의 성분**을 **외래키로 연결**해 저장해야 한다(재료↔성분 다대다).
- **FR-008**: 동일 **(재료, 성분)** 매핑은 중복 저장되지 않아야 한다.
- **FR-009**: 매핑은 **기존 공유 재료**(`ingredient`)와 **성분 카탈로그**(US1)를 외래키로 참조하며 둘 다 복제하지 않는다.
- **FR-010**: 시스템은 **재료 식별자 집합으로 매핑된 성분 집합을 조회**할 수 있어야 한다(재료별 구분, 미매핑 재료는 빈 집합).

#### 음식 단위 도출 (US3)

- **FR-011**: 시스템은 **음식의 구성 재료들에 매핑된 성분의 합집합**(중복 없음)을 도출할 수 있어야 한다.

#### 공통

- **FR-012**: 카탈로그·매핑은 **읽기 전용 참조 데이터**다 — 런타임 사용자 CRUD 없이 **시드(Flyway)로만** 적재·관리한다.
- **FR-013**: 모든 조회는 **소프트 삭제(ACTIVE)** 만 반영한다.
- **FR-014**: 본 기능은 카탈로그 영속화·매핑·조회에 한정한다 — 사용자 프로필, 판정 등급, 분류별 경고 문구, 음식 상세조회 응답 연결은 **범위 밖**(후속).

### Key Entities *(include if feature involves data)*

- **회피·주의 성분 (Avoidance substance)**: 카탈로그 1행. 유일 코드 + ko 원문 명칭 + 9개 대상 언어 번역(언어별 컬럼). member 의 사용자 제약과 food 의 재료 매핑이 공유하는 공통 기준.
- **성분 분류 멤버십 (Substance category membership)**: 한 성분이 속한 한 분류. (성분, 분류) 쌍으로 유일. 성분당 1~3개. 분류 값은 ALLERGEN/DIETARY_RULE/PERSONAL_AVOIDANCE 3종 고정.
- **재료–성분 매핑 (Ingredient–substance mapping)**: 한 재료와 한 성분의 연결. (재료, 성분) 쌍으로 유일. 다대다. 재료·성분 모두 외래키 참조.
- **재료 (기존)**: food 컨텍스트 공유 지식베이스. 매핑 대상이며 본 기능에서 새로 만들지 않는다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 시드 후 81종이 100% 저장되며 코드 중복 0건, 각 성분이 ko 명칭과 1~3개 유효 분류를 갖는다.
- **SC-002**: 모든 성분이 1~3개 분류에 속하고 분류값은 3종 외 0건, (성분,분류) 중복 0건.
- **SC-003**: 번역 등록 성분은 요청 언어로 100% 해당 명칭, 부재 시 100% ko 폴백(빈 명칭 0).
- **SC-004**: 재료 식별자 집합 조회 시 매핑 성분이 100% 정확히 반환되고 미매핑 재료는 빈 집합.
- **SC-005**: (재료,성분) 중복 0건, 동일 데이터 중복 시드 시 중복 행 0건(멱등).
- **SC-006**: 임의 음식의 성분 합집합이 구성 재료 매핑 합집합과 정확히 일치(중복 없음).
- **SC-007**: 코드·분류·재료 식별자가 후속(member·food·#16·#17)이 참조하기에 안정적이다.

## Assumptions

- **콘텐츠 출처**: 81종 코드·ko·9번역·분류는 **004 enum 의 현재(mock) 데이터를 DB 시드로 이전**한다. 확정 콘텐츠 수령 시 시드 교체. 재료↔성분 매핑 값은 콘텐츠 의존 — 확정 전 대표 mock 시드.
- **번역 비정규화**: 정적 81행이라 9개 언어를 성분 테이블 컬럼으로 둔다(기존 `food_name_translation` 정규화 패턴과 의도적으로 다름 — 정적·소량이라 합리적). ko 는 `korean_name` 원문 컬럼, 번역 컬럼은 9개 타겟 언어.
- **분류 enum 유지**: 분류 값(3종)은 고정 라벨이라 enum 으로 두고 VARCHAR 로 저장(RiskLevel·EntityStatus 패턴과 동일). 성분↔분류 멤버십만 테이블.
- **enum 유지(공존)**: 004 의 `AvoidanceSubstance`·`AvoidanceSubstanceTranslations`·`AvoidanceCatalog`·`AvoidanceCategory` 는 **제거하지 않는다**. DB 엔티티·리포지토리·도메인 모델을 **추가**하고, enum 데이터를 시드 원천으로 쓴다. enum 은 도메인 로직(예: #16 판정의 타입 안전 참조)에서 계속 쓰일 수 있다. enum↔DB 데이터 정합은 테스트로 강제. enum 의 최종 제거/존치는 본 작업 말미 또는 후속에 판단(과도기 공존).
- **읽기 전용**: 어드민 CRUD 없음. 시드로만.
- **소유 컨텍스트**: 카탈로그·매핑은 avoidance 가 소유(도메인 모델·port). JPA 엔티티·어댑터는 `:infra:persistence`(원칙 IV). 음식↔성분 조합은 application.
- **다국어 폴백**: ADR-0003(ko + 9 언어, ko 폴백)과 동일.

## Dependencies / Open Questions

- **헌법 원칙 V 개정 의존**: 현재 원칙 V 예외 단서가 "고정 reference taxonomy 는 컴파일 enum 저장 허용"을 명시한다. 본 기능은 그 반대(DB 영속화)이므로 **별도 `/speckit-constitution` 개정**으로 단서를 조정해야 한다(governance, 본 기능과 분리하되 선행 권장).
- **004 와의 관계**: 본 기능은 004 위에 DB 영속화를 **추가**한다(enum 제거 아님). enum 데이터를 DB 시드 원천으로 이전하되 enum 자체는 유지. 최종 정리(enum 제거 vs 존치, 헌법 원칙 V 단서 조정)는 후속.
- **기존 재료 시드**(food V3) 존재에 의존(매핑 대상).
- **확정 매핑 콘텐츠**(어떤 재료=어떤 성분)는 시드 단계에서 수령.
- **미지원 언어 에러(후속 작업으로 분리)**: "미지원 언어 코드 → 에러 + 지원 언어 목록 메시지" 는 공유 `LanguageCode`/`LanguageResolver` 동작 변경이라 음식 상세조회·메뉴 스캔에도 영향을 준다(현재 `LanguageCode.from` 은 미지원 코드를 조용히 `KO` 처리). 일관 적용이 필요하므로 **본 기능에서 제외하고 별도 후속 작업**으로 다룬다(strict 해석 통일 + 기존 사용처 회귀). 본 기능은 ko 폴백만 구현.
