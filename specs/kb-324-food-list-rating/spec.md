# Feature Specification: 음식 목록 응답에 리뷰 평점·개수 추가

**Feature Branch**: `kb-324-food-list-rating`

**Created**: 2026-08-11

**Status**: Draft

**Input**: User description: "KB-324 — 음식 리스트 조회에서 리뷰 평점과 개수를 포함. 리뷰 3개·평균 4.3인 음식이 목록 화면에선 '— · 0'으로 뜸(FE 실기 발견 8/11). 목록 아이템 스키마에 평점 필드가 없어서이며, 음식 목록·홈 인기 섹션·검색 레일이 전부 같은 스키마라 한 번에 해결 대상."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 음식 카드에서 평점·리뷰 수 확인 (Priority: P1)

사용자가 음식 목록·홈 인기 섹션·검색 결과를 둘러볼 때, 각 음식 카드에 평균 평점과 리뷰 수가 표시된다. 리뷰가 쌓인 음식(예: 리뷰 3개·평균 4.3)이 "— · 0" 으로 보이는 문제가 사라지고, 상세 화면에 들어가지 않아도 음식의 평판을 한눈에 비교할 수 있다.

**Why this priority**: 세 화면이 같은 목록 아이템 응답을 공유하므로 이 하나로 전 화면이 해결된다. 평점은 음식 선택의 핵심 판단 근거인데 현재 목록에서 보이지 않는다(상세에는 이미 있음).

**Independent Test**: 리뷰가 있는 음식과 없는 음식을 준비한 뒤 목록·검색·홈 응답을 조회하면, 각 음식 아이템에 평균 평점·리뷰 수가 포함되고 상세 조회의 전체 집계 값과 일치하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 리뷰 3건(평균 4.3)이 등록된 음식이 있을 때, **When** 음식 목록을 조회하면, **Then** 그 음식 아이템에 평균 평점 4.3 과 리뷰 수 3 이 포함된다.
2. **Given** 같은 음식이 있을 때, **When** 검색 결과·홈 인기 섹션을 조회하면, **Then** 목록과 동일한 평점·리뷰 수가 포함된다.
3. **Given** 리뷰가 하나도 없는 음식이 있을 때, **When** 목록을 조회하면, **Then** 평점은 값 없음, 리뷰 수는 0 으로 내려간다.
4. **Given** 리뷰 일부가 삭제된 음식이 있을 때, **When** 목록을 조회하면, **Then** 삭제된 리뷰를 뺀 집계가 내려가고 상세 화면의 집계와 일치한다.

---

### Edge Cases

- 리뷰가 0건인 음식 — 평점은 값 없음(0.0 이 아닌 "없음"), 리뷰 수 0. 화면의 "—" 표시와 자연스럽게 대응.
- 소프트 삭제된 리뷰는 집계에서 제외된다(상세 집계와 동일 규칙).
- 탈퇴·차단 회원의 리뷰는 집계에 포함된다 — 상세 집계·리뷰 노출 규칙에서 확정한 "목록만 필터, 집계 불변" 원칙과 일치. 목록·상세의 수치가 서로 다르면 안 된다.
- 목록 페이지에 음식이 많아도 응답 속도가 리뷰 수에 비례해 느려지지 않아야 한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 음식 목록 아이템 응답에 평균 평점과 리뷰 수가 포함되어야 한다.
- **FR-002**: 음식 목록·홈 인기 섹션·검색 결과 세 경로 모두 동일하게 적용되어야 한다(공유 스키마 1곳 수정).
- **FR-003**: 평균 평점·리뷰 수는 음식 상세의 전체(overall) 집계와 항상 같은 값이어야 한다(집계 규칙 동일 — 삭제 리뷰 제외, 탈퇴·차단 리뷰 포함).
- **FR-004**: 리뷰가 없는 음식은 평점 값 없음·리뷰 수 0 으로 내려간다.
- **FR-005**: 기존 목록 응답 필드는 이름·타입·의미 모두 유지된다(필드 추가만).

### Key Entities

- **음식 목록 아이템**: 목록·홈·검색이 공유하는 음식 요약 표현 — 평균 평점·리뷰 수가 추가된다.
- **리뷰**: 집계의 원천. 이번 기능에서 변경되지 않는다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 리뷰가 있는 음식이 목록·검색·홈 어디에서도 "— · 0" 으로 표시되지 않는다.
- **SC-002**: 목록 아이템의 평점·리뷰 수가 같은 음식의 상세 화면 전체 집계와 100% 일치한다.
- **SC-003**: 클라이언트가 목록 화면의 평점 표시를 위해 추가 조회를 0회 수행한다.
- **SC-004**: 목록 조회 응답 시간이 페이지 내 음식들의 리뷰 총량과 무관하게 유지된다.

## Assumptions

- 목록에는 상세의 이중 집계(전체·동일 국적) 중 **전체(overall) 집계만** 내려간다 — 카드 표시에는 전체 평점이면 충분하고, 국적별 비교는 상세 화면 몫.
- 리뷰 0건의 평점 표현은 "값 없음"(null)으로 한다 — 상세의 0.0 표현과 다르지만 목록 "—" 표시 요구와 맞으며, 구체 표현은 FE 와 계약 문서로 확정한다.
- 평점 소수 표현(반올림 자릿수)은 상세와 동일 규칙을 따른다.
- 정렬(평점순 등)·필터는 이번 범위 밖이다 — 표시 전용.
