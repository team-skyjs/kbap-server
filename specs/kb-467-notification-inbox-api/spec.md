# Feature Specification: 회원 알림함 API — 최근 7일 알림 목록·읽음 처리

**Feature Branch**: `kb-467-notification-inbox-api`

**Created**: 2026-09-07

**Status**: Draft

**Jira**: [KB-467](https://simhani1.atlassian.net/browse/KB-467) (에픽 KB-463 푸시 알림 — 토큰·설정·알림함 API와 Expo 배치 발송)

**Input**: User description: "사용자에게 보낸 알림 히스토리 목록 조회, 읽음 처리를 만들어야 한다. 알림은 여러 종류가 있지만 히스토리는 종류 구분 없이 전체 조회하면 된다." 명확화(2026-09-07): **회원 전용**. **미읽음 수 미제공**(홈은 항상 새 알림이 있는 것처럼 표시). **최근 7일 이내 알림만 반환하므로 페이징 없음.** **읽음 취소 없음**(한 번 읽으면 끝). **모두 읽기 없음.** 항목 정보는 **제목·본문·알림 시각·읽음 여부**(읽지 않음 = 새 알림)면 된다.

## 배경

앱의 알림함 화면은 지금 기기에 남은 푸시 payload 만 보여 준다. 앱을 지우거나 기기를 바꾸면 이력이 사라지고, 서버가 배치로 보낸 알림이 실제로 누구에게 갔는지 앱에서 확인할 길이 없다.

KB-464 가 알림 1건마다 `notification` 행(수신자·유형·제목·본문·부가 데이터·읽은 시각)을 남기는 저장 기반을 만들었다. 이 기능은 그 행 중 **최근 7일치**를 회원 알림함의 정본으로 앱에 열어 준다. 종류를 가리지 않고 시간 역순 한 줄기로 보여 주며, 7일이 지난 알림은 알림함에서 사라진다. 알림함은 "최근에 무슨 일이 있었나" 를 보는 곳이지 보관함이 아니다.

알림 행을 **만드는** 쪽(발송 배치, KB-468 이후)은 이 기능의 범위가 아니다.

## 범위

- **포함**: 회원 본인의 최근 7일 알림 목록(최신순, 한 번에 전부), 알림 1건 읽음 처리.
- **제외**: 페이징, 모두 읽기, 읽음 취소, 미읽음 개수, 종류별 필터, 삭제, 7일보다 오래된 알림 조회, 게스트 알림함, 알림 생성·발송, 조회 시점 언어 재렌더(저장된 제목·본문 그대로).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 회원이 최근 7일 알림을 최신순으로 본다 (Priority: P1)

회원이 알림함을 열면 최근 7일 안에 자신에게 온 알림이 최신 것부터 한 번에 나온다. 종류에 상관없이 한 목록이고, 각 항목에 제목·본문·알림 시각·읽음 여부가 있다. 읽지 않은 항목이 곧 "새 알림" 이다. 7일이 지난 알림은 나오지 않는다.

**Why this priority**: 알림함의 존재 이유. 읽음 처리(P2)는 목록이 있어야 의미가 있다.

**Independent Test**: 회원에게 7일 이내 알림과 7일 지난 알림을 심고 조회 → 이내 것만 최신순으로 전부, 다른 회원 알림은 없음.

**Acceptance Scenarios**:

1. **Given** 알림이 한 건도 없는 회원, **When** 목록을 조회하면, **Then** 빈 목록을 받는다.
2. **Given** 7일 이내 알림 5건과 8일 전 알림 2건을 가진 회원, **When** 목록을 조회하면, **Then** 5건만 알림 시각 역순으로 온다.
3. **Given** 종류가 섞인 알림(도움됨·공지·식사 제안)을 가진 회원, **When** 목록을 조회하면, **Then** 종류 구분 없이 한 목록에 시간 역순으로 섞여 나온다.
4. **Given** 회원 A 와 B 가 각각 알림을 가진 상태, **When** A 가 조회하면, **Then** B 의 알림은 한 건도 보이지 않는다.
5. **Given** 읽은 알림과 안 읽은 알림이 섞인 회원, **When** 조회하면, **Then** 읽은 항목은 읽음, 안 읽은 항목은 읽지 않음으로 표시되고 정렬은 읽음 여부와 무관하게 시간 역순이다.
6. **Given** 인증 없는 요청, **When** 조회하면, **Then** 인증 오류로 거절된다.

---

### User Story 2 - 회원이 알림 하나를 읽음 처리한다 (Priority: P2)

회원이 알림 항목을 누르면 그 알림이 읽음으로 바뀐다. 한 번 읽으면 되돌릴 수 없고, 이미 읽은 알림을 다시 눌러도 오류 없이 그대로다. 남의 알림은 존재 자체를 알 수 없다.

**Why this priority**: 목록 다음의 기본 상호작용.

**Independent Test**: 안 읽은 알림 읽음 처리 → 읽음. 다시 처리 → 그대로 성공. 타인 알림 id → 없음 오류.

**Acceptance Scenarios**:

1. **Given** 안 읽은 알림을 가진 회원, **When** 그 알림을 읽음 처리하면, **Then** 성공하고 이후 목록에서 읽음으로 표시된다.
2. **Given** 이미 읽은 알림, **When** 다시 읽음 처리하면, **Then** 성공하고 상태는 읽음 그대로다.
3. **Given** 회원 A, **When** 회원 B 의 알림 id 로 읽음 처리하면, **Then** "알림 없음" 오류를 받고 B 의 알림은 바뀌지 않는다.
4. **Given** 존재하지 않는 알림 id, **When** 읽음 처리하면, **Then** "알림 없음" 오류를 받는다(타인 알림과 구분되지 않는다).
5. **Given** 7일이 지난 본인 알림, **When** 읽음 처리하면, **Then** 성공한다(읽음 처리는 기간 제한 없음 — 목록에 안 보일 뿐).
6. **Given** 인증 없는 요청, **When** 읽음 처리하면, **Then** 인증 오류로 거절된다.

---

### Edge Cases

- **"7일" 의 경계는?** 조회 시각 기준 정확히 168시간 전 이후. 날짜 단위로 자르지 않는다.
- **7일 안에 알림이 수백 건이면?** 전부 반환한다. 발송 정책상 회원 1인당 하루 수 건 수준이라 상한을 두지 않는다.
- **회원이 로그인하기 전 기기(게스트)로 받은 알림은?** 회원 알림함에 보이지 않는다. 게스트 알림의 회원 승계는 범위 밖이다.
- **삭제(소프트)된 알림은?** 목록에 나오지 않고 읽음 처리 대상도 아니다("알림 없음").
- **탈퇴한 회원의 알림은?** 탈퇴 회원은 인증이 거절되므로 도달하지 않는다.
- **제목·본문은 어느 언어로 나오나?** 저장된 그대로. 발송 시점에 수신자 언어로 렌더된 문자열을 저장한다는 전제다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 인증된 회원 본인의 알림만 목록으로 제공해야 한다. 다른 회원·게스트 기기의 알림은 어떤 경우에도 포함하지 않는다.
- **FR-002**: 목록은 조회 시각 기준 최근 7일(168시간) 이내 알림 전부이며 알림 시각 역순(최신 먼저)이다. 페이징·필터가 없다.
- **FR-003**: 각 항목은 식별자·제목·본문·알림 시각·읽음 여부를 담는다. 제목·본문은 저장된 문자열 그대로이고, 알림 시각은 앱의 다른 목록(리뷰·주문)과 같은 숫자 타임스탬프 형식이다.
- **FR-004**: 회원은 자신의 알림 1건을 읽음 처리할 수 있다. 처리는 멱등이며 되돌릴 수 없다. 기간 제한이 없다.
- **FR-005**: 타인의 알림·존재하지 않는 알림·삭제된 알림에 대한 읽음 처리는 "알림 없음" 으로 거절하며, 셋을 구분해 알려 주지 않는다.
- **FR-006**: 두 기능 모두 인증 없는 요청을 거절한다.
- **FR-007**: 모두 읽기·읽음 취소·미읽음 개수는 제공하지 않는다(2026-09-07 결정).

### Key Entities

- **알림(Notification)**: 회원에게 보낸 알림 1건. 수신 회원, 제목, 본문, 알림 시각, 읽은 시각. KB-464 의 기존 저장 구조를 그대로 쓰며 새 저장 항목은 없다. 종류·부가 데이터는 저장돼 있으나 이 기능의 응답에는 싣지 않는다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 회원이 알림함을 열면 최근 7일 목록이 1초 안에 나타난다.
- **SC-002**: 7일 경계 밖 알림이 목록에 섞여 나오는 경우 0건.
- **SC-003**: 읽음 처리 후 즉시 다시 조회하면 100% 읽음으로 반영돼 있다.
- **SC-004**: 타인 알림 id 로 읽음 처리를 시도한 경우 100% 거절되고 대상 알림은 변하지 않는다.
- **SC-005**: 앱을 지우고 다시 설치한 뒤 로그인해도 최근 7일 알림이 그대로 보인다(서버 정본).

## Assumptions

- 알림 행은 발송 배치(KB-468 이후)가 만든다. 검증은 저장소에 직접 심은 알림으로 한다.
- 인증·회원 식별은 기존 JWT 인증 부품을 그대로 쓴다. 게스트는 대상이 아니다.
- 7일 상한이 곧 응답 크기 상한이다. 발송 빈도가 크게 늘면 그때 페이징을 붙인다.
- 응답에 종류·부가 데이터를 싣지 않는 것은 사용자 지시("제목·본문·알림 시각·읽음 여부면 된다")다. 앱이 이동 경로 등을 필요로 하면 저장돼 있는 값이라 후속에서 필드만 추가하면 된다.
- 새 경로는 JWT 보호 경로 목록에 등록해야 한다.
- **비회원(게스트) 알림은 기획 변경으로 제거 예정**(2026-09-07). 이 기능은 회원 알림에만 집중하며 게스트 경로를 설계에 반영하지 않는다. 게스트 토큰 등록 코드 제거는 별도 태스크.
