# Feature Specification: 관리자 음식 수정 안정성 — 편집 모드 토글·상태 자동 전이

**Feature Branch**: `kb-260-admin-food-edit-safety`

**Created**: 2026-07-30

**Status**: Draft

**Input**: User description: "KB-260 [BE] 관리자 음식 수정 안정성 — 편집 모드 토글·상태 자동 전이"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 상세 모달 읽기 전용 기본 + 편집 토글 (Priority: P1)

관리자가 음식 목록에서 상세보기를 열면 모달의 모든 입력 필드가 읽기 전용으로 표시된다. 값을 고치려면 '편집' 버튼을 눌러 명시적으로 편집 모드에 들어가야 하고, 편집을 취소하면 값이 원래대로 돌아가며 다시 읽기 전용이 된다. 실수로 필드를 비우거나 건드린 채 저장해 데이터가 유실되는 사고를 차단한다.

**Why this priority**: 현재 폼은 항상 편집 가능해서 스크롤·복사 중 실수로 값을 지우고 저장하면 그대로 반영된다(빈 값이 "없음/미조사"를 뜻하는 필드 포함). 데이터 유실을 막는 것이 이 이슈의 핵심 가치다.

**Independent Test**: 상세 모달을 열어 모든 필드가 편집 불가인지, '편집' 클릭 후에만 수정·저장이 가능한지, 취소 시 원값이 복원되는지를 화면 단독으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 음식 상세 모달을 연 상태, **When** 아무 조작 없이 필드를 클릭하면, **Then** 값이 수정되지 않는다(모든 입력 비활성).
2. **Given** 읽기 전용 상태의 모달, **When** '편집' 버튼을 누르면, **Then** 모든 입력 필드가 활성화되고 저장이 가능해진다.
3. **Given** 편집 모드에서 값을 바꾼 상태, **When** '취소'(편집 토글 해제)를 누르면, **Then** 바꾼 값이 열람 시점 값으로 복원되고 읽기 전용으로 돌아간다.
4. **Given** 읽기 전용 상태의 모달, **When** 저장을 시도하면, **Then** 저장이 동작하지 않는다(저장 수단 비노출 또는 비활성).

---

### User Story 2 - 저장 시 콘텐츠 완성도 기반 상태 자동 보정 (Priority: P2)

관리자가 음식 정보를 수정·저장하면, 시스템이 콘텐츠 완성도(설명·이름 번역·설명 번역·기피 성분·맵기·이미지)를 판단해 콘텐츠 상태를 자동으로 보정한다. 관리자가 상태 값을 직접 계산해 고르지 않아도, 저장만 하면 데이터 완성도와 상태가 어긋나지 않는다.

**Why this priority**: 수동 수정 후 상태가 실제 완성도와 어긋나는 휴먼 에러(예: 설명·번역이 완비됐는데 INCOMPLETE 유지)가 파이프라인·노출 판단을 오염시킨다. P1이 실수를 막는다면 P2는 올바른 결과를 보장한다.

**Independent Test**: 완성도가 서로 다른 음식 데이터를 저장해 보정된 상태가 규칙대로 나오는지 서버 동작만으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 검수 이전 상태(INCOMPLETE 또는 PENDING_IMAGE)의 음식, **When** 텍스트 콘텐츠(설명·이름 번역·설명 번역·기피 성분·맵기)를 완비해 저장하면, **Then** 상태가 완성도에 맞게 자동 전이된다(이미지 없으면 PENDING_IMAGE, 이미지까지 있으면 PENDING_REVIEW).
2. **Given** 검수 이전 상태의 음식, **When** 텍스트 콘텐츠가 미완인 채 저장하면, **Then** 상태는 INCOMPLETE 로 보정된다(관리자가 다른 검수 이전 상태를 골랐어도).
3. **Given** 음식 수정 화면, **When** 관리자가 상태를 검수 단계(PENDING_REVIEW 또는 READY)로 직접 지정해 저장하면, **Then** 지정한 상태가 그대로 유지된다(자동 보정이 검수 판단을 덮어쓰지 않는다).
4. **Given** 검수 단계(PENDING_REVIEW·READY) 상태의 음식, **When** 상태를 그대로 두고 내용만 수정해 저장하면, **Then** 상태는 바뀌지 않는다.
5. **Given** 자동 보정이 일어난 저장, **When** 목록·상세 화면을 다시 보면, **Then** 보정된 상태가 표시된다.

---

### Edge Cases

- 편집 모드에서 값을 바꾸다 모달을 닫으면(저장하지 않음) 아무것도 반영되지 않는다.
- 관리자가 검수 이전 상태를 선택했지만 콘텐츠가 완성 판정이면, 선택값이 아니라 완성도 기준 상태가 저장된다 — 관리자는 저장 직후 화면에 표시되는 최종 상태로 결과를 확인한다.
- 검수 단계(PENDING_REVIEW·READY)의 음식에서 필수 콘텐츠를 비우고 저장하는 경우: 자동 강등은 하지 않는다(검수 단계는 사람의 판단이 정본). 이런 실수 자체는 P1의 읽기 전용 기본값이 1차로 막는다.
- 기존 저장 검증(빈 이름 거절·중복 이름 거절·번역/성분 JSON 형식 오류 거절)은 그대로 동작하고, 거절된 저장에서는 상태 보정도 일어나지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 음식 상세 모달은 기본적으로 읽기 전용으로 열려야 한다 — 모든 입력 필드(이름·상태·맵기·이미지 키·설명·번역·기피 성분)가 비활성이다.
- **FR-002**: 관리자는 '편집' 버튼으로 편집 모드를 켜고 끌 수 있어야 한다. 편집 모드를 끄면(취소) 변경 중이던 값이 열람 시점 값으로 복원되고 읽기 전용으로 돌아간다.
- **FR-003**: 읽기 전용 상태에서는 저장이 불가능해야 한다.
- **FR-004**: 수정 내용을 저장할 때 시스템은 콘텐츠 완성도에 따라 콘텐츠 상태를 자동 보정해야 한다. 우선순위 규칙: 검수 단계 상태(PENDING_REVIEW·READY)는 관리자의 수동 지정·기존 값을 존중해 그대로 두고, 검수 이전 상태(INCOMPLETE·PENDING_IMAGE)는 저장 시점 완성도로 재계산한다.
- **FR-005**: 자동 보정된 최종 상태는 저장 직후 목록·상세 화면에서 확인 가능해야 한다.
- **FR-006**: 기존 저장 검증(빈 이름·중복 이름·JSON 형식 오류)과 오류 안내는 이번 변경 후에도 동일하게 동작해야 한다.
- **FR-007**: 편집 토글과 상태 자동 보정 시나리오는 구현에 앞서 실패하는 테스트로 먼저 작성한다(Red 선행 — 헌법 원칙 I).

### Key Entities

- **음식(Food)**: 관리 대상 콘텐츠. 한국어 이름(유일)·설명·이름/설명 번역·기피 성분·맵기·이미지·콘텐츠 상태를 가진다.
- **콘텐츠 상태**: INCOMPLETE → PENDING_IMAGE → PENDING_REVIEW → READY 4단계. 검수 이전 2단계는 완성도로 기계 판정 가능하고, 검수 단계 2단계는 사람의 판단이 정본이다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 편집 모드를 켜지 않고는 상세 모달에서 값 변경·저장이 일절 불가능하다 — 의도치 않은 덮어쓰기 경로가 0개가 된다.
- **SC-002**: 텍스트 콘텐츠가 완비된 음식을 저장하면 관리자가 상태 값을 손대지 않아도 상태 불일치(완비인데 INCOMPLETE 유지 등)가 남지 않는다.
- **SC-003**: 관리자는 상태 전이 규칙을 몰라도 내용만 수정·저장하면 올바른 상태를 얻는다 — 저장 후 별도의 상태 수동 보정 작업이 필요 없다.
- **SC-004**: 편집 토글·상태 보정 시나리오가 자동화 테스트로 검증되어 회귀 없이 유지된다.

## Assumptions

- 이 화면은 관리자 전용 페이지이며 사용자는 인증된 관리자뿐이다(기존 관리자 인증 체계 재사용).
- 상태 자동 보정의 완성도 판정 기준은 도메인에 이미 존재하는 전이 규칙을 단일 출처로 재사용한다 — 새 판정 규칙을 만들지 않는다.
- 수동 지정 우선순위는 기존 도메인 의미론을 따른다: 검수 단계(PENDING_REVIEW·READY)는 자동 전이 대상이 아니므로 수동 지정이 우선하고, 검수 이전 단계는 완성도 재계산이 우선한다. 검수 단계에서의 자동 강등은 범위 밖이다.
- 편집 토글은 화면 단 상호작용으로 충분하며 별도 서버 상태(편집 잠금·동시 편집 제어)는 범위 밖이다 — 관리자 페이지는 소수 인원이 사용한다.
- 목록·상세 UX 개선(스크롤 유지·이미지 렌더링)은 KB-259 별도 이슈 범위다.
