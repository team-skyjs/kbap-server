# API Contract: 스캔 무료 3회 제한 (v2 전용)

## POST /api/scans — 잠김 회원의 시도

무료 3회(성공 스캔 누적)를 소진했고 해금되지 않은 회원:

```jsonc
// HTTP 403
{
  "success": false,
  "code": "SCAN-004",
  "message": "무료 스캔 횟수를 모두 사용했습니다. 리뷰를 작성하면 무제한으로 이용할 수 있어요"
}
```

- **클라이언트 분기**: `SCAN-004` → "리뷰 작성 시 해제" 안내 화면. 메시지 문구는 자유 변경 — code 로만 분기.
- 거절 시 서버는 이미지 검증·비전 호출·이력 기록·카운트 증가를 일절 수행하지 않는다(비용 0).
- **v2(X-API-Version 2.0) 전용** — v1(무버전)은 구버전 앱 동결 계약이라 크레딧 제한을 적용하지 않는다(정상 스캔·카운트 누적만). 크레딧 릴리스는 v2 앱과 동행.

## 스캔 티켓 (v2 필수 — POST /api/scans/tickets)

v2 스캔은 **서버 발급 티켓**이 필수다. 플로우: **티켓 발급 → 이미지 업로드 → 스캔**.

- `POST /api/scans/tickets` — 서버 서명 티켓(jti=멱등 키, exp 기본 300초) 발급. **무료 3회 소진·미해금이면 발급 단계에서 403 SCAN-004** — 사진 촬영·업로드 전에 차단된다.
- 스캔 요청의 `X-Scan-Ticket` 헤더에 티켓을 싣는다. 티켓은 시도 단위 — 시도마다 새로 발급.
- 위조·만료·타인 티켓은 **400 SCAN-007**("유효하지 않은 스캔 티켓이에요") — 티켓 재발급 후 재시도.
- 클라이언트 임의 생성 키는 받지 않는다 — 멱등 키(jti)는 서버 서명 안에만 존재해 조작 불가.
- v1(무버전)은 티켓·한도 게이트 모두 미적용 — 구버전 앱 계약 보존(크레딧은 v2 전용).
- 발급 부하 제어(rate limit — 예: 5분 5회)는 후속 태스크.

같은 티켓의 스캔이 **아직 처리 중**인 상태에서 중복 전달되면(응답 유실 재전송):

```jsonc
// HTTP 409
{
  "success": false,
  "code": "SCAN-005",
  "message": "이미 처리 중인 스캔 요청입니다"
}
```

- 중복 요청은 새 무료 슬롯을 소모하지 않고, 비전 호출도 발생하지 않는다.
- 처리가 끝난(성공/실패/만료) 티켓은 유효 시간 내 재사용이 기술적으로 가능하다(서버는 완료 이력을 보관하지 않음) — 클라이언트는 시도마다 새 티켓을 발급받는 것이 규칙이다.

## 허용 규칙

| 상태 | 스캔 |
|---|---|
| 성공 스캔 누적 < 3 | 허용 |
| 리뷰 작성으로 해금됨(`scan_unlocked`) | 허용 (무제한) |
| 누적 ≥ 3 · 해금 안 됨 | **403 SCAN-004** |

- 처리 시작 전에 **Redis 예약 슬롯**(requestId 단위, Lua 원자 판정: DB 확정 횟수 + 처리 중 예약 수 < 3)을 선점한다 — 동시 버스트로도 잔여분을 초과해 통과할 수 없다. `scan_count`(DB)는 성공 확정 시에만 +1 되고, 실패·크래시(TTL 만료)면 예약만 사라져 횟수가 소모되지 않는다.
- 해금은 리뷰 작성 즉시(POST /api/reviews 성공 시) 반영 — 별도 대기 없음.
- 리뷰 삭제 시 즉시 재잠금되지 않음 — 재잠금은 별도 태스크의 주기 배치.

## 스캔 실패 코드 분리 (SCAN-006)

LLM 서버측 장애(timeout·5xx·연결 실패)로 스캔이 실패하면 SCAN-002 와 구분되는 전용 코드로 응답한다:

```jsonc
// HTTP 503
{
  "success": false,
  "code": "SCAN-006",
  "message": "스캔을 완료하지 못했어요. 횟수 차감 없이 다시 시도할 수 있어요."
}
```

- **클라이언트 분기**: `SCAN-006` → 서버측 문제 안내 + 재시도 유도 모달. `SCAN-002`(그 외 인식 실패)·`SCAN-003`(비메뉴판 — 재촬영 안내)은 기존 분기 유지.
- 어느 실패든 무료 횟수는 소모되지 않는다(예약만 제거).

## 무변경

- 허용된 스캔의 요청·응답 계약 전체(v1·v2) · 비회원 401(AUTH-003, 회원가입 유도 분기 근거) · 기존 스캔 실패 코드(SCAN-001/002/003)의 의미.
