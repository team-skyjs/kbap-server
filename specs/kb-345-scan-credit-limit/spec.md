# Feature Specification: 회원 스캔 이용 정책 — 무료 3회·리뷰 작성 시 해금

**Feature Branch**: `kb-345-scan-credit-limit`

**Created**: 2026-08-19

**Status**: Draft

**Input**: User description: "KB-345 — 회원 누적 3회 스캔 제한, 리뷰 1회 이상 작성 시 해금. 단순 API 호출만으로 카운트가 증가해선 안 되며 어뷰징 방어 필요."

## 맥락

- 8/15 기획 결정: 회원의 스캔은 **누적 3회까지 무료**, **리뷰를 1건 이상 작성하면 무제한 해금**. 리뷰 작성 유도를 통한 콘텐츠 축적이 목적.
- 현재 스캔 횟수 제한은 없다 — `scanCount` 는 랭킹용 누적 카운터일 뿐 게이트가 아니다.
- 비회원 스캔은 이미 401 로 거절된다(스캔은 회원 전용) — 클라이언트는 이 코드로 회원가입 유도 분기가 가능함을 계약으로 확인한다.
- **어뷰징·오차감 방어**: 카운트는 "스캔이 실제로 성공해 판정 결과를 받은 경우"에만 증가한다. 현재 구조가 이미 이 시점(추출·판정·이력 기록 완료 후)에 카운트하므로, 실패한 호출(이미지 검증 실패·비전 인식 실패·비메뉴판 400)은 무료 횟수를 소모하지 않는다 — 임의 반복 호출이나 실패 유도로는 횟수가 줄지도, 제한을 우회하지도 못한다(성공 스캔은 실제 비용이 발생하므로 차감이 정당).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 무료 3회를 소진하면 스캔이 잠긴다 (Priority: P1)

리뷰를 쓴 적 없는 회원은 성공한 스캔 누적 3회까지만 이용할 수 있고, 4회째 시도는 "리뷰를 작성하면 풀린다"고 안내할 수 있는 전용 코드로 거절된다.

**Why this priority**: 정책의 본체 — 제한이 있어야 해금도 의미가 있다.

**Independent Test**: 리뷰 0건 회원으로 스캔 3회 성공 → 4회째 전용 에러. 실패 스캔은 횟수 미소모 확인.

**Acceptance Scenarios**:

1. **Given** 리뷰 0건·성공 스캔 2회 회원, **When** 스캔하면, **Then** 정상 동작하고 누적 3회가 된다.
2. **Given** 리뷰 0건·성공 스캔 3회 회원, **When** 4회째 스캔을 시도하면, **Then** 전용 에러 코드로 거절된다(클라이언트가 "리뷰 작성 시 해제" 안내로 분기).
3. **Given** 리뷰 0건·성공 스캔 3회 회원, **When** 거절된 시도를 반복하면, **Then** 계속 같은 코드로 거절되고 카운트·비용이 발생하지 않는다(거절은 스캔 실행 전에 판정).
4. **Given** 스캔 시도가 실패(이미지 검증 실패·비전 인식 실패·비메뉴판)하면, **When** 응답을 받으면, **Then** 무료 횟수는 소모되지 않는다.
5. **Given** 제한 판정, **When** v2 스캔(티켓 발급 포함)에서, **Then** 적용된다 — v1(구버전 앱 동결 계약)은 제한 밖(2026-08-20 재결정, research R4-2).

---

### User Story 2 - 리뷰를 작성하면 스캔이 무제한 해금된다 (Priority: P1)

리뷰를 1건 이상 작성한 회원은 무료 횟수 소진과 무관하게 스캔을 제한 없이 이용한다.

**Why this priority**: 제한의 짝 — 해금 경로가 있어야 정책이 완성된다.

**Independent Test**: 3회 소진·잠김 회원이 리뷰 1건 작성 → 즉시 스캔 가능.

**Acceptance Scenarios**:

1. **Given** 스캔이 잠긴(3회 소진·리뷰 0건) 회원, **When** 리뷰를 1건 작성한 뒤 스캔하면, **Then** 정상 동작한다(별도 대기·재로그인 불필요).
2. **Given** 리뷰를 이미 작성한 회원, **When** 스캔을 몇 번을 하든, **Then** 제한이 적용되지 않는다.
3. **Given** 해금된 회원, **When** 작성한 리뷰를 모두 삭제하면, **Then** 이번 범위에서는 해금이 유지된다 — 재잠금은 **별도 태스크의 주기 배치**가 담당한다(리뷰 0건 해금 회원 검사·잠금 회수, 2026-08-19 분리 확정). 해금 상태는 이 배치가 소비할 수 있는 형태로 저장한다.

---

### Edge Cases

- 성공 스캔의 정의는? — 판정 결과가 정상 반환된 경우(추출 실패·비메뉴판·이미지 검증 실패는 실패 — 미소모). 카운트 시점이 스캔 성공 뒤라 "단순 API 호출"로는 증가하지 않는다.
- 기존 회원(배포 시점에 이미 성공 스캔 3회 이상)은? — **일괄 적용**(명확화 확정, 2026-08-19). 기존 회원 상태를 반영하는 백필 마이그레이션은 만들지 않는다 — 해금 상태는 배포 이후의 리뷰 작성으로만 세워지므로, 과거에 리뷰를 썼던 회원도 무료 3회 소진 상태면 새 리뷰를 작성해야 해금된다(감수).
- 4회째 거절 시 스캔 비용은? — 제한 판정을 스캔 실행(비전 호출) 전에 수행해 LLM 비용·이력 기록이 발생하지 않는다.
- 동시 요청으로 3회를 초과하면? — **초과하지 않는다**(재개정 2026-08-19). 처리 시작 전에 요청 단위 예약 슬롯을 원자적으로 선점(확정 횟수 + 처리 중 예약 수 < 3)하고, 성공 확정 시에만 횟수를 소모한다 — 잔여분만큼만 통과하며 실패·장애 시 예약은 자동 회수된다. 같은 요청 식별자의 중복 전달은 새 슬롯을 쓰지 않고 거절된다(409).
- 비회원은? — 기존 401 그대로(이미 회원 전용) — 신규 코드 불필요, 계약 문서에 회원가입 유도 분기 근거로 명시.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 리뷰 작성 이력이 없는 회원의 스캔은 **성공 누적 3회**까지 허용된다. 제한은 **v2 전용**이다(티켓 발급·스캔 게이트) — v1 은 구버전 앱 동결 계약이라 미적용(2026-08-20 재결정).
- **FR-002**: 무료 횟수를 소진한(그리고 리뷰가 없는) 회원의 스캔 시도는 **전용 에러 코드**로 거절된다 — 클라이언트가 "리뷰를 작성하면 해제됩니다" 안내로 분기할 수 있는 안정 식별자.
- **FR-003**: 거절 판정은 스캔 실행 전에 수행된다 — 거절된 시도는 비용(외부 호출)·스캔 이력·카운트를 발생시키지 않는다.
- **FR-004**: 실패한 스캔(이미지 검증 실패·인식 실패·비메뉴판 등 오류 응답)은 무료 횟수를 소모하지 않는다 — 카운트는 성공 응답에만 증가한다.
- **FR-005**: 리뷰를 작성하면 즉시 무제한 해금된다. 해금 상태는 저장되며 스캔 판정은 이 상태를 본다.
- **FR-006**: 리뷰 삭제 시점에 즉시 재잠금하지 않는다 — 재잠금(리뷰 0건 해금 회원의 주기 검사·회수)은 **별도 태스크의 배치**가 담당하며, 이번 범위는 그 배치가 판정에 쓸 해금 상태 저장까지다.
- **FR-007**: 비회원 스캔은 기존과 동일하게 인증 오류로 거절된다 — 클라이언트 회원가입 유도 분기의 계약 근거를 문서화한다.
- **FR-008**: 이 제한은 스캔 성공의 의미·응답 계약을 바꾸지 않는다 — 허용된 스캔의 동작은 종전과 동일하다.

### Key Entities

- **회원 스캔 이용 상태**: 성공 스캔 누적 횟수 + **해금 상태(저장값)** 로 판정한다 — 허용 = 누적 3회 미만 또는 해금 상태. 해금은 리뷰 작성 시 즉시 세워지고, 배치가 리뷰 0건 회원의 해금을 주기적으로 회수한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 리뷰 0건 회원의 4회째 스캔 시도는 100% 전용 코드로 거절되고, 거절 시도에서 외부 비용·이력이 0건 발생한다.
- **SC-002**: 실패 스캔으로 무료 횟수가 줄어드는 경우가 0건이다 — 반복 실패 호출로 제한을 조작할 수 없다.
- **SC-003**: 리뷰 작성 후 첫 스캔부터 즉시 해금된다 — 지연·재로그인 0건.
- **SC-004**: 허용된 스캔(1~3회차·해금 후)의 기존 동작 회귀 0건.

## Assumptions

- 무료 한도 3회는 고정 정책값이다(회원별·기간별 변동 없음 — 기간제 리셋 아님, 누적).
- 재잠금 배치는 별도 태스크로 분리(2026-08-19) — 그 전까지 리뷰 삭제 후에도 해금이 잔존하는 것은 감수한다.
- 기존 회원 백필 마이그레이션은 만들지 않는다 — 배포 시점 리뷰 보유 회원도 해금 상태가 아니므로, 3회 소진 시 새 리뷰 작성으로 해금한다.
- 잔여 횟수 표시용 별도 조회 API 는 범위 밖 — 클라이언트는 전용 에러 코드로 잠김을 인지한다(필요 시 후속).
- 스캔 크레딧의 결제·충전 개념은 범위 밖(8/15 결정에 없음).
- 어뷰징 방어의 핵심은 (1) 성공에만 카운트, (2) 거절을 실행 전에 판정해 비용 차단 — 두 가지로 충분하며, 기기/IP 단위 추가 방어는 범위 밖.
