# Jira 데일리 스탠드업 코멘트 등록 (KB 프로젝트)

특정 Jira 이슈에 **그날의 진행 상황을 데일리 스탠드업 포맷**으로 코멘트로 남기는 표준 절차. 날짜는 자동으로 채우고, 세 항목의 내용은 **Claude 가 그날 작업 내역에서 직접 작성**한다 — 이번 세션에서 실제로 한 일·오늘 커밋(git log)·남은 후속을 근거로 **개조식, 항목당 5개 이하**로 간결히 요약하고, 적을 게 없는 섹션은 `없음` 으로 채운다. 사용자에게 각 항목을 되묻지 않는다(초안을 채워 미리보기로 보여주고 승인만 받는다).

## 코멘트 포맷 (고정)

```
yyyy-mm-dd
진행한 것
- ~~~
블락된 것
- ~~~
진행할 것
- ~~~
```

- 첫 줄은 **오늘 날짜**(`yyyy-mm-dd`), 자동 채움.
- 세 섹션(`진행한 것`·`블락된 것`·`진행할 것`) 각각 아래에 **개조식 불릿**으로 Claude 가 작성한 요약을 넣는다.
- **각 섹션 불릿은 최대 5개.** 핵심만 추려 간결한 명사형/개조식으로 쓴다.
- **항목 순서·라벨은 바꾸지 않는다.** 적을 게 없는 섹션은 단일 불릿 `없음`.

## 사전 조건

- `create-jira-task` 스킬과 동일한 Jira 접속 조건을 따른다 — Atlassian MCP 서버 연결(`/mcp` 에서 `atlassian` ✓ Connected), 도구 스키마는 `ToolSearch` 로 `mcp__atlassian__*` 를 불러온 뒤 호출.
- Jira 사이트 `simhani1.atlassian.net`, cloudId `50957656-c97c-4cc0-b1ca-f209cef7d5c9`(불확실하면 `getAccessibleAtlassianResources` 로 재확인).

## 절차 (체크리스트)

1. **대상 이슈 확정** — 코멘트를 달 이슈 키(예: `KB-88`)를 정한다.
   - 사용자가 호출에 이슈 키를 줬으면 그걸 쓴다.
   - 없으면 현재 작업 중인 이슈 키를 사용자에게 **묻는다**(브랜치명 등에서 유추 가능하면 제안하되 확정은 사용자에게).

2. **오늘 날짜 채우기** — `date +%Y-%m-%d` 를 실행해 헤더 날짜를 얻는다(로컬 타임존 Asia/Seoul 기준). 사용자에게 날짜를 되묻지 않는다.

3. **세 항목 자동 작성 (Claude 가 직접, 되묻지 않음)** — 사용자에게 항목을 역질문하지 않고, **그날 작업 내역에서 Claude 가 세 항목을 직접 채운다**. 순서·라벨은 `진행한 것` → `블락된 것` → `진행할 것` 고정.
   - **근거 소스**: (a) **현재 브랜치에서 개발한 핵심 기능/변경**(무엇을·어떻게 동작), (b) 오늘 커밋·diff — `git log --since=00:00 --author="$(git config user.name)"`·`git diff develop...HEAD`(로컬 Asia/Seoul)로 개발 내용을 파악(커밋 제목을 그대로 붙이지 말 것), (c) 진행 중 태스크의 다음 단계·차단.
   - **① 진행한 것**: **현재 브랜치에서 개발한 핵심 내용과 그 설명** 최대 5개. `PR 생성`·`커밋`·`문서 정리` 같은 프로세스 잡무가 아니라, **무엇을 만들었고 어떻게 동작하는지**를 개발 관점으로 쓴다(예: "메뉴 목록 조회 API — keyset 커서 무한스크롤 구현").
   - **② 블락된 것**: 진행을 막은 의존/이슈. 실제 블로커가 없으면 **`없음`**. 없는 걸 지어내지 않는다.
   - **③ 진행할 것**: **진행 중인 태스크의 다음 단계 = 내일 할 일** 최대 5개. `PR 리뷰 반영`·`리네임 검토` 같은 개인적·프로세스 행동이 아니라 **태스크 관점의 다음 작업**(예: "상세 조회 foodId 정합 KB-98 착수"). 진행 중 태스크가 없으면 `없음`.
   - 각 불릿은 **간결한 개조식**(명사형 위주), 섹션당 **5개 이하**. 근거가 불확실하면 추측으로 채우지 말고 그 섹션은 보수적으로(핵심만 또는 `없음`) 둔다.
   - **Jira 이슈 키를 언급하면(예: `KB-98`) 예외 없이 그 키에 하이퍼링크를 건다**(ADF `link` 마크 — 아래 "ADF 규약"). 코멘트를 다는 **대상 이슈 자신(예: `KB-90`)도 포함**한다.
   - 실제 한 일이 세션 밖에 있어 파악이 어려우면, 되묻기 전에 **git log·현재 브랜치/PR 상태**로 먼저 추정하고, 그래도 비면 `없음` 으로 둔 채 4번 미리보기에서 사용자가 보완하게 한다.

4. **미리보기 + 확인 게이트** — Claude 가 채운 초안 코멘트(날짜 헤더 + 세 섹션 개조식)를 사용자에게 **그대로 보여주고 승인을 받는다**. 대상 이슈 키도 함께 확인시킨다.
   - 사용자가 수정/추가/삭제를 원하면 반영하고 다시 보여준다. **승인 전에는 등록하지 않는다.**
   - Jira 에 실제로 올라가는 액션이므로 이 게이트는 건너뛰지 않는다(내용은 Claude 초안이지만 최종 책임 확인은 사용자 몫).

5. **코멘트 등록** — 승인되면 `addCommentToJiraIssue`(`contentFormat:"adf"`):
   - `cloudId` = 위 값, `issueIdOrKey` = 1번 이슈 키
   - `commentBody` = 아래 "ADF 규약"의 문서(날짜 heading + 섹션별 라벨 + 개조식 불릿)

6. **보고** — 코멘트를 단 이슈 키·URL(`https://simhani1.atlassian.net/browse/<KEY>`)을 사용자에게 전달한다.

## ADF 규약

- **마크다운이 아니라 ADF** 로 넣는다(개조식 불릿이 렌더되도록).
  - 날짜 → `heading`(level 3)
  - 섹션 라벨(`진행한 것` 등) → `paragraph` 안 **`strong` 텍스트**
  - 각 섹션 내용 → `bulletList` / `listItem` / `paragraph`
- **본문에 등장하는 모든 Jira 이슈 키(`KB-NN`)에 `link` 마크를 달아 `https://simhani1.atlassian.net/browse/KB-NN` 로 하이퍼링크한다.** 다른 태스크든 코멘트 대상 이슈 자신이든 예외가 없다. 불릿 한 줄이 "일반 텍스트 + 링크 + 일반 텍스트" 조합이면 `paragraph.content` 에 text 노드를 여러 개 나눠 담고 링크 텍스트에만 `link` 마크를 붙인다.
- 한글은 `\u` 이스케이프 대신 **한글 그대로** 넣는다.

### ADF 예시

```json
{
  "type": "doc",
  "version": 1,
  "content": [
    { "type": "heading", "attrs": { "level": 3 }, "content": [{ "type": "text", "text": "2026-07-06" }] },

    { "type": "paragraph", "content": [{ "type": "text", "text": "진행한 것", "marks": [{ "type": "strong" }] }] },
    { "type": "bulletList", "content": [
      { "type": "listItem", "content": [{ "type": "paragraph", "content": [{ "type": "text", "text": "메뉴 스캔 API 응답 스키마 확정" }] }] }
    ] },

    { "type": "paragraph", "content": [{ "type": "text", "text": "블락된 것", "marks": [{ "type": "strong" }] }] },
    { "type": "bulletList", "content": [
      { "type": "listItem", "content": [{ "type": "paragraph", "content": [{ "type": "text", "text": "없음" }] }] }
    ] },

    { "type": "paragraph", "content": [{ "type": "text", "text": "진행할 것", "marks": [{ "type": "strong" }] }] },
    { "type": "bulletList", "content": [
      { "type": "listItem", "content": [{ "type": "paragraph", "content": [
        { "type": "text", "text": "상세 조회 foodId 정합 " },
        { "type": "text", "text": "KB-98", "marks": [{ "type": "link", "attrs": { "href": "https://simhani1.atlassian.net/browse/KB-98" } }] },
        { "type": "text", "text": " 착수 — 목록→상세 클릭스루 완결" }
      ] }] }
    ] }
  ]
}
```

## 흔한 함정

- **항목을 사용자에게 되묻기** — 3번은 **Claude 가 직접** 채운다. 세션 내역·오늘 커밋으로 추정하고, 비면 `없음`. 승인은 4번 미리보기 게이트에서만 받는다.
- **섹션당 6개 이상·장황한 문장** — 각 섹션 **최대 5개**, 간결한 개조식. 사소한 것까지 나열하지 말고 핵심만.
- **없는 블로커를 지어내기** — 실제 차단이 없으면 `블락된 것`·`진행할 것` 은 `없음`. 채우려고 억지 항목을 만들지 않는다.
- **이슈 키를 맨 텍스트로 두기** — `KB-NN` 이 본문에 보이면 대상 이슈 자신이라도 반드시 `link` 마크를 단다.
- **날짜를 되묻기** — 날짜는 자동(`date +%Y-%m-%d`). 사용자에게 묻지 않는다.
- **마크다운 본문** → 불릿/라벨이 안 뜬다. 반드시 `contentFormat:"adf"`.
- **Jira 네이티브 "작업 로그(worklog)" 와 혼동** — 이건 시간 기록(worklog)이 아니라 **일반 코멘트**다. `addCommentToJiraIssue` 를 쓰고 `addWorklogToJiraIssue` 는 쓰지 않는다.
- **대상 이슈 불명확** — 이슈 키가 없으면 임의로 고르지 말고 사용자에게 확인한다.
- **확인 없이 등록** — 실제로 Jira 에 올라가는 액션이므로, 미리보기+승인 게이트(4번)를 건너뛰지 말 것.
