# Jira 데일리 스탠드업 코멘트 등록 (KB 프로젝트)

특정 Jira 이슈에 **그날의 진행 상황을 데일리 스탠드업 포맷**으로 코멘트로 남기는 표준 절차. 날짜는 자동으로 채우고, 세 항목의 내용은 **사용자에게 한 항목씩 단계별로 역질문해서 받은 그대로** 넣는다 — **윤문·재작성·요약 등 수정은 하지 않는다**(원문 그대로). 표현을 다듬고 싶으면 이 스킬이 아니라 별도로 처리한다.

## 코멘트 포맷 (고정)

```
yyyy-mm-dd
진행한 것
- ~~~
블락된 것
- ~~~
진행할 것
- ~~~
```

- 첫 줄은 **오늘 날짜**(`yyyy-mm-dd`), 자동 채움.
- 세 섹션(`진행한 것`·`블락된 것`·`진행할 것`) 각각 아래에 **개조식 불릿**으로 사용자 원문을 넣는다.
- **항목 순서·라벨·문구를 바꾸지 않는다.** 사용자가 준 텍스트를 줄 단위로 그대로 불릿에 매핑한다.

## 사전 조건

- `create-jira-task` 스킬과 동일한 Jira 접속 조건을 따른다 — Atlassian MCP 서버 연결(`/mcp` 에서 `atlassian` ✓ Connected), 도구 스키마는 `ToolSearch` 로 `mcp__atlassian__*` 를 불러온 뒤 호출.
- Jira 사이트 `simhani1.atlassian.net`, cloudId `50957656-c97c-4cc0-b1ca-f209cef7d5c9`(불확실하면 `getAccessibleAtlassianResources` 로 재확인).

## 절차 (체크리스트)

1. **대상 이슈 확정** — 코멘트를 달 이슈 키(예: `KB-88`)를 정한다.
   - 사용자가 호출에 이슈 키를 줬으면 그걸 쓴다.
   - 없으면 현재 작업 중인 이슈 키를 사용자에게 **묻는다**(브랜치명 등에서 유추 가능하면 제안하되 확정은 사용자에게).

2. **오늘 날짜 채우기** — `date +%Y-%m-%d` 를 실행해 헤더 날짜를 얻는다(로컬 타임존 Asia/Seoul 기준). 사용자에게 날짜를 되묻지 않는다.

3. **세 항목 단계별 역질문 (한 번에 하나씩)** — 세 항목을 **순서대로 한 번에 하나씩** 묻는다. 플랜 세울 때처럼 **이전 답을 받은 뒤에 다음 항목으로 넘어간다**. 순서는 `진행한 것` → `블락된 것` → `진행할 것`.
   - **① 진행한 것** 을 먼저 묻고 답을 받는다 → 받으면 **② 블락된 것** 을 묻는다 → 받으면 **③ 진행할 것** 을 묻는다.
   - 각 단계에서 물을 때, 지금이 몇 번째/무엇을 묻는지 명확히 한다(예: "①/③ 진행한 것 — 오늘 한 일을 알려주세요"). 다음 질문은 **직전 답을 받은 뒤에만** 던진다.
   - 사용자가 한 항목에 여러 줄을 주면 각 줄을 하나의 불릿으로 취급한다.
   - **비어 있는 섹션**(예: 블로커 없음)은 단일 불릿 `없음` 으로 채운다. 사용자가 "없음"·"스킵"·"넘어가" 등으로 답하면 그대로 `없음` 처리하고 다음 항목으로 넘어간다.
   - 받은 텍스트는 **그대로** 사용한다 — 오타 교정·윤문·재배열 금지.
   - **세 항목을 한꺼번에 몰아 묻지 않는다.** 반드시 하나 받고 다음으로 넘어간다. (사용자가 먼저 셋을 한 번에 다 준 경우에만 추가 질문 없이 4번으로 진행.)

4. **미리보기 + 확인 게이트** — 조립된 코멘트(날짜 헤더 + 세 섹션 개조식)를 사용자에게 **그대로 보여주고 승인을 받는다**. 대상 이슈 키도 함께 확인시킨다.
   - 사용자가 수정/추가를 원하면 반영하고 다시 보여준다. **승인 전에는 등록하지 않는다.**
   - 내용 자체는 원문 그대로 유지(윤문 금지) — 게이트는 "이 이슈에 이대로 올릴지"를 확인하는 용도지 문장을 다듬는 단계가 아니다.

5. **코멘트 등록** — 승인되면 `addCommentToJiraIssue`(`contentFormat:"adf"`):
   - `cloudId` = 위 값, `issueIdOrKey` = 1번 이슈 키
   - `commentBody` = 아래 "ADF 규약"의 문서(날짜 heading + 섹션별 라벨 + 개조식 불릿)

6. **보고** — 코멘트를 단 이슈 키·URL(`https://simhani1.atlassian.net/browse/<KEY>`)을 사용자에게 전달한다.

## ADF 규약

- **마크다운이 아니라 ADF** 로 넣는다(개조식 불릿이 렌더되도록).
  - 날짜 → `heading`(level 3)
  - 섹션 라벨(`진행한 것` 등) → `paragraph` 안 **`strong` 텍스트**
  - 각 섹션 내용 → `bulletList` / `listItem` / `paragraph`
- 한글은 `\u` 이스케이프 대신 **한글 그대로** 넣는다.

### ADF 예시

```json
{
  "type": "doc",
  "version": 1,
  "content": [
    { "type": "heading", "attrs": { "level": 3 }, "content": [{ "type": "text", "text": "2026-07-06" }] },

    { "type": "paragraph", "content": [{ "type": "text", "text": "진행한 것", "marks": [{ "type": "strong" }] }] },
    { "type": "bulletList", "content": [
      { "type": "listItem", "content": [{ "type": "paragraph", "content": [{ "type": "text", "text": "메뉴 스캔 API 응답 스키마 확정" }] }] }
    ] },

    { "type": "paragraph", "content": [{ "type": "text", "text": "블락된 것", "marks": [{ "type": "strong" }] }] },
    { "type": "bulletList", "content": [
      { "type": "listItem", "content": [{ "type": "paragraph", "content": [{ "type": "text", "text": "없음" }] }] }
    ] },

    { "type": "paragraph", "content": [{ "type": "text", "text": "진행할 것", "marks": [{ "type": "strong" }] }] },
    { "type": "bulletList", "content": [
      { "type": "listItem", "content": [{ "type": "paragraph", "content": [{ "type": "text", "text": "food 상세조회 위험도 정책 문서화" }] }] }
    ] }
  ]
}
```

## 흔한 함정

- **내용을 다듬으려는 유혹** — 이 스킬은 원문 그대로 넣는 게 핵심이다. 오타·비문이 보여도 교정하지 말 것(사용자가 명시적으로 고쳐달라고 할 때만).
- **세 항목을 한꺼번에 묻기** — 3번은 **한 항목씩 단계별로** 묻는다. `진행한 것`→`블락된 것`→`진행할 것` 순으로 하나 받고 다음으로 넘어간다(플랜 세우듯). 단, 사용자가 처음부터 셋을 다 준 경우엔 그대로 진행.
- **날짜를 되묻기** — 날짜는 자동(`date +%Y-%m-%d`). 사용자에게 묻지 않는다.
- **마크다운 본문** → 불릿/라벨이 안 뜬다. 반드시 `contentFormat:"adf"`.
- **Jira 네이티브 "작업 로그(worklog)" 와 혼동** — 이건 시간 기록(worklog)이 아니라 **일반 코멘트**다. `addCommentToJiraIssue` 를 쓰고 `addWorklogToJiraIssue` 는 쓰지 않는다.
- **대상 이슈 불명확** — 이슈 키가 없으면 임의로 고르지 말고 사용자에게 확인한다.
- **확인 없이 등록** — 실제로 Jira 에 올라가는 액션이므로, 미리보기+승인 게이트(4번)를 건너뛰지 말 것.
