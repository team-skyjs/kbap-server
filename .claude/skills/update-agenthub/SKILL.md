# 지식 허브(kbap-agenthub) 갱신

이번 세션의 작업에서 나온 **코드로 알 수 없는 도메인 지식·결정**을 `../kbap-agenthub` 위키에 반영하는 절차. 새 문서 추가만이 아니라 **이번 작업으로 거짓이 된 기존 문서의 정정까지**가 한 세트다.

## 사전 조건

- 허브 위치: `/Users/simjonghan/source_code/swm-kbap/kbap-agenthub` (kbap·kbap-langchain 공유, 독립 repo, main 직커밋 운영 — PR 없음).
- 기록 규칙의 단일 출처는 **허브의 `CLAUDE.md`** — 절차가 어긋나 보이면 그쪽이 우선.

## 절차 (체크리스트)

1. **기록 대상 선별** — 이번 세션에서 다음에 해당하는 것만 고른다:
   - 코드·ADR·`docs/` 를 읽어도 알 수 없는 결정과 그 **근거**(예: "선택 헤더로 두고 필수화 안 함 — 기배포 앱이 깨져서").
   - 정책·수위 판단(예: MDC 에 담는 정보의 수위), 배포 순서 제약, 반복될 함정.
   - **넣지 않는 것**: 구현 세부(각 repo `docs/`), SpecKit 산출물(`specs/`), 코드 읽으면 아는 것. 남길 게 없으면 "갱신할 것 없음"으로 보고하고 끝낸다.

2. **INDEX.md 먼저 읽기** — `../kbap-agenthub/INDEX.md` 로 기존 문서를 파악한다. **기존 주제와 겹치면 그 문서를 갱신**(위키는 살아있는 문서)하고, 정말 새 주제일 때만 새 파일을 만든다.

3. **낡아진 기존 문구 정정** — 이번 작업으로 사실이 바뀐 부분을 위키에서 키워드 grep 으로 찾아 함께 고친다(예: 헤더 필수화 후에도 "미전송이면 1.0" 으로 남은 문구). 새 지식 추가보다 이 정정이 누락되기 쉽다.

4. **새 문서 작성 규칙** — `wiki/<kebab-case-topic>.md`, repo 전용이면 frontmatter 에 `repo: kbap`(또는 `kbap-langchain`) 한 줄. 관련 문서는 `[[문서명]]` 으로 링크. 개조식·간결하게, "코드로 안 보이는 결정" 중심으로.

5. **INDEX.md 갱신** — 문서 생성·이름변경 시 반드시 `- [제목](wiki/파일.md) — 한줄 요약` 한 줄을 추가·갱신한다. 색인이 곧 분류다.

6. **허브에서 커밋 + 푸시** — main 직커밋:
   ```bash
   cd /Users/simjonghan/source_code/swm-kbap/kbap-agenthub && git add -A && git commit -m "wiki: <요약>" && git push
   ```

7. **보고** — 추가/정정한 문서 목록과 커밋 해시를 사용자에게 전달한다.

## 주의

- **데일리 로그(`daily/`)는 건드리지 않는다** — `/clear` 시 SessionEnd 훅이 자동 기록하는 append-only 영역이다. 이 스킬의 대상은 `wiki/` 뿐이다.
- **cwd 리셋 함정**: 셸 cwd 가 명령 사이에 메인 체크아웃으로 돌아올 수 있다 — 허브 작업은 절대경로 또는 `cd ... && ...` 단일 명령으로 묶는다.
- 위키 본문을 통째로 로드하지 않는다 — INDEX 로 고르고 필요한 문서만 읽는다.
